真题 · 2024 年第 2 题：表达式 x + y * (z − u) / v 的等价后缀式是（　）。A. xyzu−*v/+　B. xyzu−v/*+　C. +x/*y−zuv　D. +x*y/−zuv
解（用栈转换）：操作数直接输出，运算符按优先级与结合性入栈：x 输出；+ 入栈；y 输出；* 优先级高于 +，入栈；( 入栈；z 输出；− 入栈；u 输出；遇 ) 弹出 −；/ 与 * 同级且左结合，先弹出 * 再将 / 入栈；v 输出；收尾依次弹出 /、+。得到 xyzu−*v/+ → A。
2. KMP（克努特–莫里斯–普拉特模式匹配算法） 串模式匹配 · next 数组与 nextval ★★☆☆☆

核心思想：匹配失配时主串指针 i 不回退，只按 next 数组回退模式串指针，跳过已知不可能匹配的位置。复杂度：求 next 为 O(m)，匹配为 O(n)，总计 O(n + m)，空间 O(m)；朴素 BF 最坏 O(n·m)。

例（next 与 nextval 全计算）：模式串 P = ABABAC，用 408 / 王道口径（下标 1 起）：next[1] = 0，next[j] = 「P 前 j − 1 个字符的最长相等真前缀与真后缀长度」+ 1。逐位算：
j1 (A)2 (B)3 (A)4 (B)5 (A)6 (C)
考察串—AABABAABABABABA
最长相等前后缀—001 (A)2 (AB)3 (ABA)
next[j]011234
nextval[j]010104
nextval 是 next 的「防白比」优化：若 P[j] = P[next[j]]，失配跳过去还会再失配，索性一步跳到底，nextval[j] = nextval[next[j]]；不同则 nextval[j] = next[j]。如 j = 5：P[5] = A，P[next[5]] = P[3] = A，相同 → nextval[5] = nextval[3]；而 P[3] = A = P[1]，nextval[3] = nextval[1] = 0，故 nextval[5] = 0。j = 6：P[6] = C ≠ P[4] = B → nextval[6] = next[6] = 4。
手算口诀：在失配位置之前划一条分界线，将模式串逐步后退，直到分界线之前的前缀能与刚划过的后缀对齐，此时 j 指向哪里，next 值就是多少。滑动规则：失配时主串指针 i 不动，模式串右移 j − next[j] 位。

另有「长度定义」（下标 0 起）：next 值即最长相等真前后缀长度本身，如 ABABAC 依次为 0, 0, 1, 2, 3, 0。两套口径数值整体差 1，做题先认题干给的定义。

真题 · 2019 年第 9 题：设主串 T = “abaabaabcabaabc”，模式串 S = “abaabc”，采用 KMP 算法进行模式匹配，到匹配成功时为止，单个字符间的比较次数是（　）。A. 9　B. 10　C. 12　D. 15
解：S 的 next 数组（下标 0 起口径）为 −1, 0, 0, 1, 1, 2。第一趟从 T[0] 起连比 6 次，在 T[5] = a 与 S[5] = c 处失配；按 next[5] = 2 回退，S[2] 与 T[5] 对齐继续，连比 4 次（T[5..8] 依次对 S[2..5]）匹配成功。共 6 + 4 = 10 次 → B。
坑：不同教材下标起点不同（0 起 / 1 起），next 数值会整体差 1。做题先认题干给的 next 定义，不要硬背一组数字。
3. 二叉树性质公式 ★★★★☆
结点数：n = n0 + n1 + n2　（n0 叶子，n1 度为 1，n2 度为 2）
边数：n − 1 = n1 + 2n2
  • 叶子结点：n0 = n2 + 1（任意二叉树成立）。
  • 第 i 层最多结点数：2i−1（i ≥ 1）。
  • 高度为 h 的二叉树最多结点数：2h − 1。
4. 完全二叉树编号规律 ★★☆☆☆

结点从 1 开始编号，结点 i：

  • 父结点：⌊i2⌋。
  • 左孩子：2i；右孩子：2i + 1。
  • n 个结点的完全二叉树高度：h = ⌈log2(n+1)⌉ = ⌊log2 n⌋ + 1。
图：10 个结点的完全二叉树（编号 1 ~ 10）：结点 i 的父结点为 ⌊i / 2⌋，左、右孩子为 2i、2i + 1。
真题 · 2009 年第 5 题：已知一棵完全二叉树的第 6 层（设根为第 1 层）有 8 个叶结点，则该完全二叉树的结点个数最多是（　）。A. 39　B. 52　C. 111　D. 119
解：结点数最多 → 取树高 7。前 6 层为满二叉树：26 − 1 = 63 个；第 6 层共 32 个结点，其中 8 个是叶结点，其余 24 个各带 2 个孩子，第 7 层有 48 个结点。总数 = 63 + 48 = 111 → C。
【坑】从 0 开始编号时：左孩子 2i+1，右孩子 2i+2，父结点 ⌊i−12⌋。

真题 · 2020 年第 4 题：森林 F 的先根遍历序列是 a, b, c, d, e, f，中根遍历序列是 b, a, d, f, e, c，则 F 对应二叉树 T 的后根遍历序列是（　）。A. b, a, d, f, e, c　B. b, d, f, e, c, a　C. b, f, e, d, c, a　D. f, e, d, c, b, a

6. 二叉树：由遍历序列定树 ★★★★☆
组合能否唯一确定
先序 + 中序能
后序 + 中序能
先序 + 后序不能（分不出左右子树分界；如先序 AB、后序 BA，B 可为左孩子或右孩子）
仅任一种遍历不能
  • 构造口诀：先序找根（首个）/ 后序找根（末个），中序按根分左右，递归还原。
  • 先序序列 == 中序序列 ⇒ 所有非叶结点只有右子树。
  • 中序序列 == 后序序列 ⇒ 所有非叶结点只有左子树。
  • 先序与后序互为逆序 ⇒ 每个结点至多一个孩子，树是一条单链（高 = 结点数）。
图：由先序 A B D E C F 与中序 D B E A F C 唯一确定的二叉树（其后序为 D E B F C A）。
7. 线索二叉树 · 线索化与找前驱 / 后继 ★★☆☆☆

动机：n 个结点的二叉链表有 n + 1 个空指针，把空指针利用起来指向前驱 / 后继，就不用再递归找遍历顺序。

结点加两个标志：ltag = 0 表示左孩子、= 1 表示左线索；rtag 同理。按某种遍历顺序线索化后，中序线索树可不借助栈遍历。

图：中序线索二叉树，中序序列 D B E A C F。线索共 5 条：D 的右线索 → B、E 的左线索 → B、E 的右线索 → A、C 的左线索 → A、F 的左线索 → C；序列首尾的 D 左、F 右两个空指针无线索可指，置空。6 个结点恰有 7 = n + 1 个空指针。
中序线索树找法
找后继rtag = 1 时右指针即后继；rtag = 0 时后继是右子树中最左下的结点
找前驱ltag = 1 时左指针即前驱；ltag = 0 时前驱是左子树中最右下的结点
真题 · 2013 年第 5 题：若 X 是后序线索二叉树中的叶结点，且 X 存在左兄弟结点 Y，则 X 的右线索指向（　）。A. X 的父结点　B. 以 Y 为根的子树的最左下结点　C. X 的左兄弟结点 Y　D. 以 Y 为根的子树的最右下结点
解：X 有左兄弟 ⇒ X 是右孩子。后序遍历按左、右、根的次序，右孩子叶结点在后序序列中的后继正是其父结点 → A。
记忆：先序线索找后继要小心——先序后继可能是左孩子或右孩子，左子树存在时后继必在左子树，不能只按“右指针”判断；中序最规整，是考题主力。

10. 图的遍历与生成树 ★★★★☆

DFS（深度优先）一路走到底再回头，得到深度优先生成树 / 森林；BFS（广度优先）按层推进，得到广度优先生成树 / 森林。连通图遍历一次得生成树，非连通图得生成森林。序列怎么来，看例子：

例（同一张图跑 DFS 与 BFS）：无向图邻接表（邻接点按编号从小到大）：V1: V2, V3；V2: V1, V4, V5；V3: V1, V5；V4: V2, V6；V5: V2, V3, V6；V6: V4, V5。从 V1 出发。
DFS：访问 V1 → 钻 V2 → 钻 V4 → 钻 V6 → V6 的邻居只剩 V5 未访，钻 V5 → V5 的邻居只剩 V3，钻 V3 → 全部访问完回溯。序列：V1, V2, V4, V6, V5, V3。
BFS：访问 V1，V2、V3 入队；出队 V2，V4、V5 入队；出队 V3（邻居都已在队中）；出队 V4，V6 入队；再依次出队 V5、V6。序列：V1, V2, V3, V4, V5, V6。
真题 · 2020 年第 6 题：修改递归实现的 DFS 算法，将输出顶点信息的语句移到退出递归前（递归返回时才输出）。用修改后的算法遍历有向无环图 G，若输出结果包含 G 中的全部顶点，则输出的顶点序列是 G 的（　）。A. 拓扑有序序列　B. 逆拓扑有序序列　C. 广度优先搜索序列　D. 深度优先搜索序列
解：任取一条边 ⟨vi, vj⟩：vi 入栈后必须先递归遍历完其后继 vj 才会返回输出，故 vj 总在 vi 之前输出——每条边都是终点在前、起点在后，正是逆拓扑序 → B。
坑：邻接表存储时，遍历序列不唯一（取决于边的存储顺序）。
11. 最小生成树对比 · Prim vs Kruskal ★★★☆☆
项目Prim（点出发）Kruskal（边出发）
做法从任一顶点长出一棵树，每步加「树内—树外」最小边边按权从小到大排序，依次加不成环的边（并查集判环）
时间复杂度邻接矩阵 O(V2)；邻接表 + 堆 O(E log V)排序主导 O(E log E) = O(E log V)
适合图稠密图稀疏图
停止条件连通图：共加 V − 1 条边；非连通图只能得到最小生成森林
例（同一张图，两种算法）：无向图边（端点，权）：(1,2)6、(1,3)1、(1,4)5、(2,3)5、(2,5)3、(3,4)5、(3,5)6、(3,6)4、(4,6)2、(5,6)6。
Prim（从 1 出发，每步在「已收顶点 ↔ 未收顶点」的边里挑最小）：先收 (1,3)=1；候选里最小是 (3,6)=4；再 (6,4)=2；再 (3,2)=5；最后 (2,5)=3。选中边的权依次为 1、4、2、5、3，总权 15。
Kruskal（边按权从小到大，能连不同集合就要）：(1,3)=1 ✓、(4,6)=2 ✓、(2,5)=3 ✓、(3,6)=4 ✓（合并两组）、(1,4)=5 ✗（已在同一集合，加了成环，跳过）、(2,3)=5 ✓。共 5 条边，总权 15。
本例两条路线选边顺序不同，但最终选中的边集相同、得到同一棵树。一般规律是：最小生成树的权和唯一，树本身可以不唯一（存在可替代的等权边时）。另：求最小生成树的前提是图连通；非连通图没有覆盖全部顶点的生成树，两种算法都只能得到最小生成森林——Kruskal 跑完自然成森林，Prim 需对每个连通分量各启动一次。

真题 · 2020 年第 8 题：若用 AOE 网估算工程进度，则下列叙述中正确的是（　）。A. 关键路径是从源点到汇点边数最多的一条路径　B. 关键路径是从源点到汇点路径长度最长的路径　C. 增加任一关键活动的时间不会延长工程的工期　D. 缩短任一关键活动的时间将会缩短工程的工期
解：关键路径按路径长度（权值之和）最大界定，与边数无关，A 错、B 对；关键活动的时间余量为 0，增时会延长工期，C 错；存在多条关键路径时，只缩短其中一条路径上的活动不一定能缩短工期，D 错 → B。
坑：关键路径可能不唯一；缩短工期要求每条关键路径都被缩短——加快所有关键路径共有的关键活动最直接，也可分别加快每条关键路径上的活动；只加快某一条路径上的活动、其他关键路径不缩短，工期不变；关键活动缩过头会变成非关键活动（新关键路径出现），工期不再减少；但延长任一关键活动必延长工期。
15. 顺序查找 ASL（平均查找长度） ★★★☆☆
  • 顺序查找：从表的一端逐个比较，顺序表、链表都行，有序、无序表都能用；时间复杂度 O(n)，适合 n 较小、或插入删除频繁的表。
  • 无序表 ASL：成功 ASL = n + 12（等概率），失败 ASL = n + 1（要一直比到表尾）。
  • 有序表 ASL：成功仍为 n + 12；失败可提前停（key 一旦小于当前元素即判定失败），失败 ASL = 1 + 2 + … + n + nn + 1，约为 n2，可用判定树逐层数出来。
  • 哨兵法：在表的一端设哨兵存放待查值，循环里免去下标越界判断，代码更简洁；ASL 不变。
  • 概率不等时：把查找概率高的元素排在前面，ASL 才最小。

星级注：本卡与《折半查找判定树与 ASL》共享「平均查找长度 + 数组查找」标签口径（9 年），顺序查找本身的考查频度更低，星级为按载体细化的上位口径估计，非独立统计。

16. 折半查找判定树与 ASL（平均查找长度） ★★★★☆
  • 判定树：反复取中点 mid = ⌊low + high2⌋ 为根递归构造，是一棵平衡的二叉排序树；圆结点 = 元素（成功），方框结点 = 失败区间，共 n + 1 个。
  • 查找成功的比较次数 = 元素在判定树中的层数（根为第 1 层）；查找失败的比较次数 = 失败方框结点的父结点层数。
ASL(成功) = Σ 各层结点数 × 层数n；　ASL(失败) = Σ 各失败区间父层数n + 1
  • 例：n = 11 时 ASL(成功) = 1×1 + 2×2 + 3×4 + 4×411 = 3，ASL(失败) = 113；近似式 ASL(成功) ≈ log2(n+1) − 1。
  • 折半查找时间复杂度 O(log2 n)，比较次数至多 ⌊log2 n⌋ + 1。
真题 · 2023 年第 8 题：对含有 600 个元素的有序顺序表进行折半查找，关键字之间的比较次数最多是（　）。A. 9　B. 10　C. 30　D. 300
解：最坏比较次数 = 判定树高度 = ⌊log2 600⌋ + 1 = 9 + 1 = 10 → B。
17. 二叉排序树 BST · 查找 / 插入 / 删除 ★★★★☆

定义：左子树所有关键字 < 根，右子树所有关键字 > 根；中序遍历得到有序序列。查找从根出发，比当前结点小走左、大走右，相等即命中，走到空指针即失败。

操作做法
插入按查找路径走到空指针处挂上新结点；已存在相同关键字则不插入
删除叶子直接删，父结点指针置空
删除仅一子结点用其孩子顶替它
删除有两子结点用中序前驱（左子树最大）或中序后继（右子树最小）顶替，再删去那个前驱 / 后继结点
时间：平均 O(log n)，最坏退化成单链 O(n)。删除后仍须保持 BST 性质；“用前驱 / 后继顶替”是大题最常考的点。

19. B 树性质 ★★★★☆

m 阶 B 树：

  • 根结点：若不是叶子，至少 2 个子树。
  • 非根结点：至少 ⌈m2⌉ 个子树，至少 ⌈m2⌉ − 1 个关键字。
  • 所有结点：最多 m 个子树，最多 m − 1 个关键字。
  • 所有叶结点在同一层（平衡）。
  • 叶结点口径注：本合辑从王道口径，叶结点指最底层不含关键字的外部失败结点（《B 树 vs B+ 树对比》卡同此口径）；另有教材把最底层含关键字的终端结点称作叶结点，此时树的层数比本口径少一层——高度、层数类计算先认题干采用的定义。

20. B 树 vs B+ 树对比 ★★★★☆

《B 树性质》讲 B 树的结构性质与高度，本卡补它缺的另一半：B+ 树与 B 树的成对区别。B 树考性质与高度，B+ 树考“数据只在叶层、叶链表”带来的查找与范围查询差异。

对比项B 树B+ 树

  • 适用：B+ 树是数据库与文件系统索引的主流选择，范围查询多时优势明显；只考单点查找时两者差距不大。

21. 分块查找与散列表 ASL（平均查找长度） ★★★★☆

分块查找（表长 n 分 b 块、每块 s 个，块间有序、块内无序；ASL = 索引表 ASL + 块内 ASL）：

索引、块内均顺序查找：ASL(成功) = b+12 + s+12 = s2 + 2s + n2s，当 s = √n 时最小，为 √n + 1。
  • 索引改用折半查找时：ASL = 折半查索引的 ASL + s+12；其中折半部分的平均 ASL 用近似式 log2(b+1) − 1（满判定树近似）；⌈log2(b+1)⌉ 是查索引的最坏比较次数（判定树高度），不要把它当成平均 ASL。

散列表（装填因子 α = nm）：实际 ASL 取决于散列函数、冲突处理方法、装填因子 α 以及关键字分布（聚集程度），必须按具体探测过程逐个计算；只有在均匀散列假设下，期望 ASL 才只由 α 决定。

  • 反例：m = 5、H(k) = k mod 5、线性探测，α 同为 0.6：插入 0、1、2 时成功 ASL = 1，插入 0、5、10 时成功 ASL = 2——α 相同，实际 ASL 不同。
  • 成功 ASL：每个已有元素的探测次数之和 ÷ 元素个数 n（建表时放入的探测次数；链地址法中 = 元素在链中的序号）。
  • 失败 ASL：对每个初始地址算到判定失败为止的比较次数，求和 ÷ 失败入口个数 = 散列函数值域大小（除留余数法即模 p），不是表长、不是 n+1。
  • 线性探测：逐个后探，遇到第一个空单元即失败，比较次数算到空单元为止（含空单元）。
  • 链地址：失败比较次数 = 该桶的链长（空桶为 0，走到空指针不再多算）。
真题 · 2019 年第 8 题：现有长度为 11、初始为空的散列表 HT，散列函数 H(key) = key % 7，采用线性探测法解决冲突，将关键字序列 87, 40, 30, 6, 11, 22, 98, 20 依次插入 HT 后，HT 查找失败的平均查找长度是（　）。A. 4　B. 5.25　C. 6　D. 6.29
解：各关键字的散列值依次为 3, 5, 2, 6, 4, 1, 0, 6（20 与 6 冲突，后探至 7），落位后 0 ~ 7 号单元连成一片、8 ~ 10 号为空。失败查找只能从散列值 0 ~ 6 出发（分母 = 散列函数值域大小 7），探到第一个空单元为止的比较次数依次为 9, 8, 7, 6, 5, 4, 3，和为 42，ASL(失败) = 42 / 7 = 6 → C。
【坑】散列失败 ASL 的分母是散列函数的值域大小（除留余数法就是那个模 p），这是最常见的丢分点；另：线性探测失败次数是否把「探到空单元的那次」算作一次比较，个别题目口径不同，以题目说明为准。

23. 堆操作与堆排序过程 ★★★☆☆

合辑《排序全家福》只给了堆排序的复杂度与稳定性，本卡补它缺的过程：堆是什么、插入怎么上浮、删顶怎么下沉、建堆为什么是 O(n)。堆排序大题考的就是这套手算过程。

定义：堆（Heap）是采用顺序存储的完全二叉树，且满足父子有序：大根堆（Max Heap）父结点 ≥ 子结点，根即最大值；小根堆（Min Heap）父结点 ≤ 子结点，根即最小值。堆常用于实现优先队列（Priority Queue）：取最值只需 O(1) 看堆顶。

下标换算（先认题干从几起）：下标 1 起：父结点 ⌊i/2⌋，左孩子 2i，右孩子 2i+1；下标 0 起：父结点 ⌊(i−1)/2⌋，左孩子 2i+1，右孩子 2i+2。

操作做法时间
插入（上浮）新元素放队尾（数组末尾），与父结点比较，违背堆序则交换上浮，直至满足堆序或到达根O(log n)
删除堆顶（下沉）堆顶与队尾元素交换，删去队尾（即原堆顶），新堆顶与较大（大根堆）/ 较小（小根堆）的孩子比较，违背则交换下沉，直至满足堆序O(log n)
建堆从最后一个非叶结点（下标 1 起为 ⌊n/2⌋）开始，从后向前对每个子树做下沉O(n)
堆排序建堆后重复：堆顶与堆内末尾交换（该元素落到最终位置，堆规模减 1），再对新堆顶下沉O(n log n)，空间 O(1)，不稳定
例题（同一串数字走全程，下标 1 起，大根堆，程序验算）：初始序列 53, 17, 78, 09, 45, 65, 87, 32。
建堆：从 ⌊8/2⌋ = 4 号结点起逐个下沉 → 87, 45, 78, 32, 17, 65, 53, 09（验算：87 的孩子 45、78；45 的孩子 32、17；78 的孩子 65、53；32 的孩子 09，均满足父 ≥ 子 ✓）。
插入 90：放队尾后上浮 90 → 87 → 根 → 90, 87, 78, 45, 17, 65, 53, 09, 32。
删除堆顶：删 90 后队尾 32 补顶再下沉 → 回到建堆结果 87, 45, 78, 32, 17, 65, 53, 09（插入又删除恰好还原，可自查）。
堆排序第 1 轮：堆顶 87 与堆内末尾 09 交换，09 下沉 → 78, 45, 65, 32, 17, 09, 53, [87]，方括号内 87 已是最终位置，此后下沉范围只限前 7 个元素。

坑：① 堆不是二叉排序树（Binary Search Tree）：只保证父子有序，兄弟之间无序，不要用“左小右大”去判堆。② 升序排序用大根堆（每轮最大值沉底），降序用小根堆，方向一反全错。③ 建堆是 O(n) 不是 O(n log n)：高层结点数量少、但每个可下沉的距离长，底层结点数量多、但下沉距离短，两者相消，逐层求和收敛到 O(n)；逐个插入建堆才是 O(n log n)。④ 堆排序不稳定：堆顶与末尾交换会打乱相等元素的相对顺序。

24. 外部排序 · 置换-选择、多路归并与败者树 ★★★☆☆

合辑《排序全家福》讲的全是内部排序，前提是数据能一次装进内存。文件大到装不下时换的是另一套打法：先分段排序写回外存，再把各段归并起来——这套流程本身就是考点。

总框架（归并范式）：① 生成初始归并段：把文件分批读入内存排序、写回外存，得到若干有序段；② 多路归并：一趟同时归并 k 个段中的记录，直到只剩一个有序段。外部排序的总代价主要由外存读写次数决定（408 口径），不是比较次数。

置换-选择排序（Replacement Selection，生成初始段）：工作区能放 w 条记录。工作区内分活动区（小根堆）与冻结区：不断输出堆顶，同时从输入文件补进一条新记录——新记录 ≥ 刚输出的记录就进活动区（能接进本段），< 刚输出的记录就进冻结区（留给下一段）；活动区空时，本段结束，冻结区整体解冻成为下一段的活动区。结果：各段长度不等，在随机输入下平均段长约为 2w，比「读满 w 条排一次」的定长分段（段长恰 w）段数减半。

多路平衡归并与趟数：设初始归并段数为 r、每趟最多 k 路归并，则归并趟数 = ⌈logk r⌉（最后一趟的路数可以小于 k）。每趟要把全部数据读一遍、写一遍，故外存块读写总次数 = 2 × 文件总块数 ×（归并趟数 + 1）（+1 是生成初始归并段的那一趟）。增大 k 能减少趟数，但每输出一条记录要在 k 个段的当前记录中选最小：逐个扫描要比较 k − 1 次；用败者树（Loser Tree）后，初始建树完成、每输出一条记录并补入新记录时，沿败者树调整只需 ⌈log2 k⌉ 次比较，总比较次数约 (n − 1) × ⌈log2 k⌉，比较代价只随 log k 增长——这正是「k 可以放心加大」的前提。但 k 还受另一头限制：k 路归并需要 k 个输入缓冲区，缓冲区总数有限时 k 有上限。

例题（程序验算）：① 置换-选择：工作区 w = 4，输入序列 51, 12, 49, 88, 25, 63, 37, 76, 44, 90, 18, 55。按上法模拟：初始装入 51, 12, 49, 88 建小根堆；依次输出并补入——得归并段 1：12, 25, 49, 51, 63, 76, 88, 90（长 8 = 2w）；归并段 2：18, 37, 44, 55（长 4）。定长分段本应是 3 段，置换-选择只用 2 段。② 读写次数：文件共 100 个块，生成初始段时工作区可放 3 块（归并阶段另有足够缓冲，支持 4 个输入缓冲块和 1 个输出缓冲块），置换-选择平均段长 2 × 3 = 6 块 → 初始段数 ≈ ⌈100 / 6⌉ = 17；做 4 路归并，趟数 = ⌈log4 17⌉ = 3（42 = 16 < 17 ≤ 64 = 43）；按实际形成 17 个初始段、每趟完整读写全部 100 块计，块读写总次数 = 2 × 100 × (3 + 1) = 800 次。
坑：① 「平均段长 2w」是随机输入下的期望，不是每段都恰好 2w——输入本身有序时一段到底，逆序时每段恰为 w。② 归并趟数公式里的 r 是初始归并段数，不是记录总数也不是块数，代错数整题皆错。③ k 不是越大越好：败者树只压住了比较代价，输入缓冲区随 k 线性增加，且并行读入的段越多、单段缓冲越小，外存访问反而可能变碎。④ 败者树记的是「败者」、胜者向上继续比，别与胜者树混写。

25. 特殊矩阵与稀疏矩阵的压缩存储 ★★☆☆☆

合辑没有一张讲矩阵怎么存。这一类题不难、但公式全靠现推最耗时间：把对称、三角、三对角三种特殊矩阵的存储量与地址公式，以及稀疏矩阵的三元组与快速转置，一次记清。

压缩存储（Compressed Storage）总原则：按矩阵的结构规律分配存储：多个值相同的元素只分配一个存储空间，值为 0 的元素不分配空间，从而减少冗余存储。下表前三类（对称 / 三角 / 三对角）设矩阵为 n 阶方阵、元素下标从 1 起、压缩数组 B 下标从 0 起；稀疏矩阵不限于方阵。

矩阵存法存储量地址公式（B 的下标 k）
对称矩阵只存下三角（含对角线），按行优先n(n + 1) / 2i ≥ j 时 k = i(i − 1) / 2 + j − 1；i < j 时取 aji 的位置
三角矩阵只存下（或上）三角 + 对角线外常数 c 另存 1 份n(n + 1) / 2 + 1下三角同对称矩阵；常数 c 存在数组最后一格
三对角矩阵（带状）只存 |i − j| ≤ 1 的三条对角带，按行优先3n − 2k = 2i + j − 3（仅对带内元素成立）
稀疏矩阵非零元个数 t 远小于 n2：存三元组（行号， 列号， 值）3t（顺序三元组表）无地址公式；顺序访问靠扫描；十字链表便于按行、按列遍历与动态修改非零元，不保证任意元素 O(1) 随机访问

稀疏矩阵转置 · 快速转置法：普通转置对每列扫描一遍三元组表，时间 O(列数 × t)。快速转置先统计原矩阵每列的非零元个数 num[col]，再算每列首个非零元在转置三元组表中的位置 cpot[col]（cpot[1] = 1；cpot[col] = cpot[col − 1] + num[col − 1]），然后一趟扫描原三元组表、按 cpot 直接落位并递增，时间 O(列数 + t)。

例题（程序验算）：① 三对角：n = 100 → 存储量 = 3 × 100 − 2 = 298；元素 a50,51（带内，|50 − 51| = 1 ✓）→ k = 2 × 50 + 51 − 3 = 148，即存入 B[148]。② 快速转置：6 行 7 列稀疏矩阵，非零元三元组（按行优先）：(1,2,12), (1,3,9), (3,1,−3), (3,6,14), (4,3,24), (5,2,18), (6,1,15), (6,4,−7)。统计得 num = [2, 2, 2, 1, 0, 1, 0]（第 1～7 列），cpot = [1, 3, 5, 7, 8, 8, 9]；一趟落位后转置三元组（按行优先）为：(1,3,−3), (1,6,15), (2,1,12), (2,5,18), (3,1,9), (3,4,24), (4,6,−7), (6,3,14) ✓（逐元核对：行列互换、值不变、按新行号有序）。
坑：① 三套公式都建立在「下标从 1 起、B 从 0 起」之上：题干若用 0 起下标或 B 从 1 起，公式整体差一位，先认题干再套。② 三对角公式只对带内元素有意义：|i − j| > 1 的元素根本没存，不要硬套公式算出一个位置。③ cpot[col] 是「位置」不是「个数」，且每落一位要 +1 更新，别拿原值重复落位。④ 对称矩阵 aij（i < j）查的是 aji 的格子，不是另存了一份（本卡按存下三角写；题目若按上三角存储，查法方向正好相反、下标公式也不同，不能直接照搬下三角公式，先认存法再套公式）。

26. 循环队列 · 判空判满与元素个数 ★★★☆☆

合辑《栈与队列经典应用》只讲了队列拿来干什么，没讲队列本身怎么实现。顺序队列假溢出、循环队列（Circular Queue，循环队列）判空判满，是选择题里反复出现的固定题型，公式记混一个符号整题皆错。

约定（王道口径，题干另有定义时以题干为准）：数组大小为 MaxSize，下标 0 ～ MaxSize − 1，空间当作一个环。队头指针 front 在队列非空时指向队头元素（队空时不存在队头元素）；队尾指针 rear 指向下一次入队要写入的位置（牺牲一格法下该位置恒为空位；采用下文 size / tag 法且队列已满时，该位置不一定为空）。入队：先把 x 存入 Q[rear]，再 rear = (rear + 1) % MaxSize；出队：先取 Q[front]，再 front = (front + 1) % MaxSize。

牺牲一个存储单元法（最常考）：故意空出一格不用，以区分空与满。

状态判据
队空front == rear
队满(rear + 1) % MaxSize == front
元素个数(rear − front + MaxSize) % MaxSize
最多可存MaxSize − 1 个元素

不牺牲一格的另两法（见到题先确认用的是哪套）：① 增设 size 变量记元素个数：入队 size++、出队 size−−，size == 0 为空、size == MaxSize 为满；② 增设 tag 标志：最近一次操作是入队且结果 front == rear 判满，最近一次是出队且 front == rear 判空。两法都不浪费空间，但判据与上表不同，不能混用。

例题（程序模拟验算）：MaxSize = 5 的循环队列，初始 front = rear = 0。依次入队 A、B、C：rear 走到 3，元素个数 = (3 − 0 + 5) % 5 = 3。出队两次（取出 A、B）：front 走到 2。再依次入队 D、E、F：rear 从 3 经 4 绕回 0、再到 1；此时元素个数 = (1 − 2 + 5) % 5 = 4，且 (rear + 1) % 5 = 2 == front → 队满，队列内容依次为 C、D、E、F ✓（绕圈与判满均经模拟核对）。附指针小题：MaxSize = 6、front = 1、rear = 4 时，元素个数 = (4 − 1 + 6) % 6 = 3。
坑：① 有的教材约定 rear 指向队尾元素本身，判据随之全变——做题第一步先看题干对 front / rear 的定义，别背死一套公式套所有题。② 元素个数公式别漏「+ MaxSize 再取模」：rear < front 时直接 rear − front 会得出负数。③ 牺牲一格法里数组开 MaxSize 只能存 MaxSize − 1 个，问「最多存几个」答错一位是经典丢分点。④ 链式队列不存在绕圈与假溢出，别把循环队列判据往链队列上套。

存取方式随机存取：按下标 O(1) 直达任一元素顺序存取：找第 i 个元素须从头逐个顺链，O(n)
按值查找无序时 O(n)（逐个比）；有序时折半查找 O(log n)O(n)
插入 / 删除须移动元素腾位 / 补位，平均移动约 n / 2 或 (n − 1) / 2 个，O(n)已知操作位置的指针时只改指针，O(1)；但找前驱 / 按序号定位仍是 O(n)

扩容静态分配容量固定，存满后无法直接扩容；动态分配在容量不足时可重新申请更大的连续空间并复制原有元素逐结点申请、用完释放，长度天然可变
例题（枚举验算）：长度 n = 10 的顺序表：插入一个元素，合法插入位置共 11 个（第 1 ～ 11 位），各位置须移动的元素个数依次为 10, 9, …, 1, 0，平均 = 55 ÷ 11 = 5 = n / 2；删除一个元素，合法位置共 10 个，移动个数依次为 9, 8, …, 0，平均 = 45 ÷ 10 = 4.5 = (n − 1) / 2 ✓。推广：长度为 n 时插入平均移动 n / 2 个、删除平均移动 (n − 1) / 2 个（均设各位置等概率）。
坑：① 「链表插入删除是 O(1)」有前提：已经拿到操作位置（或其前驱）的指针；若题目给的是「在第 i 个位置插入」，定位本身 O(n)，整体仍是 O(n)。② 单链表中删除结点 p 本身（只给 p、不给前驱）不能直接 O(1) 摘除：常规做法须从头找前驱 O(n)；把后继的值拷进 p 再删后继的变通法对尾结点无后继可用、且改变了结点身份，选项若笼统说「只给 p 就能 O(1) 删除」要警惕。③ 顺序表的「随机存取 O(1)」只对按下标 / 按序号成立，按值查找无序时仍是 O(n)。④ 双链表在已知结点指针时可经前驱指针 O(1) 找到前驱；但循环单链表找前驱通常仍须沿链遍历、O(n)，且链表改变不了「顺序存取」这一本质，别与顺序表混答。

2. 补码运算规则 ★★★★★

求 [−X]补：[X]补 连同符号位取反加 1。

溢出判断（双符号位法）：00 正确（正）、11 正确（负）、01 正溢出、10 负溢出。如 +11 与 +13 用双符号位相加：001011 + 001101 = 011000，双符号位 01 → 正溢出（一眼可判，不用看数值位）。

Booth 算法（补码一位乘）：[X×Y]补 不能由 [X]补 与 [Y]补 直接相乘得到，要走部分积递推：看乘数相邻两位之差决定加 [X]补、加 [−X]补 还是加 0，再把（部分积， 乘数）整体算术右移一位；符号位全程参与运算。下面用定点整数完整走一遍。小数双符号位版与整数版的核心 Booth 判断及加减规则相同，但操作步数和最后移位安排不同（见本卡末注），不能混用：

例（Booth 全过程）：X = −13（[X]补 = 10011，[−X]补 = 01101），Y = +11（[Y]补 = 01011）。部分积 A 初值 00000，附加位 Q−1 = 0；每步看（Q 最低位， Q−1）这一对：(1,0) 加 [−X]补，(0,1) 加 [X]补，(0,0)/(1,1) 加 0，随后（A, Q）算术右移。
步判断位操作右移后 A右移后 QQ−1
1(1, 0)A += [−X]补 → 0110100110101011
2(1, 1)A += 000011010101
3(0, 1)A += [X]补 → 1011011011001010
4(1, 0)A += [−X]补 → 0100000100000101
5(0, 1)A += [X]补 → 1011111011100010
乘数 5 位就走 5 步。结果 = A 拼 Q = 11011 10001 = [−143]补。验算：−13 × 11 = −143 ✓。注意：整数单符号位版与小数双符号位版的轮数和移位安排不同，不要混用——整数版执行 n 轮、每轮均移位；小数双符号位版（见《定点数乘除运算》卡）通常执行 n + 1 步、最后一步只加减不移位。
3. 定点数乘除运算 · 原码一位乘 / Booth 算法 / 不恢复余数除法 ★★☆☆☆

《补码运算规则》只给了 Booth 算法（布斯算法）的一句话判位规则，本卡补齐完整手算流程，并补上原码一位乘与除法——三者是计组计算大题的常客，符号与移位方式一混就全错。

原码一位乘：符号位异或单独定，数值部分单独算。部分积初值为 0；每步看乘数最低位：为 1 则加被乘数绝对值，为 0 则加 0；然后部分积与乘数整体逻辑右移一位；数值位共 n 位就做 n 次。

例（原码一位乘）：被乘数绝对值 0.11012 = 13/16，乘数绝对值 0.10112 = 11/16（寄存器里参与运算的是尾数位串 1101、1011，各步加法按位串进行），部分积初值 00000，乘数 1011。
步 1：最低位 1 → 加 01101 得 01101 → 右移 → 部分积 00110，乘数 1101；
步 2：最低位 1 → 00110 + 01101 = 10011 → 右移 → 部分积 01001，乘数 1110；
步 3：最低位 0 → 不变 01001 → 右移 → 部分积 00100，乘数 1111；
步 4：最低位 1 → 00100 + 01101 = 10001 → 右移 → 部分积 01000，乘数 1111。
积的尾数位串 = 部分积低 4 位 1000 与乘数 1111 拼接 = 10001111（拼接不是相加；部分积首位的 0 是移位多出的一位），即 0.100011112 = 143/256；符号位 0 ⊕ 0 = 0，故结果为 +0.10001111。验算：整数 13 × 11 = 143 只验证尾数位串，数值须按缩放还原：(13/16) × (11/16) = 143/256 ✓

Booth 算法：符号位参与运算，另设附加位 Q−1 初值为 0。每步看乘数末两位 YnYn+1：00 / 11 加 0；01 加 [X]补；10 加 [−X]补；然后累加器 A、乘数 Q、附加位 Q−1 整体算术右移一位（符号位复制）。乘数 n 位（含符号位）做 n 次。

例（Booth 算法）：X = −13（5 位补码 10011），Y = 11（01011），A 初值 00000，Q = 01011，Q−1 = 0。
步 1：末两位 10 → A = A − X = 0 − (−13) = 13（01101）→ 右移 → A = 00110，Q = 10101，Q−1 = 1；
步 2：末两位 11 → 不变 → 右移 → A = 00011，Q = 01010，Q−1 = 1；
步 3：末两位 01 → A = A + X = 3 + (−13) = −10（10110）→ 右移 → A = 11011，Q = 00101，Q−1 = 0；
步 4：末两位 10 → A = A − X = −5 − (−13) = 8（01000）→ 右移 → A = 00100，Q = 00010，Q−1 = 1；
步 5：末两位 01 → A = A + X = 4 + (−13) = −9（10111）→ 右移 → A = 11011，Q = 10001。
积 A:Q = 11011 10001，换算回十进制正是 −143，即 (−13) × 11 ✓

定点除法（原码）：商符 = 被除数符号 ⊕ 除数符号，数值部分单独算；先判 |被除数| < |除数|，否则商溢出。恢复余数法：每步试减，不够减商 0 并恢复余数；不恢复余数法（加减交替法）：余数与除数同号则 2R − |除数|、商 1，异号则 2R + |除数|、商 0，不用恢复，末位余数按左移次数还原，余数符号与被除数同号。

例（不恢复余数法）：被除数 0.1010，除数 0.1100，|0.1010| < |0.1100|，可除。
步 1：余数 ≥ 0 → 2R − Y = 1.0100 − 0.1100 = 0.1000，商 1；
步 2：余数 ≥ 0 → 2R − Y = 1.0000 − 0.1100 = 0.0100，商 1；
步 3：余数 ≥ 0 → 2R − Y = 0.1000 − 0.1100 = −0.0100，商 0；
步 4：余数 < 0 → 2R + Y = −0.1000 + 0.1100 = 0.0100，商 1。
商 0.1101；末位余数还原：0.0100 ÷ 24 = 0.000001。验算：0.1101 × 0.1100 = 0.10011100，被除数 0.10100000 − 0.10011100 = 0.00000100 ✓
易错：原码乘符号位不参与、移位是逻辑右移；Booth 算法符号位参与、移位是算术右移，两者移位方式混用必错；除法动手前先判 |被除数| < |除数|，漏判溢出是送分题丢分主因。

星级注：本卡星级为上位口径估计——按「运算电路 + 逻辑移位」标签 5 年定档，定点数乘除本身无独立标签统计。

4. IEEE 754 浮点数【必背】 ★★★★★

例（十进制 → 单精度）：把 −18.625 写成 IEEE 754 单精度。四步：① 符号位：负数 → 1。② 把数值写成 1.××× × 2e 形式：18.625 = 10010.1012 = 1.0010101 × 24，故 e = 4。③ 阶码 = e + 偏置 127 = 131 = 10000011。④ 尾数存小数部分 0010101，后补 0 凑满 23 位：00101010000000000000000。拼起来：1 10000011 00101010000000000000000（十六进制 C1950000）。反过来读一个数也一样：先拆三段，阶码减 127 得真阶，尾数前面补回隐含的 1。
坑：特殊编码要分清四种——阶码全 0 且尾数全 0 = ±0；阶码全 0、尾数非 0 = 次正规数（没有隐含 1）；阶码全 1、尾数全 0 = ±∞；阶码全 1、尾数非 0 = NaN。另：尾数存的是去掉隐含 1 之后的小数部分，别把 1 也写进去占位。
5. 浮点数加减运算 · 五步法 ★☆☆☆☆

五步法光背步骤没用，跟着一个例子走一遍就会了。设阶码 4 位补码（可表示 −8 ~ +7）、尾数双符号位、6 位数值位，均用补码，算 X + Y，其中 X = 23 × 0.1010（= 5），Y = 24 × 0.1101（= 13）。

  1. 1对阶（小阶向大阶看齐，阶差几位、尾数右移几位）：X 的阶 3 < Y 的阶 4，差 1 → [X]尾补 = 00.101000 算术右移 1 位，得 00.010100，阶变为 4。移出的位是 0，本次不丢精度。
  2. 2尾数加减（按补码相加）：00.110100 + 00.010100 = 01.001000。双符号位出现 01，是尾数溢出的形态——先别慌，这不是运算溢出，看第 3 步。
  3. 3规格化：补码规格化形式是正数 00.1×××××、负数 11.0×××××。现在是 01.×××，尾数溢出 → 右规：尾数右移 1 位得 00.100100，阶码 4 + 1 = 5。若结果形如 00.0××× 或 11.1×××（首数值位与符号位相同），则反过来左规：尾数每左移 1 位、阶码减 1，直到达标。
  4. 4舍入：对阶、右规时被移掉的位要处理。看一小段：尾数 00.100100 对阶右移 3 位，移出位恰为 100（正好半个单位）→ 按「0 舍 1 入」末位进 1，得 00.000101；若右移 4 位，移出位为 0100（不足半个单位）→ 直接舍去，得 00.000010。本例对阶、右规都没移出有效位，无舍入。（注：这是教学简化舍入；IEEE 754 默认是就近舍入、遇半取偶，不同。）
  5. 5溢出判断（只看阶码）：阶码 5 在 −8 ~ +7 内 → 无溢出。阶码上溢才是真溢出；阶码下溢按机器零处理（408 教学简化口径；IEEE 754 则用次正规数实现渐进下溢，数值过小时仍可能因舍入变为 0）。

结果：25 × 0.100100 = 18。十进制验算：5 + 13 = 18 ✓。

真题 · 2009 年第 13 题：浮点数加减运算包括对阶、尾数运算、规格化、舍入和判溢出等步骤。设浮点数的阶码和尾数均采用补码表示，位数分别为 5 位和 7 位（均含 2 位符号位）。若 X = 27 × 29/32，Y = 25 × 5/8，则用浮点加法计算 X + Y 的最终结果是（　）。A. 00111 1100010　B. 00111 0100010　C. 01000 0010001　D. 发生溢出
解：对阶（小阶向大阶看齐）：Y 尾数右移 2 位；尾数相加得 01,00010，符号位 01 需右规：尾数 00,10001、阶码 + 1 变为 8。阶码数值位只有 3 位、最大可表示 7，阶码 8 超出范围 → 判溢出 → D。（速算验证：X + Y = 27 × (29/32 + 5/32) = 28 × 17/32，阶 8 同样超限。）
易错：尾数溢出 ≠ 运算溢出——尾数溢出只需右规；只有阶码上溢才算溢出。尾数「双符号位判溢出」是定点数那套，别搬到浮点数上。
6. 存储器容量计算 ★★★★☆
总容量 = 字数 × 字长 = 2地址位数 × 数据位数
  • 地址线 n 条 → 可寻址 2n 个存储单元。
  • 数据线 m 条 → 每单元 m 位。
真题 · 2022 年第 17 题：某内存条包含 8 个 8192 × 8192 × 8 位的 DRAM 芯片，按字节编址，支持突发传送，对应存储器总线宽度为 64 位，每个芯片内有一个行缓冲区。下列关于该内存条的叙述中，不正确的是（　）。A. 内存条的容量为 512 MB　B. 采用多模块交叉编址方式　C. 芯片的地址引脚为 26 位　D. 芯片内行缓冲有 8192 × 8 位
解：容量 = 8 × 8192 × 8192 × 8 bit = 512 MB，A 正确；每芯片一次只能输出 8 位，凑满 64 位总线需 8 体交叉编址，B 正确；DRAM 行、列地址分时复用同一组引脚，行列各 8192 = 213，地址引脚只需 13 位，C 不正确；行缓冲存放一整行 = 8192 × 8 位，D 正确 → 选不正确的 C。
【注】上式的前提是存储芯片按 2n × m 位组织、按字编址（一个存储单元 = m 位）；数据线条数只决定一次并行传送的位数。按字节编址时每个存储单元固定为 8 位，与数据总线宽度无关，不能把数据位数无条件当作每单元的位数。
【记】1KB = 210 B，1MB = 220 B，1GB = 230 B。
7. Cache 地址划分与平均访问时间 · 计算 ★★★★★

主存地址 = 标记位 + 组号 / 行号 + 块内地址。块大小 B 字节 → 块内地址 log2B 位，组号位数 = log2（组数）；直接映射每组 1 行（组数 = 行数），全相联只有 1 组、无组号字段；Cache 行数 = Cache 容量B；组数 = 行数路数。

例题：主存 1GB（地址 30 位），Cache 32KB，块 32B。块内地址 5 位（25=32），Cache 行数 32KB32B = 1024 行。
映射方式组号 / 行号标记位校验
直接映射行号 10 位（210=1024）15 位15+10+5 = 30 ✓
4 路组相联组号 8 位（组数 10244 = 256）17 位17+8+5 = 30 ✓
全相联无组号25 位25+5 = 30 ✓

平均访问时间 Ta，命中率 h，Cache 访问时间 Tc，主存访问时间 Tm——先看题干是哪种访问模型：

模型公式例：Tc=10ns，Tm=100ns，h=0.95
先查 Cache，未命中再访存（串行）Ta = Tc + (1−h)·Tm10 + 0.05×100 = 15ns
Cache 与主存同时访问（并行）Ta = h·Tc + (1−h)·Tm0.95×10 + 0.05×100 = 14.5ns
真题 · 2022 年第 16 题：某计算机主存地址为 32 位，按字节编址，某 Cache 的数据区容量为 32 KB，主存块大小为 64 B，采用 8 路组相联映射方式，该 Cache 中比较器的个数和位数分别为（　）。A. 8, 20　B. 8, 23　C. 64, 20　D. 64, 23
解：块内地址 = log2 64 = 6 位；Cache 块数 = 32 KB / 64 B = 512，8 路一组共 64 组，组号 = 6 位；标记 = 32 − 6 − 6 = 20 位。组相联每路设一个比较器、每个比较标记位数 → 8 个、20 位 → A。
易错：串行模型不要漏掉那次 Tc；并行模型不要把未命中写成 Tc+Tm。两模型只差 0.5ns 也要按题干选，阅卷按模型给分。
8. Cache 替换算法与写策略 ★★☆☆☆

替换算法只在组相联 / 全相联才需要：直接映射中每个主存块只对应一个固定 Cache 行，冲突时直接替换该行，没有「选哪块换出」的问题。

替换算法换出对象特点
FIFO（先进先出）最先进入 Cache 的块实现简单，不看实际使用情况
LRU（最近最久未使用）最久未被访问的块有时间局部性的访问下通常命中率较高（但不保证对任何访问串都优于 FIFO），实现代价较大
LFU（最不经常使用）访问次数最少的块需维护计数；曾高频的旧块计数居高难被换出，对访问模式变化适应差
随机替换随机选一块实现最简单，命中率略低
例（同一访问串，两种算法）：Cache 共 3 行，块访问串 2, 1, 3, 2, 4, 2, 5, 1, 2, 3。
FIFO（只看进场先后）：2✗、1✗、3✗ 装满；2✓；4✗ 换出最老的 2；2✗ 换出 1；5✗ 换出 3；1✗ 换出 4；2✓；3✗ 换出 2 → 缺失 8 次。
LRU（看最近使用）：2✗、1✗、3✗ 装满；2✓（2 变最新）；4✗ 换出最久未用的 1；2✓；5✗ 换出 3；1✗ 换出 4；2✓；3✗ 换出 5 → 缺失 7 次。
差别就在第 5 步：2 刚被访问过，LRU 保它、FIFO 照样按进场顺序把它换出——这就是本例中 LRU 缺失次数更少的原因。
写策略（写命中时）代价 / 注意
写直通同时写 Cache 和主存：主存始终一致，写操作慢；无需脏位；常配非写分配
写回只写 Cache 并置脏位，换出时才写回主存：写得快，需脏位，一致性处理更复杂；常配写分配

写直通 / 写回说的是「写命中」；写不命中是另配一对策略（写分配 / 非写分配），两对不要混成一对答。

9. 虚存地址变换与页表规模 · 计算 ★★★★★

逻辑地址 = 页号 + 页内偏移。页面 4KB = 212B → 页内偏移 12 位。

例题：逻辑地址 32 位，页面 4KB。页号 20 位，单级页表项数 220，每项 4B → 页表占 220×4B = 4MB，常驻内存太贵——这就是多级页表的动机。

二级页表（页号 10 + 10 拆分）：页目录 210 项 × 4B = 4KB（恰一页）；每张二级页表同样 210×4B = 4KB，且只给实际用到的虚页建表，不用一次建满。

带 TLB（快表，即转换后备缓冲区） 的有效访问时间（EAT）：TLB 命中率 α，TLB 查找时间 t，访存时间 m。命中：t + m；缺失：t + 查页表 m + 取数据 m = t + 2m。

EAT = α·(t+m) + (1−α)·(t+2m)。例：α=0.9，t=10ns，m=100ns → 0.9×110 + 0.1×210 = 99 + 21 = 120ns。

若题干说“忽略 TLB 本身查找时间”，则 EAT = α·m + (1−α)·2m = 0.9×100 + 0.1×200 = 110ns。先看题干给没给 t，再选公式。以上 EAT 均为一级页表模型：TLB 未命中时访存查页表一次、再访存取数据一次。

真题 · 2024 年第 17 题：某计算机按字节编址，采用页式虚拟存储管理，虚拟地址 32 位、主存地址 30 位、页大小 1 KB。若 TLB 共有 32 个表项、采用 4 路组相联映射，则 TLB 表项中标记字段的位数至少是（　）。A. 17　B. 18　C. 19　D. 20
解：页内偏移 10 位，虚拟页号 = 32 − 10 = 22 位；TLB 共 32 / 4 = 8 组，组索引 = log2 8 = 3 位；标记 = 22 − 3 = 19 位 → C。
口诀：页表规模题先算“项数 × 项大小”；多级题先拆页号位数，再算每级表占几页。

补充：页表项数 = 虚拟地址空间页面大小；页表项大小须容纳物理块号 + 控制位，通常向上对齐到 2 的幂次。

10. 指令格式与寻址方式 · 计算 ★★★★★

操作码 n 位 → 最多 2n 条指令；扩展操作码：上一级留一个编码作扩展标志，下一级才能继续分。

11. 指令执行阶段（五阶段） ★★★☆☆

  • 2译码（ID）：分析操作码和地址码。
  • 3执行（EX）：ALU 运算。
  • 4访存（MEM）：读写内存（Load / Store）。
  • 5写回（WB）：结果写回。

12. CPU 数据通路与微操作 · 步骤与控存容量 ★★★★★

  1. 1(PC) → MAR（存储器地址寄存器），读命令送主存
  2. 2M(MAR) → MDR（存储器数据寄存器）（取出的指令字进数据寄存器）
  3. 3(MDR) → IR（指令寄存器）（指令译码），同时 (PC)+1 → PC（PC + 1 的前提与《指令执行阶段》卡一致：按指令字编址；按字节编址时应加当前指令长度）
  4. 4执行周期按指令分流：例如 ADD M（加法）：Ad(IR) → MAR；M(MAR) → MDR；(ACC) + (MDR) → ACC（累加器）

微指令编码方式（硬布线 / 微程序对比见《控制器对比》卡，此处只补编码）：

编码方式做法特点
直接编码微指令每位直接控制一个微命令并行性最好，微指令字最长

18. 中断与 DMA（直接存储器访问） · 步骤与三种访存方式计算 ★★★★★

完整流程：中断请求 → 中断判优 → 中断隐指令 → 中断服务程序。

各步内容（纵向编号）：

  1. 1中断判优：多个中断同时请求时，由硬件排队器选出优先级最高者，最快。注意：软件查询是另一种识别中断源的方式——由程序逐个查询设备状态来确定来源，慢但灵活，不要与硬件判优混为一谈
  2. 2中断隐指令（硬件自动完成）：① 关中断 ② 保存断点（PC 和 PSW）③ 查中断向量表得服务程序入口
  3. 3执行中断服务程序：先由服务程序保存通用寄存器等现场（保护现场），再处理中断请求
  4. 4恢复现场、开中断、返回断点继续执行
真题 · 2020 年第 22 题：若设备采用周期挪用 DMA 方式进行输入输出，每次 DMA 传送的数据块大小为 512 字节，I/O 接口中有一个 32 位数据缓冲寄存器。对于数据输入过程，下列叙述中错误的是（　）。A. 每准备好 32 位数据，DMA 控制器就发出一次总线请求　B. 相对于 CPU，DMA 控制器的总线使用权优先级更高　C. 在整个数据块的传送过程中，CPU 不可以访问主存储器　D. 数据块传送结束时，会产生“DMA 传送结束”的中断请求
解：周期挪用每次只挪用一个存储周期完成一次字的传送，其余时间总线仍归 CPU，C 把“挪用一个周期”夸大为“全程封锁”，错误；A、B、D 都是周期挪用的正常机制 → 选错误的 C。
【坑】保存通用寄存器（现场）是中断服务程序做的，不是隐指令。
向量地址例：向量表项 4 字节，基址为 0，中断类型号 08H → 入口地址 = 8×4 = 32 = 20H。通用式：入口 = 基址 + 类型号 × 表项字节数。

DMA 与 CPU 分时访存的三种方式（王道口径命名）：

方式CPU 状态适用 / 代价
停止 CPU 访问整批传送期间 CPU 完全停访存实现最简单；CPU 利用率最低
周期挪用DMA 有请求时挪用 1 个或几个存取周期，平时 CPU 照常CPU 停的时间被打散，适合低速设备
交替访存一个 CPU 周期一分为二：C1 供 DMA，C2 供 CPU，无需申请 / 建立 / 归还总线要求 CPU 周期大于主存存取周期（例：CPU 1.2μs、存取 0.6μs，正好一分为二）
数量例：DMA 传 1000 个字，每字存取周期 0.5μs → 停止方式下 CPU 停访存 1000×0.5μs = 500μs；周期挪用方式下 CPU 同样累计停 500μs，但分散在传送全程、每次只停 1 个周期。

DMA vs 中断方式的根本区别：中断方式每传一个字（或一批）都要 CPU 干预；DMA 方式 CPU 只在传送前初始化、传送完发一次中断时干预，中间数据直通、不经过 CPU。

19. 流水线冒险与冲突处理 ★★★☆☆

合辑《流水线相关公式》只给了时间、吞吐率与时序图，本卡补它缺的另一半：流水线为什么会停顿、三种冒险各怎么解。流水线大题的后半段几乎必问这个。

冒险含义解法
结构冒险（Structural Hazard）多条指令争用同一硬件资源，如取指与访存共用一个存储器端口，某指令访存时下一条指令无法取指资源复制：指令 Cache 与数据 Cache 分离；或暂停流水线等资源空闲
数据冒险（Data Hazard）后一条指令要用的数据还没算出来：RAW（写后读，Read After Write）最常见；WAR（读后写）、WAW（写后写）主要出现在乱序、多发射等复杂流水线语境，答题先看题干流水线类型转发（Forwarding，又称旁路）+ 暂停；Load-use 冒险转发也救不了，必须暂停 1 拍（见下）
控制冒险（Control Hazard）分支指令的结果未定，后续指令是否该执行未知；已取入的指令可能全作废分支预测、延迟分支（延迟槽）、提前在译码段判断分支（把损失压到 1 拍）

转发（Forwarding / 旁路）：不经过写回与寄存器堆，直接把上一条指令在流水线寄存器里的结果送到下一条指令的执行段。例：ADD R1, R2, R3 紧跟 SUB R4, R1, R5——SUB 在执行段需要 R1 时，ADD 的结果已在 EX/MEM 寄存器中，直接转发，0 暂停；若中间隔一条指令，结果在 MEM/WB 寄存器中，同样转发。

转发救不了的情形（必考）：Load-use 冒险。LOAD R1, 0(R2) 紧跟 ADD R3, R1, R4——LOAD 要到访存段（MEM）才拿到数据，而 ADD 在执行段（EX）就需要 R1，时间上赶不上，转发也来不及，只能暂停 1 拍、插入 1 个气泡（Bubble），让 ADD 的执行段推迟到 LOAD 的访存段之后。口诀：算术指令间的数据冒险靠转发，Load 后紧跟用它的指令必停 1 拍。（注：停 1 拍是经典五级流水线、带转发时的结论；暂停周期数取决于流水线级数、数据在哪一段产出、在哪一段被使用以及转发路径，结构不同须按时序图重算，不是普适常数。）

控制冒险展开：分支预测分静态（固定预测不跳转，或固定预测跳转）与动态（按分支历史表预测，历史准了就几乎不损失）；延迟分支是在分支指令后放一条“无论如何都执行”的延迟槽指令，把作废损失换成有用功；若在译码段就能算出分支目标与条件，控制冒险的损失可压到 1 拍（只作废已取入的那一条）。

图：Load-use 冒险时空图——ADD 的执行段须等到 LOAD 的访存段之后，中间插入 1 个气泡。
真题 · 2023 年第 19 题：在采用“取指、译码 / 取数、执行、访存、写回”5 段流水线的 RISC 处理器中，执行指令序列 I1: add s2, s1, s0；I2: load s3, 0(s2)；I3: beq t2, s3, L1；I4: addi t2, t2, 20（L1 为 I5）。采用转发技术处理数据冒险、硬件阻塞处理控制冒险，则 I1 ~ I4 执行过程中发生流水线阻塞的指令有（　）。A. 仅 I3　B. 仅 I2、I4　C. 仅 I3、I4　D. 仅 I2、I3、I4
解：I2 要用 s2：I1 的结果在其执行段末尾已经生成，经转发直达 I2 的执行段，I2 不阻塞。I3 要用 s3：I2 是 load，数据到访存段末尾才就绪，转发赶不上（Load-use 冒险），I3 阻塞 1 拍。I4 紧跟分支 I3 之后：分支在访存段才判定，I4 的取指必须等待，I4 被阻塞 → C。
坑：① 暂停（Stall）与冲刷（Flush）别混：暂停是“冻住前面几段、插入气泡”，冲刷是“作废已取入的错误路径指令”，前者用于数据/结构冒险，后者用于控制冒险。② 转发不是万能：见到 Load-use 先写“停 1 拍”，不要只写“转发解决”。③ 结构冒险的根治是“资源分开”，不是“加快时钟”——时钟由最慢段决定，资源冲突不会因提频消失。

20. 存储芯片扩展 · 位扩展 / 字扩展 / 字位同时扩展 ★★★☆☆

合辑《存储器容量计算》只给了「容量 = 字数 × 字长」的公式，没讲单片芯片不够用时怎么拼：需要几片、地址线怎么分、每片占哪段地址——这才是这类计算题真正考的后半截。

方式扩什么接法要点
位扩展字长（位数）各片同地址、同片选同时工作，数据线各分担一段；不增加地址线条数
字扩展字数（单元数）各片数据线并联共用，靠片选信号（CS，Chip Select，片选信号）分时选中一片；高位地址经译码器产生片选
字位同时字数与字长都扩先位扩展成组、再字扩展分组，总片数 = 两者相乘
公式：总片数 =（目标字数 ÷ 芯片字数）×（目标字长 ÷ 芯片字长）；片内地址线数 = log2（芯片字数）；片选地址线数 = log2（字扩展组数）；在芯片字数与扩展组数均为 2 的整数次幂、规则连续编址的条件下，覆盖整个模块所需的最少地址位数（按存储字编址）= 片内地址线 + 片选地址线；若按字节编址，还须加上字内字节偏移的位数，且 CPU 实际地址总线宽度由其体系结构决定、不一定等于该模块所需位数。每组包含的存储字数 = 单片芯片字数：按字编址时每组占芯片字数个字地址，按字节编址时每组占用的字节地址空间 = 芯片字数 × 目标字长 ÷ 8；各组按连续地址段分配时互不重叠（是否连续编址以题目译码设计为准）。
例题（公式重算 + 范围枚举核对）：① 用 16K × 8 位芯片构成 64K × 32 位存储器（本问按 32 位存储字编址）：字扩展组数 = 64K ÷ 16K = 4，每组位扩展片数 = 32 ÷ 8 = 4，总片数 = 4 × 4 = 16 片；覆盖该模块所需地址线 = log264K = 16 根（A15 ～ A0），其中低 14 根接各片片内地址，高 2 根（A15A14）经译码产生 4 组片选；数据线 32 根，每组 4 片各提供 8 位。② 地址范围：用 8K × 8 位芯片构成 32K × 8 位、起始地址 0000H（按字节编址）：共 4 片，各占 8K = 2000H 大小，范围依次为 0000H–1FFFH、2000H–3FFFH、4000H–5FFFH、6000H–7FFFH ✓。
坑：① 位扩展不产生新的地址、也不需要多组片选，各片是「一起被选中、各出一部分位」；字扩展不加宽数据线，各片是「同一时刻只选中一片」——两者接法正好相反，选项常互换设套。② 算地址范围先把容量换成 2 的幂再换十六进制：8K 的跨度是 2000H，不是 8000H。③ 题目混用 ROM 与 RAM 芯片时，总片数分开算；地址空间如何排布由题目译码设计决定，要求连续编址时才连续排布，哪类放低地址以题干为准。④ 片选若用线选法（高位地址线直连片选）可省译码器，但可能造成地址空间利用率低、片选组合设计不当还可能多片同时被选中，与译码法结论不同，先看题干给的连接方式。

来源：2027 考纲组成原理“存储器层次结构：主存储器与 CPU 的连接”；王道《计算机组成原理》主存储器与 CPU 的连接一节。星级：上位口径「主存容量的扩展」11 年（合辑 co-4 口径），芯片扩展为其计算子项、无独立年份统计，保守定 3★（非独立统计）。

21. CPU 性能指标 · CPI / MIPS 与执行时间 ★★★☆☆

合辑有流水线、指令格式、数据通路，唯独没有计组第一章的性能计算：一个程序到底跑多久、两种机器谁快——CPI（Cycles Per Instruction，每条指令的时钟周期数）、主频与 MIPS（Million Instructions Per Second，百万条指令每秒）是每年都可能出现的公式计算题，合辑全文 0 覆盖。

核心公式：CPU 执行时间 TCPU = 指令条数 IC × CPI × 时钟周期 Tc，即 TCPU = IC × CPI ÷ f（f 为主频）。加权 CPI = Σ（各类指令 CPIi × 该类指令占比）。MIPS = f ÷ (CPI × 106) = IC ÷ (TCPU × 106)（f 以 Hz 计）。三者知二求一：主频管「周期多短」、CPI 管「每条指令占几个周期」、IC 管「一共多少条」。
例题（公式重算、两式互证）：① 某机主频 2.5 GHz，程序含 5 × 108 条指令，平均 CPI = 2。时钟周期 = 1 ÷ 2.5 GHz = 0.4 ns；执行时间 = 5 × 108 × 2 ÷ (2.5 × 109) = 0.4 s；MIPS = 2500 ÷ 2 = 1250，与 IC ÷ 执行时间 = 5 × 108 ÷ 0.4 = 1.25 × 109 条 / 秒 = 1250 MIPS 一致 ✓。② 加权 CPI：某程序中算术指令占 60%、CPI = 1，访存指令占 20%、CPI = 4，分支指令占 20%、CPI = 3，则平均 CPI = 0.6 × 1 + 0.2 × 4 + 0.2 × 3 = 2.0；该程序若共 108 条指令、在主频 2 GHz 的机器上执行，时间 = 108 × 2.0 ÷ (2 × 109) = 0.1 s ✓。
坑：① 主频高 ≠ 一定快：执行时间由 IC、CPI、主频三者共同决定，只比主频是经典错误选项。② MIPS 随指令集与程序构成变化：同一机器跑不同程序 MIPS 不同，不同指令系统的机器之间不能只凭 MIPS 比快慢（一条复杂指令干的活可能顶几条简单指令）。③ 算加权 CPI 用的是各类指令的条数占比，不是时间占比；题目给各类条数时先求总条数再算权重。④ 单位换算：GHz 是 109 Hz、MIPS 里的 M 是 106，代公式前先统一到 Hz 与条 / 秒，别在指数上丢分。

来源：2027 考纲组成原理“计算机系统概述：计算机性能指标”；王道《计算机组成原理》计算机性能指标一节。星级：本卡无独立年份统计；「指令执行指标」相关口径仅作上位参考、非 CPI / MIPS 的独立命中年份，3★ 为复习优先级估计（非独立统计）。

真题 · 2023 年第 29 题：进程 P1、P2、P3 进入就绪队列的时刻分别为 0 ms、20 ms、30 ms，优先值（越大优先权越高）分别为 1、10、100，CPU 执行时间分别为 60 ms、42 ms、13 ms。系统采用基于优先权的抢占式调度算法，从 0 ms 开始调度，则 P1、P2、P3 的平均周转时间为（　）。A. 60 ms　B. 61 ms　C. 70 ms　D. 71 ms
解：P1 先运行，20 ms 时被高优先级的 P2 抢占；30 ms 时 P3 抢占并运行至 43 ms 完成；P2 续行至 75 ms 完成；P1 最后运行至 115 ms 完成。周转时间：P1 = 115 − 0 = 115，P2 = 75 − 20 = 55，P3 = 43 − 30 = 13，平均 = (115 + 55 + 13) / 3 = 61 ms → B。
HRRN 是“短作业优先 + 先来先服务”的折中：等待越久、要求越短，响应比越高。
4. 临界区管理原则 ★★★☆☆
  • 空闲让进：临界区空闲时允许请求进程进入。
  • 忙则等待：有进程在临界区时必须等待。
  • 有限等待：等待时间有限，不能饥饿。
  • 让权等待：等待时应释放 CPU（非必须）。
真题 · 2018 年第 32 题：在下列同步机制中，可以实现让权等待的是（　）。A. Peterson 方法　B. swap 指令　C. 信号量方法　D. TestAndSet 指令
解：swap、TestAndSet 等硬件方法靠自旋忙等实现互斥，不能让权等待；Peterson 方法同样是忙等；记录型信号量在资源不可用时把进程阻塞、让出处理机，可以实现让权等待 → C。
【记】TSL / CAS 等自旋锁违背让权等待原则。

星级注：本卡星级为上位口径估计——由同步原则、进程互斥、临界资源等相关标签合并口径（6 年）定档，单标签口径更低。

5. 信号量 PV 操作 ★★★★★

P(S)：S = S − 1；若 S < 0，阻塞当前进程。V(S)：S = S + 1；若 S ≤ 0，唤醒一个等待进程。互斥信号量初值 = 1；同步信号量初值 = 资源数量或 0。S 的读法跟着例子走一遍就懂：

例（信号量值全程追踪）：某资源共 2 台，信号量 S 初值 2。
时刻动作S发生了什么
t1P1 执行 P(S)1P1 占用 1 台，剩 1 台空闲
t2P2 执行 P(S)0P2 占用最后 1 台，无空闲
t3P3 执行 P(S)−1无资源，P3 阻塞等待；等待进程数 = |S| = 1
t4P1 执行 V(S)0S ≤ 0 → 唤醒 P3，P3 接手那台资源
t5P2 执行 V(S)1无人等待，空闲资源回到 1 台
读法就此立住：S > 0 时 S 就是空闲资源数；S < 0 时 |S| 就是等待进程数；S = 0 表示资源刚好占满、无人等待。
真题 · 2010 年第 25 题：设与某资源关联的信号量初值为 3，当前值为 1。若 M 表示该资源的可用个数，N 表示等待该资源的进程数，则 M、N 分别是（　）。A. 0、1　B. 1、0　C. 1、2　D. 2、0
解：信号量当前值 > 0 时，其值就是可用资源个数，M = 1；此时没有进程在等待，N = 0（只有当前值为负时，等待进程数才等于其绝对值）→ B。
坑：生产者—消费者问题中，P 操作顺序不能换（先 P 同步，后 P 互斥）。
6. 经典同步问题 · 生产者-消费者 / 读者-写者 ★★★★★

生产者-消费者（有界缓冲，容量 n）：信号量 mutex = 1（互斥），empty = n（空位），full = 0（产品数）。

生产者：P(empty) → P(mutex) → 放入产品 → V(mutex) → V(full)。  消费者：P(full) → P(mutex) → 取出产品 → V(mutex) → V(empty)。

读者-写者（读者优先版）：readcount（在读人数）、mutex（保护 readcount）、wrt（读写互斥）。读者：P(mutex)，readcount++，若 readcount = 1 则 P(wrt)，V(mutex)，读；读完 P(mutex)，readcount−−，若 readcount = 0 则 V(wrt)，V(mutex)。写者：P(wrt)，写，V(wrt)。

必考坑：生产者-消费者里 P 的顺序不能反——先 P(mutex) 再 P(empty)，缓冲区满时生产者占着互斥量等空位、消费者又等互斥量，直接死锁。读者优先版会饿死写者；要写者优先需再加一个写互斥信号量。
7. 死锁四个必要条件【必背】 ★★★☆☆
  • 1互斥条件：资源不能共享。
  • 2请求和保持条件：持有资源同时请求新资源。
  • 3不剥夺条件：资源不能被强制回收。

8. 银行家算法核心 ★★★☆☆
Need[i] = Max[i] − Allocation[i]
  • 安全性检查：找一个 Need ≤ Available 的进程，能找到安全序列，则系统处于安全状态。
  • 安全状态一定不会死锁，不安全状态可能死锁。
真题 · 2020 年第 27 题：某系统中有 A、B 两类资源各 6 个。t 时刻资源分配及需求情况如下：P1 已分配 (2, 3)、需求总量 (4, 4)；P2 已分配 (2, 1)、需求总量 (3, 1)；P3 已分配 (1, 2)、需求总量 (3, 4)。t 时刻安全性检测结果是（　）。A. 存在安全序列 P1、P2、P3　B. 存在安全序列 P2、P1、P3　C. 存在安全序列 P2、P3、P1　D. 不存在安全序列
解：先算 Need = Max − Allocation：P1 (2, 1)、P2 (1, 0)、P3 (2, 2)；Available = (6, 6) − (5, 6) = (1, 0)。初始只有 P2 的 Need ≤ Available；P2 完成并释放后 Available = (3, 1)，可满足 P1；P1 释放后 (5, 4)，再满足 P3。安全序列为 P2 → P1 → P3 → B。
9. 连续内存分配算法对比 ★★☆☆☆
算法选哪块效果 / 代价
首次适应从低地址起第一个够大的空闲区实现简单、通常查找开销较低；低地址碎片多，但高地址常保留大块

例（同一内存、同一请求序列，三种算法）：空闲区按地址从低到高为 100K、500K、200K、300K、600K；请求依次为 212K、417K、112K、426K。
首次适应：212 → 500K 块（余 288K）；417 → 600K 块（余 183K）；112 → 288K 余块（余 176K）；426 → 无块可容，失败（空闲总量还剩 935K，却没有一块 ≥ 426K——这就是外部碎片）。
最佳适应：212 → 300K 块（余 88K）；417 → 500K 块（余 83K）；112 → 200K 块（余 88K）；426 → 600K 块（余 174K）→ 全部装下，代价是留下三个几十 K 的小碎片。
最坏适应：212 → 600K 块（余 388K）；417 → 500K 块（余 83K）；112 → 388K 余块（余 276K）；426 → 失败。

碎片：外部碎片 = 空闲区总量够、单块都不够；内部碎片 = 已分配区内用不上的零头。紧凑（拼接）能消除外部碎片，但要移动进程、代价大。

真题 · 2019 年第 32 题：在下列动态分区分配算法中，最容易产生内存碎片的是（　）。A. 首次适应算法　B. 最坏适应算法　C. 最佳适应算法　D. 循环首次适应算法
解：最佳适应每次选取与需求大小最接近的空闲分区，剩余部分往往是难以再利用的微小空闲块，外碎片最多 → C。
10. 请求分页 · 缺页中断处理步骤 ★★★★☆
  1. 1查页表：驻留位为 0 → 产生缺页中断（内中断 / 异常，可恢复）。
  2. 2保存现场，查外存地址，确定页面所在外存位置。
  3. 3有空闲内存块 → 直接用；无空闲块 → 按置换算法选牺牲页，脏页先写回外存。
  4. 4把缺失页调入内存，修改页表（驻留位 1，修改位 / 访问位清零或置位）。
  5. 5恢复现场，重新执行引起缺页的那条访存指令（不是下一条）。
缺页中断返回点是故障指令本身，这正是它能“恢复”的关键；一般外中断返回的是下一条指令。
分配与置换组合只有三种：固定分配局部置换、可变分配全局置换、可变分配局部置换。页面频繁换入换出叫抖动，对策是工作集策略或挂起部分进程。
11. 段页式存储管理与地址变换 ★★☆☆☆

《连续内存分配》与《请求分页》之外，把两者合起来的段页式常单独出题：逻辑地址是三段，变换是“先段后页”，访存次数与越界检查是选择题与计算题的双料考点。

逻辑地址结构：段号 S | 段内页号 P | 页内偏移 W。若页大小为 2w，则 W 占 w 位；段长可变，段内页数不定——这是它与纯分页（一维地址）最根本的区别。

表表项内容一张还是多张
段表段长、页表始址（该段页表的基址）每进程一张
页表页框号，以及状态 / 权限位每段一张
  1. 查段表：段号 S ≥ 段表长度 → 越界中断。
  2. 查段长：段内偏移 = P × 页大小 + W，若 ≥ 该段段长 → 越界中断。
  3. 查页表：由段表项给出的页表基址 + P 找到页表项；页表项不存在或页面不在内存 → 缺页中断（请求段页式下由系统调页），权限不符 → 访问越权中断。
  4. 拼物理地址：物理地址 = 页框号 × 页大小 + W；页内偏移在变换前后原样保留。

真题 · 2016 年第 28 题：某进程的段表内容如下：段 0：段长 100、内存起始地址 6000、只读、在内存；段 1：段长 200、读写、不在内存；段 2：段长 300、内存起始地址 4000、读写、在内存。当访问段号为 2、段内地址为 400 的逻辑地址时，地址转换的结果是（　）。A. 段缺失异常　B. 得到内存地址 4400　C. 越权异常　D. 越界异常
解：段 2 在内存、权限为读写，均无问题；但段内地址 400 ≥ 段长 300，越界检查不通过 → D。（检查顺序：段号合法 → 段长越界 → 权限，不要一看到数字就先去拼物理地址。）
易错：变换顺序是“先段后页”，不要先拼页号再查段；页内偏移变换前后不变，凡是把偏移也换算一遍的都是错的；段页式仍有缺页中断，别因“段已在内存”就断定页一定在内存。

星级注：本卡星级依据弱——段页式无独立标签，按「段式内存管理」3 年（2009、2016、2019）的上位口径定档，2★ 为保守定档，待更细的逐题统计校准。

16. 磁盘调度算法 ★★★☆☆

FCFS（先来先服务）：按请求到达顺序服务，简单但效率低。SSTF（最短寻道时间优先）：每次选离磁头最近的请求，可能饥饿。SCAN（电梯）：磁头单向移动服务沿途请求，到端点再反向。C-SCAN：到端点后直接返回起点、只单向服务。LOOK / C-LOOK：不用到端点，到本方向最远请求即返回。

例（同一请求队列，四种算法）：磁道 0 ~ 199，磁头在 53，请求队列依次为 98, 183, 37, 122, 14, 124, 65, 67。

FCFS98, 183, 37, 122, 14, 124, 65, 67（原序）640
SSTF65, 67, 37, 14, 98, 122, 124, 183236
SCAN（先向大号）65, 67, 98, 122, 124, 183,（到 199 后反向）37, 14331

FCFS 的 640 几乎全浪费在来回横跳上；SSTF 贪心就近最省路，但远处请求可能一直等；SCAN 多走「到端点」的路，换来公平、无饥饿。
真题 · 2021 年第 26 题：某系统中磁盘的磁道数为 200（0 ~ 199），磁头当前在 184 号磁道上。用户进程提出的磁盘访问请求对应的磁道号依次为 184, 187, 176, 182, 199。若采用最短寻道时间优先（SSTF）调度算法完成磁盘访问，则磁头移动的距离（磁道数）是（　）。A. 37　B. 38　C. 41　D. 42
解：184 就地服务（移动 0）；当前最近的是 182（2）；再选 187（5）；再选 176（11）；最后 199（23）。总移动距离 = 0 + 2 + 5 + 11 + 23 = 41 → C。
17. 磁盘访问时间 ★★★☆☆
T = T寻道 + T旋转延迟 + T传输

  • 传输时间 = 数据量传输速率。
  • 转速 RPM → 转一圈时间 = 60RPM 秒。

18. 磁盘空闲空间管理 · 位示图与成组链接法 ★★★☆☆

合辑讲了磁盘调度与访问时间、文件物理结构，但没讲空闲盘块本身怎么管。文件系统大题问“盘上还剩多少空闲块、某块分给谁”时，答案就在这张卡。

位示图法（Bitmap）：用 1 位表示 1 个盘块，位示图常驻内存。约定（王道口径，题干若反着给以题干为准）：1 = 已分配，0 = 空闲。设字长为 w 位、盘块号为 b（均从 0 起数）：字号 = ⌊b / w⌋，位号 = b mod w；反推：块号 = 字号 × w + 位号。若块号、字号、位号均从 1 起数，须先对块号减 1 再套上式：字号 = ⌊(b − 1) / w⌋ + 1，位号 = (b − 1) mod w + 1；反推：块号 =（字号 − 1）× w + 位号。分配：找 0 位置 1，返回块号；回收：对应位置 0。找空闲块时可按字扫描——先找非全 1 的字，再在字内找 0 位。

例题（程序验算）：① 盘块号 100，字长 32 位 → 字号 = 100 ÷ 32 = 3，位号 = 100 mod 32 = 4（3 × 32 + 4 = 100 ✓）。反推：字号 5、位号 7 → 块号 = 5 × 32 + 7 = 167。② 磁盘容量 256 MB，盘块 4 KB → 盘块总数 = 256 MB ÷ 4 KB = 65,536 块，位示图需 65,536 位 = 8,192 B = 8 KB。③ 位示图大小通用式：盘块数 ÷ 8（字节数），算完记得把位换成字节。④ 编号 1 起的边界（w = 32，程序验算）：b = 32 → 字号 = ⌊31 / 32⌋ + 1 = 1，位号 = 31 mod 32 + 1 = 32；b = 33 → 字号 = 2，位号 = 1。

空闲链表法（对照）：空闲盘块链——每个空闲块存下一个空闲块号，链首在专用块；空闲盘区链——连续空闲区为一个结点，存首块号与块数。实现简单，但分配/回收要顺链改指针，不如位示图找块快。

成组链接法（Grouped Linking，UNIX 采用）：把空闲块分组（王道例中每组 100 块，组内块数上限以题干为准），除第一组外，每组的组首块（链接块）存放下一组的空闲块数与各块号；第一组的信息存放在专用块（超级块）中。分配：从专用块取一块；组内取空时，把下一组的信息读入专用块再取。回收：专用块所指组未满，直接把回收块号加入；组已满时，先把专用块内容写入新回收块（它成为新一组的链接块），再把该回收块号写入专用块作组首。

真题 · 2023 年第 25 题：某系统采用页式存储管理，用位图管理空闲页框。若页大小为 4 KB，物理内存大小为 16 GB，则位图所占空间的大小是（　）。A. 128 B　B. 128 KB　C. 512 KB　D. 4 MB
解：页框数 = 16 GB / 4 KB = 234 / 212 = 222，位图需 222 位 = 219 B = 512 KB → C。
坑：① 字号/位号的起点（0 起还是 1 起）是本题最常见的丢分点：0 起时字号 = ⌊b/w⌋；1 起时先对块号减 1 再套公式（字号 = ⌊(b−1)/w⌋ + 1、位号 = (b−1) mod w + 1），切勿在 0 起的结果上直接各加 1——b 恰为 w 的整数倍时会整字错位。做题先看题干编号方式，不要硬套。② 位示图“1 空闲还是 0 空闲”各教材相反，题干给的约定优先于记忆。③ 成组链接回收的两条路不要混：组未满是“直接加入”，组满是“旧专用块内容先落盘成新组首”，顺序一反，下一组的链就断了。

19. SPOOLing 假脱机技术 ★★★☆☆

合辑的 I/O 部分讲了中断与 DMA，却没有这项把独占设备「变」成共享设备的经典技术——它几乎只考选择题，概念边界一错就丢分。

SPOOLing（假脱机技术，Simultaneous Peripheral Operations On Line，同时联机外围操作）：在多道程序环境下，用磁盘（可共享设备）作中转，模拟脱机输入/输出：利用磁盘上的输入井和输出井实现数据暂存与排队——输入方向由输入进程把设备数据送入输入井、供进程读取，输出方向由进程把数据提交到输出井、再由输出进程送往设备。这样多个进程可以排队共享同一台独占设备的使用权，设备在逻辑上表现为一台虚拟设备，但同一时刻仍只服务一个作业。

组成作用
输入井 / 输出井磁盘上开辟的两块存储区：输入井暂存外部设备送来的数据，输出井暂存各进程待输出的数据（按作业组织成文件排队）
输入 / 输出缓冲区内存中的缓冲，负责井与设备、井与进程之间的数据中转，抹平速度差
输入 / 输出进程常驻的井管理进程（守护进程）：把设备数据搬进输入井、把输出井队列里的数据逐个送往设备

打印全流程（输出 SPOOLing）：① 进程申请打印，系统在输出井给它分配空闲空间，把要打印的数据拷入输出井；② 系统把这次打印请求挂到输出井的请求队列上；③ 进程至此即可返回继续运行，不必等打印机；④ 输出进程按队列顺序，把输出井里的数据逐份送打印机打完。多个进程可以先后「申请打印」，各自的数据在井里排队——对每个进程而言，打印机仿佛是它独占的，实则共享。

例题（示意数字，程序验算）：某作业要打印 200 页，打印机速度 5 页/分钟，实际打印需 200 ÷ 5 = 40 分钟。无 SPOOLing 且采用同步独占打印方式时，进程可能因等待打印设备而长时间阻塞；有 SPOOLing 时，进程只需把 200 页数据按磁盘速度写入输出井、挂上请求队列即可返回做别的事，40 分钟的打印由输出进程在后台完成，打印机完成 200 页仍需 40 分钟。结论：SPOOLing 解耦的是「进程的等待时间」与「设备的服务时间」，设备本身一分钟也快不了。
坑：① SPOOLing 没有把打印机变成真共享设备：同一时刻打印机仍只服务一个作业，共享的是「排队提交」这一层，别选「多进程可同时打印」。② 「井」在磁盘上，不在内存——把它说成内存缓冲区的选项是错的；内存里只有输入/输出缓冲区。③ 与缓冲技术分工不同：缓冲是内存中转、解决速度不匹配；SPOOLing 是外存设井 + 专门进程排队调度，核心目的是独占改共享，两者常配合但不是一回事。

来源：2027 考纲操作系统“I/O 管理：SPOOLing 技术”；王道《操作系统》I/O 管理一节。星级：上位口径「I/O 管理与设备管理」子项（合辑 v6 os-11/os-20 口径），本考点以选择题形式反复附带考查，保守定 3★（非独立年份统计）。

20. 进程通信 IPC · 共享存储 / 消息传递 / 管道 ★★★☆☆

合辑讲了进程、线程、信号量，但讲的都是同一进程内部或同步问题；不同进程地址空间互相隔离、彼此看不见对方的变量，它们之间怎么交换数据——进程通信（IPC，Inter-Process Communication，进程间通信）——合辑 0 覆盖。这是王道进程管理一节的固定考点。

方式怎么传特点
共享存储在内存中划一块双方都能直接读写的共享区，数据就放在区里，不经内核搬运速度最快（适合大批量、高频交换）；但共享内存本身不自动保证应用层操作的同步，有并发读写冲突时须另配信号量、互斥锁等同步机制
消息传递用 send / receive 原语，经操作系统内核把消息从发送方复制到接收方不要求进程共享用户地址空间，避免了直接共享同一数据缓冲区带来的部分竞争问题（收发顺序仍需协调）；但每次都要经内核复制，速度较慢。分直接通信（指名收发进程）与间接通信（经信箱 / 端口中转）
管道由内核维护的、有限容量的字节流缓冲区（不是普通磁盘文件），按先进先出顺序读写半双工：同一管道同一时刻只能单向传，双向要两根管道。无名管道通常经创建进程继承文件描述符、用于父子等有亲缘关系的进程，当所有引用它的文件描述符都关闭后内核才释放；命名管道（FIFO）可供有相应权限的任意进程按路径打开、不要求亲缘关系

速度差的根源（爱考的解释题）：共享存储只在建立共享区时需要系统参与，之后读写都是进程直接访问内存；消息传递每发一条都要陷入内核做复制——「谁经内核、谁不经」就是快慢分界。

例题（选型判断）：① 两个进程要高频交换大块数据、追求最快 → 共享存储，再配信号量防读写冲突。② 两个无亲缘关系的进程只需单向传一串字节流 → 命名管道（按 408 常规的管道创建与继承模型，无亲缘关系的进程通常选用命名管道）。③ 两个进程不希望共享地址空间、只偶尔传递少量控制信息 → 消息传递，慢一点但隔离干净。
坑：① 「共享存储最快」的前提是只比数据搬运：它不自带同步，忘了配互斥照样出错——选项里「共享存储无需同步」是错的。② 管道是半双工不是全双工，「用一根管道双向通信」不成立。③ 消息传递的「慢」是相对共享存储而言、慢在经内核复制，不是慢在要等对方在线。④ 无名管道在全部引用它的文件描述符关闭后才释放、且通常限亲缘进程，与命名管道的适用范围别记反。

来源：2027 考纲操作系统“进程管理：进程通信”；王道《操作系统》进程通信一节。星级：上位口径「进程管理」为合辑操作系统高频大类（进程状态 11 年、进程与线程 6 年等口径），进程通信无独立年份统计，保守定 3★（非独立统计）。

21. 缓冲管理 · 单缓冲 / 双缓冲 / 缓冲池 ★★★☆☆

合辑在生产者-消费者与 SPOOLing 卡里都提到缓冲，但缓冲本身——为什么能抹平速度差、单缓冲与双缓冲处理一块数据各要多久——没有卡。缓冲（Buffering，缓冲）是王道输入 / 输出管理一章的计算考点，公式就两条，代错对象整题皆错。

为什么要缓冲：① 缓和 CPU 与设备之间速度不匹配的矛盾；② 减少对 CPU 的中断次数、放宽对中断响应时间的限制；③ 解决数据粒度不匹配（一次产生 / 消费的数据量与设备传输块大小不一致）；④ 提高 CPU 与设备、设备与设备之间的并行性。

记号（王道口径）：T = 设备把一块数据送入缓冲区的时间；M = 缓冲区数据传送到用户区（工作区）的时间；C = CPU 处理（计算）工作区中这块数据的时间。以下均为连续处理多块数据时的稳态平均每块时间（忽略第一块的装入）。

方式平均每块处理时间为什么
单缓冲max(C, T) + M缓冲区只有一个：数据在缓冲区与用户区之间传送（M）期间设备不能往里送下一块；但 CPU 计算当前块（C）时设备可同时装入下一块（T），两者取大者，再串上每块都躲不掉的 M
双缓冲max(T, C + M)两个缓冲区轮换：设备装一块（T）与用户侧「传送 + 计算」上一块（M + C）可并行，稳态由较慢的一侧决定
缓冲池—（不考公式，考构成）系统公用缓冲池由空缓冲队列、装满输入数据的输入队列、装满输出数据的输出队列管理，工作方式有四种：收容输入、提取输入、收容输出、提取输出，输入进程与输出进程共享使用
例题（公式重算）：设 T = 100 μs、M = 20 μs、C = 80 μs。单缓冲：max(80, 100) + 20 = 120 μs / 块；双缓冲：max(100, 80 + 20) = 100 μs / 块。即双缓冲把瓶颈压到设备侧的 T 上——当 T ≥ C + M 时再加缓冲区也压不下每块时间，瓶颈在设备本身 ✓。
坑：① 两条公式里 M 的位置不同：单缓冲的 M 串在 max 之外（每块必付），双缓冲的 M 在 max 之内（与 T 并行比大小）——记混是头号丢分点。② 双缓冲不是「时间减半」：它只消掉可重叠部分的等待，稳态下限是 max(T, C + M)，设备慢时（T 大）加缓冲无用。③ 缓冲在内存中、SPOOLing 的「井」在外存上：两者目的也不同（缓冲抹速度差，SPOOLing 把独占设备改造成可共享的虚拟设备），别混为一谈。④ 循环缓冲是缓冲区的组织方式（多个缓冲区环形轮转、配 in / out 指针），适合数据流连续到达的场合，与「双缓冲 = 恰好两个」不是一回事。

来源：2027 考纲操作系统“输入 / 输出管理：I/O 软件层次结构与缓冲管理”；王道《操作系统》缓冲管理一节。星级：缓冲管理为操作系统输入 / 输出管理子项，暂无独立考频统计，3★ 为复习优先级估计（非独立统计）。

1. 香农公式与奈奎斯特公式 ★★★☆☆
奈奎斯特（无噪声）：C = 2W · log2 V
香农公式（有噪声）：C = W · log2(1 + S/N)
  • W：带宽（Hz）；V：信号电平数；S/N：信噪比。
真题 · 2016 年第 34 题：若某链路的频率带宽为 8 kHz，信噪比为 30 dB，该链路实际数据传输速率约为理论最大数据传输速率的 50%，则该链路的实际数据传输速率约是（　）。A. 8 kbit/s　B. 20 kbit/s　C. 40 kbit/s　D. 80 kbit/s
解：信噪比 30 dB → S/N = 1030/10 = 1000。香农公式：C = 8000 × log2(1 + 1000) ≈ 8000 × 10 = 80 kbit/s；实际速率 ≈ 80 × 50% = 40 kbit/s → C。
【坑】注意 dB 换算：10·log10(S/N)；30dB = 103 = 1000（信噪比）。
2. 物理层编码 · 不归零 / 曼彻斯特 / 差分曼彻斯特 ★★☆☆☆

《香农公式与奈奎斯特公式》只讲了信道容量，没讲数据怎么变成信号。本卡补物理层三种编码的规则对照——画波形题与“哪种编码自同步、带宽几倍”的选择题都从这里出。

编码规则（王道 / 802.3 约定）同步与带宽
不归零编码1 为高电平，0 为低电平（或相反，题干为准）；一位一个码元，码元内无跳变带宽利用高，但长串 0 / 1 无跳变，接收方难以同步，且有直流分量
曼彻斯特编码每位中间必跳变：1 为高 → 低，0 为低 → 高；中间跳变既传数据又作时钟自同步好，无直流分量；码元速率 = 2 × 数据速率，占用带宽约为不归零编码的 2 倍；用于 10 Mbps 以太网
差分曼彻斯特编码每位中间必跳变作时钟；位开始处：有跳变表示 0，无跳变表示 1自同步好；信号线接反仍可解码，对极性不敏感；用于令牌环等
例（数据 1011，曼彻斯特与差分曼彻斯特按每位前后两半列出，H 为高电平、L 为低电平）：
不归零编码：H　L　H　H；
曼彻斯特编码：H L　|　L H　|　H L　|　H L；
差分曼彻斯特编码（设起始电平为低）：L H　|　L H　|　H L　|　L H。
核对差分曼彻斯特编码：第 1 位 1，开始无跳变（L），中间跳变（H）；第 2 位 0，开始跳变（L），中间跳变（H）；第 3 位 1，开始无跳变（H），中间跳变（L）；第 4 位 1，开始无跳变（L），中间跳变（H）✓
  • 补充：4B/5B 编码是分组码：每 4 位数据编为 5 位码字，效率 80%，码字经挑选保证有足够跳变助同步，用于快速以太网等；它不靠每位中间跳变，与曼彻斯特编码不是一回事。
易错：曼彻斯特编码与差分曼彻斯特编码的 1 / 0 规则不要只记“有跳变 = 1”：差分曼彻斯特编码是开始处有跳变表示 0；有些教材的曼彻斯特编码 1 / 0 取反，做题先看题干约定，以题干为准。

星级注：本卡星级为上位口径估计——按「编码方法 + 调制方法」5 年定档，其中编码方法本身仅约 2 年，非独立统计。

3. CRC 循环冗余校验 · 计算步骤 ★★☆☆☆
  1. 1收发双方约定生成多项式 G(x)，校验位数 r = G(x) 的最高次数。
  2. 2信息码左移 r 位，低位补 0。
  3. 3对移位后的码做模 2 除法（按位异或，不借位、不比较大小），得 r 位余数。
  4. 4余数补足 r 位作帧检验序列 FCS，拼在信息码后发送。
  5. 5接收端对整帧再模 2 除 G(x)：余数为 0 认为无错；余数非 0 则出错，丢弃 / 重传。
真题 · 2023 年第 37 题：若甲向乙发送数据时采用 CRC 校验，生成多项式为 G(x) = x4 + x + 1（即 G = 10011），则乙接收到下列比特串时，可以断定其在传输过程中未发生错误的是（　）。A. 101110000　B. 101110100　C. 101111000　D. 101111100
解：接收端把收到的比特串模 2 除以 10011，余数为 0 才可断定无错。逐个计算（程序复核）：A 余 1100，B 余 1000，C 余 0100，D 余 0000 → 仅 D。
CRC 只检错、不纠错；能检出全部单比特错、全部奇数个错（前提：生成多项式 G(x) 含有因子 (x + 1)）和长度 ≤ r 的突发错。余数为 0 不等于“绝对无错”，只是漏检概率极低。
4. 汉明码检错纠错 · 校验位个数与出错定位 ★★☆☆☆

《CRC 循环冗余校验》是只能检错的检错码，本卡补能定位并纠正 1 位错的纠错码：汉明码（Hamming 码，又译海明码）。口径注：汉明码在组成原理校验码一节已删，但在计算机网络差错控制一节仍保留——按计网考，不要因计组删了就跳过。

校验位个数：信息位 k，校验位 r，总长 n = k + r，须满足 2r ≥ k + r + 1（r 个校验位要能区分“无错”与 n 个位置各错一位，共 n + 1 种状态）。
速查：k = 1 → r = 2；k = 2～4 → r = 3；k = 5～11 → r = 4；k = 12～26 → r = 5；k = 27～57 → r = 6。
  • 校验位位置：校验位 Pi 放在位号为 2i−1 的位置（1、2、4、8…），其余位置按序放信息位。本卡把码字从左到右记为 H7…H1，H1 在最右，校验位在位号 1、2、4 处。
  • 分组规则：Pi 管所有位号二进制第 i 位为 1 的位置（含自身）。本卡按偶校验：每组内 1 的个数为偶数（题干若给奇校验则改为奇数，规则不变）。
  • 出错定位：收方重算各组偶校验，Si = 组内异或（组出错为 1，否则为 0）；S3S2S1 拼成的二进制数即出错位号，0 表示无错，定位后把该位取反即纠正。
例题（编码）：信息位 1010，记为 D4D3D2D1。k = 4 → r = 3（23 = 8 ≥ 4 + 3 + 1 = 8 ✓）。分布：H7 = D4 = 1，H6 = D3 = 0，H5 = D2 = 1，H4 = P3，H3 = D1 = 0，H2 = P2，H1 = P1。
P1 = H3 ⊕ H5 ⊕ H7 = 0 ⊕ 1 ⊕ 1 = 0；P2 = H3 ⊕ H6 ⊕ H7 = 0 ⊕ 0 ⊕ 1 = 1；P3 = H5 ⊕ H6 ⊕ H7 = 1 ⊕ 0 ⊕ 1 = 0。
码字 H7…H1 = 1010010。
例题（检错纠错）：若传输中 H5 翻转为 0，收到 1000010。重算：S1 = H1 ⊕ H3 ⊕ H5 ⊕ H7 = 0 ⊕ 0 ⊕ 0 ⊕ 1 = 1；S2 = H2 ⊕ H3 ⊕ H6 ⊕ H7 = 1 ⊕ 0 ⊕ 0 ⊕ 1 = 0；S3 = H4 ⊕ H5 ⊕ H6 ⊕ H7 = 0 ⊕ 0 ⊕ 0 ⊕ 1 = 1。S3S2S1 = 101（二进制）= 5 → H5 出错，取反恢复为 1010010 ✓
真题 · 2013 年第 15 题：用海明码对长度为 8 位的数据进行检 / 纠错时，若能纠正一位错，则校验位数至少为（　）。A. 2　B. 3　C. 4　D. 5
解：能纠一位错需满足 2r ≥ n + r + 1。n = 8：r = 3 时 8 < 8 + 3 + 1 = 12，不够；r = 4 时 16 ≥ 8 + 4 + 1 = 13，足够 → C。
易错：汉明码只能纠 1 位错；两位错可能被误判为另一位，不要当成万能；校验位个数公式里的 +1 是“无错”状态，漏了它 r 会算小一位；位号方向以题干为准，不要按左右死记位置，算分组时看位号的二进制取值。
5. 信道利用率公式 ★★★☆☆
U = TDTD + RTT + TA ≈ TDTD + RTT
  • 停止等待协议：发送窗口 = 1。
  • 滑动窗口协议：U = W · TDTD + RTT + TA（W 为窗口大小）。
真题 · 2020 年第 36 题：假设主机甲采用停等协议向主机乙发送数据帧，数据帧长与确认帧长均为 1000 B。数据传输速率是 10 kbit/s，单向传播时延是 200 ms。则甲的最大信道利用率是（　）。A. 80%　B. 66.7%　C. 44.4%　D. 40%
解：发送一帧的时间 = 1000 × 8 / 10 000 = 800 ms，确认帧发送时间同为 800 ms。一个完整发送周期 = 800（发数据帧）+ 200（传播）+ 800（发确认帧）+ 200（确认回传播）= 2000 ms，利用率 = 800 / 2000 = 40% → D。传播与确认的耗时占比越大，停等利用率越低——这正是要用滑动窗口的原因。
【坑】信道利用率不能超过 100%，若计算结果 > 1 则取 1。

设序号位数为 n 位，序号范围 0 ～ 2n − 1。GBN（后退 N 帧）：发送窗口 WT ≤ 2n − 1，接收窗口 WR = 1。SR（选择重传）：发送窗口 + 接收窗口 ≤ 2n，通常各取 2n−1。为什么 GBN 的接收窗口只能是 1、代价是什么，看例子：

例（一帧丢失，两种协议的反应）：序号 3 bit，发送窗口取 4。发送方连发 0、1、2、3 号帧，其中 1 号帧在途中丢失。
GBN：接收方只按序接收——0 号收下；2、3 号到达时，它期待的是 1 号，乱序帧直接丢弃（重复发送对 0 号帧的累计确认；若按「下一期待帧」编号则写作 ACK 1）。发送方超时后从 1 号起重传 1、2、3 三帧：2、3 明明已经到过一次，还得白传一遍，这就是「后退 N 帧」的代价。接收窗口 = 1 的根源就在这：它不缓存乱序帧。
SR：接收窗口同样是 4，2、3 号先缓存下来；发送方只需单独重传 1 号；1 号一到，1、2、3 按序一起交付。只补缺口、不传冤枉路，代价是接收方要有缓存、双方窗口都要受「和 ≤ 2n」约束。
真题 · 2023 年第 35 题：假设通过同一信道，数据链路层分别采用停等协议、GBN 协议和 SR 协议（发送窗口和接收窗口相等）传输数据，三个协议数据帧长相同，忽略确认帧长度，帧序号位数为 3 bit。若三个协议的发送方最大信道利用率分别是 U1、U2、U3，则它们满足的关系是（　）。A. U1 ≤ U2 ≤ U3　B. U1 ≤ U3 ≤ U2　C. U2 ≤ U3 ≤ U1　D. U3 ≤ U2 ≤ U1
解：在未饱和前，发送窗口越大、信道利用率越高（达到 100% 后饱和、不再增长）：停等窗口为 1，最小；GBN 发送窗口最大 23 − 1 = 7；SR 发送窗口最大 23−1 = 4。故 U1 ≤ U3 ≤ U2 → B。
7. 介质访问控制对比 · CSMA/CD（载波监听多路访问/碰撞检测） vs CSMA/CA（载波监听多路访问/碰撞避免） ★★★★★
项目CSMA/CD（检测）CSMA/CA（避免）
适用有线以太网 IEEE 802.3无线局域网 IEEE 802.11
核心动作先听后发，边发边听；冲突立即停发并发送干扰信号先听，空闲后等帧间间隔 + 随机退避再发；发时无法同时监听（自身信号会掩盖他人信号）
冲突后截断二进制指数退避：退避时隙数在 [0, 2k−1] 内随机，k = min(重传次数, 10)；重传 16 次失败则放弃；争用期 51.2 μs（10 Mbps，最小帧 64 B）随机退避 + RTS / CTS 握手 + 接收方 ACK 确认；仍不能完全消除冲突
真题 · 2023 年第 36 题：已知 10BaseT 以太网的争用时间片为 51.2 μs。若网卡在发送某帧时发生了连续 4 次冲突，则基于二进制指数退避算法确定的再次尝试重发该帧前等待的最长时间是（　）。A. 51.2 μs　B. 204.8 μs　C. 768 μs　D. 819.2 μs
解：第 k 次冲突后，等待时隙在 0 ~ 2k − 1 之间随机取：k = 4 时最长 24 − 1 = 15 个时隙，15 × 51.2 μs = 768 μs → C。
CD 是“检测到再处理”，CA 是“尽量事前避免”——无线用 CA 不是因为它更强，而是因为无线环境下冲突检测本身做不到。

15. TCP（传输控制协议） 滑动窗口与流量控制 ★★★☆☆

接收方在确认段中通告 rwnd（接收窗口），发送方实际发送窗口 = min(rwnd, cwnd)：rwnd 管流量控制（别淹没接收方），cwnd（拥塞窗口） 管拥塞控制（别淹没网络），两者取小。

零窗口：rwnd = 0 时发送方停发数据，但启动持续计时器，超时后发 1 字节探测段，接收方回告当前窗口——防止“接收方已恢复、发送方却永远等着”的死锁。

图：发送窗口分区（真题 · 2021 年第 40 题的状态）：窗口左界 501、大小 500 字节、右界 1001。
真题 · 2021 年第 40 题：设主机甲通过 TCP 向主机乙发送数据。甲在 t0 时刻发送一个序号 seq = 501、封装 200 B 数据的段，在 t1 时刻收到乙发送的序号 seq = 601、确认序号 ack = 501、接收窗口 rwnd = 500 B 的段，则甲在未收到新的确认段之前，可以继续向乙发送的数据序号范围是（　）。A. 501 ~ 1000　B. 601 ~ 1100　C. 701 ~ 1000　D. 801 ~ 1100
解：ack = 501 说明 501 起的段尚未得到确认；发送窗口右界 = 501 + 500 = 1001，其中 501 ~ 700 已发送未确认（见上图），还能发送的序号范围是 701 ~ 1000，共 300 B → C。
区分：流量控制是端到端的接收能力问题；拥塞控制是全网负载问题。糊涂窗口综合征（接收方通告极小窗口、发送方发极小段）是流量控制的副作用，解法是接收方攒够再通告、发送方用 Nagle 算法攒够再发。
16. TCP（传输控制协议） 拥塞控制四阶段 ★★★★☆
  • 慢开始：cwnd（拥塞窗口） 从 1 开始，每 RTT（往返时延） 翻倍。
  • 拥塞避免：cwnd 超过 ssthresh（慢开始门限） 后，每 RTT + 1。
  • 快重传：收到 3 个重复 ACK 立即重传。
  • 快恢复：ssthresh = cwnd2，cwnd = ssthresh。
真题 · 2022 年第 38 题：假设主机甲和主机乙已建立一个 TCP 连接，最大段长 MSS = 1 KB，甲一直有数据向乙发送。当甲的拥塞窗口为 16 KB 时计时器发生了超时，则甲的拥塞窗口再次增长到 16 KB 所需要的时间至少是（　）。A. 4 RTT　B. 5 RTT　C. 11 RTT　D. 16 RTT
解：超时后 ssthresh = 16 / 2 = 8，cwnd = 1 重新慢开始：1 → 2 → 4 → 8 用 3 个 RTT；达到 ssthresh 后转拥塞避免，每 RTT 加 1：8 → 9 → … → 16 再用 8 个 RTT。共 3 + 8 = 11 RTT → C。
【坑】超时时 ssthresh = cwnd2，cwnd = 1，从慢开始重来！
【口径】快恢复（cwnd = ssthresh）是 408 简化模型；TCP Reno 实现中还会把已收到的重复 ACK 计入窗口（cwnd = ssthresh + 3）。考试按简化模型答。

21. TCP 可靠传输 · 序号、确认与超时重传 ★★★☆☆

合辑已有 TCP 滑动窗口（流量控制）、拥塞控制、握手挥手，本卡补传输层另一半：数据丢了、乱了，TCP 靠什么发现并补回来。注意与《GBN / SR 窗口》卡对照：TCP 的接收方行为与 GBN 不同。

序号（Sequence Number）：TCP 是字节流：每个字节编一个序号，报文段的序号 = 其首字节的序号；初始序号（ISN，Initial Sequence Number）随机选取，避免旧连接的报文混入新连接。32 位序号按模 232 循环，空间用完即回绕。回绕未必很慢：以 1 Gbit/s 持续发送计，绕完 232 字节只需约 34.4 s，可能短于报文的最大生存时间，旧报文的序号可能与新数据重叠。两件事分工不同：随机 ISN 让不同连接实例的序号空间错开，降低旧连接的报文混入新连接的风险；同一连接在高速传输中发生序号回绕时，则靠 TCP 时间戳与 PAWS（Protection Against Wrapped Sequence Numbers，序号回绕保护）按时间戳新旧拒收旧段。

确认（Acknowledgment）：累计确认：确认号 ack = 期望收到的下一字节序号，表示该号之前的所有字节已正确收到；确认可捎带在数据段中发出。收到失序段时，TCP 接收方一般缓存该段并立即发重复 ACK——这与 GBN（接收窗口为 1，失序段直接丢弃）不同，是选择题常设的对比点。校验和出错的段直接丢弃，发送方靠超时重传补回（TCP 没有否定确认 NAK）。

超时重传（Retransmission Timeout, RTO）：发送方发完段启动计时器，超时未收到确认即重传。RTO 不能定死：网络时延会变，故用加权平均估计（Jacobson 算法，王道口径，α = 1/8，β = 1/4）：

平滑往返时间 SRTT（Smoothed Round-Trip Time）：SRTT新 = (1 − α) × SRTT旧 + α × RTT样本
往返时间偏差 RTTVAR：RTTVAR新 = (1 − β) × RTTVAR旧 + β × |SRTT旧 − RTT样本|
超时重传时间：RTO = SRTT新 + 4 × RTTVAR新
例题（程序验算）：SRTT旧 = 100 ms，RTTVAR旧 = 20 ms，新测 RTT样本 = 120 ms → SRTT新 = 0.875 × 100 + 0.125 × 120 = 102.5 ms；RTTVAR新 = 0.75 × 20 + 0.25 × |100 − 120| = 15 + 5 = 20 ms；RTO = 102.5 + 4 × 20 = 182.5 ms。
重传触发条件随后处理（接《拥塞控制》卡）
超时重传计时器超时仍未收到确认慢开始门限 ssthresh = cwnd / 2，cwnd = 1，从慢开始重来
快重传（Fast Retransmit）收到 3 个重复 ACK，不等超时立即重传缺失段快恢复：ssthresh = cwnd / 2，cwnd = ssthresh（408 简化模型），进入拥塞避免
真题 · 2011 年第 40 题：主机甲与主机乙之间已建立一个 TCP 连接，主机甲向主机乙发送了 3 个连续的 TCP 段，分别包含 300 字节、400 字节和 500 字节的有效载荷，第 3 个段的序号为 900。若主机乙仅正确接收到第 1 和第 3 个段，则主机乙发送给主机甲的确认序号是（　）。A. 300　B. 500　C. 1200　D. 1400
解：由第 3 个段的序号倒推：第 2 个段序号 = 900 − 400 = 500（第 1 个段序号为 200）。TCP 采用累积确认，确认号 = 期望收到的下一个字节的序号；乙缺第 2 个段，确认号停在 500（第 3 个段只缓存，不越过缺口确认）→ B。
坑：① 快重传的门槛是“3 个重复 ACK”，即连同原确认共 4 个相同 ack，不要写成“3 个 ACK”。② 超时与快重传的 cwnd 处理不同：超时回 1，快重传不回 1——这是拥塞控制卡与本卡的联动考点。③ RTO 公式里的偏差项用的是旧 SRTT 与样本之差的绝对值，不是新 SRTT；α、β 别互换（α 管 SRTT 为 1/8，β 管偏差为 1/4）。

22. 信道复用 · 频分 / 时分 / 波分 / 码分 ★★★☆☆

合辑的 CSMA/CD vs CSMA/CA 卡讲的是随机访问，本卡补另一大类介质访问控制：信道划分（多路复用，Multiplexing）。csgraduates 介质访问控制一节明确把“多路复用和 CSMA/CA”列为选择题考点。

复用方式划分依据要点
FDM（频分复用）频率各路信号占不同频段，可同时传；频段间需留保护频带防串扰；适合模拟信号，传统电话、广播常用
TDM（时分复用）时间时间划为时隙，各路轮流占用；同步时分时隙固定，某路无数据时时隙空闲浪费
STDM（统计时分复用）时间（动态）时隙按需动态分配，适合突发数据；时隙中需附加地址/标志以区分归属；集中器场景典型
WDM（波分复用）波长即光纤上的频分复用：多路光信号用不同波长在同一光纤中传输，大幅提升光纤容量
CDM（码分复用）码型各站码片序列互正交，可同频同时传；是码分多址 CDMA（Code Division Multiple Access）的基础（见下）

英文全称：FDM = Frequency Division Multiplexing，TDM = Time Division Multiplexing，STDM = Statistical Time Division Multiplexing，WDM = Wavelength Division Multiplexing，CDM = Code Division Multiplexing。

码分复用 / CDMA 计算：每个站被指派一个 m 位码片序列（Chip Sequence），1 个比特时间 = m 个码片时间。发送比特 1 → 发原码片序列；发送比特 0 → 发其反码（不是全 0）。多站同时发送时信道中信号线性叠加；接收方用本站码片序列求规格化内积（对应位相乘求和再除以 m）：结果为 1 → 对方发 1，−1 → 发 0，0 → 该站未发送。正交是前提：不同站码片序列的规格化内积为 0。

例题（程序验算，码片长 4）：站 A 码片 (+1, +1, −1, −1)，站 B (+1, −1, +1, −1)，站 C (+1, −1, −1, +1)，两两内积均为 0，正交 ✓。A 发 1（原码）、B 发 0（反码 −1, +1, −1, +1）、C 未发 → 信道叠加 S = (0, +2, −2, 0)。分离：A：(0×1 + 2×1 + (−2)×(−1) + 0) ÷ 4 = 1 → A 发 1 ✓；B：(0×1 + 2×(−1) + (−2)×1 + 0) ÷ 4 = −1 → B 发 0 ✓；C：(0 + (−2) + 2 + 0) ÷ 4 = 0 → C 未发 ✓。代价：码片速率 = m × 数据速率，占用频带展宽 m 倍。
真题 · 2014 年第 37 题：站点 A、B、C 通过 CDMA 共享链路，A、B、C 的码片序列分别是 (1, 1, 1, 1)、(1, −1, 1, −1) 和 (1, 1, −1, −1)。若 C 从链路上收到的序列是 (2, 0, 2, 0, 0, −2, 0, −2, 0, 2, 0, 2)，则 C 收到 A 发送的数据是（　）。A. 000　B. 101　C. 110　D. 111
解：把收到序列按码片长度 4 分组，与 A 的码片序列做内积并除以 4：(2 + 0 + 2 + 0) / 4 = 1 → 比特 1；(0 − 2 + 0 − 2) / 4 = −1 → 比特 0；(0 + 2 + 0 + 2) / 4 = 1 → 比特 1。得 101 → B。
坑：① 发 0 是“反码”不是“不发”：不发对应内积 0，发 0 对应 −1，三者务必分清。② 规格化内积别忘了除以 m，否则数值差 m 倍。③ 同步时分与统计时分的区别只在“时隙固定还是按需”：题干出现“用户无数据时时隙空闲”指向同步时分的浪费，出现“按需分配、需附加标志”指向统计时分。

23. CIDR 与路由聚合 · 最长前缀匹配 ★★★☆☆

合辑《子网划分计算》讲的是把一个网分小；本卡补反方向：用 CIDR（Classless Inter-Domain Routing，无分类域间路由选择）把多个连续小网在路由表里合并成一条，以及路由器拿到目的地址后到底按哪条走。划分与聚合是一对镜像考点。

CIDR 记法：地址写成 a.b.c.d / x，x 为网络前缀位数（等价于掩码中 1 的个数）。它取消了 A / B / C 类的固定边界，前缀长短可任意。

路由聚合（超网）：把若干网络号连续的网络合并为一条路由。能整段聚合的条件有三：① 地址连续；② 高位（二进制前缀）相同，共同前缀有多长、聚合后的 /x 就是多少；③ 起始地址对齐——聚合块的起始地址必须是块大小的整数倍（等价于被合并段恰好构成一个完整的对齐块）。聚合能减少路由表项、降低路由信息的存储与维护开销、提高可扩展性，这是 CIDR 的主要目的（实际转发速度是否提升还取决于路由器的查表实现）。

例题（ipaddress 模块独立验证）：① 聚合：将 192.168.0.0/24、192.168.1.0/24、192.168.2.0/24、192.168.3.0/24 四个网合并。第三段字节 0～3 的二进制为 00000000 ～ 00000011，前 6 位相同 → 聚合为 192.168.0.0/22（前缀 24 − 2 = 22）✓。② 对齐反例：192.168.4.0/24 与 192.168.5.0/24 可聚合成 192.168.4.0/23；但 192.168.5.0/24 与 192.168.6.0/24 虽然地址连续，不能整段聚合成一条 /23——/23 块必须从偶数段起（5 与 6 跨了对齐边界），只能写成两条 ✓。

最长前缀匹配（Longest Prefix Match，最长前缀匹配）：转发时路由表可能有多条都「匹配」目的地址，规则是选前缀最长（网络最具体）的那一条优先；默认路由 0.0.0.0/0 前缀长为 0、能匹配一切地址，永远是最后兜底。

例题（ipaddress 模块独立验证）：路由表：192.168.0.0/16 → 接口 0；192.168.5.0/24 → 接口 1；192.168.5.128/25 → 接口 2。目的 192.168.5.200 三条全匹配，取最长的 /25 → 接口 2；目的 192.168.5.10 只匹配 /16 与 /24 两条 → 接口 1 ✓。
坑：① 聚合只看「连续」不够，还要对齐——5.0 与 6.0 连续但不可整聚，是最常见的设套点。② 精确聚合要求聚合块恰好覆盖原有网络、且这些网络能经相同下一跳正确到达：把额外的网包进聚合块又无更具体路由兜底，会误收本应转发他人的分组、甚至形成黑洞。③ 最长前缀匹配先比前缀长度，不是先比跳数或度量；度量只在同一前缀的多条路由之间再比。④ /x 里的 x 数的是前缀位数：/22 的掩码是 255.255.252.0，别与主机位数混算。

来源：2027 考纲计算机网络“网络层：IPv4 地址与 CIDR、路由选择”；王道《计算机网络》CIDR 与路由聚合一节。星级：上位口径「子网划分 + 子网聚合」并集 10 年（合辑 net-9 口径），CIDR 聚合与最长前缀为其子项、无独立年份统计，保守定 3★（非独立统计）。

24. 以太网交换机 · 自学习与帧转发 ★★★☆☆

合辑有以太网帧格式与 CSMA/CD，但交换机本身怎么知道一帧该往哪个端口送——只在 net-12 的星级注里被提过一句，没有卡。交换机自学习是数据链路层选择题的常客，规则就三步，记牢能稳拿分。

交换表（MAC 地址表）：每项记（MAC 地址，所在端口，老化时间）。交换机对收到的每一帧做：

  1. 学源：把帧的源 MAC 地址与进入端口记入交换表（已有该项则更新端口并刷新老化计时）——学的是「谁从哪个口进来」。
  2. 查目的：用帧的目的 MAC 地址查表。查到且端口 ≠ 入端口 → 只从该端口转发（单播）；查到且端口 == 入端口 → 丢弃（过滤，说明收发双方在同一侧，不必转发）。
  3. 查不到就泛洪（Flooding，泛洪）：向除入端口外的所有端口转发；目的地址为全 1 的广播帧同样泛洪。
例题（按规则逐步推演）：交换机 4 个端口分别接主机 A（口 1）、B（口 2）、C（口 3）、D（口 4），初始交换表为空。① A → B：学 A 在口 1；目的 B 查不到 → 泛洪到口 2、3、4。② B → A：学 B 在口 2；目的 A 在口 1 → 只从口 1 转发。③ C → A：学 C 在口 3；目的 A 在口 1 → 只从口 1 转发。④ A → C：A 已在表（刷新计时）；目的 C 在口 3 → 只从口 3 转发。最终交换表：A–1、B–2、C–3；D 从未发过帧、不在表中，此后发往 D 的帧仍要泛洪 ✓。
坑：① 学的是源 MAC、查的是目的 MAC——方向记反是此题型头号丢分点。② 交换机按 MAC 在数据链路层转发，不看 IP、不做路由选择，别与路由器混。③ 未划分 VLAN 的普通交换机每个端口是独立的冲突域、但整机默认仍是同一个广播域：广播帧照样泛洪到所有端口；配置 VLAN 后不同 VLAN 属于不同广播域，划分广播域也可经路由器。④ 表项会老化：主机久不发帧其表项被删，下次发往它的帧又变回泛洪，不是「学过就永远单播」。⑤ 与集线器对比：集线器（Hub，集线器）无交换表、收到信号都向除接收端口外的其他端口重复转发，且所有端口同属一个冲突域。

来源：2027 考纲计算机网络“数据链路层：局域网、以太网交换机”；王道《计算机网络》以太网交换机与自学习算法一节。星级：上位口径「以太网与介质访问控制」为合辑 net-16 口径（相关标签并集 13 年），交换机自学习为其子项、无独立年份统计，保守定 3★（非独立统计）。

25. DNS 解析与 DHCP 分配过程 ★★★☆☆

合辑《应用层协议对比》里 DNS（Domain Name System，域名系统）与 DHCP（Dynamic Host Configuration Protocol，动态主机配置协议）各只占一行表格，但两者的工作过程是选择题的固定考法：谁问谁、先问谁、用广播还是单播，一步记错整题皆错。本卡把两个过程补齐。

DNS 解析（主机查 www 的 IP 地址为例）：域名空间是分层树：根域名服务器 → 顶级域名服务器 → 权威（权限）域名服务器，主机先问本地 DNS 服务器，本地服务器代它向各级查询，结果层层缓存（缓存有生存时间 TTL，到期失效）。

方式含义用在哪一段
递归查询被问的服务器必须给出最终答案：自己不知道就替询问者继续问下去，最后把结果带回主机 → 本地 DNS 服务器
迭代查询被问的服务器不知道就返回「下一级该问谁」，由询问者自己接着问本地 DNS 服务器 → 根 / 顶级 / 权威服务器（通常）
例题（流程计数）：设主机与本地 DNS 服务器均未缓存结果，解析不涉及额外域名委派、CNAME 跳转及重试，采用根 → 顶级 → 权威三级查询模型。主机查一个这样的域名：主机向本地服务器发 1 次递归查询；本地服务器依次向根、顶级、权威服务器发 3 次迭代查询，拿到地址后答复主机。全程查询报文共 4 次（不计各级之间的答复报文）；若本地服务器缓存命中，则对外查询为 0 次、直接答复 ✓。

DHCP 分配（四步 DORA，以下指首次申请地址时）：新主机还没有 IP 地址，只能用 0.0.0.0 作源地址、向 255.255.255.255 广播（客户端口 68、服务器端口 67、基于 UDP）：

  1. 发现 Discover：客户端广播找服务器；
  2. 提供 Offer：服务器（可有多台）各自提出一个待分配的地址等配置；
  3. 请求 Request：客户端选定一个后仍以广播形式正式请求——广播是为了让未被选中的服务器知道、收回各自的 Offer（续租阶段通常可改用单播）；
  4. 确认 ACK：被选服务器向客户端发送 DHCPACK，确认地址租约及配置——ACK 可采用广播或单播，取决于客户端状态与广播标志等条件；客户端收到确认后才能正式使用该地址（租期到期前要续租）。

跨子网时客户端广播到不了外网的服务器，由 DHCP 中继代理（通常在路由器上）代为转发。

坑：① 递归与迭代的主体别记反：「主机对本地服务器是递归」指本地服务器负全责；本地服务器对根服务器一般是迭代——被问者只指路、不代跑。② DNS 主要用 UDP 53，但区域传送以及响应过大等场合用 TCP 53，「DNS 只用 UDP」是错误选项。③ DHCP 的 Request 还用广播不是失误：此时地址尚未经 ACK 确认、客户端还不能当作自己的单播地址用，且需要通知落选服务器。④ DHCP 分配的不只是 IP 地址，还包括子网掩码、默认网关与 DNS 服务器地址等配置；「自动分配」不等于「永久拥有」，地址有租期。

来源：2027 考纲计算机网络“应用层：DNS 与 DHCP”；王道《计算机网络》应用层 DNS、DHCP 两节。星级：本卡两协议同属应用层轮考范围，但解析与分配过程无独立年份统计，不能由应用层整体口径直接证明过程题考频，3★ 为复习优先级估计（非独立统计）。

26. 组帧与透明传输 · 零比特填充 ★★★☆☆

合辑讲了物理层编码与 CRC，却没讲数据到了链路层先要解决的问题：一段比特流里，帧从哪儿开始、到哪儿结束；数据里恰好出现定界符的图案时怎么办。这正是组帧与透明传输。

组帧（Framing）四种方法：

方法定界方式关键点
字符计数法帧首字段给出本帧的字节数计数字段一旦出错，可能导致后续所有帧边界失去同步、无自同步能力，现已少用
字符填充法帧首尾用特殊字符（如 DLE STX / DLE ETX）定界数据中出现 DLE 时，发送方在其前再填充一个 DLE、写成 DLE DLE 实现转义（单独的 STX／ETX 不带 DLE 前缀、不转义）；接收方见到成对 DLE 删去第一个、还原为数据 DLE，见到 DLE STX／DLE ETX 则作帧定界
零比特填充法帧首尾用标志字段 01111110 定界（HDLC，高级数据链路控制规程采用）见下：靠「连续 5 个 1 后插 0」保证数据中永不出现 6 个连 1
违规编码法用物理层不会出现的编码组合定界如曼彻斯特编码中用「高—高」「低—低」这种违规电平组合，只适用于有冗余编码的物理层

透明传输（Transparent Transmission）：不管数据里是什么比特组合，都能原样、无歧义地传过去——实现手段就是上面的填充/转义：发送方加工，接收方逆向还原。

零比特填充规则（必背）：发送方扫描整个数据字段，每遇到连续 5 个 1，就在其后自动插入 1 个 0；接收方反向操作：每收到连续 5 个 1，若其后是 0 就删掉这个 0（填充位）；若其后是第 6 个 1，须再看下一位才能判定——第 7 位是 0 才是标志字段（01111110），第 7 位仍是 1（连 1 达 7 个以上）则是帧出错／中止，不能仅凭第 6 个 1 就下结论。这样数据字段中最多出现 5 个连 1，标志图案 01111110 永不与数据混淆。

例题（程序验算）：数据字段比特串：01101111101111111111011111（26 位）。按规则逐段处理：其中出现 4 处「5 个连 1」，各插入 1 个 0 → 发送比特串：011011111001111101111100111110（30 位，共填充 4 个 0；此位数仅指填充后的数据字段，不含首尾标志字段等帧开销）。接收方按逆规则删去这 4 个 0 后恰好还原为原 26 位 ✓（已做插删往返验证）。
坑：① 插入点是「5 个 1 之后」，不是等出现 6 个 1 再插——真出现 6 个连 1 已经是标志或错误了。② 填充统计要数清每一段连 1：连 1 跨过 5 后继续数（如 10 个连 1 要在第 5、第 10 个后各插一个 0，共 2 个）。③ 透明传输不是没有代价：填充使实际发送长度膨胀（例题 26 → 30 位），算有效数据率时别忘了扣。④ 字符计数法的死穴是「一错全乱」，与有自同步能力的填充法正好相对，选项里常互换设套。

来源：2027 考纲计算机网络“数据链路层：组帧、透明传输”；王道《计算机网络》数据链路层一节。星级：上位口径「数据链路层」子项（合辑 v6 net 口径），零比特填充计算为反复出现的选择题题型，保守定 3★（非独立年份统计）。
