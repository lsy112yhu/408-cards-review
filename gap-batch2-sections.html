文件共享与保护

本卡前面说过：目录项只有「文件名 + inode 号」，文件名不在 inode 里。共享就是从这条长出来的——同一个文件可以有几个名字，区别只在「几个名字怎么指向文件」。

　硬链接符号链接（软链接）
存的是什么新目录项直接指向同一个 inode，与原目录项平级，没有主次一个独立的新文件（有自己的 inode），文件内容就是目标文件的路径名字符串
对 inode 计数的影响inode 的链接计数 +1目标 inode 的计数不变
删除语义删除一个硬链接使链接计数减 1；链接计数降为 0 且没有其他打开引用时，才最终回收 inode 与数据块删目标（或目标改名）后链接还在、但指向的路径已不存在 → 悬空（失效）链接，打开时报错；删链接本身不影响目标
能力边界不能跨文件系统（inode 号只在本文件系统内有意义）；一般不能给目录建硬链接（防目录成环）可以跨文件系统、可以指向目录；代价是每次打开都要多走一遍路径解析
例 · 一次建链、两次删除，把计数走完（脚本模拟计数断言）
初始：建文件 /a/report.txt，占 inode 42，链接计数 = 1。
第 1 步 建硬链接 /b/report2.txt：新增目录项指向同一个 inode 42，计数 1 → 2。两个名字平级，改哪个名字的内容，另一个读到的也变。
第 2 步 建符号链接 /c/link.txt，内容存路径「/a/report.txt」：它占自己的 inode，inode 42 的计数仍是 2。此时经 /c/link.txt 打开，能正常读到数据。
第 3 步 删 /a/report.txt：计数 2 → 1，文件不回收，经 /b/report2.txt 照样读得到数据。
但 /c/link.txt 此时已经悬空：它认的是路径名不是 inode，路径 /a/report.txt 的目录项没了，哪怕数据还躺在 /b 名字下，经它打开也报「文件不存在」。
第 4 步 再删 /b/report2.txt：计数 1 → 0，这时才真正回收 inode 42 与数据块（假设没有进程保持该文件打开）✓
结论口诀：硬链接删名字不删文件，计数归零才删；符号链接认路不认人，路断即悬空。

访问控制（保护）——谁能对文件做什么，三种说法其实是一张表：

访问控制矩阵
全局表：行 = 主体（用户 / 进程），列 = 客体（文件），格子 = 允许的操作（读 / 写 / 执行…）。概念原型，真实系统太大、太稀疏，不直接存整表
访问控制表 ACL
把矩阵按列存：每个文件带一张表，写明「哪些用户 / 组对本文件有什么权限」。查一个文件的权限最直接；反过来查「某人能碰哪些文件」要扫全部文件
UNIX rwx
传统 UNIX 权限位是比 ACL 更简单的权限控制机制：只分文件主 / 同组用户 / 其他用户三组，每组 3 位 r（读）w（写）x（执行），共 9 位。判定顺序：先看是不是文件主，是则只用文件主那组位，不再往后看；不是再看组、再看其他
例 · 权限位判定（真题风格）
文件 report.txt 的权限为 rwxr-x---，文件主是 alice，所属组是 dev。bob 不是文件主、但在 dev 组内；carol 既不是文件主、也不在 dev 组。问：bob、carol 各能做什么？
bob 按组位判定：r-x → 可读、可执行，不可写——想改文件内容会被拒。
carol 按其他用户位判定：--- → 读、写、执行全无，连读都不行。
alice 按文件主位判定：rwx 全开。注意判定是「命中一档即停」：哪怕 alice 同时也在 dev 组，也只按文件主那组位算，不会两组取并集 ✓
坑
① 符号链接本身是一个文件、有自己的 inode；说「软链接不占 inode」是错的——它只是不动目标的计数。
② 硬链接的两个名字没有「原件 / 副本」之分，删掉所谓「原件」文件毫发无损，直到最后一个名字删掉。
③ 文件名保存在目录项中，改名通常无需修改文件数据；创建硬链接会增加目标 inode 的链接计数，删除硬链接会减少计数。
④ rwx 对目录的含义要换：r = 能列目录名，w = 能在目录内建 / 删文件，x = 能进入并访问目录内文件；目录没有 x 位时，就算文件本身可读也打不开。
I/O 接口

上一张表比的是「数据怎么传」（查询 / 中断 / DMA / 通道），这里补「设备接在哪儿」：CPU 不直接连外设，中间隔着一层 I/O 接口（设备控制器）——它对 CPU 一侧长着几个寄存器，对设备一侧管着具体的机械 / 电气动作，CPU 只跟寄存器说话。

组成部分干什么CPU 怎么用它
数据寄存器暂存 CPU 与设备之间传送的数据；输入、输出方向常各设一个读它 = 取设备送来的数据；写它 = 把数据发给设备
状态寄存器放设备的状态位，如「就绪 Ready」「忙 Busy」「错误」只读为主：查询方式靠反复读它判断能不能传；中断方式下它也是认中断源的线索
控制寄存器接收 CPU 的命令字，如启动、停止、读写选择只写：CPU 写命令，接口译码后去驱动设备动作
数据缓冲在寄存器与设备之间再垫一层缓冲，抹平 CPU 的高速与设备的低速之差，并攒够一次传送的量CPU 不直接感知，体现为「写满一批再启动设备」而不是逐字干等
端口译码（地址译码）把地址总线送来的端口地址译成片选信号，只选中被点名的那个寄存器决定每个寄存器分到哪个端口地址；同一接口的几个端口地址通常连续编排

I/O 端口就是接口里这些可被 CPU 寻址的寄存器。给端口编号（编址）只有两条路：

　独立编址（I/O 映射）统一编址（存储器映射）
地址空间端口有独立的地址空间，与内存分开端口占用内存地址空间的一部分，分给端口的那段就不能再当内存用
访问指令必须用专门的 I/O 指令（如 IN / OUT），普通访存指令碰不到端口用普通访存指令（如 MOV）就能读写端口，不需要专用指令
优点不吃内存地址空间；I/O 地址译码简单；指令短、好辨认指令丰富，访存的寻址方式全可用于端口；编程灵活，不必另设 I/O 指令
缺点指令功能弱，传送多半只能经累加器；控制线要分内存 / I/O 两套吃掉一部分内存地址；从地址上分不清是访存还是访 I/O
辨认口诀题干出现 IN / OUT 指令、单独的端口地址 → 独立编址题干说「用访存指令访问 I/O」「某段地址留给设备」→ 统一编址
例 · 端口地址范围与编址辨认（脚本验算）
条件甲：某机 I/O 端口独立编址，端口地址为 8 位。条件乙：其中一个接口含数据输入、数据输出、状态、控制共 4 个寄存器，端口连续编址，起始地址 F0H。条件丙（对照）：另一台机器统一编址，地址线 16 位、按字节编址，把顶部 1KB 地址分给 I/O 端口。
甲：端口总数 = 28 = 256 个，地址范围 00H～FFH，与内存地址空间相互独立。
乙：4 个寄存器依次占 F0H（数据输入）、F1H（数据输出）、F2H（状态）、F3H（控制），该接口占用范围 F0H～F3H——CPU 读 F2H 就是在查设备状态，写 F3H 就是在下命令。
丙：按字节编址，总地址空间 216 = 65536 B；被 I/O 占用 1024 B 后，可用于存储器的地址空间为 65536 − 1024 = 64512 B = 63 KiB ✓（这里只算地址空间，不推断实际物理内存。）
辨认：甲乙说的是独立编址（有专属端口地址空间）；丙是统一编址，代价直接体现在「内存少了 1KB」上。
【坑】「端口」是接口里的寄存器，不是接口本身：一个接口可包含多个端口，也可能连接多个设备；状态寄存器和控制寄存器有时共用一个端口地址（一个只读、一个只写，靠读写方向分开），题目给「3 个端口」不代表只有 3 个寄存器。
RISC 与 CISC

本卡讲的寻址方式多少、指令怎么编码，背后站着两种设计哲学：CISC（复杂指令集）想让一条指令多干活，RISC（精简指令集）反过来让每条指令只干一件小事、但干得快而规整。对照着同一件活看最清楚：

例 · 同一运算 C = A + B（A、B、C 都是存储器变量），两种风格各写一遍（脚本计数核对）
CISC 写法：1 条。ADD C, A, B —— 一条存储器—存储器型指令内部把「取 A、取 B、相加、存回 C」全做完。指令条数最少，但这条指令长短不定、内部步骤多，译码与执行都复杂。注：以下为假想指令集示意，假设该 CISC 支持三操作数存储器运算指令；具体机器是否存在此指令形式由其 ISA 决定。
RISC 写法：4 条。LOAD R1, A；LOAD R2, B；ADD R3, R1, R2；STORE C, R3 —— RISC 的运算指令只准碰寄存器（Load / Store 结构），碰内存只能靠这两条专门的装入 / 存回指令。
再看自增 X = X + 1：CISC 一条 INC X 搞定；RISC 要 LOAD、ADD（加立即数 1）、STORE 共 3 条。
账要两面算：RISC 条数多（4 条 vs 1 条），但传统 RISC 通常采用规整的指令格式和简单的 Load/Store 结构，便于流水线实现；本例按统一 32 位计时，4 条共 16B。现代架构可能支持压缩指令，实际执行周期也取决于指令与硬件；CISC 条数少，单条却变长又多步，流水线里步调参差 ✓
对比项CISCRISC
指令条数（种类）多，几百条不稀奇少，只留最常用的一小套
指令长度变长，一条可长可短传统上多为定长、格式规整；现代架构可能支持压缩指令
寻址方式多，运算指令可直接带存储器操作数少；运算只在寄存器间，访存只靠 Load / Store
通用寄存器较少，常有专用寄存器分工多，一组通用寄存器随便用，少访存
执行与流水线多数指令执行步数参差，多为微程序控制，难流水传统 RISC 通常采用规整的指令格式和简单的 Load/Store 结构，便于流水线实现；现代架构可能支持压缩指令，实际执行周期也取决于指令与硬件
编译器的活轻松些：复杂动作有现成指令可挑重些：复杂动作要自己拼指令序列
典型代表x86（桌面 / 服务器常见）ARM、MIPS、RISC-V

注：上表列的是典型特点而非绝对规律。

易混：
「RISC 指令条数少」说的是种类少，不是把一段活干完用的指令总数少——上面的例题恰恰相反，同一运算 RISC 用的条数更多。
变长 / 定长看的是指令字长：传统 CISC 常采用变长指令，传统 RISC 常采用规整的定长指令；现代 RISC 也可能支持压缩指令。指令字长与操作码字段长度不是同一概念。
交换方式

前面的例题默认了「存储转发」——那其实只是三种交换方式里的一种。同样一份报文过网，三种方式的时延账算法完全不同，先把骨架分清：

　电路交换报文交换分组交换
传送前必须先建立连接（占用一段建立时延），释放也要拆线不需要建立连接不需要建立连接（数据报方式）；虚电路方式另有建立，但内部仍按分组转发
传送单位整份数据连续流过，比特直达，不在中间结点落盘排队整个报文：结点收齐整份才往下发分组：报文先切成定长小块，结点收齐一个分组就往下发，前后分组流水线并行
时延大头建立时延 + 一次发送时延 + 传播时延每过一段都要重付整份报文的发送时延第一段付全部 n 个分组的发送时延，之后每多一段只多付一个分组的发送时延
资源占用连接存续期间独占线路，没数据发时也占着，利用率低只在传送瞬间占线路；但结点要备大缓冲存整份报文只在传送瞬间占线路（统计复用），利用率高；代价是分组带首部开销、可能失序
例 3 · 同一报文、同一链路，三种交换方式各算一遍（脚本验算；参数与例 1、例 2 错开）
条件：报文长 107 bit，经 2 段链路、1 个中间结点到达终点；每段速率 5 Mbit/s、传播时延 2 ms；电路交换的建立时延 50 ms；分组交换把报文切成 104 bit 一组（为简化不另计首部开销）。不计处理、排队时延。
先算公共量：分组数 n = 107 ÷ 104 = 1000 组；整报文在一段上的发送时延 = 107 ÷ (5 × 106) = 2000 ms；一个分组一段的发送时延 = 104 ÷ (5 × 106) = 2 ms。
电路交换：建立 50 + 发送 2000（整份只付一次，比特连续流过中间结点不再停）+ 传播 2 × 2 = 2054 ms。
报文交换：每段都要收齐整份再发：(2000 + 2) × 2 段 = 4004 ms——段数越多、报文越长，它涨得越狠。
分组交换：第一段串行发出 1000 组要 1000 × 2 = 2000 ms；第一组到达中间结点后，第二段只需再多等它转发 1 组的发送时延 2 ms，最后一组随即跟到；再加传播 2 × 2。总计 2000 + 2 + 4 = 2006 ms。
排序：分组 2006 ms < 电路 2054 ms < 报文 4004 ms ✓ 电路输在一次性建立开销，报文输在整份重发；分组靠流水线把第二段的等待压到只剩一个分组。
内存管理概念（前置）

后面的分配算法表回答的是「空闲区选哪块」，但一道内存题真正常问的第一步在更前面：程序是怎么进内存的、地址是在什么时候定死的。先把这条链走一遍：源程序 → 编译 → 链接 → 装入 → 运行，每一步都在推迟或提前「地址定死」的时刻。

装入方式地址什么时候改过程与代价
绝对装入编译时就知道驻留地址，直接生成绝对地址（物理地址）装入程序按地址原样放进去即可；只适合单道环境，地址一旦被别人占了就没法跑
可重定位装入（静态重定位）装入时一次性把逻辑地址全部改成物理地址（地址变换 = 装入地址 + 逻辑地址）装入后代码里写的就是物理地址，运行时不再变换；代价：运行期间不能再移动、必须一次分到连续整块内存
动态运行时装入（动态重定位）装入时一个地址都不改，推迟到每条指令真正执行、访存的那一刻才变换靠硬件重定位寄存器（基址寄存器）：物理地址 = 基址 + 逻辑地址，每次访存自动加；程序可以在内存里被移动，搬完只改基址寄存器的值，代码一字不动
链接方式什么时候链接特点
静态链接装入之前，把目标模块与库函数拼成一个完整装入模块运行时不再需要库；每个程序各带一份库代码，浪费内存，库更新要重新链接
装入时动态链接装入时，边装入边找外部模块链接装入时动态链接：程序装入时解析和链接所需模块，模块加载由具体装入和链接机制决定；几个程序可共享同一份库模块
运行时动态链接运行时第一次用到某模块时才链接并装入运行时动态链接：允许将部分模块的加载或链接推迟到实际需要时，可能减小初始装入工作量，但首次调用及总运行开销仍取决于具体实现；便于更新与共享
逻辑地址
又叫相对地址 / 虚拟地址：程序自己视角的地址，从 0 开始编（如「本程序第 2500 号单元」），与最终住在哪儿无关
物理地址
内存的绝对门牌号，地址总线最终送出的就是它；逻辑地址经地址变换（静态在装入时、动态在运行时逐次）落到物理地址

分配与置换的「四问」框架——分页、请求调页的题，不管问到哪一步，都先落回这四个问题定位：

问题问的是对应策略
何时调入页面什么时候从外存进内存调入策略：预调页（预先调入预测将被访问的若干页面，可能调错白占内存）vs 请求调页（缺页才调，必用得上但缺页中断多）
从哪调入缺的那页应从其后备存储位置读入从哪调入由页面的后备存储位置决定。在教材简化模型中，外存可划分为文件区与对换区；具体页面应从其当前保存的位置读取，不是每次缺页都按固定的对换区→文件区顺序搜索。
本节的『对换区』指请求分页系统用于保存换出页面的后备存储空间，不是作为独立内存管理技术的进程整体交换与覆盖机制（该专题已不在考纲内）。
调入哪儿内存里放进哪个空闲位置分配策略：固定分配 / 可变分配 × 局部置换 / 全局置换的组合（固定+局部、可变+全局、可变+局部）
淘汰谁内存满了、又没空闲框时赶走哪页置换策略：OPT / FIFO / LRU / CLOCK 等页面置换算法，赶错了就多缺页
例 · 动态重定位的地址换算（脚本验算）
条件：某程序用动态运行时装入，逻辑地址空间长 6000（限长寄存器 = 6000），装入后重定位寄存器（基址）= 12000。程序执行中访问逻辑地址 2500 与 6500，各发生什么？
访 2500：先比限长，2500 < 6000 合法 → 物理地址 = 12000 + 2500 = 14500，地址总线送 14500 出去访存。
访 6500：6500 ≥ 6000，越界——还没轮到加基址就被限长寄存器拦下，产生地址越界中断，进程被处理，这次访存不发生。
再想一步：若系统把这份程序整体挪到 20000 处（腾地方做紧凑），静态重定位的版本只能重新装入改地址；动态版本只把重定位寄存器改成 20000，逻辑地址 2500 自然落到 22500，程序代码一字不改 ✓
【坑】静态重定位与动态重定位的分界是「地址改没改进行时」：静态在装入时把地址写死进代码，动态永远不改代码、只靠寄存器在访存瞬间算。还有一对别混：链接的三种与装入的三种名字像、问的不是一回事——链接管「模块拼不拼、什么时候拼」，装入管「地址定不定、什么时候定」。
传输介质

本卡前面讲的是「比特怎么变成波形」（编码），这里补「波形在哪儿跑」：介质选错，后面的编码与速率都无从谈起。四类介质按「认特性、辨场景」记，不背参数表。

介质构造与原理特性与适用
双绞线两根绝缘铜线按规则绞合，绞合抵消相互干扰；多对再包成一根电缆。屏蔽双绞线（STP）每对 / 整缆外加金属屏蔽层，非屏蔽双绞线（UTP）没有最便宜、最易布线，局域网主力；STP 抗电磁干扰强于 UTP，但更贵更硬。5 类双绞线可用于 100BASE-TX，也可在满足相应布线要求时用于 1000BASE-T；超 5 类通常提供更好的传输裕量，常见于千兆以太网布线
同轴电缆内导体 + 绝缘层 + 网状外导体 + 护套，同心共轴；外导体兼作屏蔽抗干扰强于双绞线、带宽更高；基带同轴（50Ω）传数字信号、曾用于早期以太网，宽带同轴（75Ω）传模拟信号、用于有线电视。现在局域网里基本被双绞线与光纤取代
光纤纤芯（高折射率）+ 包层（低折射率），光在纤芯内靠全反射前进；发送端光源把电信号变光脉冲，接收端检测器再变回来带宽极大、损耗低、抗电磁干扰、不串扰、保密性好；贵、脆、接续难。两种见下行辨析
无线介质电磁波在自由空间传播：无线电波、微波、红外线等，不用铺线能过障碍到有线到不了的地方；代价是易受干扰、衰减随环境变、保密性差，定性辨析见下
单模光纤
纤芯很细（约 8～10 μm），光只沿一条路径（一个模式）直进，没有模式色散；用激光光源，衰减小、带宽大，适合长距离、大容量（骨干、城域），但光源与连接都贵
多模光纤
纤芯较粗（约 50 μm 量级），光以多条路径反射前进，各路径到达时间不同 → 模式色散把脉冲展宽，带宽与距离受限；可用便宜的 LED 光源，适合短距离（楼内、园区）
无线定性辨析
在其他条件可比时，较高频率的无线电波通常绕射能力较弱，穿透障碍物时的损耗也往往较大；具体传播损耗仍取决于介质、环境和天线条件。
例 · 介质说法逐项判（真题风格，脚本逐项核对）
问：下列关于传输介质的说法中，错误的是（　）。
A. 5 类非屏蔽双绞线可支持 100 Mbit/s 的以太网 —— 成立，类别与速率对应正是 5 类的定位。
B. 单模光纤纤芯细、使用激光光源、适合长距离传输 —— 成立，三点恰是单模与多模的分界。
C. 多模光纤存在模式色散，限制了带宽与传输距离 —— 成立，多路径到达时间差把脉冲展宽。
D. 无线电波频率越高，穿透能力越强、衰减越小 —— 不成立：错在把频率与穿透、衰减的关系说成必然规律——在其他条件可比时，高频电磁波通常绕射较弱、穿透障碍物的损耗往往较大；具体结果还受传播环境与材料等因素影响。→ 答案 D ✓
易错：光源别配反——单模配激光、多模常用 LED，题干常把两者对调设错；「屏蔽」防的是外界电磁干扰，STP 不是「更快」的代名词，速率看类别不看屏蔽；光纤传的是光脉冲不是电流，「抗电磁干扰」正因为它根本不导电，别写成「屏蔽得好」。
