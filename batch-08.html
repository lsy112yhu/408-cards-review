一、数据结构 （本辑 1 张）
1. 循环队列 · 判空判满与元素个数 ★★★☆☆

合辑《栈与队列经典应用》只讲了队列拿来干什么，没讲队列本身怎么实现。顺序队列假溢出、循环队列（Circular Queue，循环队列）判空判满，是选择题里反复出现的固定题型，公式记混一个符号整题皆错。

约定（王道口径，题干另有定义时以题干为准）：数组大小为 MaxSize，下标 0 ～ MaxSize − 1，空间当作一个环。队头指针 front 在队列非空时指向队头元素（队空时不存在队头元素）；队尾指针 rear 指向下一次入队要写入的位置（牺牲一格法下该位置恒为空位；采用下文 size / tag 法且队列已满时，该位置不一定为空）。入队：先把 x 存入 Q[rear]，再 rear = (rear + 1) % MaxSize；出队：先取 Q[front]，再 front = (front + 1) % MaxSize。

牺牲一个存储单元法（最常考）：故意空出一格不用，以区分空与满。

状态判据
队空front == rear
队满(rear + 1) % MaxSize == front
元素个数(rear − front + MaxSize) % MaxSize
最多可存MaxSize − 1 个元素

不牺牲一格的另两法（见到题先确认用的是哪套）：① 增设 size 变量记元素个数：入队 size++、出队 size−−，size == 0 为空、size == MaxSize 为满；② 增设 tag 标志：最近一次操作是入队且结果 front == rear 判满，最近一次是出队且 front == rear 判空。两法都不浪费空间，但判据与上表不同，不能混用。

例题（程序模拟验算）：MaxSize = 5 的循环队列，初始 front = rear = 0。依次入队 A、B、C：rear 走到 3，元素个数 = (3 − 0 + 5) % 5 = 3。出队两次（取出 A、B）：front 走到 2。再依次入队 D、E、F：rear 从 3 经 4 绕回 0、再到 1；此时元素个数 = (1 − 2 + 5) % 5 = 4，且 (rear + 1) % 5 = 2 == front → 队满，队列内容依次为 C、D、E、F ✓（绕圈与判满均经模拟核对）。附指针小题：MaxSize = 6、front = 1、rear = 4 时，元素个数 = (4 − 1 + 6) % 6 = 3。
坑：① 有的教材约定 rear 指向队尾元素本身，判据随之全变——做题第一步先看题干对 front / rear 的定义，别背死一套公式套所有题。② 元素个数公式别漏「+ MaxSize 再取模」：rear < front 时直接 rear − front 会得出负数。③ 牺牲一格法里数组开 MaxSize 只能存 MaxSize − 1 个，问「最多存几个」答错一位是经典丢分点。④ 链式队列不存在绕圈与假溢出，别把循环队列判据往链队列上套。

来源：2027 考纲数据结构“栈和队列：队列的顺序存储结构与基本操作”；王道《数据结构》队列一节。星级：上位口径「栈与队列」为合辑 ds-13 口径（相关标签并集 14 年），循环队列判空判满为其实现子项、无独立年份统计，保守定 3★（非独立统计）。

二、计算机组成原理 （本辑 1 张）
2. 存储芯片扩展 · 位扩展 / 字扩展 / 字位同时扩展 ★★★☆☆

合辑《存储器容量计算》只给了「容量 = 字数 × 字长」的公式，没讲单片芯片不够用时怎么拼：需要几片、地址线怎么分、每片占哪段地址——这才是这类计算题真正考的后半截。

方式扩什么接法要点
位扩展字长（位数）各片同地址、同片选同时工作，数据线各分担一段；不增加地址线条数
字扩展字数（单元数）各片数据线并联共用，靠片选信号（CS，Chip Select，片选信号）分时选中一片；高位地址经译码器产生片选
字位同时字数与字长都扩先位扩展成组、再字扩展分组，总片数 = 两者相乘
公式：总片数 =（目标字数 ÷ 芯片字数）×（目标字长 ÷ 芯片字长）；片内地址线数 = log2（芯片字数）；片选地址线数 = log2（字扩展组数）；在芯片字数与扩展组数均为 2 的整数次幂、规则连续编址的条件下，覆盖整个模块所需的最少地址位数（按存储字编址）= 片内地址线 + 片选地址线；若按字节编址，还须加上字内字节偏移的位数，且 CPU 实际地址总线宽度由其体系结构决定、不一定等于该模块所需位数。每组包含的存储字数 = 单片芯片字数：按字编址时每组占芯片字数个字地址，按字节编址时每组占用的字节地址空间 = 芯片字数 × 目标字长 ÷ 8；各组按连续地址段分配时互不重叠（是否连续编址以题目译码设计为准）。
例题（公式重算 + 范围枚举核对）：① 用 16K × 8 位芯片构成 64K × 32 位存储器（本问按 32 位存储字编址）：字扩展组数 = 64K ÷ 16K = 4，每组位扩展片数 = 32 ÷ 8 = 4，总片数 = 4 × 4 = 16 片；覆盖该模块所需地址线 = log264K = 16 根（A15 ～ A0），其中低 14 根接各片片内地址，高 2 根（A15A14）经译码产生 4 组片选；数据线 32 根，每组 4 片各提供 8 位。② 地址范围：用 8K × 8 位芯片构成 32K × 8 位、起始地址 0000H（按字节编址）：共 4 片，各占 8K = 2000H 大小，范围依次为 0000H–1FFFH、2000H–3FFFH、4000H–5FFFH、6000H–7FFFH ✓。
坑：① 位扩展不产生新的地址、也不需要多组片选，各片是「一起被选中、各出一部分位」；字扩展不加宽数据线，各片是「同一时刻只选中一片」——两者接法正好相反，选项常互换设套。② 算地址范围先把容量换成 2 的幂再换十六进制：8K 的跨度是 2000H，不是 8000H。③ 题目混用 ROM 与 RAM 芯片时，总片数分开算；地址空间如何排布由题目译码设计决定，要求连续编址时才连续排布，哪类放低地址以题干为准。④ 片选若用线选法（高位地址线直连片选）可省译码器，但可能造成地址空间利用率低、片选组合设计不当还可能多片同时被选中，与译码法结论不同，先看题干给的连接方式。

来源：2027 考纲组成原理“存储器层次结构：主存储器与 CPU 的连接”；王道《计算机组成原理》主存储器与 CPU 的连接一节。星级：上位口径「主存容量的扩展」11 年（合辑 co-4 口径），芯片扩展为其计算子项、无独立年份统计，保守定 3★（非独立统计）。

三、操作系统 （本辑 1 张）
3. 进程通信 IPC · 共享存储 / 消息传递 / 管道 ★★★☆☆

合辑讲了进程、线程、信号量，但讲的都是同一进程内部或同步问题；不同进程地址空间互相隔离、彼此看不见对方的变量，它们之间怎么交换数据——进程通信（IPC，Inter-Process Communication，进程间通信）——合辑 0 覆盖。这是王道进程管理一节的固定考点。

方式怎么传特点
共享存储在内存中划一块双方都能直接读写的共享区，数据就放在区里，不经内核搬运速度最快（适合大批量、高频交换）；但共享内存本身不自动保证应用层操作的同步，有并发读写冲突时须另配信号量、互斥锁等同步机制
消息传递用 send / receive 原语，经操作系统内核把消息从发送方复制到接收方不要求进程共享用户地址空间，避免了直接共享同一数据缓冲区带来的部分竞争问题（收发顺序仍需协调）；但每次都要经内核复制，速度较慢。分直接通信（指名收发进程）与间接通信（经信箱 / 端口中转）
管道由内核维护的、有限容量的字节流缓冲区（不是普通磁盘文件），按先进先出顺序读写半双工：同一管道同一时刻只能单向传，双向要两根管道。无名管道通常经创建进程继承文件描述符、用于父子等有亲缘关系的进程，当所有引用它的文件描述符都关闭后内核才释放；命名管道（FIFO）可供有相应权限的任意进程按路径打开、不要求亲缘关系

速度差的根源（爱考的解释题）：共享存储只在建立共享区时需要系统参与，之后读写都是进程直接访问内存；消息传递每发一条都要陷入内核做复制——「谁经内核、谁不经」就是快慢分界。

例题（选型判断）：① 两个进程要高频交换大块数据、追求最快 → 共享存储，再配信号量防读写冲突。② 两个无亲缘关系的进程只需单向传一串字节流 → 命名管道（按 408 常规的管道创建与继承模型，无亲缘关系的进程通常选用命名管道）。③ 两个进程不希望共享地址空间、只偶尔传递少量控制信息 → 消息传递，慢一点但隔离干净。
坑：① 「共享存储最快」的前提是只比数据搬运：它不自带同步，忘了配互斥照样出错——选项里「共享存储无需同步」是错的。② 管道是半双工不是全双工，「用一根管道双向通信」不成立。③ 消息传递的「慢」是相对共享存储而言、慢在经内核复制，不是慢在要等对方在线。④ 无名管道在全部引用它的文件描述符关闭后才释放、且通常限亲缘进程，与命名管道的适用范围别记反。

来源：2027 考纲操作系统“进程管理：进程通信”；王道《操作系统》进程通信一节。星级：上位口径「进程管理」为合辑操作系统高频大类（进程状态 11 年、进程与线程 6 年等口径），进程通信无独立年份统计，保守定 3★（非独立统计）。

四、计算机网络 （本辑 2 张）
4. CIDR 与路由聚合 · 最长前缀匹配 ★★★☆☆

合辑《子网划分计算》讲的是把一个网分小；本卡补反方向：用 CIDR（Classless Inter-Domain Routing，无分类域间路由选择）把多个连续小网在路由表里合并成一条，以及路由器拿到目的地址后到底按哪条走。划分与聚合是一对镜像考点。

CIDR 记法：地址写成 a.b.c.d / x，x 为网络前缀位数（等价于掩码中 1 的个数）。它取消了 A / B / C 类的固定边界，前缀长短可任意。

路由聚合（超网）：把若干网络号连续的网络合并为一条路由。能整段聚合的条件有三：① 地址连续；② 高位（二进制前缀）相同，共同前缀有多长、聚合后的 /x 就是多少；③ 起始地址对齐——聚合块的起始地址必须是块大小的整数倍（等价于被合并段恰好构成一个完整的对齐块）。聚合能减少路由表项、降低路由信息的存储与维护开销、提高可扩展性，这是 CIDR 的主要目的（实际转发速度是否提升还取决于路由器的查表实现）。

例题（ipaddress 模块独立验证）：① 聚合：将 192.168.0.0/24、192.168.1.0/24、192.168.2.0/24、192.168.3.0/24 四个网合并。第三段字节 0～3 的二进制为 00000000 ～ 00000011，前 6 位相同 → 聚合为 192.168.0.0/22（前缀 24 − 2 = 22）✓。② 对齐反例：192.168.4.0/24 与 192.168.5.0/24 可聚合成 192.168.4.0/23；但 192.168.5.0/24 与 192.168.6.0/24 虽然地址连续，不能整段聚合成一条 /23——/23 块必须从偶数段起（5 与 6 跨了对齐边界），只能写成两条 ✓。

最长前缀匹配（Longest Prefix Match，最长前缀匹配）：转发时路由表可能有多条都「匹配」目的地址，规则是选前缀最长（网络最具体）的那一条优先；默认路由 0.0.0.0/0 前缀长为 0、能匹配一切地址，永远是最后兜底。

例题（ipaddress 模块独立验证）：路由表：192.168.0.0/16 → 接口 0；192.168.5.0/24 → 接口 1；192.168.5.128/25 → 接口 2。目的 192.168.5.200 三条全匹配，取最长的 /25 → 接口 2；目的 192.168.5.10 只匹配 /16 与 /24 两条 → 接口 1 ✓。
坑：① 聚合只看「连续」不够，还要对齐——5.0 与 6.0 连续但不可整聚，是最常见的设套点。② 精确聚合要求聚合块恰好覆盖原有网络、且这些网络能经相同下一跳正确到达：把额外的网包进聚合块又无更具体路由兜底，会误收本应转发他人的分组、甚至形成黑洞。③ 最长前缀匹配先比前缀长度，不是先比跳数或度量；度量只在同一前缀的多条路由之间再比。④ /x 里的 x 数的是前缀位数：/22 的掩码是 255.255.252.0，别与主机位数混算。

来源：2027 考纲计算机网络“网络层：IPv4 地址与 CIDR、路由选择”；王道《计算机网络》CIDR 与路由聚合一节。星级：上位口径「子网划分 + 子网聚合」并集 10 年（合辑 net-9 口径），CIDR 聚合与最长前缀为其子项、无独立年份统计，保守定 3★（非独立统计）。

5. 以太网交换机 · 自学习与帧转发 ★★★☆☆

合辑有以太网帧格式与 CSMA/CD，但交换机本身怎么知道一帧该往哪个端口送——只在 net-12 的星级注里被提过一句，没有卡。交换机自学习是数据链路层选择题的常客，规则就三步，记牢能稳拿分。

交换表（MAC 地址表）：每项记（MAC 地址，所在端口，老化时间）。交换机对收到的每一帧做：

  1. 学源：把帧的源 MAC 地址与进入端口记入交换表（已有该项则更新端口并刷新老化计时）——学的是「谁从哪个口进来」。
  2. 查目的：用帧的目的 MAC 地址查表。查到且端口 ≠ 入端口 → 只从该端口转发（单播）；查到且端口 == 入端口 → 丢弃（过滤，说明收发双方在同一侧，不必转发）。
  3. 查不到就泛洪（Flooding，泛洪）：向除入端口外的所有端口转发；目的地址为全 1 的广播帧同样泛洪。
例题（按规则逐步推演）：交换机 4 个端口分别接主机 A（口 1）、B（口 2）、C（口 3）、D（口 4），初始交换表为空。① A → B：学 A 在口 1；目的 B 查不到 → 泛洪到口 2、3、4。② B → A：学 B 在口 2；目的 A 在口 1 → 只从口 1 转发。③ C → A：学 C 在口 3；目的 A 在口 1 → 只从口 1 转发。④ A → C：A 已在表（刷新计时）；目的 C 在口 3 → 只从口 3 转发。最终交换表：A–1、B–2、C–3；D 从未发过帧、不在表中，此后发往 D 的帧仍要泛洪 ✓。
坑：① 学的是源 MAC、查的是目的 MAC——方向记反是此题型头号丢分点。② 交换机按 MAC 在数据链路层转发，不看 IP、不做路由选择，别与路由器混。③ 未划分 VLAN 的普通交换机每个端口是独立的冲突域、但整机默认仍是同一个广播域：广播帧照样泛洪到所有端口；配置 VLAN 后不同 VLAN 属于不同广播域，划分广播域也可经路由器。④ 表项会老化：主机久不发帧其表项被删，下次发往它的帧又变回泛洪，不是「学过就永远单播」。⑤ 与集线器对比：集线器（Hub，集线器）无交换表、收到信号都向除接收端口外的其他端口重复转发，且所有端口同属一个冲突域。

来源：2027 考纲计算机网络“数据链路层：局域网、以太网交换机”；王道《计算机网络》以太网交换机与自学习算法一节。星级：上位口径「以太网与介质访问控制」为合辑 net-16 口径（相关标签并集 13 年），交换机自学习为其子项、无独立年份统计，保守定 3★（非独立统计）。
