1. 程序的机器级代码表示 ★★★★★ · 近6年×4

定位：CO 第 4 章指令系统。合辑已有《指令格式与寻址方式》讲一条指令长什么样，这一卡往前一步：一段 C 代码编译之后在机器级长什么样——参数、局部变量、数组元素到底落在哪个地址。真题的做法通常是给一段短 C 代码（或它的汇编片段），问某个变量 / 成员的地址、某条指令访问的内存单元，或返回之后栈恢复成什么样。读这类题只有一条路：先把栈帧的相对位置钉死，再逐个算地址。

前提：以下汇编及栈帧为教学用的 32 位 x86、固定调用约定、未做优化的示意布局，并非 C 语言规定的唯一布局；实际考题以题干所给的调用约定、汇编指令或栈帧图为准。
本卡约定
32 位、按字节编址、栈向低地址生长；call 把返回地址（4B）压栈；被调用函数先 push ebp、再 mov ebp, esp，用帧指针 EBP 定位一切；参数由调用者按从右到左的顺序压栈；int 4B、short 2B、char 1B，结构体按 4B 对齐填充。真题题干另给约定时以题干为准——要练的是这套「先定帧、再算址」的读法，不是背死某一台编译器的分配顺序。
贯穿例子
全卡只用一个函数：
struct Rec { char flag; int score; short delta; };
int calc(int x, int y) {
　struct Rec r;
　int buf[3];
　r.score = x;
　r.delta = (short)y;
　buf[1] = r.score + r.delta;
　return buf[1];
}
一、结构体先算布局：成员偏移从哪来

访问 r.score 之前，编译器先把 Rec 的布局定死：成员按声明顺序放，每个成员的起始地址须是其自身对齐的倍数，放不下就先填充。

flag 是 char，占 1B，放偏移 0。
score 是 int，须 4 的倍数地址：偏移 1 不合，先填充 3B，score 放偏移 4，占 4B 到偏移 7。
delta 是 short，须偶数地址：偏移 8 正合，占 2B 到偏移 9。
结构体总大小须是最大成员对齐（4）的倍数：末尾再填充 2B，sizeof(Rec) = 12B。于是任一 Rec 变量 v 都有：&v.flag = 基址 + 0，&v.score = 基址 + 4，&v.delta = 基址 + 8。
二、C 语句怎么落成指令：跟着 calc 走一遍
push ebp　　　　　　; 保存调用者的帧指针
mov ebp, esp　　　　; 立起本函数的帧
sub esp, 24　　　　 ; 一次留出局部区：r 占 12B + buf 占 12B
mov eax, [ebp+8]　　; 取参数 x（位置见第三节）
mov [ebp−8], eax　　; r.score = x：r 基址在 ebp−12，score 偏移 +4 → ebp−8
mov eax, [ebp+12]　 ; 取参数 y
mov [ebp−4], ax　　 ; r.delta = (short)y：delta 偏移 +8 → ebp−4，只写低 16 位
mov eax, [ebp−8]　　; 取回 r.score
movsx edx, word [ebp−4]　; 取 r.delta 并符号扩展成 32 位再相加
add eax, edx
mov [ebp−20], eax　 ; buf[1] = 和：buf 基址在 ebp−24，元素 [1] 偏移 +4 → ebp−20
mov eax, [ebp−20]　 ; 返回值按约定放 eax
mov esp, ebp；pop ebp；ret　; 拆帧，最后 ret 把返回地址弹进 PC

看懂这段只需抓住三件事：本例中各赋值的机器级实现体现为「算出右边的值 → 存到左边的地址」；源码里的变量名在机器级全部消失，只剩基址 + 偏移；偏移在编译时就已算死，运行时不再查表。

三、数组与结构体访问：地址全是同一条公式

数组元素：&a[i] = 数组首址 + i × sizeof(元素类型)。int buf[3] 的元素 4B 一个，buf[1] 就是首址 + 4。结构体成员：&v.成员 = v 的基址 + 该成员在布局中的偏移。两者叠起来就是结构体数组：元素先按 sizeof(整个结构体) 跳，成员再加自己的偏移。

例：struct Rec db[5] 的首址为 0x00404000。求 &db[2].score：先跳 2 个元素 2 × 12 = 24，再加 score 的偏移 4，得 0x00404000 + 28 = 0x0040401C；同理 &db[2].delta = 0x00404000 + 24 + 8 = 0x00404020（程序验算）。易错点在中间这步：跳元素用的是含填充的 sizeof = 12，不是三个成员裸大小之和 1 + 4 + 2 = 7。
四、过程调用的栈帧：谁压栈、何时压、压完在哪
1调用者压参数：执行 call calc(…) 前，先按从右到左把 y、x 依次压栈——后压的 x 离栈顶更近，所以第一个参数离返回地址最近。
2call 压返回地址：call 把「下一条指令的地址」压栈再跳走。这 4B 是被调用者帧的最高地标，函数最后靠 ret 把它弹回 PC。
3被调用者立帧：push ebp 把调用者的旧帧指针存下，mov ebp, esp 让 EBP 钉在本帧的锚点上。此后无论 ESP 因局部区怎么动，参数和局部变量相对 EBP 的位置都不变。
4留局部区：sub esp, 24，一次把 r 与 buf 的 24B 留出。按本卡约定，局部变量按声明顺序向低地址排：先声明的 r 紧贴 EBP 下方（基址 ebp−12），buf 在 r 下方（基址 ebp−24），ESP 停在 buf 的最低端。
5返回拆帧：返回值放 eax；mov esp, ebp 把 ESP 收回锚点，pop ebp 恢复调用者的帧指针，ret 弹出返回地址。一步错位，后面全盘皆错——真题最爱在这条链上挖坑。
[EBP+12]
参数 y（第二个参数，离锚点更远）
[EBP+8]
参数 x（第一个参数）
[EBP+4]
返回地址（call 压入）
[EBP+0]
保存的旧 EBP ← EBP 锚点在这里
[EBP−12]
局部变量 r 的基址（r.score 在 [EBP−8]，r.delta 在 [EBP−4]）
[EBP−24]
局部数组 buf 的基址 ← ESP 停在这里（buf[1] 在 [EBP−20]）
例题
例 · 栈帧地址全家福（真题风格，程序验算）
承贯穿例子：calc 执行期间 EBP = 0x0012FF80。求：(1) 返回地址、参数 x、参数 y 各存在哪个地址；(2) r.score、r.delta、buf[1] 的地址；(3) 此时 ESP 的值。
推导：锚点之上按 +4 一格一跳：保存的旧 EBP 在 0x0012FF80，返回地址在 [EBP+4] = 0x0012FF84，x 在 [EBP+8] = 0x0012FF88，y 在 [EBP+12] = 0x0012FF8C。
锚点之下先落 r：r 基址 = EBP − 12 = 0x0012FF74，r.score = 基址 + 4 = 0x0012FF78（即 [EBP−8]），r.delta = 基址 + 8 = 0x0012FF7C（即 [EBP−4]）。
再落 buf：buf 基址 = EBP − 24 = 0x0012FF68，buf[1] = 基址 + 1 × 4 = 0x0012FF6C（即 [EBP−20]）。
局部区共 12 + 12 = 24B，ESP 停在最低端 = 0x0012FF68，恰与 buf 基址相同 ✓（以上地址与偏移均经脚本逐项验算，含 ctypes 对结构体布局的交叉核对）。
坑：
① 返回地址不是 [EBP] 也不是 [EBP+8]：[EBP] 存的是旧 EBP，返回地址在它上面一格 [EBP+4]，第一个参数还要再上一格才是 [EBP+8]。把旧 EBP 忘了，整条链全错位 4B。
② 参数相对位置由压栈顺序定：从右到左压栈 ⇒ 第一个参数离返回地址最近。题目若改成从左到右压栈，x、y 的位置立刻对调，先看题干约定再套。
③ 结构体跳元素用含填充的 sizeof：Rec 三个成员裸大小共 7B，但 sizeof = 12B，db[2] 要跳 24B 不是 14B；成员偏移同理，score 在 +4 不是 +1。
④ 栈向低地址生长：局部变量的地址比 EBP 小、参数比 EBP 大。方向画反，[EBP−8] 会写成 [EBP+8]，正好和参数 x 撞车。
⑤ short 成员只占 2B：mov [ebp−4], ax 只写低 16 位，别按 int 的 4B 去推相邻成员的位置；读出参与 32 位运算时还要先符号扩展。
2. 计算机系统层次结构 ★★★★☆ · 近6年×2

定位：CO 第 1 章系统概述（薄卡）。这一考点只考三件事：层次怎么分、同一功能为什么软硬件都能做、几个「字长」为什么不能混。题量不大，但每个都是送分与丢分只差一个概念的判断题。下面用同一条语句从顶层一路沉到底层，把三件事一次带出。

一、一条语句的下沉之旅：z = x + y 经过的每一层

设 int x、y、z 是内存中的三个整型变量，C 语句 z = x + y; 在每一层眼里长得完全不同——每一层都是一个「虚拟机器」：只认本层的语言，靠翻译或解释把本层程序变成下一层能执行的动作。

高级语言级
你看到的是 z = x + y; ——变量有名字、类型。靠编译：编译程序把整个源程序一次译成汇编 / 机器语言程序，再执行。
汇编语言级
变成三条符号指令：LOAD R1, x（取 x 进寄存器）；ADD R1, y（与 y 相加）；STORE R1, z（存回 z）。靠汇编：汇编程序把符号指令逐条译成二进制机器指令。
操作系统级
介于汇编与机器级之间的一层：程序要用输入输出、文件等资源时不直接碰硬件，而是发系统调用由操作系统代办。本例纯算术不经过它，但它在层次图里有正式位置，别漏画。
传统机器级
只剩二进制机器指令：操作码指明「加」，地址码指明操作数在哪。CPU 取指、译码、执行，一条指令一个指令周期——这一层的语言就是指令系统。
微程序机器级
一条机器指令再被拆成一串微指令：每条微指令发出一组微命令，直接开合数据通路上的门电路，把寄存器和 ALU 接通一次。这一层不必展开过深，只需知道：机器指令是被「更小的程序」解释执行的，这是微程序控制器的地盘（详见《控制器对比》卡）。

往下再沉就是数字逻辑电路，没有新的「语言层」了。各层之间只有两种衔接方式：翻译（先把高层程序整体译成低层程序再执行，如编译、汇编）和解释（逐条把高层指令译成低层动作并立即执行，不生成完整译本，如微指令解释机器指令）。

二、软硬件逻辑等价：同一件事，谁做都行

还是这条加法链里的「相加」：乘法运算可以交给硬件——CPU 里放一个乘法器，一条乘法指令直接出结果；也可以不放乘法器，改用软件——写一段「移位 + 相加」的循环，用已有的加法和移位指令凑出乘法。两种实现对上层程序员逻辑上完全等价，程序照样算出积，区别只在速度与成本。

这就是软硬件逻辑等价：任何操作都能由软件实现，也能由硬件实现，软硬件的分界不是逻辑分界、而是性能与成本的分界，并且可以上下移动——常用功能往硬件沉（快），少用功能留给软件（省）。固件就是这条界线上的中间态：把软件固化进只读存储器，形态是程序、干活像硬件。

三、字长四兄弟：只有一个由寄存器位数定
机器字长（= 字长）
CPU 一次能并行处理的二进制位数，由通用寄存器位数 / ALU 位数决定。说「32 位机」指的就是它。
数据通路宽度
CPU 内部数据总线一次能传送的位数。内部通路通常与机器字长相等；但外部数据总线可以更窄——字还是 32 位，只是要分次送出（理想传送次数见例题）。
指令字长
一条指令占的位数，由指令格式定，与机器字长彼此独立：32 位机完全可以用 16 位的定长指令。
存储字长
一个存储单元存放的位数，由存储器组织定，同样独立：它决定取一个存储字拿到几位，不决定 CPU 一次算几位。
例题
例 · 字长认亲（真题风格，程序验算）
某机：通用寄存器 32 位、ALU 32 位、内部数据通路 32 位；外部数据总线 16 位、指令字长 16 位、存储字长 16 位。问：(1) 该机机器字长是多少位、合多少字节；(2) 把一个机器字经外部数据总线送到外设要几拍；(3) 一个 64 位数据在 CPU 内部处理算几个机器字、经外部总线送出要几拍。
推导：(1) 机器字长看通用寄存器 / ALU 位数 = 32 位 = 4 字节。题干里的三个 16 位全是干扰：外部总线、指令字长、存储字长都不参与定字长。
(2) 一个机器字 32 位，外部总线每次最多送 16 位：32 ÷ 16 = 2 次。这是忽略协议开销、每拍传满总线宽度的理想传送次数。字长没变，只是传送被拆开——这正是「外部通路可以窄于字长」的含义。
(3) 64 位数据相当于 2 个 32 位机器字；若只考虑 32 位内部数据通路上的纯数据传送，理论上至少分 2 次传输；实际处理所需周期不能仅由机器字长确定。经外部总线送出时，在忽略协议开销、每拍传满总线宽度的理想模型下，传送次数为 64 ÷ 16 = 4 次（以上计数均经脚本验算）。
坑：
① 「多少位机」只认机器字长（寄存器 / ALU 位数）。选项拿指令字长、存储字长或外部总线宽度冒充字长，是本考点最固定的干扰设计。
② 层次是逻辑上的虚拟机器，不是把机器物理拆成五层：除了微程序级与电路，下面的层大多是软件。「某功能只能由硬件实现」这类说法错在违背软硬件逻辑等价。
③ 翻译与解释别混：编译、汇编是翻译（先生成低层程序）；微指令执行机器指令是解释（逐条译、立即做）。问「哪种方式不生成目标程序」选解释。
④ 操作系统级有正式位置（在传统机器级之上、汇编级之下），画层次图漏掉它，或把它排到高级语言之上，都是常见错位。
3. 数据类型转换 ★★★★★ · 近6年×2

C 表达式算出什么，不只看数值，还看每个数在计算的哪一步被换成了什么类型。转换发生在三个关口：运算前先把小整型抬上来、混算时按高位一方看齐、赋值时再把结果塞进目标类型的格子——本卡每条都跟着一个数实际走一遍。

平台前提：本卡统一采用 408 常见计算模型：8 位有符号 char、16 位 short、32 位 int/unsigned int，有符号整数采用补码，浮点数采用 IEEE 754 binary32/binary64 并按就近舍入、遇中间值取偶数处理。超出目标有符号类型表示范围的整数转换，按本模型的低位截取与补码解释计算；在 C11 中，这类转换的结果可能属于实现定义行为。
先跟一遍：两个 char 相加的旅程
设 char a = 100, b = 100; 求 a + b。a、b 在参与运算之前先被整型提升为 int，于是加法是在 int 里做的：100 + 100 = 200，中间过程根本没溢出。
把结果存回 int，得到 200；存回 char，赋值那一刻才截断：200 超出 char 的 −128～127，只留低 8 位，200 − 256 = −56。
乘法同理：a × b 先按 int 算得 10000，存进 int 安然无恙；存进 char 则只留低 8 位，10000 mod 256 = 16。
所以「char 运算会先溢出」是假象——本例的 int 中间运算未溢出，结果转换为较窄类型时才发生值变化。
整型提升：小整型一运算就先升格
设 unsigned char uc = 255;，uc + 1 里 uc 先提升为 int，算得 256，并不回绕成 0；只有把 256 再赋回 unsigned char 变量时，才按 mod 256 变成 0。
提升去向看 int 装不装得下：unsigned short 的取值（0～65535）int 全装得下，所以 unsigned short us = 65535; 的 us + 1 是按有符号 int 算的，得 65536，不是无符号回绕。
通常先进行整型提升；若 int 无法表示原类型全部取值，可能提升为 unsigned int。
混进一个无符号数：有符号一方整体看齐
设 int x = −1; unsigned int u = 1; 比较 x > u：两者同为 4 字节、级别相同，按通常算术转换，x 被换成 unsigned int 再比——−1 的补码一位不变地读作 4294967295，于是 x > u 的结果是真，与数学直觉正好相反。
同一个 x 和 u 相加：4294967295 + 1 按 232 取模，得 0，且表达式的类型是 unsigned int，之后再参与比较或赋值都按无符号解释。
再看 −20 与 10u：−20 换成无符号是 4294967276，比 10 大得多；两者相加得 4294967286（仍是无符号数），若题目把它赋给 int 再打印，才会重新按补码读回 −10——读法取决于最后落进哪种类型。
判断口诀落到过程上：同级别混算时，先把有符号数「按补码原样改读」成无符号数，再做运算，全程不再回头。
赋值截断：结果没变，是格子太小
int n = 300; char c = n;——300 的低 8 位是 0010 1100，即 44，c 得到 44；赋给 unsigned char 也是 44（300 mod 256）。
int m = 70000; short s = m;——70000 mod 65536 = 4464，s 得到 4464，正负看截断后最高位：本例落在正区间，若余数 ≥ 32768 还要再减 65536 读作负数（前面的 200 → −56 就是这么来的）。
强制转换 (char)n 与赋值给 char 变量走的是同一条截断路；表达式本身在 int 里算出的值不受影响。
整型与浮点互转：精度在哪一步丢
float 的有效位只有 24 位（含隐含位），能精确表示的最大连续整数到 224 = 16777216 为止。int big = 16777217; float f = big; 存入时 224 + 1 无处安放，舍入为 16777216，再转回 int 也是 16777216，丢了 1；同样的数存进 double（有效位 53 位）则原样保留。
反方向浮点转整型是截尾不是四舍五入：(int)3.99 = 3，(int)(−3.99) = −3，小数部分整段丢弃。
最常埋伏的一处：float r = 5 / 2; 右边两个操作数都是 int，先做整除得 2，之后才转成 float，r = 2.0；写成 5.0 / 2，一方是 double，另一方被抬成 double 做浮点除法，才得 2.5。转换发生的先后，决定了除法按谁的规则做。
例题
例 · 一组表达式逐项判真假（C 程序实测）
设 char a = 100, b = 100；int x = −1；unsigned int u = 1；float f。下列说法正确的有（　）。
I. a + b 的值是 200，赋给 char 变量后是 −56　II. x > u 为真　III. x + u 的值（按 unsigned int）是 0　IV. f = 16777217 后，(int)f 仍等于 16777217
A. 仅 I、II　B. 仅 II、III　C. 仅 I、III　D. 仅 I、II、III
逐项推：I——a、b 先提升为 int 相加得 200 ✓，赋值截断 200 − 256 = −56 ✓；II——x 转 unsigned 得 4294967295 > 1 ✓；III——4294967295 + 1 对 232 取模得 0 ✓；IV——float 只有 24 位有效位，16777217 舍入为 16777216，转回 int 是 16777216 ✗。
答案 D（四项数值已用 gcc 编译 C 程序逐项实测，含 sizeof 前提核对）。
以为 char、short 运算就在原地算、会当场溢出——实际先提升为 int，溢出只发生在赋回小类型时。
−1 > 1 想当然判假：只要对方是同级别无符号数，−1 先变 4294967295，比较结果反转。
float r = 5 / 2 写出 2.5：整除在赋值转换之前就已完成，r 只能是 2.0。
浮点转整型当四舍五入：是向零截尾，−3.99 转得 −3，不是 −4。
把大整数转 float 当无损：超过 224 的整数先丢精度，之后转回 int 也找不回来。
截断只记「取余」忘了读符号：余数落在目标类型负区间时还要减去模数按负数读（200 → −56）。
4. 数据的大小端与对齐存储 ★★★★☆ · 近6年×1

同一个多字节数放进内存，字节的先后有两种排法；同一组结构体成员住进内存，中间会不会留空洞——这两件事决定了从内存里读回来的到底是什么数。本卡都用具体字节和具体偏移量走一遍。

对齐前提：本卡按常见 ABI：char 1B、short 2B 且按 2B 对齐、int 4B 且按 4B 对齐、double 8B 且按 8B 对齐，结构体整体按最大成员对齐要求补齐；具体题目另给对齐规则时以题干为准。
一个数拆成字节：0x12345678 住进内存
int 值 0x12345678 占 4 个字节：最高字节 12、次高 34、次低 56、最低 78。设它存放在地址 100～103。
大端排法：高字节住低地址——100 放 12、101 放 34、102 放 56、103 放 78，顺着地址读下去正好是数的书写顺序。
小端排法：低字节住低地址——100 放 78、101 放 56、102 放 34、103 放 12，整个倒过来。
判机器是哪一端，不用背：取这个 int 首地址处的那一个字节，是 78 就是小端，是 12 就是大端。用联合体 union { int i; unsigned char c[4]; } 令 i = 0x12345678，小端机上 c[0]（最低地址字节）读得 0x78，大端机上读得 0x12——真题最爱用这一手设问。
两点边界：大小端管的是字节之间的顺序，不管字节内部的位序；单字节的 char、以及字符串里逐个存放的字符，不受大小端影响。short 值 0x1234 同理：小端机内存里先 34 后 12。
结构体里为什么有空洞：成员各就各位的过程
看 struct S1 { char a; int b; char c; }; 逐个安放：a 是 char，随便落座，占地址 0。
b 是 int，要求起始地址是 4 的倍数——地址 1 不合格，只能跳到 4，地址 1～3 空出来，这就是内部填充 3 个字节；b 占 4～7。
c 是 char，落在 8。成员到此放完共 9 个字节，但结构体总大小还须是其对齐值（成员中最大的对齐值，这里是 int 的 4）的倍数，于是尾部再补 3 个字节，sizeof(S1) = 12——尾填充是为了让这种结构体排成数组时，每个元素的 b 都仍然对齐。
同一组数值的成员换序 struct S2 { int b; char a; char c; };：b 占 0～3，a 落 4，c 落 5，只剩尾填充 2，sizeof(S2) = 8。成员一个没少，只因大成员排在前面省掉了中间的空洞。
对齐值随成员走：含 double 的 struct { char c; double d; int i; } 中，d 要求 8 的倍数地址——c 占 0 后要填 7 个字节 d 才落 8，i 落 16，尾填充 4，sizeof = 24，整个结构体的对齐值被 double 抬到了 8。数组成员按单个元素看：char a[3] 只占 3 个字节、对齐值仍是 1，后接 int 时只填 1 个字节。
例题
例 1 · 结构体偏移与总大小（C 程序 offsetof 实测）
struct Node { char x; int y; short z; char w; }，求各成员偏移量与 sizeof；若成员可任意重排，最小 sizeof 是多少？
逐个放：x 落 0；y 要求 4 的倍数，填 3 后落 4，占 4～7；z 是 short，要求 2 的倍数，落 8，占 8～9；w 落 10。已用 11 字节，结构体对齐值为 4（int 最大），尾填充 1 → sizeof = 12。
重排为 { int y; short z; char x; char w; }：y 占 0～3，z 落 4，x 落 6，w 落 7，正好 8 字节、无任何填充 → 最小 sizeof = 8。
偏移 0 / 4 / 8 / 10 与两个 sizeof 已用 gcc 的 offsetof / sizeof 逐项实测一致。
例 2 · 按字节读回一个数
小端机内存地址 200～203 依次存放 78、56、34、12（十六进制），把这 4 个字节作为一个 int 读出，其值是（　）。
小端＝低地址放低字节：地址 200 的 78 是最低字节，203 的 12 是最高字节，自高到低拼得 0x12345678。
若同一串字节出现在大端机上，低地址字节即最高字节，读出的是 0x78563412——同一片内存，两台机器读出两个数，这正是跨机传二进制数据要先约定字节序的原因。
把大小端说成「位序颠倒」：颠倒的是字节在地址上的次序，字节内部 8 位不动。
算 sizeof 只加成员大小：S1 成员共 6 字节，实际 12——内部填充与尾填充都要算进去。
漏掉尾填充：成员末尾停在 9 字节就报 9，对齐值是 4 时必须向上圆到 12；数组里下一个元素才对得齐。
以为填充只发生在成员之间：char 后接 double 填 7、末尾 int 后填 4，两处都可能出现。
联合体判端时把 c[0] 当最高字节：c[0] 对应最低地址，小端机上它恰是最低字节 0x78。
重排成员只按大小降序背口诀却不复核尾长：排完仍要按对齐值圆整总大小（本例恰满 8，纯属放得齐）。
5. 外部存储器 ★★★★☆ · 近6年×1

主存之外的存储器只看三家：磁盘、闪存、由磁盘组成的 RAID。本卡只讲存储器本身——结构、地址怎么编、性能参数怎么算、坏了怎么办；给定一批盘块请求先服务谁（磁盘调度算法）是 OS 侧 os-6 / os-7 的口径，本卡不讲；光盘已删除出考纲，不收。

磁盘：跟着一次定位走完结构与地址
一张盘片双面涂磁层，两个面各是一个记录面，每个记录面上有一圈圈同心磁道，每条磁道又切成若干扇区，扇区是磁盘读写的最小单位（常为 512 B 或 4 KB）。多张盘片同轴叠放，所有记录面上半径相同的磁道合称一个柱面。
定位一个扇区走三步：磁头组先整体移动到目标柱面（各记录面同时到位，所以地址里写柱面号而不是磁道号）→ 再选通目标盘面对应的磁头 → 盘片转起来，等目标扇区转到磁头下方。
于是磁盘地址就是三段：柱面号 ＋ 盘面号 ＋ 扇区号（有的编址把盘面号排在前，字段构成不变）。
算一本账：某磁盘组 10 个记录面、每面 1000 条磁道、每道 100 个扇区、每扇区 512 B。总容量 = 10 × 1000 × 100 × 512 = 512,000,000 B（约 512 MB 按 106 计，约 488 MiB）。
地址位数按每段的取值个数向上取整：柱面 1000 个需 10 位（210 = 1024 才够），盘面 10 个需 4 位，扇区 100 个需 7 位，地址共 21 位。
磁盘性能参数：存取时间拆成三段（设备本身口径）
承接上面的定位过程，读一个扇区的时间天然分三段：磁头移到柱面的寻道时间、盘面转半圈等扇区到来的旋转延迟、扇区从磁头下通过的传输时间。题目给出平均寻道时间时直接取用，那是设备参数，不是调度算出来的。
代入具体数：转速 7200 转/分 → 每转 60 ÷ 7200 s ≈ 8.33 ms，平均旋转延迟取半转 ≈ 4.17 ms。每磁道 64 个扇区，则数据传输率 = 64 × 512 B × 120 转/s = 3,932,160 B/s（约 3.93 MB/s），传一个扇区用 8.33 ÷ 64 ≈ 0.13 ms。
平均寻道时间给 5 ms 时，读一个扇区的平均存取时间 = 5 + 4.17 + 0.13 ≈ 9.30 ms——三段里旋转与寻道是大头，传输时间常可忽略，但题目问到就得算全。
闪存：按页读写、按块擦除
闪存（NAND）内部按页组织（常为 4 KB），若干页（此例 64 页）合成一个块（256 KB）。读、写都以页为单位进行，唯独擦除只能整块来。
跟着改一个数走：NAND 闪存按页读写、按块擦除，已写入页面通常不能直接覆盖更新；SSD 常将新数据写入其他可用页、旧页标为无效，待垃圾回收时搬迁有效数据并按块擦除；因此更新少量数据也可能引起额外搬迁（写放大）。教材简化模型有时以整块擦除重写示意。
每个块能承受的擦除次数有限（反复擦写会磨损），所以固态盘要靠磨损均衡把擦写摊到各个块上，并预留一部分空间做替换；这也是闪存与磁盘最本质的差别：磁盘可任意次原地重写，闪存先擦后写、擦写有寿命。
RAID：四种搭法，先分清镜像与条带
RAID 0、5、10 用同一组 6 块 1 TB 盘比较；RAID 1 用最基本的 2 块 1 TB 盘示例，避免把多组镜像再条带化误算成 RAID 1：
RAID 0 条带
数据切块轮流放 6 块盘，可用 6 TB、读写可并行最快；无任何冗余，坏任意 1 块，条带断裂、全部数据丢失。
RAID 1 镜像
2 块 1 TB 盘互为镜像、写同一份数据，可用 1 TB（利用率 50%）；坏任意 1 块可由另一块恢复，2 块全坏才丢数据。
RAID 5 分布校验
数据条带化，奇偶校验块轮流分布在各盘（不是独占一块校验盘），可用 (6 − 1) × 1 = 5 TB；坏任意 1 块可由其余盘的校验重构，同时坏 2 块则丢失。
RAID 10 镜像＋条带
6 块盘三组镜像再条带化——这正是 RAID 10：先两两镜像成 3 组、再在组间条带，可用 3 TB；至少坏 1 块不丢数据，最多可坏 3 块（每组各坏 1 块），兼得镜像的可靠与条带的速度。
小例复核口径：4 块 2 TB 盘做 RAID 5，可用 (4 − 1) × 2 = 6 TB——公式里的「−1」是校验等效占用一块盘的容量，与盘数无关地恒减一块。
例题
例 1 · 存取时间三段合成
某磁盘转速 7200 转/分，每磁道 64 个扇区，每扇区 512 B，平均寻道时间 5 ms。读一个扇区的平均存取时间约为（　）。
A. 5.13 ms　B. 9.30 ms　C. 13.33 ms　D. 17.50 ms
逐段算：每转 8.33 ms，平均旋转延迟取半转 4.17 ms；传输一个扇区 8.33 ÷ 64 ≈ 0.13 ms；合计 5 + 4.17 + 0.13 ≈ 9.30 ms。A 只加了传输段漏了旋转，C 误把整转当旋转延迟，D 三段之外又重复计入寻道。
答案 B（三段数值已用程序复算）。
例 2 · RAID 选型与容量
6 块 1 TB 磁盘组建阵列，要求可用容量尽量大且能容忍任意 1 块盘损坏，应选（　），可用容量为（　）。
A. RAID 0，6 TB　B. RAID 5，5 TB　C. RAID 10，3 TB
逐项判：A 容量最大但坏 1 块全丢，不满足容忍要求；C 能容忍坏盘但只用一半容量；B 可用 (6 − 1) × 1 = 5 TB 且坏任意 1 块可重构，两条都满足。
答案 B（所选仍为 RAID 5、5 TB；各级容量已按 rev2 口径用程序复算）。
盘片数当记录面数：地址与容量算的是记录面，盘片双面记录时面数是盘片数的 2 倍（本卡例题直接给面数，按给的数算）。
平均旋转延迟取一整转：等扇区到来平均只等半转，7200 转/分是 4.17 ms 不是 8.33 ms。
说 RAID 5 有一块专门的校验盘：校验块是轮流分布在各盘的，只是容量上等效占一块；独占校验盘是 RAID 3 / 4 的做法。
RAID 0 的「0」记成零故障：恰恰是零冗余，坏一块盘整个阵列的数据都读不回来。
把闪存当磁盘原地改写：闪存必须先整块擦除再写，擦除按块不按页，且次数有限、要磨损均衡。
在本卡里套磁盘调度算法：存取时间三段是设备参数口径，题目给平均寻道时间就直接用，先服务哪个请求是 OS 调度卡的事。
6. I/O 设备与控制方式（OS 侧） ★★★★★ · 近6年×4

定位：OS 第 5 章输入输出管理。合辑 co-11／co-20 讲的是计组口径——中断响应的硬件时序、DMA 怎样访存，那些本卡不重复；本卡只回答 OS 这一侧的问题：设备怎么分类、四种控制方式下 OS 如何组织一次 I/O、一次请求在 I/O 软件的各层之间怎样分工。第二节把 A1 点「设备独立性软件」并入本卡。

一、I/O 设备与控制方式

先摆一个场景：一台机器上同时挂着键盘、行式打印机和磁盘，三个进程分别要用它们。OS 管理设备的第一步，是先按三个维度认清每台设备是什么脾气——分类不是背表，每个维度都直接决定后面怎么管。

按传输速率键盘、鼠标是低速设备（每秒几个到几百字节）；行式打印机是中速设备；磁盘是高速设备（每秒兆字节量级）。考题只认典型设备所属的量级，不抠精确边界。
按交换单位磁盘是块设备：数据以固定大小的数据块为单位交换，块可按地址寻址、随机存取。键盘、打印机是字符设备：数据像水流一样逐字符进出，不能寻址，来了就得及时接，所以天然适合中断方式。
按共享属性打印机是独占设备：一段时间内只能分给一个进程，否则两份作业的输出会交错成一团。磁盘是共享设备：多个进程交替访问同一盘面互不干扰。独占设备经 SPOOLing 可以改造成逻辑上可排队共享的虚拟设备（见《SPOOLing 假脱机技术》卡）。

认清设备之后，OS 要决定「一次传送由谁盯着」。同样是读入数据，四种控制方式下 CPU 和进程的状态完全不同：

程序查询驱动发出读命令后，CPU 反复读控制器的状态寄存器问「好了没」，进程忙等不让出 CPU，设备没就绪就一直空转。CPU 与设备严格串行，只适合极简单、慢速的场合。
中断驱动在典型的阻塞式 I/O 请求中，进程发出请求后就阻塞、让出 CPU 去跑别的进程；设备传完一个数据单位就发一次中断，中断处理把它接走、再唤醒或继续喂下一个单位。键盘敲一个字中断一次，正合适；但单位一多，中断就频繁。
DMA进程要整块读盘时，驱动把内存首址、字节数写进 DMA 控制器就阻塞等待；DMA 控制器自己管着把整批数据在内存与设备之间搬完；在本卡的一次批量传输模型中，整批全部完成才中断一次。为高速块设备而生（搬运细节与访存计算在计组卡里，本卡只记 OS 的分工）。
通道设备很多的大型系统里，CPU 把一串 I/O 操作写成存放在内存中的通道程序，只发一条启动指令把首址交给通道；通道是一个独立的 I/O 处理机，自己取通道指令执行、管着一组控制器和设备，在本卡的一次批量传输模型中，整串活干完才向 CPU 发一次中断。

通道再分三种（了解即可）：字节多路通道轮流为多台低速设备按字节交叉服务；数组选择通道独占通路伺候一台高速设备、一批传完才换人；数组多路通道让多台高速设备按数据块交叉传送。

OS 眼中的设备从来不是设备本体。进程要读盘，OS 碰的全是设备控制器的寄存器：往控制寄存器写命令、从状态寄存器读「忙／就绪／出错」、从数据寄存器取数据——机械与电气的脏活被控制器挡在下面，一台控制器还可以挂多台同类设备。再往上，通道在 OS 眼中是一个能代管一串 I/O 的下级处理机：CPU 只下「启动」，通道负责盯着它那组控制器把活干完。一条链记清：CPU — 通道 — 控制器 — 设备，OS 的命令逐级向下、完成报告逐级向上。

例题 1（真题风格，程序验算）
某系统有键盘、行式打印机、磁盘各一台。① 给三台设备分别按传输速率、交换单位、共享属性分类；② 进程要从磁盘一次读入 8 个数据块，分别比较中断方式与 DMA 方式的「完成中断次数」和「CPU 启动开销」；③ 磁盘这次读应选哪种控制方式？
推导 ①：键盘——低速、字符设备；行式打印机——中速、字符设备、独占设备；磁盘——高速、块设备、共享设备。三个维度互相独立，一台设备要在每个维度上各落一个格。
推导 ②：先分开两个指标。完成中断次数：中断方式每传完 1 个块产生 1 次完成中断，8 个块共 8 次；DMA 把 8 个块作为一次批量任务，整批完成产生 1 次完成中断。CPU 启动开销另计：在本示意模型中，中断方式要逐块发起或续发，启动处理随块数增长（计 8 次）；DMA 只在任务开始时设置控制器参数，计 1 次启动开销，完成中断的处理不算启动开销。程序查询不产生完成中断，它的反复轮询开销也不能与完成中断次数并列相加；通道承接整串任务时同样是 1 次完成中断，另有 1 次发启动指令的开销。
推导 ③：磁盘是高速块设备、批量大，选 DMA：一次任务只有 1 次完成中断，CPU 启动开销也只在开始设置参数时发生一次。若误用中断方式，8 次完成中断还只是小数目，大批量读盘时 CPU 会被频繁的完成中断和逐块启动处理淹没。
结论：分类抓「典型设备落格」，选型抓「批量越大、越要选打扰少的」。
二、设备独立性软件（I/O 软件层次）

一次 I/O 要分清两条路径，不能把四层软件的排列误读成一条单向调用链：

请求路径：用户进程 → 用户层 I/O 软件 → 设备独立性软件 → 设备驱动程序 → 控制器与设备。

完成路径：硬件中断 → 中断处理程序 → 完成通知、唤醒等待进程。

层次排列≠调用路径：中断处理程序位于软件层次的底层，并不表示用户请求先经它转发到硬件。

用户层离进程最近：提供库函数，把请求先加工成标准格式——如 printf 先把整数、浮点数拼成字符串，才发出系统调用。SPOOLing 的排队守护进程也住在这一层。
独立性层本节主角，对上给出统一接口：不管底下是磁盘还是打印机，进程用的都是同一套读／写调用，硬件细节被屏蔽。所有设备共有的公共活也都在这层干：逻辑设备名到物理设备的映射、独占设备的分配与回收、公共缓冲管理、差错处理与报告、按权限做设备保护。
驱动层与硬件直接绑定，一类设备一个驱动程序（同类不同型号也可各有驱动）：把上层抽象的「读第 k 块」翻译成往这台控制器的哪个寄存器写什么命令，并负责设置、检查寄存器状态。它只听独立性层的抽象命令，不负责分配和命名。
中断处理层离硬件最近的软件层：中断一到，先保存被中断进程的现场、辨认中断源，把最急的处理做完，再唤醒等待这次 I/O 的进程；中断的细节被它挡住，上层软件感觉不到。

映射具体怎么走一遍：进程用逻辑名 printer1 发起打印，独立性层查逻辑设备表，得到实际是哪台物理打印机、该用哪个驱动；再查设备状态，空闲就把这台独占打印机分配给该进程（正忙则让进程排队等待），随后把请求交给对应驱动去操作控制器；打印完成、逐层返回后，独立性层再回收设备给下一个进程。正因为映射在独立性层，临时把 printer1 改指另一台同型号打印机，进程的代码一个字都不用改——这就是「设备独立性」四个字的落点。

例题 2（真题风格，程序验算）
下列工作各属哪一层？I. printf 把待输出的整数格式化为字符串；II. 把逻辑设备名 printer1 映射到 2 号物理打印机；III. 为打印请求分配公共缓冲区并在出错时向上报告；IV. 向打印机控制器的寄存器写入启动命令；V. 中断到达时保存现场并唤醒等待打印的进程。
推导：I 发生在进程调用库函数、还没进内核的阶段 → 用户层。II、III 都是所有设备共有的公共事务、与具体硬件无关 → 设备独立性层（映射、缓冲、差错正是独立性层的三件标志性工作）。IV 直接摆弄寄存器、话里全是这台设备的细节 → 设备驱动程序。V 是中断现场的第一手处理 → 中断处理程序。
结论：I 用户层；II、III 设备独立性层；IV 驱动层；V 中断处理层。判题口诀：沾寄存器的是驱动，管公共事务的是独立性层。
坑：
① 查询方式下进程是忙等、不让出 CPU；中断方式下才是发完请求就阻塞。把两者状态说反是本节头号坑。
② DMA 不是「全程不用 CPU」：启动时设参数、完成时处理中断都要 CPU，它省的是搬运途中的干预。
③ 通道不是一种设备、也不是控制器：它是能执行通道程序的 I/O 处理机，站在控制器之上。
④ 块设备／字符设备看的是交换单位不是快慢：打印机再快也是字符设备，磁盘的立身之本是「以块为单位、可寻址」。
⑤ 设备独立性靠的是独立性层的统一接口，不是驱动通用——恰恰相反，驱动是每类设备专用的，正因为驱动各异，才需要独立性层来屏蔽差异。
⑥ 缓冲、差错、分配三件公共事都在设备独立性层：别把设备分配安到驱动头上，驱动只负责把分到手的设备操作起来（缓冲的单／双／池细节见《缓冲管理》卡）。
⑦ 层次顺序别倒：自上而下是用户层 → 独立性层 → 驱动层 → 中断处理层；中断处理层在最底，不是最上。

来源：王道《操作系统》第 5 章输入输出管理（设备分类与控制方式、I/O 软件层次与设备独立性）。真题依据：I/O 设备与控制方式 A 类正考 2010、2012、2017、2019、2022、2023、2024、2026；设备独立性软件 A 类正考 2009、2011、2012、2013、2020、2026（两点合并一卡两节）。例题经脚本状态／归属断言验算。与 co-11／co-20 分工：硬件中断时序、DMA 访存计算不在本卡。

7. 网络层的功能 ★★★☆☆ · 近6年×2

定位：NET 第 4 章网络层的总纲。后面各卡分别细讲 IP、子网、分片、路由协议，本卡先立框架：网络层一共管哪几件事、每件事由谁做。用一个分组的旅程贯穿全卡：主机 A（以太网，10.0.1.2）要把一个 IP 分组送给另一个以太网里的主机 B（10.0.3.9），途中依次经过路由器 R1、一段广域网 PPP 链路、路由器 R2。

转发 vs 路由选择：查表与建表是两件事

分组到达 R1 时，R1 做的事只有一件：看分组的目的 IP，查本机的转发表，决定从哪个端口送出去——这叫转发。它逐分组发生、只看自己手里这张表、只管眼前这一步。那张表从哪来？路由协议可独立于具体用户数据分组持续运行和更新路由信息：路由器之间互相交换路由信息，运行路由算法（如 RIP、OSPF，细则见《RIP 与 OSPF 对比》卡）算出到各个网络该走哪条路，生成并更新转发表——这叫路由选择。一句话记牢：路由选择负责建表（控制层面，面向全网），转发负责查表（数据层面，面向单个分组）；考题最爱把两者的定义对调。

网络互联：把异构网络缝成一个网络

这趟旅程的三段路并不相同：两段以太网用的是一种帧格式，中间 PPP 链路是另一种，地址格式、最大帧长也各不一样。分组每经过一个路由器，链路层封装通常需要重新建立；无 NAT 时源、目的 IP 通常不变，但 IPv4 的 TTL 与首部校验和会相应更新；经不同链路时帧格式及寻址字段也可能不同（例如以太网帧有 MAC 地址字段，PPP 帧没有）。网络层的核心本事，就是用统一的 IP 协议把这些物理上异构的网络屏蔽成一个逻辑网络。路由器是通过网络层实现不同 IP 网络互联的典型设备；具有三层转发能力的交换设备也能承担路由功能；普通二层交换机主要在同一二层网络内转发帧。中继器只放大信号（物理层），缝不了异构网络。途经小 MTU 链路时的分片处理见《IP 数据报分片》卡。

拥塞控制在网络层的定位：辅助位，不是主角

假设旅程中 PPP 链路突然被大量分组挤满、路由器队列溢出，这就是拥塞：整个网络的负载超过了它的处理能力，是全局问题（区别于流量控制——那是收发双方点对点的事）。定位要记准：根据拥塞反馈真正调小发送速率的主体在传输层，即 TCP 的慢开始与拥塞避免（见《TCP 拥塞控制四阶段》卡）；网络层站在辅助位：路由选择时绕开拥塞热点，路由器通过队列调度、丢弃或标记分组，把「堵了」的信号递给端系统。所以「拥塞控制完全由网络层负责」和「拥塞与网络层无关」两种说法都错。

SDN：把「建表」从路由器里搬出来

传统网络里，转发和路由选择挤在同一台路由器中。SDN（软件定义网络）把两者拆开：数据平面只剩下交换机，按流表做匹配—转发，相当于纯粹的转发员；控制平面是一个逻辑集中的控制器，掌握全网视图，集中算好流表再下发给各交换机。两类接口别记反：控制器与交换机之间是南向接口（典型协议 OpenFlow），管的是「向下发流表」；上层网络应用与控制器之间是北向接口（一组 API），管的是「向上供应用调用」。

例题（真题风格，程序验算）
沿上面的旅程回答：① 分组离开 A 时 TTL＝64，到达 B 时 TTL 是多少？② 下列说法正确的有哪几项？I. R1 查转发表把分组送往 R2 方向的端口，属于转发；II. 各路由器运行 OSPF 更新转发表，属于路由选择；III. SDN 控制器通过北向接口向交换机下发流表；IV. 拥塞控制完全由网络层负责，传输层不参与。
推导 ①：TTL 只在被路由器转发时减 1，主机发出和二层设备转发都不减。这趟旅程只有 R1、R2 两台路由器：64 → 经 R1 得 63 → 经 R2 得 62。
推导 ②：I ✓——查现成的表、送单个分组，正是转发的定义。II ✓——运行路由协议算路建表，正是路由选择。III ✗——向交换机下发流表走的是南向接口，北向接口朝上服务应用，方向反了。IV ✗——拥塞控制的主体是传输层的 TCP，网络层只是辅助，「完全由网络层负责」错。
结论：① 62；② 只有 I、II 正确。
坑：
① 转发≠路由选择：一个查表送分组、一个算路建表，定义对调是本点头号出题法。
② 逐跳看链路层与网络层：链路层封装通常需要重新建立，帧格式及寻址字段也可能不同；无 NAT 时源、目的 IP 通常不变，但 IPv4 的 TTL 与首部校验和会相应更新。经普通二层交换机转发不减 TTL。
③ 路由器是通过网络层实现不同 IP 网络互联的典型设备；具有三层转发能力的交换设备也能承担路由功能；普通二层交换机主要在同一二层网络内转发帧。
④ SDN 接口方向：南向朝下对交换机（OpenFlow），北向朝上对应用（API）——按「向下／向上」的画面记，别按字母记。
⑤ 拥塞控制（全网、主体在传输层、网络层辅助）≠流量控制（点对点、收发双方之间），两个概念的范围和楼层都不同。
