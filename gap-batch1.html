24. 操作系统的运行环境 · 内核态 / 用户态与态切换 ★★★★★ · 近6年×5

一个程序跑起来时 CPU 处在什么态、哪些指令它能碰、态在什么时候翻面——这张卡讲清。只讲 OS 侧的态与特权级；中断的硬件响应过程（压栈、查向量表）是计组 co-20 的口径，本卡不重复。

先看一个过程：用户程序想在屏幕上打印一句话
① 程序在用户态执行普通指令，先把要打印的字符串算好、放进自己的数组。
② 它调用库函数 printf——这一步仍在用户态，库函数只是把参数整理好。
③ 库函数执行一条系统调用（trap / 访管指令）请求写设备——执行到这条指令的那一刻，硬件把 CPU 切到内核态并保存现场。
④ 内核按调用号找到写设备的服务程序，在内核态驱动设备把字符送出去。
⑤ 服务完成，内核恢复刚才保存的现场、切回用户态，程序从 trap 的下一条接着跑。
整个过程只有「陷入—服务—返回」这一段在内核态，用户程序自己从头到尾没碰过 I/O 指令。
两种态与特权指令
  • 内核态（管态 / 核心态）：能执行全部指令、访问全部软硬件资源；操作系统运行在此态。
  • 用户态（目态）：只能执行非特权指令、只能访问本进程的地址空间；用户程序运行在此态。
  • CPU 里程序状态字（PSW）有一位专门记当前处于哪一态，态切换时由硬件改写。
  • 特权指令（只能在内核态执行）：I/O 指令、开 / 关中断指令、置时钟、修改 PSW 与访存保护寄存器、停机指令。
  • 非特权指令（用户态可执行）：算术逻辑运算、在本进程空间内的取数存数、用户空间内的转移指令。
  • 用户态一旦执行特权指令，硬件立刻触发异常，控制权交内核处理（通常终止该进程）。
态翻面的三种入口（都从用户态进内核态）
  • 系统调用：程序主动请求服务，靠 trap 指令自愿陷入——如请求读写文件、创建进程。
  • 异常（内中断）：当前指令被动引发，与指令同步——缺页、除零、访存越界、在用户态用特权指令。
  • 外部中断：与当前指令无关的外部事件，异步到达——时钟中断、I/O 操作完成中断。
  • 三者共同点：响应时硬件自动保存 PSW 与 PC 并切到内核态；处理结束按保存的现场恢复、回到原来的态。
例题
例 · 哪些事件会引起用户态 → 内核态（状态机模拟）
下列事件中，会引起 CPU 由用户态转为内核态的是（　）。
I. 用户程序执行系统调用　II. 时钟中断发生　III. 用户程序在用户态执行一条特权指令　IV. 用户程序访问数组越界
A. 仅 I、II　B. 仅 I、III　C. 仅 II、III、IV　D. I、II、III、IV
逐条判：I 是 trap 自愿陷入 ✓；II 外中断响应必须进内核处理 ✓；III 特权指令在用户态执行触发异常 ✓；IV 越界触发异常 ✓。
四条全中 → D（已用 CPU 态状态机脚本逐事件模拟验证）。
态切换 ≠ 进程切换：进内核处理完中断可以原样返回原进程，进程并没换；别一看到「进内核」就选「发生进程切换」。
调用库函数不切换——只有真正执行到 trap 指令那一刻才陷入内核，printf 前面一大半工作都在用户态。
系统调用的「请求」动作发生在用户态、「服务」执行在内核态；说「系统调用运行在用户态」是把两段混成一段。
关中断是特权指令：用户程序想「关上中断独占 CPU」做不到，这是分时系统能抢占的根基。
33. 算法时空复杂度 · 量级判定与递归式求解 ★★★★★ · 近6年×3

给一段代码判量级、给一个递归式求解、算法设计大题最后一问写复杂度——三件事都看这张卡。此点几乎每道 DS 算法大题都带一问，答法本身就是采分点。

量级判定：只数基本操作执行的次数
片段一（三角循环）：for (i = 1; i <= n; i++) for (j = 1; j <= i; j++) x++;——内层总次数 = 1 + 2 + … + n = n(n + 1) / 2 → Θ(n2)。
片段二（外层翻倍）：i = 1; while (i <= n) i = i * 2;——i 依次取 1, 2, 4, …, 2k，2k ≈ n 时停，循环体执行约 log2n 次 → Θ(log n)。
收口：找重复执行的那条基本操作（比较、赋值、访问结点……），数它执行的次数；只留最高阶项，丢掉低阶项和常数系数。
递归式求解：主方法先行，套不进再展开
T(n) = 2T(n/2) + n
f(n) 与 nlog22 = n 同量级 → Θ(n log n)（归并排序）
T(n) = 2T(n/2) + n2
f(n) 主导 → Θ(n2)
T(n) = T(n/2) + 1
Θ(log n)（折半查找）
展开法例
T(n) = T(n − 1) + n 逐层展开 = n + (n − 1) + … + 1 = n(n + 1) / 2 → Θ(n2)（直接插入最坏）
最好 / 最坏 / 平均：题目没点明时看哪个
  • 一般口径：题目未指明时按最坏情况作答（保底）；最好、平均须题目点明或给出概率分布才评。
  • 直接插入排序：最好 Θ(n)（已有序）、最坏与平均 Θ(n2)。
  • 快速排序：平均 Θ(n log n)、最坏 Θ(n2)（枢轴每趟都落在端点时）。
空间复杂度：别忘递归栈
  • 只开固定几个变量的原地算法：辅助空间 O(1)。
  • 递归算法的空间 = 递归深度（每层一帧栈）＋额外辅助空间，两者取主导。
  • 归并排序：辅助数组 Θ(n)，递归栈 O(log n)，合计 Θ(n)。
  • 快速排序：空间主要来自递归栈，平均 O(log n)、最坏 O(n)。
大题作答规范（照此写不丢分）
  • ① 先指明基本操作是什么；② 写出执行次数的求和式再化简，不直接蹦结论；③ 结论给紧界 Θ（题目明确问 O 才写 O）；④ 时间、空间分开各写一句；⑤ 要分最好 / 最坏时，把各自的触发条件一并交代。
例题
例 · 看着像 n log n，其实是 n（程序模拟）
count = 0; for (i = 1; i <= n; i *= 2) for (j = 1; j <= i; j++) count++; 求 count 的增长量级。
外层 i 依次取 1, 2, 4, …, 2k，其中 2k ≤ n < 2k+1；内层执行次数恰等于当趟的 i。
count = 1 + 2 + 4 + … + 2k = 2k+1 − 1。
由 2k ≤ n 得 2k+1 ≤ 2n，所以 count 不超过 2n − 1；取 n = 2k 程序实测：n = 1024 时 count = 2047 = 2n − 1，分毫不差。
结论：时间复杂度 Θ(n)——总和由最后一项主导，不是「外层 log n 趟 × 内层 n 次」。
只数循环层数、不数每层实际次数：「外层翻倍」型是最爱挖的坑，内层次数跟着外层涨，总和看末项。
主方法有套不进的间隙（如 f(n) = n log n 卡在两档之间），别硬套——老老实实展开或分层求和。
空间复杂度只写辅助数组、漏掉递归栈：递归深度经常就是答案的主项。
把平均情况当默认答案：题目没点明先按最坏答；要报平均，先看题目有没有给分布。
28. OSI 与 TCP/IP 参考模型 · 分层与功能归属 ★★★★★ · 近6年×3

分层、各层干什么、一个功能该归哪层追责——这张卡讲清。选择题最爱在「功能归属」上设套。

跟着一封邮件下楼：OSI 七层各干一件事
  • 应用层：直接为用户进程提供服务，HTTP、FTP、SMTP 在这里产生数据。
  • 表示层：管数据的「长相」——编码格式转换、加密解密、压缩解压。
  • 会话层：建立、管理、终止进程间的对话（会话）。
  • 传输层：把数据分段、加端口号，负责端到端的可靠传输与流量控制。
  • 网络层：给分组选路——路由选择与转发，靠 IP 地址跨网络送达。
  • 数据链路层：成帧、MAC 寻址、CRC 检错，管相邻结点之间这一段的流量控制。
  • 物理层：在介质上传比特流，规定接口与信号特性，不管比特的含义。
  • 封装路线：数据 →（传输层）段 →（网络层）分组 / 数据报 →（链路层）帧 →（物理层）比特；每往下一层添一段本层首部，链路层还加尾部。
TCP/IP 四层与对照
OSITCP/IP典型协议 / 内容
应用层 ＋ 表示层 ＋ 会话层应用层HTTP、FTP、DNS、SMTP
传输层传输层TCP、UDP
网络层网际层IP
数据链路层 ＋ 物理层网络接口层各种局域网 / 广域网接口
  • OSI 是先行制定的理论模型，结构全但没成为事实主流；TCP/IP 是先在实践中跑出来、再总结成的事实标准。
协议与服务：一个水平、一个垂直
  • 协议：同层对等实体之间通信的约定，是水平方向的——两台机器的传输层按 TCP 说话。
  • 服务：下层通过接口向上层提供的能力，是垂直方向的——传输层用网络层的分组投递服务，再向应用层提供可靠字节流服务。
  • 一句收：上层 = 用下层的服务 ＋ 本层的协议，实现本层功能，再向上提供更强的服务。
高频辨析：功能到底归哪层
路由选择、转发
网络层
端到端流量控制
传输层（发送方主机对接收方主机）
相邻结点流量控制
数据链路层（一段链路的两端）
检错
链路层用 CRC 查帧；传输层 TCP 有校验和并确认重传；IP 只校验首部、不保可靠
设备归层
中继器 / 集线器 → 物理层；网桥 / 交换机 → 数据链路层；路由器 → 网络层
例题
例 · 功能归属辨析（归属断言表核对）
在 OSI 参考模型中，下列功能由传输层实现的是（　）。
A. 路由选择　B. 数据加密　C. 端到端的流量控制　D. 帧的差错检测
逐项归层：A 是网络层的活；B 是表示层（数据表示与加密）；C 正是传输层对两端主机的流控 ✓；D 的 CRC 检错在数据链路层。
答案 C（卡内全部层归属已编成断言表逐条核对）。
流量控制不是传输层的专利：链路层管相邻一段、传输层管端到端，题目只说「流量控制」时先看范围词。
TCP/IP 的网络接口层对应 OSI 的下面两层，不是只对应物理层。
会话层、表示层在 TCP/IP 里并进应用层，是「合并」不是「功能消失」。
别把 TCP 的确认重传记到 IP 头上：网络层（IP）无连接、不可靠，可靠是传输层补的。
25. 操作系统的结构与引导 · 附概念与功能 ★★★★ · 近6年×4

操作系统自己怎么搭起来、开机后怎么被装进内存跑起来、它对外提供哪些本事——这张卡讲清（后半并入「概念与功能」一节）。

先定性：OS 是什么、管什么
  • OS 是最基本的系统软件：控制和管理整个计算机的软硬件资源，合理组织调度工作与资源分配，并提供用户与应用程序的接口。
  • 处理机管理：以进程为单位分配 CPU（进程的创建、调度、同步都在此）。
  • 存储器管理：内存的分配回收、地址变换与保护。
  • 文件管理：文件的存储、目录、共享与保护。
  • 设备管理：I/O 设备的分配、驱动与缓冲。
  • 用户接口：命令接口（敲命令）、程序接口（就是系统调用，见 os-24）、图形接口。
  • 多道程序设计：内存里同时放多道程序，一道等 I/O 时 CPU 转去跑另一道——宏观上并行、微观上串行，换来 CPU 利用率与系统吞吐量的提高。
结构：一部拆分史
  • 无结构：一堆过程互相乱调用，快而乱，不可维护——起点。
  • 模块化：按功能切成模块、定好接口，模块间按规定调用；结构清晰，但接口一乱仍会牵一发动全身。
  • 分层式：自底向上分层，每层只能调用相邻低层：易调试、易验证，代价是层层调用效率低、层次边界难划清。
  • 宏内核（单体内核）：进程、文件、网络、驱动等全部服务都挤在内核态运行——调用快，但内核庞大、一处崩全盘崩。
  • 微内核：内核只留最基本的功能——进程间通信、低级地址空间管理、中断处理、原语；文件系统、驱动、网络等做成用户态的服务进程——可靠、易扩展易移植，代价是服务之间频繁通信与态切换、性能开销大。
  • 外核：不做抽象，直接把硬件资源安全地复用分给应用程序、让应用自己管——知道这个概念即可。
虚拟化与 VMM
  • VMM（虚拟机监控器 / Hypervisor）在一台物理机上虚拟出多台「裸机」，每台虚拟机可装不同的 OS 同时运行。
  • 第一类 VMM：直接运行在硬件之上，自己就是最底层。
  • 第二类 VMM：运行在宿主 OS 之上，是一个普通应用程序，靠宿主调度硬件。
  • VMM 的活：虚拟 CPU 的调度、虚拟内存的映射截获、虚拟 I/O 设备的模拟与转发。
系统引导：从按下电源到内核接管
① 固件（BIOS / UEFI）上电自检、初始化硬件。
② 固件按设定顺序找到启动磁盘，读入引导扇区（主引导记录）里的引导程序到内存并执行它。
③ 引导程序把 OS 内核从磁盘装入内存，把控制权移交内核。
④ 内核自初始化：建中断向量表，初始化内存、进程、文件等各个管理器。
⑤ 内核创建第一个进程（如 init），此后进入登录界面 / 图形界面，系统才算「起来了」。
一句话收：先有引导程序，才有内核——内核不是自己走进内存的。
例题
例 1 · 多道程序设计的利用率（时间轴程序模拟）
两道相同的程序，每道都是「计算 10 ms → I/O 30 ms → 计算 10 ms」，各自使用独立的 I/O 设备。求单道与多道下的总完成时间和 CPU 利用率。
单道：两道串行跑完，总时间 = 2 × 50 = 100 ms，CPU 忙 40 ms → 利用率 40%，其余 60 ms CPU 在干等 I/O。
多道：画时间轴——A 先算（0–10），A 去做 I/O（10–40），B 顶上算（10–20），B 去做 I/O（20–50）；40 时 A 的 I/O 完成、续算（40–50）；50 时 B 续算（50–60）→ 全部完成 60 ms。
CPU 忙的时间仍是 40 ms，利用率 = 40 / 60 ≈ 66.7%（时间轴已用事件模拟程序验证）。
收口：多道没让任何一道程序变快，它让的是 CPU 别闲着——总吞吐上去了。
例 2 · 微内核辨析
关于微内核结构的操作系统，下列说法正确的是（　）。
A. 文件系统运行在内核态　B. 其性能开销主要来自进程间通信与频繁的态切换　C. 把所有系统服务都放进内核以提高可靠性　D. 微内核只负责进程调度
逐项判：A 错——文件系统是用户态服务进程；B ✓——服务拆到用户态后，请求要靠消息传递来回切态；C 说的恰是宏内核；D 漏了通信、地址空间管理、中断处理等基本功能。
答案 B。
微内核的服务跑在用户态——把「服务放进内核」记到微内核头上，恰好记反，那是宏内核。
多道提高的是利用率与吞吐量；单看某一道程序，它的周转时间反而可能变长（要和别人分 CPU）。
引导顺序别倒背：固件自检 → 引导程序进内存 → 内核进内存，内核排在引导程序之后。
「跑在宿主 OS 上」的是第二类 VMM；第一类直接在硬件上，别混。
分层结构效率低是因为层层调用的开销，不是因为「层数多占内存」。
