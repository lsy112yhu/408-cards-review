一、数据结构 （27 条）
1. 算法时空复杂度 · 量级判定与递归式求解 ★★★★★ · 近6年×3

给一段代码判量级、给一个递归式求解、算法设计大题最后一问写复杂度——三件事都看这张卡。此点几乎每道 DS 算法大题都带一问，答法本身就是采分点。

量级判定：只数基本操作执行的次数
片段一（三角循环）：for (i = 1; i <= n; i++) for (j = 1; j <= i; j++) x++;——内层总次数 = 1 + 2 + … + n = n(n + 1) / 2 → Θ(n2)。
片段二（外层翻倍）：i = 1; while (i <= n) i = i * 2;——i 依次取 1, 2, 4, …, 2k，2k ≈ n 时停，循环体执行约 log2n 次 → Θ(log n)。
收口：找重复执行的那条基本操作（比较、赋值、访问结点……），数它执行的次数；只留最高阶项，丢掉低阶项和常数系数。
递归式求解：主方法先行，套不进再展开
T(n) = 2T(n/2) + n
f(n) 与 nlog22 = n 同量级 → Θ(n log n)（归并排序）
T(n) = 2T(n/2) + n2
f(n) 主导 → Θ(n2)
T(n) = T(n/2) + 1
Θ(log n)（折半查找）
展开法例
T(n) = T(n − 1) + n 逐层展开 = n + (n − 1) + … + 1 = n(n + 1) / 2 → Θ(n2)（直接插入最坏）
最好 / 最坏 / 平均：先看题目问的是哪种情形
  • 先以题干条件与具体算法为准：题目明确要求最好、最坏或平均的，按指定口径作答；未注明、且执行次数随输入情形变化时，通常优先给最坏情况，平均情况是常见考点时同时说明平均；执行次数能由输入规模直接确定的，直接求量级，不必分情形。凡谈平均，必须交代输入分布或假设（如随机排列、等概率出现）。
  • 直接插入排序：最好 Θ(n)（已有序）、最坏与平均 Θ(n2)。
  • 快速排序：平均 Θ(n log n)、最坏 Θ(n2)（枢轴每趟都落在端点时）。
空间复杂度：别忘递归栈
  • 只开固定几个变量的原地算法：辅助空间 O(1)。
  • 递归算法的空间 = 递归深度（每层一帧栈）＋额外辅助空间，两者取主导。
  • 归并排序：辅助数组 Θ(n)，递归栈 O(log n)，合计 Θ(n)。
  • 快速排序：空间主要来自递归栈，平均 O(log n)、最坏 O(n)。
大题作答规范（照此写不丢分）
  • ① 先指明基本操作是什么；② 写出执行次数的求和式再化简，不直接蹦结论；③ 结论按题目要求给 O 或 Θ，一般算法设计题写 O 即可，能证得紧界时可补充 Θ；④ 时间、空间分开各写一句；⑤ 要分最好 / 最坏时，把各自的触发条件一并交代。
例题
例 · 看着像 n log n，其实是 n（程序模拟）
count = 0; for (i = 1; i <= n; i *= 2) for (j = 1; j <= i; j++) count++; 求 count 的增长量级。
外层 i 依次取 1, 2, 4, …, 2k，其中 2k ≤ n < 2k+1；内层执行次数恰等于当趟的 i。
count = 1 + 2 + 4 + … + 2k = 2k+1 − 1。
由 2k ≤ n 得 2k+1 ≤ 2n，所以 count 不超过 2n − 1；取 n = 2k 程序实测：n = 1024 时 count = 2047 = 2n − 1，分毫不差。
结论：时间复杂度 Θ(n)——总和由最后一项主导，不是「外层 log n 趟 × 内层 n 次」。
只数循环层数、不数每层实际次数：「外层翻倍」型是最爱挖的坑，内层次数跟着外层涨，总和看末项。
基础三情形版主定理有不能直接套用的情况（如边界情形带对数因子），这时可用扩展版主定理、递归树或展开求和，不可硬套不满足条件的公式。
空间复杂度只写辅助数组、漏掉递归栈：递归深度经常就是答案的主项。
不判情形就机械套默认：先判题目的输入情形与分析口径——执行次数随输入变化又未注明问哪种时，通常先给最坏，平均是考点时一并说明并交代分布假设；次数能直接定下来的直接求量级。
2. 顺序表与链表对比 · 存取与增删复杂度 ★★★★★ · 近6年×4

合辑的数据结构卡从栈与队列起步，线性表本身怎么存——顺序表（Sequential List，顺序表）与链表（Linked List，链表）——没有对比卡。这是王道线性表一章的选择题主战场：同一操作的复杂度结论在两种结构里常常正好相反。

项目顺序表单链表
存储一组地址连续的单元依次存放，逻辑相邻 = 物理相邻任意存储单元，靠指针指示后继，逻辑相邻 ≠ 物理相邻
存取方式随机存取：按下标 O(1) 直达任一元素顺序存取：找第 i 个元素须从头逐个顺链，O(n)
按值查找无序时 O(n)（逐个比）；有序时折半查找 O(log n)O(n)
插入 / 删除须移动元素腾位 / 补位，平均移动约 n / 2 或 (n − 1) / 2 个，O(n)已知操作位置的指针时只改指针，O(1)；但找前驱 / 按序号定位仍是 O(n)
存储密度= 1，无指针开销< 1，每个结点多付一个指针域
扩容静态分配容量固定，存满后无法直接扩容；动态分配在容量不足时可重新申请更大的连续空间并复制原有元素逐结点申请、用完释放，长度天然可变
例题（枚举验算）：长度 n = 10 的顺序表：
插入一个元素，合法插入位置共 11 个（第 1 ～ 11 位），各位置须移动的元素个数依次为 10, 9, …, 1, 0，平均 = 55 ÷ 11 = 5 = n / 2
删除一个元素，合法位置共 10 个，移动个数依次为 9, 8, …, 0，平均 = 45 ÷ 10 = 4.5 = (n − 1) / 2 ✓
推广：长度为 n 时插入平均移动 n / 2 个、删除平均移动 (n − 1) / 2 个（均设各位置等概率）。
坑：
① 「链表插入删除是 O(1)」有前提：已经拿到操作位置（或其前驱）的指针；若题目给的是「在第 i 个位置插入」，定位本身 O(n)，整体仍是 O(n)。
② 单链表中删除结点 p 本身（只给 p、不给前驱）不能直接 O(1) 摘除：常规做法须从头找前驱 O(n)；把后继的值拷进 p 再删后继的变通法对尾结点无后继可用、且改变了结点身份，选项若笼统说「只给 p 就能 O(1) 删除」要警惕。
③ 顺序表的「随机存取 O(1)」只对按下标 / 按序号成立，按值查找无序时仍是 O(n)。
④ 双链表在已知结点指针时可经前驱指针 O(1) 找到前驱；但循环单链表找前驱通常仍须沿链遍历、O(n)，且链表改变不了「顺序存取」这一本质，别与顺序表混答。
3. 栈与队列经典应用 ★★★★★ · 近6年×4
结构经典应用
栈括号匹配、表达式求值、递归、进制转换、迷宫求解
队列层次遍历、BFS、打印缓冲区、CPU 调度
  • 用两个栈模拟队列：入队 O(1)，出队均摊 O(1)。
表达式转换与求值（栈的经典用法）
中缀 → 后缀：从左到右扫，操作数直接输出；运算符入栈前，先把栈顶优先级 ≥ 它的运算符（「(」除外）依次弹出输出、再入栈；遇「(」直接入栈，遇「)」把栈顶弹到「(」为止（「(」只出栈、不输出）；扫完后把栈中运算符依次弹出输出。
后缀表达式求值：扫表达式，操作数入栈；遇运算符，弹出栈顶两个数（先弹出的那个是右操作数）做运算、结果入栈；扫完后栈中唯一的数就是结果。
中缀直接求值（双栈法）：一个操作数栈 + 一个运算符栈，运算符出栈时立刻取两个操作数运算、结果压回操作数栈。
4. 循环队列 · 判空判满与元素个数 ★★★★ · 近6年×1

合辑《栈与队列经典应用》只讲了队列拿来干什么，没讲队列本身怎么实现。顺序队列假溢出、循环队列（Circular Queue，循环队列）判空判满，是选择题里反复出现的固定题型，公式记混一个符号整题皆错。

约定（王道口径，题干另有定义时以题干为准）：数组大小为 MaxSize，下标 0 ～ MaxSize − 1，空间当作一个环。

队头指针 front 在队列非空时指向队头元素（队空时不存在队头元素）

队尾指针 rear 指向下一次入队要写入的位置（牺牲一格法下该位置恒为空位；采用下文 size / tag 法且队列已满时，该位置不一定为空）

入队：先把 x 存入 Q[rear]，再 rear = (rear + 1) % MaxSize

出队：先取 Q[front]，再 front = (front + 1) % MaxSize。

牺牲一个存储单元法（最常考）：故意空出一格不用，以区分空与满。

状态判据
队空front == rear
队满(rear + 1) % MaxSize == front
元素个数(rear − front + MaxSize) % MaxSize
最多可存MaxSize − 1 个元素

不牺牲一格的另两法（见到题先确认用的是哪套）：① 增设 size 变量记元素个数：入队 size++、出队 size−−，size == 0 为空、size == MaxSize 为满

② 增设 tag 标志：最近一次操作是入队且结果 front == rear 判满，最近一次是出队且 front == rear 判空。

两法都不浪费空间，但判据与上表不同，不能混用。

例题（程序模拟验算）：MaxSize = 5 的循环队列，初始 front = rear = 0。
依次入队 A、B、C：rear 走到 3，元素个数 = (3 − 0 + 5) % 5 = 3。
出队两次（取出 A、B）：front 走到 2。
再依次入队 D、E、F：rear 从 3 经 4 绕回 0、再到 1
此时元素个数 = (1 − 2 + 5) % 5 = 4，且 (rear + 1) % 5 = 2 == front → 队满，队列内容依次为 C、D、E、F ✓（绕圈与判满均经模拟核对）。
附指针小题：MaxSize = 6、front = 1、rear = 4 时，元素个数 = (4 − 1 + 6) % 6 = 3。
坑：
① 有的教材约定 rear 指向队尾元素本身，判据随之全变——做题第一步先看题干对 front / rear 的定义，别背死一套公式套所有题。
② 元素个数公式别漏「+ MaxSize 再取模」：rear < front 时直接 rear − front 会得出负数。
③ 牺牲一格法里数组开 MaxSize 只能存 MaxSize − 1 个，问「最多存几个」答错一位是经典丢分点。
④ 链式队列不存在绕圈与假溢出，别把循环队列判据往链队列上套。
5. 特殊矩阵与稀疏矩阵的压缩存储 ★★★

合辑没有一张讲矩阵怎么存。这一类题不难、但公式全靠现推最耗时间：把对称、三角、三对角三种特殊矩阵的存储量与地址公式，以及稀疏矩阵的三元组与快速转置，一次记清。

压缩存储（Compressed Storage）总原则：按矩阵的结构规律分配存储：多个值相同的元素只分配一个存储空间，值为 0 的元素不分配空间，从而减少冗余存储。

下表前三类（对称 / 三角 / 三对角）设矩阵为 n 阶方阵、元素下标从 1 起、压缩数组 B 下标从 0 起；稀疏矩阵不限于方阵。

矩阵存法存储量地址公式（B 的下标 k）
对称矩阵只存下三角（含对角线），按行优先n(n + 1) / 2i ≥ j 时 k = i(i − 1) / 2 + j − 1；i < j 时取 aji 的位置
三角矩阵只存下（或上）三角 + 对角线外常数 c 另存 1 份n(n + 1) / 2 + 1下三角同对称矩阵；常数 c 存在数组最后一格
三对角矩阵（带状）只存 |i − j| ≤ 1 的三条对角带，按行优先3n − 2k = 2i + j − 3（仅对带内元素成立）
稀疏矩阵非零元个数 t 远小于 n2：存三元组（行号， 列号， 值）3t（顺序三元组表）无地址公式；顺序访问靠扫描；十字链表便于按行、按列遍历与动态修改非零元，不保证任意元素 O(1) 随机访问

稀疏矩阵转置 · 快速转置法：普通转置对每列扫描一遍三元组表，时间 O(列数 × t)。

快速转置先统计原矩阵每列的非零元个数 num[col]，

再算每列首个非零元在转置三元组表中的位置 cpot[col]（cpot[1] = 1；cpot[col] = cpot[col − 1] + num[col − 1]），

然后一趟扫描原三元组表、按 cpot 直接落位并递增，时间 O(列数 + t)。

例题（程序验算）：① 三对角：n = 100 → 存储量 = 3 × 100 − 2 = 298
元素 a50,51（带内，|50 − 51| = 1 ✓）→ k = 2 × 50 + 51 − 3 = 148，即存入 B[148]。
② 快速转置：6 行 7 列稀疏矩阵，非零元三元组（按行优先）：(1,2,12), (1,3,9), (3,1,−3), (3,6,14), (4,3,24), (5,2,18), (6,1,15), (6,4,−7)。
统计得 num = [2, 2, 2, 1, 0, 1, 0]（第 1～7 列）。
cpot 逐列递推代入（cpot[col] = cpot[col − 1] + num[col − 1]）：cpot[1] = 1；cpot[2] = 1 + 2 = 3；cpot[3] = 3 + 2 = 5；cpot[4] = 5 + 2 = 7；cpot[5] = 7 + 1 = 8；cpot[6] = 8 + 0 = 8（第 5 列没有非零元，第 6 列与第 5 列同起点）；cpot[7] = 8 + 1 = 9 → cpot = [1, 3, 5, 7, 8, 8, 9]。
再一趟扫描、逐个落位（看原三元组的列号查 cpot，落位后该列 cpot + 1）：(1,2,12) → 第 3 格 (2,1,12)，cpot[2] → 4；(1,3,9) → 第 5 格 (3,1,9)，cpot[3] → 6；(3,1,−3) → 第 1 格 (1,3,−3)，cpot[1] → 2；(3,6,14) → 第 8 格 (6,3,14)，cpot[6] → 9；(4,3,24) → 第 6 格 (3,4,24)，cpot[3] → 7；(5,2,18) → 第 4 格 (2,5,18)，cpot[2] → 5；(6,1,15) → 第 2 格 (1,6,15)，cpot[1] → 3；(6,4,−7) → 第 7 格 (4,6,−7)，cpot[4] → 8。8 格恰好填满。
一趟落位后转置三元组（按行优先）为：(1,3,−3), (1,6,15), (2,1,12), (2,5,18), (3,1,9), (3,4,24), (4,6,−7), (6,3,14) ✓（逐元核对：行列互换、值不变、按新行号有序）。
坑：
① 三套公式都建立在「下标从 1 起、B 从 0 起」之上：题干若用 0 起下标或 B 从 1 起，公式整体差一位，先认题干再套。
② 三对角公式只对带内元素有意义：|i − j| > 1 的元素根本没存，不要硬套公式算出一个位置。
③ cpot[col] 是「位置」不是「个数」，且每落一位要 +1 更新，别拿原值重复落位。
④ 对称矩阵 aij（i < j）查的是 aji 的格子，不是另存了一份（本卡按存下三角写；题目若按上三角存储，查法方向正好相反、下标公式也不同，不能直接照搬下三角公式，先认存法再套公式）。
6. KMP（克努特–莫里斯–普拉特模式匹配算法） 串模式匹配 · next 数组与 nextval ★★★ · 近6年×1

核心思想：匹配失配时主串指针 i 不回退，只按 next 数组回退模式串指针，跳过已知不可能匹配的位置。

复杂度：求 next 为 O(m)，匹配为 O(n)，总计 O(n + m)，空间 O(m)；朴素 BF 最坏 O(n·m)。

例（next 与 nextval 全计算）：模式串 P = ABABAC，用 408 / 王道口径（下标 1 起）：next[1] = 0，next[j] = 「P 前 j − 1 个字符的最长相等真前缀与真后缀长度」+ 1。逐位算：
j1 (A)2 (B)3 (A)4 (B)5 (A)6 (C)
考察串—AABABAABABABABA
最长相等前后缀—001 (A)2 (AB)3 (ABA)
next[j]011234
nextval[j]010104
nextval 是 next 的「防白比」优化：若 P[j] = P[next[j]]，失配跳过去还会再失配，索性一步跳到底，nextval[j] = nextval[next[j]]；不同则 nextval[j] = next[j]。
如 j = 5：P[5] = A，P[next[5]] = P[3] = A，相同 → nextval[5] = nextval[3]；而 P[3] = A = P[1]，nextval[3] = nextval[1] = 0，故 nextval[5] = 0。
j = 6：P[6] = C ≠ P[4] = B → nextval[6] = next[6] = 4。
手算口诀：在失配位置之前划一条分界线，将模式串逐步后退，直到分界线之前的前缀能与刚划过的后缀对齐，此时 j 指向哪里，next 值就是多少。
滑动规则：失配时主串指针 i 不动，模式串右移 j − next[j] 位。

另有「长度定义」（下标 0 起）：next 值即最长相等真前后缀长度本身，如 ABABAC 依次为 0, 0, 1, 2, 3, 0。两套口径数值整体差 1，做题先认题干给的定义。

坑：
不同教材下标起点不同（0 起 / 1 起），next 数值会整体差 1。做题先认题干给的 next 定义，不要硬背一组数字。

11. 线索二叉树 · 线索化与找前驱 / 后继 ★★★★★ · 近6年×4

动机：n 个结点的二叉链表有 n + 1 个空指针，把空指针利用起来指向前驱 / 后继，就不用再递归找遍历顺序。

结点加两个标志：ltag = 0 表示左孩子、= 1 表示左线索；rtag 同理。

按某种遍历顺序线索化后，中序线索树可不借助栈遍历。

中序线索树找法
找后继rtag = 1 时右指针即后继；rtag = 0 时后继是右子树中最左下的结点
找前驱ltag = 1 时左指针即前驱；ltag = 0 时前驱是左子树中最右下的结点
记忆：先序线索找后继要小心——先序后继可能是左孩子或右孩子，左子树存在时后继必在左子树，不能只按“右指针”判断；中序最规整，是考题主力。
后序线索树找后继（最麻烦）：结点是父结点的右孩子 → 后继就是父结点；结点是父结点的左孩子且父无右孩子 → 后继也是父结点；结点是父的左孩子且父有右子树 → 后继是父的右子树中后序遍历的第一个结点（从右孩子出发，能向左就向左、否则向右，走到的最左下结点）。根结点无后继。

15. 最小生成树对比 · Prim vs Kruskal ★★★★
项目Prim（点出发）Kruskal（边出发）
做法从任一顶点长出一棵树，每步加「树内—树外」最小边边按权从小到大排序，依次加不成环的边（并查集判环）
时间复杂度邻接矩阵 O(V2)；邻接表 + 堆 O(E log V)排序主导 O(E log E) = O(E log V)
适合图稠密图稀疏图
停止条件连通图：共加 V − 1 条边；非连通图只能得到最小生成森林
例（同一张图，两种算法）
无向图边（端点，权）：(1,2)6、(1,3)1、(1,4)5、(2,3)5、(2,5)3、(3,4)5、(3,5)6、(3,6)4、(4,6)2、(5,6)6。
Prim（从 1 出发，每步在「已收顶点 ↔ 未收顶点」的边里挑最小）：先收 (1,3)=1。
候选里最小是 (3,6)=4。
再 (6,4)=2。
再 (3,2)=5。
最后 (2,5)=3。
选中边的权依次为 1、4、2、5、3，总权 15。
Kruskal（边按权从小到大，能连不同集合就要）：(1,3)=1 ✓。
(4,6)=2 ✓。
(2,5)=3 ✓。
(3,6)=4 ✓（合并两组）。
(1,4)=5 ✗（已在同一集合，加了成环，跳过）。
(2,3)=5 ✓。
共 5 条边，总权 15。
本例两条路线选边顺序不同，但最终选中的边集相同、得到同一棵树。
一般规律是：最小生成树的权和唯一，树本身可以不唯一（存在可替代的等权边时）。
另：求最小生成树的前提是图连通。
非连通图没有覆盖全部顶点的生成树，两种算法都只能得到最小生成森林——Kruskal 跑完自然成森林，Prim 需对每个连通分量各启动一次。

17. 拓扑排序（AOV 网：顶点活动网） ★★★★★ · 近6年×4

做法只有三步：

① 选一个入度为 0 的顶点输出。

② 删掉它和它的全部出边（邻接点入度减 1）。

③ 重复，直到输出全部顶点，或无入度为 0 的顶点可选（说明有环）。

跟着例子走：

例（拓扑排序全过程）
有向边：1→3、2→3、2→4、3→5、4→5、5→6、1→2。初始入度：1: 0、2: 1、3: 2、4: 1、5: 2、6: 1。
输出 1 → 2、3 入度减 1（2 变 0）。
输出 2 → 3、4 入度减 1（都变 0）。
输出 3 → 5 入度变 1。
输出 4 → 5 入度变 0。
输出 5 → 6 入度变 0。
输出 6。
得到序列 1, 2, 3, 4, 5, 6。
第 3 步时 3、4 同时可选，先输出 4 也合法（1, 2, 4, 3, 5, 6）——拓扑序列一般不唯一。
若中途输出数 < 顶点总数就无点可选，说明网中有环、工程不可行。
一个现成的判定：若有向图按顶点编号写出的邻接矩阵下三角全零（所有边都从小编号指向大编号），则图必无环，且 1, 2, …, n 本身就是一个拓扑序列。反过来不成立——有拓扑序不代表矩阵下三角全零，拓扑序也不一定唯一。
18. 关键路径（AOE 网：边活动网） ★★★★★ · 近6年×4

20. 二叉排序树 BST · 查找 / 插入 / 删除 ★★★★ · 近6年×3

定义：左子树所有关键字 < 根，右子树所有关键字 > 根；中序遍历得到有序序列。

查找从根出发，比当前结点小走左、大走右，相等即命中，走到空指针即失败。

操作做法
插入按查找路径走到空指针处挂上新结点；已存在相同关键字则不插入
删除叶子直接删，父结点指针置空
删除仅一子结点用其孩子顶替它
删除有两子结点用中序前驱（左子树最大）或中序后继（右子树最小）顶替，再删去那个前驱 / 后继结点
时间：平均 O(log n)，最坏退化成单链 O(n)。删除后仍须保持 BST 性质。
“用前驱 / 后继顶替”是大题最常考的点。
图：二叉排序树示例：根 4，左子树 2（左 1、右 3），右子 5；中序序列 1, 2, 3, 4, 5。
易错：删除两子结点时只换关键字值、不动结构位置，再去删前驱 / 后继——不要把整棵子树搬过去。

23. B 树 vs B+ 树对比 ★★★★★ · 近6年×4

《B 树性质》讲 B 树的结构性质与高度，本卡补它缺的另一半：B+ 树与 B 树的成对区别。
B 树考性质与高度，B+ 树考“数据只在叶层、叶链表”带来的查找与范围查询差异。

对比项B 树B+ 树
关键字分布分布在整棵树中，每个关键字只出现一次全部关键字都在叶层；分支结点关键字是子结点关键字的副本，只起索引作用，不带记录指针
分支结点n 棵子树 → n − 1 个关键字n 棵子树 → n 个关键字（王道口径）；分支结点关键字常取子结点最大关键字作分界
叶结点叶层是不含关键字的失败结点，查找失败落到此处叶层含全部关键字与记录指针，且按关键字从小到大用链表链接
查找终点可能在分支结点命中，提前结束无论如何都要走到叶层，查找长度更稳定
顺序 / 范围查找需中序遍历整棵树定位到起始叶后沿叶链表顺序扫，范围查找快
插入分裂满结点分裂，中间关键字上移到父结点叶分裂时中间关键字仍保留在叶层，父结点只多一个索引副本
删除删分支结点关键字需用前驱 / 后继替换只删叶层关键字；分支索引失效时更新为新的分界关键字，叶下限不足时向兄弟借或合并，合并后父结点索引项相应删除
  • 共同点：所有叶在同一层、平衡；m 阶时除根外每个结点至少有 ⌈m / 2⌉ 棵子树；查找时间复杂度均为 O(log n)。
  • 适用：B+ 树是数据库与文件系统索引的主流选择，范围查询多时优势明显；只考单点查找时两者差距不大。

例（范围查找）：叶链表为 …[10, 20] → [30, 40] → [50, 60]…，查 15～35：先定位到含 20 的叶，沿链表读到含 30 的叶，遇 40 超界即停，不必回溯到根再中序遍历。
易错：不同教材对叶结点关键字上限的表述有差异（m − 1 还是 m），做题以题干给的阶定义为准；不要把 B+ 树的分支关键字当成“多存了一份数据”——数据只在叶层，分支结点只有索引。

分块查找（表长 n 分 b 块、每块 s 个，块间有序、块内无序；ASL = 索引表 ASL + 块内 ASL）：

索引、块内均顺序查找：ASL(成功) = b+12 + s+12 = s2 + 2s + n2s，当 s = √n 时最小，为 √n + 1。
  • 索引改用折半查找时：ASL = 折半查索引的 ASL + s+12；其中折半部分的平均 ASL 用近似式 log2(b+1) − 1（满判定树近似）。
  • ⌈log2(b+1)⌉ 是查索引的最坏比较次数（判定树高度），不要把它当成平均 ASL。
散列表

（装填因子 α = nm）。

实际 ASL 取决于散列函数、冲突处理方法、装填因子 α 以及关键字分布（聚集程度），必须按具体探测过程逐个计算。

只有在均匀散列假设下，期望 ASL 才只由 α 决定。

  • 失败 ASL：对每个初始地址算到判定失败为止的比较次数，求和 ÷ 失败入口个数 = 散列函数值域大小（除留余数法即模 p），不是表长、不是 n+1。
  • 线性探测：逐个后探，遇到第一个空单元即失败，比较次数算到空单元为止（含空单元）。

① 散列失败 ASL 的分母是散列函数的值域大小（除留余数法就是那个模 p），这是最常见的丢分点。
② 另：线性探测失败次数是否把「探到空单元的那次」算作一次比较，个别题目口径不同，以题目说明为准。

26. 堆操作与堆排序过程 ★★★★★ · 近6年×3

合辑《排序全家福》只给了堆排序的复杂度与稳定性，本卡补它缺的过程：堆是什么、插入怎么上浮、删顶怎么下沉、建堆为什么是 O(n)。堆排序大题考的就是这套手算过程。

定义：堆（Heap）是采用顺序存储的完全二叉树，且满足父子有序。

大根堆（Max Heap）父结点 ≥ 子结点，根即最大值。

小根堆（Min Heap）父结点 ≤ 子结点，根即最小值。

堆常用于实现优先队列（Priority Queue）：取最值只需 O(1) 看堆顶。

下标换算（先认题干从几起）：

下标 1 起：父结点 ⌊i/2⌋，左孩子 2i，右孩子 2i+1。

下标 0 起：父结点 ⌊(i−1)/2⌋，左孩子 2i+1，右孩子 2i+2。

操作做法时间
插入（上浮）新元素放队尾（数组末尾），与父结点比较，违背堆序则交换上浮，直至满足堆序或到达根O(log n)
删除堆顶（下沉）堆顶与队尾元素交换，删去队尾（即原堆顶），新堆顶与较大（大根堆）/ 较小（小根堆）的孩子比较，违背则交换下沉，直至满足堆序O(log n)
建堆从最后一个非叶结点（下标 1 起为 ⌊n/2⌋）开始，从后向前对每个子树做下沉O(n)
堆排序建堆后重复：堆顶与堆内末尾交换（该元素落到最终位置，堆规模减 1），再对新堆顶下沉O(n log n)，空间 O(1)，不稳定

坑：① 堆不是二叉排序树（Binary Search Tree）：只保证父子有序，兄弟之间无序，不要用“左小右大”去判堆。② 升序排序用大根堆（每轮最大值沉底），降序用小根堆，方向一反全错。③ 建堆是 O(n) 不是 O(n log n)：高层结点数量少、但每个可下沉的距离长，底层结点数量多、但下沉距离短，两者相消，逐层求和收敛到 O(n)；逐个插入建堆才是 O(n log n)。④ 堆排序不稳定：堆顶与末尾交换会打乱相等元素的相对顺序。
27. 外部排序 · 置换-选择、多路归并与败者树 ★★★★ · 近6年×3

合辑《排序全家福》讲的全是内部排序，前提是数据能一次装进内存。文件大到装不下时换的是另一套打法：先分段排序写回外存，再把各段归并起来——这套流程本身就是考点。

总框架（归并范式）：

① 生成初始归并段：把文件分批读入内存排序、写回外存，得到若干有序段。

② 多路归并：一趟同时归并 k 个段中的记录，直到只剩一个有序段。

外部排序的总代价主要由外存读写次数决定（408 口径），不是比较次数。

置换-选择排序（Replacement Selection，生成初始段）：工作区能放 w 条记录。

工作区内分活动区（小根堆）与冻结区：不断输出堆顶，同时从输入文件补进一条新记录——新记录 ≥ 刚输出的记录就进活动区（能接进本段），< 刚输出的记录就进冻结区（留给下一段）。

活动区空时，本段结束，冻结区整体解冻成为下一段的活动区。

结果：各段长度不等，在随机输入下平均段长约为 2w，比「读满 w 条排一次」的定长分段（段长恰 w）段数减半。

多路平衡归并与趟数：设初始归并段数为 r、每趟最多 k 路归并，则归并趟数 = ⌈logk r⌉（最后一趟的路数可以小于 k）。

每趟要把全部数据读一遍、写一遍，故外存块读写总次数 = 2 × 文件总块数 ×（归并趟数 + 1）（+1 是生成初始归并段的那一趟）。

增大 k 能减少趟数，但每输出一条记录要在 k 个段的当前记录中选最小：逐个扫描要比较 k − 1 次。

用败者树（Loser Tree）后，初始建树完成、每输出一条记录并补入新记录时，沿败者树调整只需 ⌈log2 k⌉ 次比较，总比较次数约 (n − 1) × ⌈log2 k⌉，比较代价只随 log k 增长——这正是「k 可以放心加大」的前提。

但 k 还受另一头限制：k 路归并需要 k 个输入缓冲区，缓冲区总数有限时 k 有上限。

例题（程序验算）
① 置换-选择：工作区 w = 4，输入序列 51, 12, 49, 88, 25, 63, 37, 76, 44, 90, 18, 55。
按上法模拟：初始装入 51, 12, 49, 88 建小根堆，活动区 = {12, 49, 51, 88}，冻结区为空。下面逐条走（每步先出堆顶、再补一条）：
出 12 → 补 25：25 ≥ 12 能续上本段，进活动区 {25, 49, 51, 88}。
出 25 → 补 63：63 ≥ 25，进活动区 {49, 51, 63, 88}。
出 49 → 补 37：37 < 49，接不上本段，进冻结区 {37}；活动区余 {51, 63, 88}。
出 51 → 补 76：76 ≥ 51，进活动区 {63, 76, 88}；冻结区仍 {37}。
出 63 → 补 44：44 < 63，进冻结区 {37, 44}；活动区余 {76, 88}。
出 76 → 补 90：90 ≥ 76，进活动区 {88, 90}；冻结区仍 {37, 44}。
出 88 → 补 18：18 < 88，进冻结区 {18, 37, 44}；活动区余 {90}。
出 90 → 补 55：55 < 90，进冻结区 {18, 37, 44, 55}；活动区已空，本段结束——归并段 1：12, 25, 49, 51, 63, 76, 88, 90（长 8 = 2w）。
冻结区整体解冻成新活动区 {18, 37, 44, 55}，输入文件已读完、无新记录补入，依次出堆即归并段 2：18, 37, 44, 55（长 4）。
定长分段本应是 3 段，置换-选择只用 2 段。
② 读写次数：文件共 100 个块，生成初始段时工作区可放 3 块（归并阶段另有足够缓冲，支持 4 个输入缓冲块和 1 个输出缓冲块），置换-选择平均段长 2 × 3 = 6 块 → 初始段数 ≈ ⌈100 / 6⌉ = 17。
做 4 路归并，趟数 = ⌈log4 17⌉ = 3（42 = 16 < 17 ≤ 64 = 43）。
按实际形成 17 个初始段、每趟完整读写全部 100 块计，块读写总次数 = 2 × 100 × (3 + 1) = 800 次。
坑
① 「平均段长 2w」是随机输入下的期望，不是每段都恰好 2w——输入本身有序时一段到底，逆序时每段恰为 w。
② 归并趟数公式里的 r 是初始归并段数，不是记录总数也不是块数，代错数整题皆错。
③ k 不是越大越好：败者树只压住了比较代价，输入缓冲区随 k 线性增加，且并行读入的段越多、单段缓冲越小，外存访问反而可能变碎。
④ 败者树记的是「败者」、胜者向上继续比，别与胜者树混写。
二、计算机组成原理 （26 条）
1. 计算机系统层次结构 ★★★★ · 近6年×2

定位：CO 第 1 章系统概述（薄卡）。这一考点只考三件事：层次怎么分、同一功能为什么软硬件都能做、几个「字长」为什么不能混。题量不大，但每个都是送分与丢分只差一个概念的判断题。下面用同一条语句从顶层一路沉到底层，把三件事一次带出。

一、一条语句的下沉之旅：z = x + y 经过的每一层

设 int x、y、z 是内存中的三个整型变量，C 语句 z = x + y; 在每一层眼里长得完全不同——每一层都是一个「虚拟机器」：只认本层的语言，靠翻译或解释把本层程序变成下一层能执行的动作。

高级语言级
你看到的是 z = x + y; ——变量有名字、类型。靠编译：编译程序把整个源程序一次译成汇编 / 机器语言程序，再执行。
汇编语言级
变成三条符号指令：LOAD R1, x（取 x 进寄存器）；ADD R1, y（与 y 相加）；STORE R1, z（存回 z）。靠汇编：汇编程序把符号指令逐条译成二进制机器指令。
操作系统级
介于汇编与机器级之间的一层：程序要用输入输出、文件等资源时不直接碰硬件，而是发系统调用由操作系统代办。本例纯算术不经过它，但它在层次图里有正式位置，别漏画。
传统机器级
只剩二进制机器指令：操作码指明「加」，地址码指明操作数在哪。CPU 取指、译码、执行，一条指令一个指令周期——这一层的语言就是指令系统。
微程序机器级
一条机器指令再被拆成一串微指令：每条微指令发出一组微命令，直接开合数据通路上的门电路，把寄存器和 ALU 接通一次。这一层不必展开过深，只需知道：机器指令是被「更小的程序」解释执行的，这是微程序控制器的地盘（详见《控制器对比》卡）。

往下再沉就是数字逻辑电路，没有新的「语言层」了。各层之间只有两种衔接方式：翻译（先把高层程序整体译成低层程序再执行，如编译、汇编）和解释（逐条把高层指令译成低层动作并立即执行，不生成完整译本，如微指令解释机器指令）。

二、软硬件逻辑等价：同一件事，谁做都行

还是这条加法链里的「相加」：乘法运算可以交给硬件——CPU 里放一个乘法器，一条乘法指令直接出结果；也可以不放乘法器，改用软件——写一段「移位 + 相加」的循环，用已有的加法和移位指令凑出乘法。两种实现对上层程序员逻辑上完全等价，程序照样算出积，区别只在速度与成本。

这就是软硬件逻辑等价：任何操作都能由软件实现，也能由硬件实现，软硬件的分界不是逻辑分界、而是性能与成本的分界，并且可以上下移动——常用功能往硬件沉（快），少用功能留给软件（省）。固件就是这条界线上的中间态：把软件固化进只读存储器，形态是程序、干活像硬件。

三、字长四兄弟：只有一个由寄存器位数定
机器字长（= 字长）
CPU 一次能并行处理的二进制位数，由通用寄存器位数 / ALU 位数决定。说「32 位机」指的就是它。
数据通路宽度
CPU 内部数据总线一次能传送的位数。内部通路通常与机器字长相等；但外部数据总线可以更窄——字还是 32 位，只是要分次送出（理想传送次数见例题）。
指令字长
一条指令占的位数，由指令格式定，与机器字长彼此独立：32 位机完全可以用 16 位的定长指令。
存储字长
一个存储单元存放的位数，由存储器组织定，同样独立：它决定取一个存储字拿到几位，不决定 CPU 一次算几位。
例题
例 · 字长认亲（真题风格，程序验算）
某机：通用寄存器 32 位、ALU 32 位、内部数据通路 32 位；外部数据总线 16 位、指令字长 16 位、存储字长 16 位。问：(1) 该机机器字长是多少位、合多少字节；(2) 把一个机器字经外部数据总线送到外设要几拍；(3) 一个 64 位数据在 CPU 内部处理算几个机器字、经外部总线送出要几拍。
推导：(1) 机器字长看通用寄存器 / ALU 位数 = 32 位 = 4 字节。题干里的三个 16 位全是干扰：外部总线、指令字长、存储字长都不参与定字长。
(2) 一个机器字 32 位，外部总线每次最多送 16 位：32 ÷ 16 = 2 次。这是忽略协议开销、每拍传满总线宽度的理想传送次数。字长没变，只是传送被拆开——这正是「外部通路可以窄于字长」的含义。
(3) 64 位数据相当于 2 个 32 位机器字；若只考虑 32 位内部数据通路上的纯数据传送，理论上至少分 2 次传输；实际处理所需周期不能仅由机器字长确定。经外部总线送出时，在忽略协议开销、每拍传满总线宽度的理想模型下，传送次数为 64 ÷ 16 = 4 次（以上计数均经脚本验算）。
坑：
① 「多少位机」只认机器字长（寄存器 / ALU 位数）。选项拿指令字长、存储字长或外部总线宽度冒充字长，是本考点最固定的干扰设计。
② 层次是逻辑上的虚拟机器，不是把机器物理拆成五层：除了微程序级与电路，下面的层大多是软件。「某功能只能由硬件实现」这类说法错在违背软硬件逻辑等价。
③ 翻译与解释别混：编译、汇编是翻译（先生成低层程序）；微指令执行机器指令是解释（逐条译、立即做）。问「哪种方式不生成目标程序」选解释。
④ 操作系统级有正式位置（在传统机器级之上、汇编级之下），画层次图漏掉它，或把它排到高级语言之上，都是常见错位。
2. CPU 性能指标 · CPI / MIPS 与执行时间 ★★★★★ · 近6年×4

一个程序到底跑多久、两种机器谁快——靠的就是这一卡。

CPI（每条指令的时钟周期数）、主频、MIPS（百万条指令每秒），是每年都可能出现的公式计算题。

核心公式
执行时间
TCPU = 指令条数 IC × CPI × 时钟周期 Tc　＝ IC × CPI ÷ f（f 为主频）
加权 CPI
平均 CPI = Σ（各类指令 CPIi × 该类指令占比）
MIPS
MIPS = f ÷ (CPI × 106)　＝ IC ÷ (TCPU × 106)（f 以 Hz 计）
三者知二求一：主频管「周期多短」、CPI 管「每条指令占几个周期」、IC 管「一共多少条」。
例题
例 1 · 基本公式（两式互证）
某机主频 2.5 GHz，程序含 5 × 108 条指令，平均 CPI = 2。
时钟周期 = 1 ÷ 2.5 GHz = 0.4 ns
执行时间 = 5 × 108 × 2 ÷ (2.5 × 109) = 0.4 s
MIPS = 2500 ÷ 2 = 1250
换个算法验算：IC ÷ 执行时间 = 5 × 108 ÷ 0.4 = 1250 MIPS，一致 ✓
例 2 · 加权 CPI
某程序：算术指令占 60%、CPI = 1；访存指令占 20%、CPI = 4；分支指令占 20%、CPI = 3。
平均 CPI = 0.6 × 1 + 0.2 × 4 + 0.2 × 3 = 2.0
该程序共 108 条指令，在主频 2 GHz 的机器上执行：
时间 = 108 × 2.0 ÷ (2 × 109) = 0.1 s ✓
坑
① 主频高 ≠ 一定快：执行时间由 IC、CPI、主频三者共同决定，只比主频是经典错误选项。
② MIPS 不能跨指令集比快慢：同一机器跑不同程序 MIPS 不同；一条复杂指令干的活可能顶几条简单指令。
③ 加权 CPI 用的是各类指令的条数占比，不是时间占比；题目给各类条数时，先求总条数再算权重。
④ 单位先统一：GHz 是 109 Hz、MIPS 里的 M 是 106，代公式前先换算，别在指数上丢分。

4. 补码运算规则 ★★★★★ · 近6年×6

求 [−X]补：[X]补 连同符号位取反加 1。

溢出判断（双符号位法）：00 正确（正）、11 正确（负）、01 正溢出、10 负溢出。

如 +11 与 +13 用双符号位相加：001011 + 001101 = 011000，双符号位 01 → 正溢出（一眼可判，不用看数值位）。

Booth 算法（补码一位乘）：[X×Y]补 不能由 [X]补 与 [Y]补 直接相乘得到，要走部分积递推。

看乘数相邻两位之差决定加 [X]补、加 [−X]补 还是加 0，再把（部分积， 乘数）整体算术右移一位。

符号位全程参与运算。

下面用定点整数完整走一遍。小数双符号位版与整数版的核心 Booth 判断及加减规则相同，但操作步数和最后移位安排不同（见本卡末注），不能混用：

例（Booth 全过程）
X = −13（[X]补 = 10011，[−X]补 = 01101），Y = +11（[Y]补 = 01011）。
部分积 A 初值 00000，附加位 Q−1 = 0。
每步看（Q 最低位， Q−1）这一对：(1,0) 加 [−X]补，(0,1) 加 [X]补，(0,0)/(1,1) 加 0，随后（A, Q）算术右移。
步判断位操作右移后 A右移后 QQ−1
1(1, 0)A += [−X]补 → 0110100110101011
2(1, 1)A += 000011010101
3(0, 1)A += [X]补 → 1011011011001010
4(1, 0)A += [−X]补 → 0100000100000101
5(0, 1)A += [X]补 → 1011111011100010
乘数 5 位就走 5 步。
结果 = A 拼 Q = 11011 10001 = [−143]补。验算：−13 × 11 = −143 ✓。
注意：整数单符号位版与小数双符号位版的轮数和移位安排不同，不要混用。
整数版执行 n 轮、每轮均移位。
小数双符号位版（见《定点数乘除运算》卡）通常执行 n + 1 步、最后一步只加减不移位。
5. 定点数乘除运算 · 原码一位乘 / Booth 算法 / 不恢复余数除法 ★★★★★ · 近6年×6

《补码运算规则》只给了 Booth 算法（布斯算法）的一句话判位规则，本卡补齐完整手算流程，并补上原码一位乘与除法——三者是计组计算大题的常客，符号与移位方式一混就全错。

原码一位乘：符号位异或单独定，数值部分单独算。

部分积初值为 0。

每步看乘数最低位：为 1 则加被乘数绝对值，为 0 则加 0。

然后部分积与乘数整体逻辑右移一位。

数值位共 n 位就做 n 次。

例（原码一位乘）
被乘数绝对值 0.11012 = 13/16，乘数绝对值 0.10112 = 11/16。
寄存器里参与运算的是尾数位串 1101、1011，各步加法按位串进行。
部分积初值 00000，乘数 1011。
步 1：最低位 1 → 加 01101 得 01101 → 右移 → 部分积 00110，乘数 1101。
步 2：最低位 1 → 00110 + 01101 = 10011 → 右移 → 部分积 01001，乘数 1110。
步 3：最低位 0 → 不变 01001 → 右移 → 部分积 00100，乘数 1111。
步 4：最低位 1 → 00100 + 01101 = 10001 → 右移 → 部分积 01000，乘数 1111。
积的尾数位串 = 部分积低 4 位 1000 与乘数 1111 拼接 = 10001111（拼接不是相加）。
部分积首位的 0 是移位多出的一位。
即 0.100011112 = 143/256。
符号位 0 ⊕ 0 = 0，故结果为 +0.10001111。
验算：整数 13 × 11 = 143 只验证尾数位串，数值须按缩放还原：(13/16) × (11/16) = 143/256 ✓

Booth 算法：符号位参与运算，另设附加位 Q−1 初值为 0。

每步看乘数末两位 YnYn+1：

00 / 11 加 0。

01 加 [X]补。

10 加 [−X]补。

然后累加器 A、乘数 Q、附加位 Q−1 整体算术右移一位（符号位复制）。

乘数 n 位（含符号位）做 n 次——本卡为定点整数口径；小数双符号位版做 n+1 次、末步只加减不移位（与《补码运算规则》卡口径一致）。

例（Booth 算法）
X = −13（5 位补码 10011），Y = 11（01011）。
A 初值 00000，Q = 01011，Q−1 = 0。
步 1：末两位 10 → A = A − X = 0 − (−13) = 13（01101）→ 右移 → A = 00110，Q = 10101，Q−1 = 1。
步 2：末两位 11 → 不变 → 右移 → A = 00011，Q = 01010，Q−1 = 1。
步 3：末两位 01 → A = A + X = 3 + (−13) = −10（10110）→ 右移 → A = 11011，Q = 00101，Q−1 = 0。
步 4：末两位 10 → A = A − X = −5 − (−13) = 8（01000）→ 右移 → A = 00100，Q = 00010，Q−1 = 1。
步 5：末两位 01 → A = A + X = 4 + (−13) = −9（10111）→ 右移 → A = 11011，Q = 10001。
积 A:Q = 11011 10001，换算回十进制正是 −143，即 (−13) × 11 ✓

定点除法（原码）：商符 = 被除数符号 ⊕ 除数符号，数值部分单独算。

先判 |被除数| < |除数|，否则商溢出。

恢复余数法：每步试减，不够减商 0 并恢复余数。

不恢复余数法（加减交替法）：先看余数符号选加减：余数 ≥ 0 则 2R − |除数|，余数 < 0 则 2R + |除数|；再看运算后的新余数定商：新余数 ≥ 0 商 1，新余数 < 0 商 0。全程不用恢复，末位余数按左移次数还原，余数符号与被除数同号。

例（不恢复余数法）
被除数 0.1010，除数 0.1100，|0.1010| < |0.1100|，可除。
步 1：余数 ≥ 0 → 2R − Y = 1.0100 − 0.1100 = 0.1000，商 1。
步 2：余数 ≥ 0 → 2R − Y = 1.0000 − 0.1100 = 0.0100，商 1。
步 3：余数 ≥ 0 → 2R − Y = 0.1000 − 0.1100 = −0.0100，商 0。
步 4：余数 < 0 → 2R + Y = −0.1000 + 0.1100 = 0.0100，商 1。
商 0.1101。
末位余数还原：0.0100 ÷ 24 = 0.000001。
验算：0.1101 × 0.1100 = 0.10011100，被除数 0.10100000 − 0.10011100 = 0.00000100 ✓
易错
原码乘符号位不参与、移位是逻辑右移。
Booth 算法符号位参与、移位是算术右移，两者移位方式混用必错。
除法动手前先判 |被除数| < |除数|，漏判溢出是送分题丢分主因。
6. IEEE 754 浮点数【必背】 ★★★★★ · 近6年×6
类型总位数符号位阶码尾数偏置值
单精度 float32 位1 位8 位23 位127
双精度 double64 位1 位11 位52 位1023

规格化尾数隐含最高位 1（即实际尾数是 1.×××，存的只是小数部分）。

例（十进制 → 单精度）
把 −18.625 写成 IEEE 754 单精度。四步：
① 符号位：负数 → 1。
② 把数值写成 1.××× × 2e 形式：18.625 = 10010.1012 = 1.0010101 × 24，故 e = 4。
③ 阶码 = e + 偏置 127 = 131 = 10000011。
④ 尾数存小数部分 0010101，后补 0 凑满 23 位：00101010000000000000000。
拼起来：1 10000011 00101010000000000000000（十六进制 C1950000）。
反过来读一个数也一样：先拆三段，阶码减 127 得真阶，尾数前面补回隐含的 1。
坑
特殊编码要分清四种：
阶码全 0 且尾数全 0 = ±0。
阶码全 0、尾数非 0 = 次正规数（没有隐含 1）。
阶码全 1、尾数全 0 = ±∞。
阶码全 1、尾数非 0 = NaN。

7. 浮点数加减运算 · 五步法 ★★★★★ · 近6年×6

五步法光背步骤没用，跟着一个例子走一遍就会了。

设阶码 4 位补码（可表示 −8 ~ +7）、尾数双符号位、6 位数值位，均用补码，算 X + Y，其中 X = 23 × 0.1010（= 5），Y = 24 × 0.1101（= 13）。

五步法
1对阶（小阶向大阶看齐，阶差几位、尾数右移几位）：X 的阶 3 < Y 的阶 4，差 1 → [X]尾补 = 00.101000 算术右移 1 位，得 00.010100，阶变为 4。移出的位是 0，本次不丢精度。
2尾数加减（按补码相加）：00.110100 + 00.010100 = 01.001000。双符号位出现 01，是尾数溢出的形态——先别慌，这不是运算溢出，看第 3 步。
3规格化：补码规格化形式是正数 00.1×××××、负数 11.0×××××。现在是 01.×××，尾数溢出 → 右规：尾数右移 1 位得 00.100100，阶码 4 + 1 = 5。若结果形如 00.0××× 或 11.1×××（首数值位与符号位相同），则反过来左规：尾数每左移 1 位、阶码减 1，直到达标。
4舍入：对阶、右规时被移掉的位要处理。看一小段：尾数 00.100100 对阶右移 3 位，移出位恰为 100（正好半个单位）→ 按「0 舍 1 入」末位进 1，得 00.000101；若右移 4 位，移出位为 0100（不足半个单位）→ 直接舍去，得 00.000010。本例对阶、右规都没移出有效位，无舍入。（注：这是教学简化舍入；IEEE 754 默认是就近舍入、遇半取偶，不同。）
5溢出判断（只看阶码）：阶码 5 在 −8 ~ +7 内 → 无溢出。阶码上溢才是真溢出；阶码下溢按机器零处理（408 教学简化口径；IEEE 754 则用次正规数实现渐进下溢，数值过小时仍可能因舍入变为 0）。

结果：25 × 0.100100 = 18。十进制验算：5 + 13 = 18 ✓。

易错
尾数溢出 ≠ 运算溢出——尾数溢出只需右规；只有阶码上溢才算溢出。
尾数「双符号位判溢出」是定点数那套，别搬到浮点数上。
8. 数据类型转换 ★★★★★ · 近6年×2

C 表达式算出什么，不只看数值，还看每个数在计算的哪一步被换成了什么类型。转换发生在三个关口：运算前先把小整型抬上来、混算时按高位一方看齐、赋值时再把结果塞进目标类型的格子——本卡每条都跟着一个数实际走一遍。

平台前提：本卡统一采用 408 常见计算模型：8 位有符号 char、16 位 short、32 位 int/unsigned int，有符号整数采用补码，浮点数采用 IEEE 754 binary32/binary64 并按就近舍入、遇中间值取偶数处理。超出目标有符号类型表示范围的整数转换，按本模型的低位截取与补码解释计算；在 C11 中，这类转换的结果可能属于实现定义行为。
先跟一遍：两个 char 相加的旅程
设 char a = 100, b = 100; 求 a + b。a、b 在参与运算之前先被整型提升为 int，于是加法是在 int 里做的：100 + 100 = 200，中间过程根本没溢出。
把结果存回 int，得到 200；存回 char，赋值那一刻才截断：200 超出 char 的 −128～127，只留低 8 位，200 − 256 = −56。
乘法同理：a × b 先按 int 算得 10000，存进 int 安然无恙；存进 char 则只留低 8 位，10000 mod 256 = 16。
所以「char 运算会先溢出」是假象——本例的 int 中间运算未溢出，结果转换为较窄类型时才发生值变化。
整型提升：小整型一运算就先升格
设 unsigned char uc = 255;，uc + 1 里 uc 先提升为 int，算得 256，并不回绕成 0；只有把 256 再赋回 unsigned char 变量时，才按 mod 256 变成 0。
提升去向看 int 装不装得下：unsigned short 的取值（0～65535）int 全装得下，所以 unsigned short us = 65535; 的 us + 1 是按有符号 int 算的，得 65536，不是无符号回绕。
通常先进行整型提升；若 int 无法表示原类型全部取值，可能提升为 unsigned int。
混进一个无符号数：有符号一方整体看齐
设 int x = −1; unsigned int u = 1; 比较 x > u：两者同为 4 字节、级别相同，按通常算术转换，x 被换成 unsigned int 再比——−1 的补码一位不变地读作 4294967295，于是 x > u 的结果是真，与数学直觉正好相反。
同一个 x 和 u 相加：4294967295 + 1 按 232 取模，得 0，且表达式的类型是 unsigned int，之后再参与比较或赋值都按无符号解释。
再看 −20 与 10u：−20 换成无符号是 4294967276，比 10 大得多；两者相加得 4294967286（仍是无符号数），若题目把它赋给 int 再打印，才会重新按补码读回 −10——读法取决于最后落进哪种类型。
判断口诀落到过程上：同级别混算时，先把有符号数「按补码原样改读」成无符号数，再做运算，全程不再回头。
赋值截断：结果没变，是格子太小
int n = 300; char c = n;——300 的低 8 位是 0010 1100，即 44，c 得到 44；赋给 unsigned char 也是 44（300 mod 256）。
int m = 70000; short s = m;——70000 mod 65536 = 4464，s 得到 4464，正负看截断后最高位：本例落在正区间，若余数 ≥ 32768 还要再减 65536 读作负数（前面的 200 → −56 就是这么来的）。
强制转换 (char)n 与赋值给 char 变量走的是同一条截断路；表达式本身在 int 里算出的值不受影响。
整型与浮点互转：精度在哪一步丢
float 的有效位只有 24 位（含隐含位），能精确表示的最大连续整数到 224 = 16777216 为止。int big = 16777217; float f = big; 存入时 224 + 1 无处安放，舍入为 16777216，再转回 int 也是 16777216，丢了 1；同样的数存进 double（有效位 53 位）则原样保留。
反方向浮点转整型是截尾不是四舍五入：(int)3.99 = 3，(int)(−3.99) = −3，小数部分整段丢弃。
最常埋伏的一处：float r = 5 / 2; 右边两个操作数都是 int，先做整除得 2，之后才转成 float，r = 2.0；写成 5.0 / 2，一方是 double，另一方被抬成 double 做浮点除法，才得 2.5。转换发生的先后，决定了除法按谁的规则做。
例题
例 · 一组表达式逐项判真假（C 程序实测）
设 char a = 100, b = 100；int x = −1；unsigned int u = 1；float f。下列说法正确的有（　）。
I. a + b 的值是 200，赋给 char 变量后是 −56　II. x > u 为真　III. x + u 的值（按 unsigned int）是 0　IV. f = 16777217 后，(int)f 仍等于 16777217
A. 仅 I、II　B. 仅 II、III　C. 仅 I、III　D. 仅 I、II、III
逐项推：I——a、b 先提升为 int 相加得 200 ✓，赋值截断 200 − 256 = −56 ✓；II——x 转 unsigned 得 4294967295 > 1 ✓；III——4294967295 + 1 对 232 取模得 0 ✓；IV——float 只有 24 位有效位，16777217 舍入为 16777216，转回 int 是 16777216 ✗。
答案 D（四项数值已用 gcc 编译 C 程序逐项实测，含 sizeof 前提核对）。
以为 char、short 运算就在原地算、会当场溢出——char、short 通常先进行整型提升；本例的中间 int 运算未溢出，结果转换为较窄类型时才发生值变化。
−1 > 1 想当然判假：只要对方是同级别无符号数，−1 先变 4294967295，比较结果反转。
float r = 5 / 2 写出 2.5：整除在赋值转换之前就已完成，r 只能是 2.0。
浮点转整型当四舍五入：是向零截尾，−3.99 转得 −3，不是 −4。
把大整数转 float 当无损：超过 224 的整数先丢精度，之后转回 int 也找不回来。
截断只记「取余」忘了读符号：余数落在目标类型负区间时还要减去模数按负数读（200 → −56）。
9. 数据的大小端与对齐存储 ★★★★ · 近6年×1

同一个多字节数放进内存，字节的先后有两种排法；同一组结构体成员住进内存，中间会不会留空洞——这两件事决定了从内存里读回来的到底是什么数。本卡都用具体字节和具体偏移量走一遍。

对齐前提：本卡按常见 ABI：char 1B、short 2B 且按 2B 对齐、int 4B 且按 4B 对齐、double 8B 且按 8B 对齐，结构体整体按最大成员对齐要求补齐；具体题目另给对齐规则时以题干为准。
一个数拆成字节：0x12345678 住进内存
int 值 0x12345678 占 4 个字节：最高字节 12、次高 34、次低 56、最低 78。设它存放在地址 100～103。
大端排法：高字节住低地址——100 放 12、101 放 34、102 放 56、103 放 78，顺着地址读下去正好是数的书写顺序。
小端排法：低字节住低地址——100 放 78、101 放 56、102 放 34、103 放 12，整个倒过来。
判机器是哪一端，不用背：取这个 int 首地址处的那一个字节，是 78 就是小端，是 12 就是大端。用联合体 union { int i; unsigned char c[4]; } 令 i = 0x12345678，小端机上 c[0]（最低地址字节）读得 0x78，大端机上读得 0x12——考题最爱用这一手设问。
两点边界：大小端管的是字节之间的顺序，不管字节内部的位序；单字节的 char、以及字符串里逐个存放的字符，不受大小端影响。short 值 0x1234 同理：小端机内存里先 34 后 12。
结构体里为什么有空洞：成员各就各位的过程
看 struct S1 { char a; int b; char c; }; 逐个安放：a 是 char，随便落座，占地址 0。
b 是 int，要求起始地址是 4 的倍数——地址 1 不合格，只能跳到 4，地址 1～3 空出来，这就是内部填充 3 个字节；b 占 4～7。
c 是 char，落在 8。成员到此放完共 9 个字节，但结构体总大小还须是其对齐值（成员中最大的对齐值，这里是 int 的 4）的倍数，于是尾部再补 3 个字节，sizeof(S1) = 12——尾填充是为了让这种结构体排成数组时，每个元素的 b 都仍然对齐。
同一组数值的成员换序 struct S2 { int b; char a; char c; };：b 占 0～3，a 落 4，c 落 5，只剩尾填充 2，sizeof(S2) = 8。成员一个没少，只因大成员排在前面省掉了中间的空洞。
对齐值随成员走：含 double 的 struct { char c; double d; int i; } 中，d 要求 8 的倍数地址——c 占 0 后要填 7 个字节 d 才落 8，i 落 16，尾填充 4，sizeof = 24，整个结构体的对齐值被 double 抬到了 8。数组成员按单个元素看：char a[3] 只占 3 个字节、对齐值仍是 1，后接 int 时只填 1 个字节。
例题
例 1 · 结构体偏移与总大小（C 程序 offsetof 实测）
struct Node { char x; int y; short z; char w; }，求各成员偏移量与 sizeof；若成员可任意重排，最小 sizeof 是多少？
逐个放：x 落 0；y 要求 4 的倍数，填 3 后落 4，占 4～7；z 是 short，要求 2 的倍数，落 8，占 8～9；w 落 10。已用 11 字节，结构体对齐值为 4（int 最大），尾填充 1 → sizeof = 12。

例 2 · 按字节读回一个数
小端机内存地址 200～203 依次存放 78、56、34、12（十六进制），把这 4 个字节作为一个 int 读出，其值是（　）。
小端＝低地址放低字节：地址 200 的 78 是最低字节，203 的 12 是最高字节，自高到低拼得 0x12345678。

若按字节编址，还须加上字内字节偏移的位数，且 CPU 实际地址总线宽度由其体系结构决定、不一定等于该模块所需位数。
每组包含的存储字数
= 单片芯片字数：按字编址时每组占芯片字数个字地址，按字节编址时每组占用的字节地址空间 = 芯片字数 × 目标字长 ÷ 8
各组按连续地址段分配时互不重叠（是否连续编址以题目译码设计为准）。
例题（公式重算 + 范围枚举核对）
例 ①
用 16K × 8 位芯片构成 64K × 32 位存储器（本问按 32 位存储字编址）：
字扩展组数 = 64K ÷ 16K = 4，每组位扩展片数 = 32 ÷ 8 = 4，总片数 = 4 × 4 = 16 片
覆盖该模块所需地址线 = log264K = 16 根（A15 ～ A0），其中低 14 根接各片片内地址，高 2 根（A15A14）经译码产生 4 组片选
数据线 32 根，每组 4 片各提供 8 位。
例 ② · 地址范围
用 8K × 8 位芯片构成 32K × 8 位、起始地址 0000H（按字节编址）：
共 4 片，各占 8K = 2000H 大小
范围依次为 0000H–1FFFH、2000H–3FFFH、4000H–5FFFH、6000H–7FFFH ✓
坑：
① 位扩展不产生新的地址、也不需要多组片选，各片是「一起被选中、各出一部分位」；字扩展不加宽数据线，各片是「同一时刻只选中一片」——两者接法正好相反，选项常互换设套。
② 算地址范围先把容量换成 2 的幂再换十六进制：8K 的跨度是 2000H，不是 8000H。
③ 题目混用 ROM 与 RAM 芯片时，总片数分开算；地址空间如何排布由题目译码设计决定，要求连续编址时才连续排布，哪类放低地址以题干为准。
④ 片选若用线选法（高位地址线直连片选）可省译码器，但可能造成地址空间利用率低、片选组合设计不当还可能多片同时被选中，与译码法结论不同，先看题干给的连接方式。
12. 多体交叉存储器 · 低位交叉与流水存取 ★★★★★ · 近6年×4

一个存储模块从启动存取到能再次启动，要占满一整个存取周期——CPU 连续访存时大半时间在等。把主存拆成几个独立模块轮流启动，就能流水起来。

多体交叉存储器（Interleaved Memory，多体交叉存储器）在合辑里只在《存储器容量计算》卡的 露过一次脸：交叉编址在那张卡里是用来凑总线宽度的，本卡讲它为提带宽的另一面。

两种编址先分清
编址模块号来自连续地址落在哪效果
低位交叉地址的低位轮流分布到各个模块连续访问正好轮转，适合流水提带宽
高位交叉地址的高位连续一大片落在同一模块本质是扩容拼接；通常的连续地址访问会撞同一模块、形不成流水（本行按连续访问场景说）
核心公式
存取周期 T
一个模块从启动一次存取到能再次启动的间隔
总线周期 r
总线每隔 r 送出一个字（也叫总线传送周期）
流水条件
模块数 m ≥ T ÷ r：轮完一圈回来，第一个模块刚好恢复，可以无缝接着启动
连续读 n 字
交叉方式：T + (n − 1) × r；单体（或顺序方式）：n × T
稳态带宽
交叉方式：字长 ÷ r；单体：字长 ÷ T
例题
例 · 4 体交叉，连续读 8 个字（公式重算）
条件：m = 4 个模块，T = 200 ns，r = 50 ns，字长 32 位。
先核流水条件：T ÷ r = 200 ÷ 50 = 4 = m ✓ 刚好不断档。
低位交叉用低 2 位选模块：地址 0 → M0、1 → M1、2 → M2、3 → M3、4 → M0……轮到 M0 时已过 4 × 50 = 200 ns = T，M0 正好恢复 ✓
连续读 8 个字：交叉 = 200 + 7 × 50 = 550 ns；单体 = 8 × 200 = 1600 ns。
带宽：交叉 = 32 bit ÷ 50 ns = 640 Mbit/s = 80 MB/s；单体 = 32 bit ÷ 200 ns = 160 Mbit/s = 20 MB/s——正好 4 倍 = m 倍 ✓
坑
① 带宽提升的关键是访存请求能分散到不同模块、形成流水，不是地址必须连续：连续地址是低位交叉最典型的有利场景，地址不连续也可以——如 4 体时依次访问 0、5、10、15，落到的模块仍依次是 M0、M1、M2、M3。怕的是请求总撞同一模块：步长为 m 的整数倍时（如 0、4、8、12 全在 M0），每次都得等满 T，退化回单体速度。
② 第一个字仍要等满一个 T 才能出来，连续读 n 字是 T + (n − 1)r，别图省事写成 n × r。
③ 别与《存储器容量计算》卡里的交叉编址混为一谈：那是同一地址下多芯片并行凑满 64 位总线宽度；本卡是不同地址在各模块间轮转启动，目的和机制都不同。
④ m 大于 T ÷ r 之后再堆模块，带宽也不涨：瓶颈转到总线周期 r 上，每 r 才能送出一个字。
13. 外部存储器 ★★★★ · 近6年×1

主存之外的存储器只看三家：磁盘、闪存、由磁盘组成的 RAID。本卡只讲存储器本身——结构、地址怎么编、性能参数怎么算、坏了怎么办；给定一批盘块请求先服务谁（磁盘调度算法）是 OS 侧 os-20 / os-21 的口径，本卡不讲；光盘已删除出考纲，不收。

磁盘：跟着一次定位走完结构与地址
一张盘片双面涂磁层，两个面各是一个记录面，每个记录面上有一圈圈同心磁道，每条磁道又切成若干扇区，扇区是磁盘读写的最小单位（常为 512 B 或 4 KB）。多张盘片同轴叠放，所有记录面上半径相同的磁道合称一个柱面。
定位一个扇区走三步：磁头组先整体移动到目标柱面（各记录面同时到位，所以地址里写柱面号而不是磁道号）→ 再选通目标盘面对应的磁头 → 盘片转起来，等目标扇区转到磁头下方。
于是磁盘地址就是三段：柱面号 ＋ 盘面号 ＋ 扇区号（有的编址把盘面号排在前，字段构成不变）。
算一本账：某磁盘组 10 个记录面、每面 1000 条磁道、每道 100 个扇区、每扇区 512 B。总容量 = 10 × 1000 × 100 × 512 = 512,000,000 B（约 512 MB 按 106 计，约 488 MiB）。
地址位数按每段的取值个数向上取整：柱面 1000 个需 10 位（210 = 1024 才够），盘面 10 个需 4 位，扇区 100 个需 7 位，地址共 21 位。
磁盘性能参数：存取时间拆成三段（设备本身口径）
承接上面的定位过程，读一个扇区的时间天然分三段：磁头移到柱面的寻道时间、盘面转半圈等扇区到来的旋转延迟、扇区从磁头下通过的传输时间。题目给出平均寻道时间时直接取用，那是设备参数，不是调度算出来的。
代入具体数：转速 7200 转/分 → 每转 60 ÷ 7200 s ≈ 8.33 ms，平均旋转延迟取半转 ≈ 4.17 ms。每磁道 64 个扇区，则数据传输率 = 64 × 512 B × 120 转/s = 3,932,160 B/s（约 3.93 MB/s），传一个扇区用 8.33 ÷ 64 ≈ 0.13 ms。
平均寻道时间给 5 ms 时，读一个扇区的平均存取时间 = 5 + 4.17 + 0.13 ≈ 9.30 ms——三段里旋转与寻道是大头，传输时间常可忽略，但题目问到就得算全。
闪存：按页读写、按块擦除
闪存（NAND）内部按页组织（常为 4 KB），若干页（此例 64 页）合成一个块（256 KB）。读、写都以页为单位进行，唯独擦除只能整块来。
跟着改一个数走：NAND 闪存按页读写、按块擦除，已写入页面通常不能直接覆盖更新；SSD 常将新数据写入其他可用页、旧页标为无效，待垃圾回收时搬迁有效数据并按块擦除；因此更新少量数据也可能引起额外搬迁（写放大）。教材简化模型有时以整块擦除重写示意。
每个块能承受的擦除次数有限（反复擦写会磨损），所以固态盘要靠磨损均衡把擦写摊到各个块上，并预留一部分空间做替换；这也是闪存与磁盘最本质的差别：磁盘可任意次原地重写，闪存先擦后写、擦写有寿命。
RAID：四种搭法，先分清镜像与条带
RAID 0、5、10 用同一组 6 块 1 TB 盘比较；RAID 1 用最基本的 2 块 1 TB 盘示例，避免把多组镜像再条带化误算成 RAID 1：
RAID 0 条带
数据切块轮流放 6 块盘，可用 6 TB、读写可并行最快；无任何冗余，坏任意 1 块，条带断裂、全部数据丢失。
RAID 1 镜像
2 块 1 TB 盘互为镜像、写同一份数据，可用 1 TB（利用率 50%）；坏任意 1 块可由另一块恢复，2 块全坏才丢数据。
RAID 5 分布校验
数据条带化，奇偶校验块轮流分布在各盘（不是独占一块校验盘），可用 (6 − 1) × 1 = 5 TB；坏任意 1 块可由其余盘的校验重构，同时坏 2 块则丢失。
RAID 10 镜像＋条带
6 块盘三组镜像再条带化——这正是 RAID 10：先两两镜像成 3 组、再在组间条带，可用 3 TB；至少坏 1 块不丢数据，最多可坏 3 块（每组各坏 1 块），兼得镜像的可靠与条带的速度。
小例复核口径：4 块 2 TB 盘做 RAID 5，可用 (4 − 1) × 2 = 6 TB——公式里的「−1」是校验等效占用一块盘的容量，与盘数无关地恒减一块。
例题
例 1 · 存取时间三段合成
某磁盘转速 7200 转/分，每磁道 64 个扇区，每扇区 512 B，平均寻道时间 5 ms。读一个扇区的平均存取时间约为（　）。
A. 5.13 ms　B. 9.30 ms　C. 13.33 ms　D. 17.50 ms
逐段算：每转 8.33 ms，平均旋转延迟取半转 4.17 ms；传输一个扇区 8.33 ÷ 64 ≈ 0.13 ms；合计 5 + 4.17 + 0.13 ≈ 9.30 ms。A 只加了传输段漏了旋转，C 误把整转当旋转延迟，D 三段之外又重复计入寻道。
答案 B（三段数值已用程序复算）。
例 2 · RAID 选型与容量
6 块 1 TB 磁盘组建阵列，要求可用容量尽量大且能容忍任意 1 块盘损坏，应选（　），可用容量为（　）。
A. RAID 0，6 TB　B. RAID 5，5 TB　C. RAID 10，3 TB　D. RAID 10，5 TB
逐项判：A 容量最大但坏 1 块全丢，不满足容忍要求；C 能容忍坏盘但只用一半容量；D 与 C 同为 RAID 10，可用容量应为 3 TB，写 5 TB 是误算；B 可用 (6 − 1) × 1 = 5 TB 且坏任意 1 块可重构，两条都满足。
答案 B（RAID 5、5 TB）。
盘片数当记录面数：地址与容量算的是记录面，盘片双面记录时面数是盘片数的 2 倍（本卡例题直接给面数，按给的数算）。
平均旋转延迟取一整转：等扇区到来平均只等半转，7200 转/分是 4.17 ms 不是 8.33 ms。
说 RAID 5 有一块专门的校验盘：校验块是轮流分布在各盘的，只是容量上等效占一块；独占校验盘是 RAID 3 / 4 的做法。
RAID 0 的「0」记成零故障：恰恰是零冗余，坏一块盘整个阵列的数据都读不回来。
把闪存当磁盘原地改写：NAND 闪存按页读写、按块擦除；SSD 更新数据通常采用异地写入，旧页失效后由垃圾回收统一处理，不能直接像磁盘一样原地覆盖。
在本卡里套磁盘调度算法：存取时间三段是设备参数口径，题目给平均寻道时间就直接用，先服务哪个请求是 OS 调度卡的事。

15. Cache 替换算法与写策略 ★★★★★ · 近6年×5

替换算法只在组相联 / 全相联才需要：直接映射中每个主存块只对应一个固定 Cache 行，冲突时直接替换该行，没有「选哪块换出」的问题。

替换算法换出对象特点
FIFO（先进先出）最先进入 Cache 的块实现简单，不看实际使用情况
LRU（最近最久未使用）最久未被访问的块有时间局部性的访问下通常命中率较高（但不保证对任何访问串都优于 FIFO），实现代价较大
LFU（最不经常使用）访问次数最少的块需维护计数；曾高频的旧块计数居高难被换出，对访问模式变化适应差
随机替换随机选一块实现最简单，命中率略低
例（同一访问串，两种算法）
Cache 共 3 行，块访问串 2, 1, 3, 2, 4, 2, 5, 1, 2, 3。
FIFO（只看进场先后）：2✗、1✗、3✗ 装满；2✓；4✗ 换出最老的 2；2✗ 换出 1；5✗ 换出 3；1✗ 换出 4；2✓；3✗ 换出 2 → 缺失 8 次。
LRU（看最近使用）：2✗、1✗、3✗ 装满；2✓（2 变最新）；4✗ 换出最久未用的 1；2✓；5✗ 换出 3；1✗ 换出 4；2✓；3✗ 换出 5 → 缺失 7 次。
差别就在第 5 步：2 刚被访问过，LRU 保它、FIFO 照样按进场顺序把它换出——这就是本例中 LRU 缺失次数更少的原因。
写策略（写命中时）代价 / 注意
写直通同时写 Cache 和主存：主存始终一致，写操作慢；无需脏位；常配非写分配
写回只写 Cache 并置脏位，换出时才写回主存：写得快，需脏位，一致性处理更复杂；常配写分配

写直通 / 写回说的是「写命中」。

写不命中是另配一对策略（写分配 / 非写分配），两对不要混成一对答。

16. 虚存地址变换与页表规模 · 计算 ★★★★★ · 近6年×6

逻辑地址 = 页号 + 页内偏移。

页面 4KB = 212B → 页内偏移 12 位。

例题
逻辑地址 32 位，页面 4KB。
页号 20 位，单级页表项数 220，每项 4B → 页表占 220×4B = 4MB，常驻内存太贵——这就是多级页表的动机。
二级页表（页号 10 + 10 拆分）：页目录 210 项 × 4B = 4KB（恰一页）；每张二级页表同样 210×4B = 4KB，且只给实际用到的虚页建表，不用一次建满。

带 TLB（快表，即转换后备缓冲区）的有效访问时间（EAT）：TLB 命中率 α，TLB 查找时间 t，访存时间 m。

命中：t + m。

缺失：t + 查页表 m + 取数据 m = t + 2m。

EAT
= α·(t+m) + (1−α)·(t+2m)
例：α=0.9，t=10ns，m=100ns → 0.9×110 + 0.1×210 = 99 + 21 = 120ns。

若题干说“忽略 TLB 本身查找时间”，则 EAT = α·m + (1−α)·2m = 0.9×100 + 0.1×200 = 110ns。先看题干给没给 t，再选公式。

以上 EAT 均为一级页表模型：TLB 未命中时访存查页表一次、再访存取数据一次。

口诀：页表规模题先算“项数 × 项大小”；多级题先拆页号位数，再算每级表占几页。

补充：页表项数 = 虚拟地址空间页面大小。

页表项大小须容纳物理块号 + 控制位，通常向上对齐到 2 的幂次。

TLB 表项长什么样：标记 + 页框号 + 有效/权限等控制位。组相联 TLB 用虚页号的低位作组索引选组、高位作标记在组内比对：组数 = 表项总数 ÷ 路数，组索引位数 = log2（组数），标记位数 = 虚页号位数 − 组索引位数。

RISC 与 CISC

本卡讲的寻址方式多少、指令怎么编码，背后站着两种设计哲学：CISC（复杂指令集）想让一条指令多干活，RISC（精简指令集）反过来让每条指令只干一件小事、但干得快而规整。对照着同一件活看最清楚：

例 · 同一运算 C = A + B（A、B、C 都是存储器变量），两种风格各写一遍（脚本计数核对）
CISC 写法：1 条。ADD C, A, B —— 一条存储器—存储器型指令内部把「取 A、取 B、相加、存回 C」全做完。指令条数最少，但这条指令长短不定、内部步骤多，译码与执行都复杂。注：以下为假想指令集示意，假设该 CISC 支持三操作数存储器运算指令；具体机器是否存在此指令形式由其 ISA 决定。
RISC 写法：4 条。LOAD R1, A；LOAD R2, B；ADD R3, R1, R2；STORE C, R3 —— RISC 的运算指令只准碰寄存器（Load / Store 结构），碰内存只能靠这两条专门的装入 / 存回指令。
再看自增 X = X + 1：CISC 一条 INC X 搞定；RISC 要 LOAD、ADD（加立即数 1）、STORE 共 3 条。
账要两面算：RISC 条数多（4 条 vs 1 条），但传统 RISC 通常采用规整的指令格式和简单的 Load/Store 结构，便于流水线实现；本例按统一 32 位计时，4 条共 16B。现代架构可能支持压缩指令，实际执行周期也取决于指令与硬件；CISC 条数少，单条却变长又多步，流水线里步调参差 ✓
对比项CISCRISC

18. 程序的机器级代码表示 ★★★★★ · 近6年×4

定位：CO 第 4 章指令系统。合辑已有《指令格式与寻址方式》讲一条指令长什么样，这一卡往前一步：一段 C 代码编译之后在机器级长什么样——参数、局部变量、数组元素到底落在哪个地址。题目通常给一段短 C 代码（或它的汇编片段），问某个变量 / 成员的地址、某条指令访问的内存单元，或返回之后栈恢复成什么样。读这类题只有一条路：先把栈帧的相对位置钉死，再逐个算地址。

前提：以下汇编及栈帧为教学用的 32 位 x86、固定调用约定、未做优化的示意布局，并非 C 语言规定的唯一布局；实际考题以题干所给的调用约定、汇编指令或栈帧图为准。
本卡约定
32 位、按字节编址、栈向低地址生长；call 把返回地址（4B）压栈；被调用函数先 push ebp、再 mov ebp, esp，用帧指针 EBP 定位一切；参数由调用者按从右到左的顺序压栈；int 4B、short 2B、char 1B，结构体按 4B 对齐填充。题目另给约定时以题目为准——要练的是这套「先定帧、再算址」的读法，不是背死某一台编译器的分配顺序。
贯穿例子
全卡只用一个函数：
struct Rec { char flag; int score; short delta; };
int calc(int x, int y) {
　struct Rec r;
　int buf[3];
　r.score = x;
　r.delta = (short)y;
　buf[1] = r.score + r.delta;
　return buf[1];
}
一、结构体先算布局：成员偏移从哪来

访问 r.score 之前，编译器先把 Rec 的布局定死：成员按声明顺序放，每个成员的起始地址须是其自身对齐的倍数，放不下就先填充。

flag 是 char，占 1B，放偏移 0。
score 是 int，须 4 的倍数地址：偏移 1 不合，先填充 3B，score 放偏移 4，占 4B 到偏移 7。
delta 是 short，须偶数地址：偏移 8 正合，占 2B 到偏移 9。
结构体总大小须是最大成员对齐（4）的倍数：末尾再填充 2B，sizeof(Rec) = 12B。于是任一 Rec 变量 v 都有：&v.flag = 基址 + 0，&v.score = 基址 + 4，&v.delta = 基址 + 8。
二、C 语句怎么落成指令：跟着 calc 走一遍
push ebp　　　　　　; 保存调用者的帧指针
mov ebp, esp　　　　; 立起本函数的帧
sub esp, 24　　　　 ; 一次留出局部区：r 占 12B + buf 占 12B
mov eax, [ebp+8]　　; 取参数 x（位置见第三节）
mov [ebp−8], eax　　; r.score = x：r 基址在 ebp−12，score 偏移 +4 → ebp−8
mov eax, [ebp+12]　 ; 取参数 y
mov [ebp−4], ax　　 ; r.delta = (short)y：delta 偏移 +8 → ebp−4，只写低 16 位
mov eax, [ebp−8]　　; 取回 r.score
movsx edx, word [ebp−4]　; 取 r.delta 并符号扩展成 32 位再相加
add eax, edx
mov [ebp−20], eax　 ; buf[1] = 和：buf 基址在 ebp−24，元素 [1] 偏移 +4 → ebp−20
mov eax, [ebp−20]　 ; 返回值按约定放 eax
mov esp, ebp；pop ebp；ret　; 拆帧，最后 ret 把返回地址弹进 PC

看懂这段只需抓住三件事：本例中各赋值的机器级实现体现为「算出右边的值 → 存到左边的地址」；源码里的变量名在机器级全部消失，只剩基址 + 偏移；偏移在编译时就已算死，运行时不再查表。

三、数组与结构体访问：地址全是同一条公式

数组元素：&a[i] = 数组首址 + i × sizeof(元素类型)。int buf[3] 的元素 4B 一个，buf[1] 就是首址 + 4。结构体成员：&v.成员 = v 的基址 + 该成员在布局中的偏移。两者叠起来就是结构体数组：元素先按 sizeof(整个结构体) 跳，成员再加自己的偏移。

例：struct Rec db[5] 的首址为 0x00404000。求 &db[2].score：先跳 2 个元素 2 × 12 = 24，再加 score 的偏移 4，得 0x00404000 + 28 = 0x0040401C；同理 &db[2].delta = 0x00404000 + 24 + 8 = 0x00404020（程序验算）。易错点在中间这步：跳元素用的是含填充的 sizeof = 12，不是三个成员裸大小之和 1 + 4 + 2 = 7。
四、过程调用的栈帧：谁压栈、何时压、压完在哪
1调用者压参数：执行 call calc(…) 前，先按从右到左把 y、x 依次压栈——后压的 x 离栈顶更近，所以第一个参数离返回地址最近。
2call 压返回地址：call 把「下一条指令的地址」压栈再跳走。这 4B 是被调用者帧的最高地标，函数最后靠 ret 把它弹回 PC。
3被调用者立帧：push ebp 把调用者的旧帧指针存下，mov ebp, esp 让 EBP 钉在本帧的锚点上。此后无论 ESP 因局部区怎么动，参数和局部变量相对 EBP 的位置都不变。
4留局部区：sub esp, 24，一次把 r 与 buf 的 24B 留出。按本卡约定，局部变量按声明顺序向低地址排：先声明的 r 紧贴 EBP 下方（基址 ebp−12），buf 在 r 下方（基址 ebp−24），ESP 停在 buf 的最低端。
5返回拆帧：返回值放 eax；mov esp, ebp 把 ESP 收回锚点，pop ebp 恢复调用者的帧指针，ret 弹出返回地址。一步错位，后面全盘皆错——考题最爱在这条链上挖坑。
[EBP+12]
参数 y（第二个参数，离锚点更远）
[EBP+8]
参数 x（第一个参数）
[EBP+4]
返回地址（call 压入）
[EBP+0]
保存的旧 EBP ← EBP 锚点在这里
[EBP−12]

[EBP−24]

例题
例 · 栈帧地址全家福（真题风格，程序验算）
承贯穿例子：calc 执行期间 EBP = 0x0012FF80。求：(1) 返回地址、参数 x、参数 y 各存在哪个地址；(2) r.score、r.delta、buf[1] 的地址；(3) 此时 ESP 的值。
推导：锚点之上按 +4 一格一跳：保存的旧 EBP 在 0x0012FF80，返回地址在 [EBP+4] = 0x0012FF84，x 在 [EBP+8] = 0x0012FF88，y 在 [EBP+12] = 0x0012FF8C。
锚点之下先落 r：r 基址 = EBP − 12 = 0x0012FF74，r.score = 基址 + 4 = 0x0012FF78（即 [EBP−8]），r.delta = 基址 + 8 = 0x0012FF7C（即 [EBP−4]）。
再落 buf：buf 基址 = EBP − 24 = 0x0012FF68，buf[1] = 基址 + 1 × 4 = 0x0012FF6C（即 [EBP−20]）。
局部区共 12 + 12 = 24B，ESP 停在最低端 = 0x0012FF68，恰与 buf 基址相同 ✓（以上地址与偏移均经脚本逐项验算，含 ctypes 对结构体布局的交叉核对）。
坑：
① 返回地址不是 [EBP] 也不是 [EBP+8]：[EBP] 存的是旧 EBP，返回地址在它上面一格 [EBP+4]，第一个参数还要再上一格才是 [EBP+8]。把旧 EBP 忘了，整条链全错位 4B。
② 参数相对位置由压栈顺序定：从右到左压栈 ⇒ 第一个参数离返回地址最近。题目若改成从左到右压栈，x、y 的位置立刻对调，先看题干约定再套。
③ 结构体跳元素用含填充的 sizeof：Rec 三个成员裸大小共 7B，但 sizeof = 12B，db[2] 要跳 24B 不是 14B；成员偏移同理，score 在 +4 不是 +1。
④ 栈向低地址生长：局部变量的地址比 EBP 小、参数比 EBP 大。方向画反，[EBP−8] 会写成 [EBP+8]，正好和参数 x 撞车。
⑤ short 成员只占 2B：mov [ebp−4], ax 只写低 16 位，别按 int 的 4B 去推相邻成员的位置；读出参与 32 位运算时还要先符号扩展。

23. 流水线冒险与冲突处理 ★★★★★ · 近6年×2

合辑《流水线相关公式》只给了时间、吞吐率与时序图，本卡补它缺的另一半：流水线为什么会停顿、三种冒险各怎么解。流水线大题的后半段几乎必问这个。

冒险含义解法
结构冒险（Structural Hazard）多条指令争用同一硬件资源，如取指与访存共用一个存储器端口，某指令访存时下一条指令无法取指资源复制：指令 Cache 与数据 Cache 分离；或暂停流水线等资源空闲
数据冒险（Data Hazard）后一条指令要用的数据还没算出来：RAW（写后读，Read After Write）最常见；WAR（读后写）、WAW（写后写）主要出现在乱序、多发射等复杂流水线语境，答题先看题干流水线类型转发（Forwarding，又称旁路）+ 暂停；Load-use 冒险转发也救不了，必须暂停 1 拍（见下）
控制冒险（Control Hazard）分支指令的结果未定，后续指令是否该执行未知；已取入的指令可能全作废分支预测、延迟分支（延迟槽）、提前在译码段判断分支（把损失压到 1 拍）
转发（Forwarding / 旁路）

不经过写回与寄存器堆，直接把上一条指令在流水线寄存器里的结果送到下一条指令的执行段。

例 · 转发
ADD R1, R2, R3 紧跟 SUB R4, R1, R5
SUB 在执行段需要 R1 时，ADD 的结果已在 EX/MEM 寄存器中，直接转发，0 暂停
若中间隔一条指令，结果在 MEM/WB 寄存器中，同样转发
转发救不了的情形（必考）：Load-use 冒险
例 · Load-use 冒险
LOAD R1, 0(R2) 紧跟 ADD R3, R1, R4
LOAD 要到访存段（MEM）才拿到数据，而 ADD 在执行段（EX）就需要 R1，时间上赶不上，转发也来不及
只能暂停 1 拍、插入 1 个气泡（Bubble），让 ADD 的执行段推迟到 LOAD 的访存段之后
口诀：算术指令间的数据冒险靠转发，Load 后紧跟用它的指令必停 1 拍。

（注：停 1 拍是经典五级流水线、带转发时的结论；暂停周期数取决于流水线级数、数据在哪一段产出、在哪一段被使用以及转发路径，结构不同须按时序图重算，不是普适常数。）

控制冒险展开

分支预测分静态（固定预测不跳转，或固定预测跳转）与动态（按分支历史表预测，历史准了就几乎不损失）。

延迟分支是在分支指令后放一条“无论如何都执行”的延迟槽指令，把作废损失换成有用功。

若在译码段就能算出分支目标与条件，控制冒险的损失可压到 1 拍（只作废已取入的那一条）。

图：三类冒险的处理

坑：① 暂停（Stall）与冲刷（Flush）别混：暂停是“冻住前面几段、插入气泡”，冲刷是“作废已取入的错误路径指令”，前者用于数据/结构冒险，后者用于控制冒险。② 转发不是万能：见到 Load-use 先写“停 1 拍”，不要只写“转发解决”。③ 结构冒险的根治是“资源分开”，不是“加快时钟”——时钟由最慢段决定，资源冲突不会因提频消失。

上一张表比的是「数据怎么传」（查询 / 中断 / DMA / 通道），这里补「设备接在哪儿」：CPU 不直接连外设，中间隔着一层 I/O 接口（设备控制器）——它对 CPU 一侧长着几个寄存器，对设备一侧管着具体的机械 / 电气动作，CPU 只跟寄存器说话。

组成部分干什么CPU 怎么用它
数据寄存器暂存 CPU 与设备之间传送的数据；输入、输出方向常各设一个读它 = 取设备送来的数据；写它 = 把数据发给设备
状态寄存器放设备的状态位，如「就绪 Ready」「忙 Busy」「错误」只读为主：查询方式靠反复读它判断能不能传；中断方式下它也是认中断源的线索
控制寄存器接收 CPU 的命令字，如启动、停止、读写选择只写：CPU 写命令，接口译码后去驱动设备动作
数据缓冲在寄存器与设备之间再垫一层缓冲，抹平 CPU 的高速与设备的低速之差，并攒够一次传送的量CPU 不直接感知，体现为「写满一批再启动设备」而不是逐字干等
端口译码（地址译码）把地址总线送来的端口地址译成片选信号，只选中被点名的那个寄存器决定每个寄存器分到哪个端口地址；同一接口的几个端口地址通常连续编排

I/O 端口就是接口里这些可被 CPU 寻址的寄存器。给端口编号（编址）只有两条路：

　独立编址（I/O 映射）统一编址（存储器映射）
地址空间端口有独立的地址空间，与内存分开端口占用内存地址空间的一部分，分给端口的那段就不能再当内存用
访问指令必须用专门的 I/O 指令（如 IN / OUT），普通访存指令碰不到端口用普通访存指令（如 MOV）就能读写端口，不需要专用指令
优点不吃内存地址空间；I/O 地址译码简单；指令短、好辨认指令丰富，访存的寻址方式全可用于端口；编程灵活，不必另设 I/O 指令
缺点指令功能弱，传送多半只能经累加器；控制线要分内存 / I/O 两套吃掉一部分内存地址；从地址上分不清是访存还是访 I/O
辨认口诀题干出现 IN / OUT 指令、单独的端口地址 → 独立编址题干说「用访存指令访问 I/O」「某段地址留给设备」→ 统一编址
例 · 端口地址范围与编址辨认（脚本验算）
条件甲：某机 I/O 端口独立编址，端口地址为 8 位。条件乙：其中一个接口含数据输入、数据输出、状态、控制共 4 个寄存器，端口连续编址，起始地址 F0H。条件丙（对照）：另一台机器统一编址，地址线 16 位、按字节编址，把顶部 1KB 地址分给 I/O 端口。
甲：端口总数 = 28 = 256 个，地址范围 00H～FFH，与内存地址空间相互独立。
乙：4 个寄存器依次占 F0H（数据输入）、F1H（数据输出）、F2H（状态）、F3H（控制），该接口占用范围 F0H～F3H——CPU 读 F2H 就是在查设备状态，写 F3H 就是在下命令。
丙：按字节编址，总地址空间 216 = 65536 B；被 I/O 占用 1024 B 后，可用于存储器的地址空间为 65536 − 1024 = 64512 B = 63 KiB ✓（这里只算地址空间，不推断实际物理内存。）
辨认：甲乙说的是独立编址（有专属端口地址空间）；丙是统一编址，代价直接体现在「内存少了 1KB」上。
【坑】「端口」是接口里的寄存器，不是接口本身：一个接口可包含多个端口，也可能连接多个设备；状态寄存器和控制寄存器有时共用一个端口地址（一个只读、一个只写，靠读写方向分开），题目给「3 个端口」不代表只有 3 个寄存器。
26. 中断与 DMA（直接存储器访问） · 步骤与三种访存方式计算 ★★★★★ · 近6年×3

完整流程：中断请求 → 中断判优 → 中断隐指令 → 中断服务程序。

各步内容（纵向编号）：

  1. 1中断判优：多个中断同时请求时，由硬件排队器选出优先级最高者，最快。
    注意：软件查询是另一种识别中断源的方式——由程序逐个查询设备状态来确定来源，慢但灵活，不要与硬件判优混为一谈
  2. 2中断隐指令（硬件自动完成）：
    ① 关中断
    ② 保存断点（PC 和 PSW）
    ③ 查中断向量表得服务程序入口
  3. 3执行中断服务程序：先由服务程序保存通用寄存器等现场（保护现场），再处理中断请求
  4. 4恢复现场、开中断、返回断点继续执行
【坑】保存通用寄存器（现场）是中断服务程序做的，不是隐指令。
向量地址例
向量表项 4 字节，基址为 0，中断类型号 08H
入口地址 = 8×4 = 32 = 20H
通用式：入口 = 基址 + 类型号 × 表项字节数

DMA 与 CPU 分时访存的三种方式（王道口径命名）：

方式CPU 状态适用 / 代价
停止 CPU 访问整批传送期间 CPU 完全停访存实现最简单；CPU 利用率最低
周期挪用DMA 有请求时挪用 1 个或几个存取周期，平时 CPU 照常CPU 停的时间被打散，适合低速设备
交替访存一个 CPU 周期一分为二：C1 供 DMA，C2 供 CPU，无需申请 / 建立 / 归还总线要求 CPU 周期大于主存存取周期（例：CPU 1.2μs、存取 0.6μs，正好一分为二）
数量例
DMA 传 1000 个字，每字存取周期 0.5μs
停止方式下 CPU 停访存 1000×0.5μs = 500μs
周期挪用方式下 CPU 同样累计停 500μs，但分散在传送全程、每次只停 1 个周期
DMA vs 中断方式的根本区别

中断方式每传一个字（或一批）都要 CPU 干预。

DMA 方式 CPU 只在传送前初始化、传送完发一次中断时干预，中间数据直通、不经过 CPU。

三、操作系统 （23 条）
1. 操作系统的运行环境 · 内核态 / 用户态与态切换 ★★★★★ · 近6年×5

一个程序跑起来时 CPU 处在什么态、哪些指令它能碰、态在什么时候翻面——这张卡讲清。只讲 OS 侧的态与特权级；中断的硬件响应过程（压栈、查向量表）是计组 co-26 的口径，本卡不重复。

先看一个过程：用户程序想在屏幕上打印一句话
① 程序在用户态执行普通指令，先把要打印的字符串算好、放进自己的数组。
② 它调用库函数 printf——这一步仍在用户态：库函数先做格式化，把字符攒进用户态的输出缓冲区，还没碰系统调用。
③ 假设缓冲区刷新（遇到换行或缓冲攒满）触发一次 write 系统调用：库函数执行 trap / 访管指令请求写出——执行到这条指令的那一刻，硬件把 CPU 切到内核态并保存现场。
④ 内核按调用号找到写设备的服务程序，把数据接进内核、驱动设备输出。
⑤ 系统调用返回、切回用户态，程序从 trap 的下一条接着跑——但返回只表示数据已交给内核，不等于字符已经显示出来，真正的设备输出可以由内核异步完成。
整个过程只有「陷入—服务—返回」这一段在内核态，用户程序自己从头到尾没碰过 I/O 指令。
两种态与特权指令
  • 内核态（管态 / 核心态）：能执行全部指令、访问全部软硬件资源；操作系统运行在此态。
  • 用户态（目态）：只能执行非特权指令、只能访问本进程的地址空间；用户程序运行在此态。
  • CPU 里程序状态字（PSW）有一位专门记当前处于哪一态，态切换时由硬件改写。
  • 特权指令（只能在内核态执行）：I/O 指令、开 / 关中断指令、置时钟、修改 PSW 与访存保护寄存器、停机指令。
  • 非特权指令（用户态可执行）：算术逻辑运算、在本进程空间内的取数存数、用户空间内的转移指令。
  • 用户态一旦执行特权指令，硬件立刻触发异常，控制权交内核处理（通常终止该进程）。
态翻面的三种入口（都从用户态进内核态）
  • 系统调用：程序主动请求服务，靠 trap 指令自愿陷入——如请求读写文件、创建进程。
  • 异常（内中断）：当前指令被动引发，与指令同步——缺页、除零、访存越界、在用户态用特权指令。
  • 外部中断：与当前指令无关的外部事件，异步到达——时钟中断、I/O 操作完成中断。
  • 三者共同点：响应时都会保存现场（概念上即 PSW 与 PC，具体保存机制因体系结构而异）并切到内核态处理；处理之后，内核可能恢复原进程继续运行，也可能调度另一个进程，严重异常还会直接终止故障进程。
例题
例 · 哪些事件会引起用户态 → 内核态（状态机模拟）
下列事件中，会引起 CPU 由用户态转为内核态的是（　）。
I. 用户程序执行系统调用　II. 时钟中断发生　III. 用户程序在用户态执行一条特权指令　IV. 用户程序访问一个无访问权限的虚拟页面

逐条判：I 是 trap 自愿陷入 ✓；II 外中断响应必须进内核处理 ✓；III 特权指令在用户态执行触发异常 ✓；IV 访问无权限的虚拟页面，触发访问保护异常 ✓。

态切换 ≠ 进程切换：进内核处理完中断可以原样返回原进程，进程并没换；别一看到「进内核」就选「发生进程切换」。
调用库函数不切换——只有真正执行到 trap 指令那一刻才陷入内核，printf 前面一大半工作都在用户态。

2. 操作系统的结构与引导 · 附概念与功能 ★★★★ · 近6年×4

操作系统自己怎么搭起来、开机后怎么被装进内存跑起来、它对外提供哪些本事——这张卡讲清（后半并入「概念与功能」一节）。

先定性：OS 是什么、管什么
  • OS 是最基本的系统软件：控制和管理整个计算机的软硬件资源，合理组织调度工作与资源分配，并提供用户与应用程序的接口。
  • 处理机管理：以进程为单位分配 CPU（进程的创建、调度、同步都在此）。
  • 存储器管理：内存的分配回收、地址变换与保护。
  • 文件管理：文件的存储、目录、共享与保护。
  • 设备管理：I/O 设备的分配、驱动与缓冲。
  • 用户接口：命令接口（敲命令）、程序接口（就是系统调用，见 os-1）、图形接口。
  • 多道程序设计：内存里同时放多道程序，一道等 I/O 时 CPU 转去跑另一道——单处理器下宏观并发、微观上交替运行（多处理器则可以真正并行），换来 CPU 利用率与系统吞吐量的提高。
结构：一部拆分史
  • 无结构：一堆过程互相乱调用，快而乱，不可维护——起点。
  • 模块化：按功能切成模块、定好接口，模块间按规定调用；结构清晰，但接口一乱仍会牵一发动全身。
  • 分层式：自底向上分层，上层通常通过下层提供的接口获得服务（是否只许调用相邻下一层，取决于具体设计）：利于模块化与验证，代价是层间调用可能带来额外开销、层次边界难划清。
  • 宏内核（单体内核）：进程、文件、网络、驱动等全部服务都挤在内核态运行——调用快，但内核庞大、一处崩全盘崩。
  • 微内核：内核只留最基本的功能——进程间通信、低级地址空间管理、中断处理、原语；文件系统、驱动、网络等通常做成用户态的服务进程——可靠、易扩展易移植，代价是服务之间频繁通信与态切换、性能开销大。
  • 外核：不做抽象，直接把硬件资源安全地复用分给应用程序、让应用自己管——知道这个概念即可。
虚拟化与 VMM
  • VMM（虚拟机监控器 / Hypervisor）在一台物理机上虚拟出多台「裸机」，每台虚拟机可装不同的 OS 同时运行。
  • 第一类 VMM：直接运行在硬件之上，自己就是最底层。
  • 第二类 VMM：运行在宿主 OS 之上，是一个普通应用程序，靠宿主调度硬件。
  • VMM 的活：虚拟 CPU 的调度、虚拟内存的映射截获、虚拟 I/O 设备的模拟与转发。
系统引导：从按下电源到内核接管
共同主线：固件上电自检、初始化硬件 → 把引导程序或内核映像加载进内存 → 内核自初始化（建中断向量表，初始化内存、进程、文件等各个管理器）→ 启动初始用户态进程（如 init / systemd），此后进入登录界面 / 图形界面，系统才算「起来了」。
传统 BIOS / MBR 路径：固件按设定顺序找到启动磁盘，执行主引导记录（MBR）里的引导代码，由它把更完整的引导程序与 OS 内核装入内存并移交控制权。
UEFI 路径：固件的启动管理器直接从 EFI 系统分区加载 EFI 引导程序，由它装入内核——不依赖 MBR 里的引导代码。
一句话收：先有引导程序，才有内核——内核不是自己走进内存的。

例 1 · 多道程序设计的利用率（时间轴程序模拟）
两道相同的程序，每道都是「计算 10 ms → I/O 30 ms → 计算 10 ms」，各自使用独立的 I/O 设备。求单道与多道下的总完成时间和 CPU 利用率。
单道：两道串行跑完，总时间 = 2 × 50 = 100 ms，CPU 忙 40 ms → 利用率 40%，其余 60 ms CPU 在干等 I/O。
多道：画时间轴——A 先算（0–10），A 去做 I/O（10–40），B 顶上算（10–20），B 去做 I/O（20–50）；40 时 A 的 I/O 完成、续算（40–50）；50 时 B 续算（50–60）→ 全部完成 60 ms。

例 2 · 微内核辨析
关于微内核结构的操作系统，下列说法正确的是（　）。
A. 文件系统运行在内核态　B. 其性能开销主要来自进程间通信与频繁的态切换　C. 把所有系统服务都放进内核以提高可靠性　D. 微内核只负责进程调度
逐项判：A 错——文件系统是用户态服务进程；B ✓——服务拆到用户态后，请求要靠消息传递来回切态；C 说的恰是宏内核；D 漏了通信、地址空间管理、中断处理等基本功能。
答案 B。
微内核的服务跑在用户态——把「服务放进内核」记到微内核头上，恰好记反，那是宏内核。
多道提高的是利用率与吞吐量；单看某一道程序，它的周转时间反而可能变长（要和别人分 CPU）。
引导顺序别倒背：固件自检 → 引导程序进内存 → 内核进内存，内核排在引导程序之后。
「跑在宿主 OS 上」的是第二类 VMM；第一类直接在硬件上，别混。
分层结构的代价在层间调用的额外开销，不是因为「层数多占内存」。

7. 信号量 PV 操作 ★★★★★ · 近6年×3
P(S)
S = S − 1；若 S < 0，阻塞当前进程。
V(S)
S = S + 1；若 S ≤ 0，唤醒一个等待进程。
互斥信号量初值 = 1。
同步信号量初值 = 资源数量或 0。
S 的读法：S > 0 时，S 就是还可用的资源数、无人等待；S = 0 时资源恰好分配完、无人等待；S < 0 时资源已分完，正在等待的进程数 = |S|。
例（信号量值全程追踪）：某资源共 2 台，信号量 S 初值 2。
时刻动作S发生了什么
t1P1 执行 P(S)1P1 占用 1 台，剩 1 台空闲
t2P2 执行 P(S)0P2 占用最后 1 台，无空闲
t3P3 执行 P(S)−1无资源，P3 阻塞等待；等待进程数 = |S| = 1
t4P1 执行 V(S)0S ≤ 0 → 唤醒 P3，P3 接手那台资源
t5P2 执行 V(S)1无人等待，空闲资源回到 1 台
读法就此立住：
S > 0 时 S 就是空闲资源数。
S < 0 时 |S| 就是等待进程数。
S = 0 表示资源刚好占满、无人等待。
坑：生产者—消费者问题中，P 操作顺序不能换（先 P 同步，后 P 互斥）。
8. 经典同步问题 · 生产者-消费者 / 读者-写者 ★★★★★ · 近6年×3

生产者-消费者（有界缓冲，容量 n）：

信号量 mutex = 1（互斥）。
empty = n（空位）。
full = 0（产品数）。
生产者：P(empty) → P(mutex) → 放入产品 → V(mutex) → V(full)。
消费者：P(full) → P(mutex) → 取出产品 → V(mutex) → V(empty)。

读者-写者（读者优先版）：

readcount（在读人数）。
mutex（保护 readcount）。
wrt（读写互斥）。
读者：P(mutex)，readcount++，若 readcount = 1 则 P(wrt)，V(mutex)，读。
读完 P(mutex)，readcount−−，若 readcount = 0 则 V(wrt)，V(mutex)。
写者：P(wrt)，写，V(wrt)。
必考坑：生产者-消费者里 P 的顺序不能反——先 P(mutex) 再 P(empty)，缓冲区满时生产者占着互斥量等空位、消费者又等互斥量，直接死锁。
读者优先版会饿死写者。要写者优先需再加一个写互斥信号量。

11. 连续内存分配算法对比 ★★★★★ · 近6年×3
算法选哪块效果 / 代价
首次适应从低地址起第一个够大的空闲区实现简单、通常查找开销较低；低地址碎片多，但高地址常保留大块

邻接适应（循环首次）从上次分配处往后找第一个够大的空闲区分布均匀；大空闲区匮乏

426 → 无块可容，失败（空闲总量还剩 935K，却没有一块 ≥ 426K——这就是外部碎片）。
最佳适应：212 → 300K 块（余 88K）。
417 → 500K 块（余 83K）。
112 → 200K 块（余 88K）。
426 → 600K 块（余 174K）→ 全部装下，代价是留下三个几十 K 的小碎片。
最坏适应：212 → 600K 块（余 388K）。
417 → 500K 块（余 83K）。
112 → 388K 余块（余 276K）。

内存管理概念（前置）

后面的分配算法表回答的是「空闲区选哪块」，但一道内存题真正常问的第一步在更前面：程序是怎么进内存的、地址是在什么时候定死的。先把这条链走一遍：源程序 → 编译 → 链接 → 装入 → 运行，每一步都在推迟或提前「地址定死」的时刻。

装入方式地址什么时候改过程与代价
绝对装入编译时就知道驻留地址，直接生成绝对地址（物理地址）装入程序按地址原样放进去即可；只适合单道环境，地址一旦被别人占了就没法跑
可重定位装入（静态重定位）装入时一次性把逻辑地址全部改成物理地址（地址变换 = 装入地址 + 逻辑地址）装入后代码里写的就是物理地址，运行时不再变换；代价：运行期间不能再移动、必须一次分到连续整块内存
动态运行时装入（动态重定位）装入时一个地址都不改，推迟到每条指令真正执行、访存的那一刻才变换靠硬件重定位寄存器（基址寄存器）：物理地址 = 基址 + 逻辑地址，每次访存自动加；程序可以在内存里被移动，搬完只改基址寄存器的值，代码一字不动
链接方式什么时候链接特点
静态链接装入之前，把目标模块与库函数拼成一个完整装入模块运行时不再需要库；每个程序各带一份库代码，浪费内存，库更新要重新链接
装入时动态链接装入时，边装入边找外部模块链接装入时动态链接：程序装入时解析和链接所需模块，模块加载由具体装入和链接机制决定；几个程序可共享同一份库模块
运行时动态链接运行时第一次用到某模块时才链接并装入运行时动态链接：允许将部分模块的加载或链接推迟到实际需要时，可能减小初始装入工作量，但首次调用及总运行开销仍取决于具体实现；便于更新与共享
逻辑地址
又叫相对地址 / 虚拟地址：程序自己视角的地址，从 0 开始编（如「本程序第 2500 号单元」），与最终住在哪儿无关
物理地址
内存的绝对门牌号，地址总线最终送出的就是它；逻辑地址经地址变换（静态在装入时、动态在运行时逐次）落到物理地址

分配与置换的「四问」框架——分页、请求调页的题，不管问到哪一步，都先落回这四个问题定位：

问题问的是对应策略
何时调入页面什么时候从外存进内存调入策略：预调页（预先调入预测将被访问的若干页面，可能调错白占内存）vs 请求调页（缺页才调，必用得上但缺页中断多）
从哪调入缺的那页应从其后备存储位置读入从哪调入由页面的后备存储位置决定。在教材简化模型中，外存可划分为文件区与对换区；具体页面应从其当前保存的位置读取，不是每次缺页都按固定的对换区→文件区顺序搜索。
本节的『对换区』指请求分页系统用于保存换出页面的后备存储空间，不是作为独立内存管理技术的进程整体交换与覆盖机制（该专题已不在考纲内）。
调入哪儿内存里放进哪个空闲位置分配策略：固定分配 / 可变分配 × 局部置换 / 全局置换的组合（固定+局部、可变+全局、可变+局部）
淘汰谁内存满了、又没空闲框时赶走哪页置换策略：OPT / FIFO / LRU / CLOCK 等页面置换算法，赶错了就多缺页
例 · 动态重定位的地址换算（脚本验算）
条件：某程序用动态运行时装入，逻辑地址空间长 6000（限长寄存器 = 6000），装入后重定位寄存器（基址）= 12000。程序执行中访问逻辑地址 2500 与 6500，各发生什么？
访 2500：先比限长，2500 < 6000 合法 → 物理地址 = 12000 + 2500 = 14500，地址总线送 14500 出去访存。
访 6500：6500 ≥ 6000，越界——还没轮到加基址就被限长寄存器拦下，产生地址越界中断，进程被处理，这次访存不发生。
再想一步：若系统把这份程序整体挪到 20000 处（腾地方做紧凑），静态重定位的版本只能重新装入改地址；动态版本只把重定位寄存器改成 20000，逻辑地址 2500 自然落到 22500，程序代码一字不改 ✓
【坑】静态重定位与动态重定位的分界是「地址改没改进行时」：静态在装入时把地址写死进代码，动态永远不改代码、只靠寄存器在访存瞬间算。还有一对别混：链接的三种与装入的三种名字像、问的不是一回事——链接管「模块拼不拼、什么时候拼」，装入管「地址定不定、什么时候定」。
12. 请求分页 · 缺页中断处理步骤 ★★★★★ · 近6年×6
  1. 1查页表：驻留位为 0 → 产生缺页中断（内中断 / 异常，可恢复）。
  2. 2保存现场，查外存地址，确定页面所在外存位置。
  3. 3有空闲内存块 → 直接用；无空闲块 → 按置换算法选牺牲页，脏页先写回外存。
  4. 4把缺失页调入内存，修改页表（驻留位 1，修改位 / 访问位清零或置位）。
  5. 5恢复现场，重新执行引起缺页的那条访存指令（不是下一条）。
缺页中断返回点是故障指令本身，这正是它能“恢复”的关键；一般外中断返回的是下一条指令。

分配与置换组合只有三种：固定分配局部置换、可变分配全局置换、可变分配局部置换。

13. 段页式存储管理与地址变换 ★★★★★ · 近6年×3

《连续内存分配》与《请求分页》之外，把两者合起来的段页式常单独出题：逻辑地址是三段，变换是“先段后页”，访存次数与越界检查是选择题与计算题的双料考点。

逻辑地址结构：段号 S | 段内页号 P | 页内偏移 W。若页大小为 2w，则 W 占 w 位；段长可变，段内页数不定——这是它与纯分页（一维地址）最根本的区别。

表表项内容一张还是多张
段表段长、页表始址（该段页表的基址）每进程一张
页表页框号，以及状态 / 权限位每段一张
  1. 查段表：段号 S ≥ 段表长度 → 越界中断。
  2. 查段长：段内偏移 = P × 页大小 + W，若 ≥ 该段段长 → 越界中断。
  3. 查页表：由段表项给出的页表基址 + P 找到页表项；页表项不存在或页面不在内存 → 缺页中断（请求段页式下由系统调页），权限不符 → 访问越权中断。
  4. 拼物理地址：物理地址 = 页框号 × 页大小 + W；页内偏移在变换前后原样保留。
方式地址碎片与共享
分页一维：页号 | 页内偏移无外碎片，每页有内零头；共享与保护较弱
分段二维：段号 | 段内偏移段长可变利共享保护，但有外碎片
段页式三段：段号 | 段内页号 | 页内偏移兼得两者：分段管共享保护，段内分页消灭外碎片，段内只剩最后一页的内零头
  • 访存次数（不计快表）：查段表 1 次 + 查页表 1 次 + 访问数据 1 次 = 3 次；段表项与页表项进入快表且命中时只需 1 次数据访问。
    • 图：段页式地址变换四步（数字即下方例题数据）：查段表、查页表各一次，再拼页内偏移。
  • 例题：页大小 4 KB，段 1 的页表中第 2 页对应页框号 45，逻辑地址（段 1，页 2，偏移 0x1A3）。物理地址 = 45 × 4096 + 0x1A3 = 184739 = 0x2D1A3。验算：页框号 45 = 0x2D，偏移 0x1A3 < 4 KB，故直接拼接得 0x2D1A3 ✓
易错：变换顺序是“先段后页”，不要先拼页号再查段；页内偏移变换前后不变，凡是把偏移也换算一遍的都是错的；段页式仍有缺页中断，别因“段已在内存”就断定页一定在内存。
14. 页面置换算法对比 ★★★★★ · 近6年×3
算法Belady 异常特点
OPT（最佳页面置换）无理论最优、不可实现
FIFO（先进先出）有可能越换内存越慢
LRU（最近最久未使用）无需要硬件支持
CLOCK有LRU 的近似
Belady 异常：给进程多分物理块（页框），缺页次数反而可能增多。
它可发生在 FIFO 与 CLOCK 上——二者都不满足栈算法的包含性。
OPT、LRU 是栈算法，不会发生。
经典例（FIFO）：访问串 1,2,3,4,1,2,5,1,2,3,4,5，分 3 块缺页 9 次，分 4 块反而 10 次。
CLOCK 反例：访问串 1,4,4,7,3,4,1,4,4,6,1,4，标准 CLOCK（第二次机会算法）下 3 页框缺页 6 次、4 页框反而 7 次（程序模拟验证）。

文件共享与保护

本卡前面说过：目录项只有「文件名 + inode 号」，文件名不在 inode 里。共享就是从这条长出来的——同一个文件可以有几个名字，区别只在「几个名字怎么指向文件」。

　硬链接符号链接（软链接）
存的是什么新目录项直接指向同一个 inode，与原目录项平级，没有主次一个独立的新文件（有自己的 inode），文件内容就是目标文件的路径名字符串
对 inode 计数的影响inode 的链接计数 +1目标 inode 的计数不变
删除语义删除一个硬链接使链接计数减 1；链接计数降为 0 且没有其他打开引用时，才最终回收 inode 与数据块删目标（或目标改名）后链接还在、但指向的路径已不存在 → 悬空（失效）链接，打开时报错；删链接本身不影响目标
能力边界不能跨文件系统（inode 号只在本文件系统内有意义）；一般不能给目录建硬链接（防目录成环）可以跨文件系统、可以指向目录；代价是每次打开都要多走一遍路径解析
例 · 一次建链、两次删除，把计数走完（脚本模拟计数断言）
初始：建文件 /a/report.txt，占 inode 42，链接计数 = 1。
第 1 步 建硬链接 /b/report2.txt：新增目录项指向同一个 inode 42，计数 1 → 2。两个名字平级，改哪个名字的内容，另一个读到的也变。
第 2 步 建符号链接 /c/link.txt，内容存路径「/a/report.txt」：它占自己的 inode，inode 42 的计数仍是 2。此时经 /c/link.txt 打开，能正常读到数据。
第 3 步 删 /a/report.txt：计数 2 → 1，文件不回收，经 /b/report2.txt 照样读得到数据。
但 /c/link.txt 此时已经悬空：它认的是路径名不是 inode，路径 /a/report.txt 的目录项没了，哪怕数据还躺在 /b 名字下，经它打开也报「文件不存在」。
第 4 步 再删 /b/report2.txt：计数 1 → 0，这时才真正回收 inode 42 与数据块（假设没有进程保持该文件打开）✓
结论口诀：硬链接删名字不删文件，计数归零才删；符号链接认路不认人，路断即悬空。

访问控制（保护）——谁能对文件做什么，三种说法其实是一张表：

访问控制矩阵
全局表：行 = 主体（用户 / 进程），列 = 客体（文件），格子 = 允许的操作（读 / 写 / 执行…）。概念原型，真实系统太大、太稀疏，不直接存整表
访问控制表 ACL
把矩阵按列存：每个文件带一张表，写明「哪些用户 / 组对本文件有什么权限」。查一个文件的权限最直接；反过来查「某人能碰哪些文件」要扫全部文件
UNIX rwx
传统 UNIX 权限位是比 ACL 更简单的权限控制机制：只分文件主 / 同组用户 / 其他用户三组，每组 3 位 r（读）w（写）x（执行），共 9 位。判定顺序：先看是不是文件主，是则只用文件主那组位，不再往后看；不是再看组、再看其他
例 · 权限位判定（真题风格）
文件 report.txt 的权限为 rwxr-x---，文件主是 alice，所属组是 dev。bob 不是文件主、但在 dev 组内；carol 既不是文件主、也不在 dev 组。问：bob、carol 各能做什么？
bob 按组位判定：r-x → 可读、可执行，不可写——想改文件内容会被拒。
carol 按其他用户位判定：--- → 读、写、执行全无，连读都不行。
alice 按文件主位判定：rwx 全开。注意判定是「命中一档即停」：哪怕 alice 同时也在 dev 组，也只按文件主那组位算，不会两组取并集 ✓
坑
① 符号链接本身是一个文件、有自己的 inode；说「软链接不占 inode」是错的——它只是不动目标的计数。
② 硬链接的两个名字没有「原件 / 副本」之分，删掉所谓「原件」文件毫发无损，直到最后一个名字删掉。
③ 文件名保存在目录项中，改名通常无需修改文件数据；创建硬链接会增加目标 inode 的链接计数，删除硬链接会减少计数。
④ rwx 对目录的含义要换：r = 能列目录名，w = 能在目录内建 / 删文件，x = 能进入并访问目录内文件；目录没有 x 位时，就算文件本身可读也打不开。

分配方式目录记什么优点缺点
连续分配起始块号 + 长度顺序、随机访问都快扩展难；外部碎片
链接分配（隐式）起始块号 + 结束块号，每块带下一块指针扩展容易，无外部碎片只支持顺序访问，随机访问须从头顺链

索引分配索引块地址；索引块集中存各逻辑块的物理块号支持随机访问；扩展容易小文件索引块利用率低；大文件需多级 / 混合索引
算例（盘块 4 KB、块号 4 B，每索引块存 1024 个块号）：单级索引最大文件 = 1024 × 4 KB = 4 MB。
两级索引最大 = 1024 × 1024 × 4 KB = 4 GB。
17. 混合索引分配 · inode 最大文件长度 ★★★★★ · 近6年×4

《文件物理结构对比》卡算过单级、两级索引的最大文件；真实系统用的是拼起来的混合式：直接地址管小文件、多级间接管大文件。

混合索引分配（Hybrid Indexed Allocation，混合索引分配）的代表是 UNIX 的 inode（索引结点）：一组地址项里同时放直接块号和各级索引块的块号。

本卡设定（王道 / UNIX 式）
盘块大小
4 KB
盘块号大小
4 B → 每个索引块能放 4 KB ÷ 4 B = 1024 个块号
单位口径
本卡 KB / MB / GB / TB 均按 1024 进位（1 KB = 210 B）
inode 地址项
共 13 个：10 个直接 + 1 个一级间接 + 1 个二级间接 + 1 个三级间接
例题
例 1 · 最大文件长度，一级一级加上去（公式重算）
直接部分：10 × 4 KB = 40 KB——文件不超过 40 KB 时，块号全在 inode 里，一步到位。
一级间接：1024 × 4 KB = 4 MB
二级间接：10242 × 4 KB = 4 GB
三级间接：10243 × 4 KB = 4 TB
最大文件长度 = 40 KB + 4 MB + 4 GB + 4 TB ≈ 4 TB（四部分全加，精确值 4,402,345,713,664 B）✓
例 2 · 一个 5 MB 的文件，要动用第几级？（公式重算）
直接 + 一级的上限 = 40 KB + 4 MB = 4136 KB。
文件 5 MB = 5120 KB > 4136 KB → 必须动用二级间接。
超出部分 = 5120 − 4136 = 984 KB → 984 ÷ 4 = 246 个数据块。
二级索引下的第一个一级索引块就能放 1024 个块号 ≥ 246 → 这部分只占二级索引里的 1 个一级索引块 ✓
顺带记：读一个数据块要几次访盘

假设 inode 已在内存、且所需间接索引块尚未被缓存：直接块 1 次（直达数据块）；一级 2 次（先读索引块）；二级 3 次；三级 4 次。若索引块已经在缓存里，实际读盘次数还会更少。这就是小文件用直接地址的原因——不只是省空间，更是少跑磁盘。

坑
① 索引块里存的是块号、不是文件数据：算最大文件长度时只累加数据块，别把索引块本身算进文件长度。
② 第一动作永远是先算「每个索引块放几个块号」= 盘块大小 ÷ 盘块号大小；盘块号若改成 8 B，每块只放 512 个，各级结果全变。
③ 最大长度是四部分之和：只写最高级的 4 TB 会漏掉 40 KB + 4 MB + 4 GB 的零头，精确选项就栽在这。
④ 与《文件物理结构对比》卡的算例别串：那张是纯单级 / 纯两级索引（没有直接地址项），本卡是四种拼在同一个 inode 里。
18. 磁盘空闲空间管理 · 位示图与成组链接法 ★★★★★ · 近6年×5

合辑讲了磁盘调度与访问时间、文件物理结构，但没讲空闲盘块本身怎么管。文件系统大题问“盘上还剩多少空闲块、某块分给谁”时，答案就在这张卡。

位示图法（Bitmap）

用 1 位表示 1 个盘块，位示图常驻内存。

约定（王道口径，题干若反着给以题干为准）：1 = 已分配，0 = 空闲。

设字长为 w 位、盘块号为 b（均从 0 起数）：字号 = ⌊b / w⌋，位号 = b mod w；反推：块号 = 字号 × w + 位号。

若块号、字号、位号均从 1 起数，须先对块号减 1 再套上式：字号 = ⌊(b − 1) / w⌋ + 1，位号 = (b − 1) mod w + 1；反推：块号 =（字号 − 1）× w + 位号。

分配：找 0 位置 1，返回块号；回收：对应位置 0。

找空闲块时可按字扫描——先找非全 1 的字，再在字内找 0 位。

例题（程序验算）
① 盘块号 100，字长 32 位 → 字号 = 100 ÷ 32 = 3，位号 = 100 mod 32 = 4（3 × 32 + 4 = 100 ✓）。反推：字号 5、位号 7 → 块号 = 5 × 32 + 7 = 167。
② 磁盘容量 256 MB，盘块 4 KB → 盘块总数 = 256 MB ÷ 4 KB = 65,536 块，位示图需 65,536 位 = 8,192 B = 8 KB。
③ 位示图大小通用式：盘块数 ÷ 8（字节数），算完记得把位换成字节。
④ 编号 1 起的边界（w = 32，程序验算）：b = 32 → 字号 = ⌊31 / 32⌋ + 1 = 1，位号 = 31 mod 32 + 1 = 32；b = 33 → 字号 = 2，位号 = 1。
空闲链表法（对照）

空闲盘块链——每个空闲块存下一个空闲块号，链首在专用块。

空闲盘区链——连续空闲区为一个结点，存首块号与块数。

实现简单，但分配/回收要顺链改指针，不如位示图找块快。

成组链接法（Grouped Linking，UNIX 采用）

把空闲块分组（王道例中每组 100 块，组内块数上限以题干为准），除第一组外，每组的组首块（链接块）存放下一组的空闲块数与各块号；第一组的信息存放在专用块（超级块）中。

分配：从专用块取一块；组内取空时，把下一组的信息读入专用块再取。

回收：专用块所指组未满，直接把回收块号加入；组已满时，先把专用块内容写入新回收块（它成为新一组的链接块），再把该回收块号写入专用块作组首。

坑：
① 字号/位号的起点（0 起还是 1 起）是本题最常见的丢分点：0 起时字号 = ⌊b/w⌋；1 起时先对块号减 1 再套公式（字号 = ⌊(b−1)/w⌋ + 1、位号 = (b−1) mod w + 1），切勿在 0 起的结果上直接各加 1——b 恰为 w 的整数倍时会整字错位。做题先看题干编号方式，不要硬套。
② 位示图“1 空闲还是 0 空闲”各教材相反，题干给的约定优先于记忆。
③ 成组链接回收的两条路不要混：组未满是“直接加入”，组满是“旧专用块内容先落盘成新组首”，顺序一反，下一组的链就断了。
位示图本身占多大：一个盘块对应 1 位，故位示图总位数 = 盘块总数，总大小 = 盘块总数 ÷ 8 B（再除以字长即得字数，与字号公式衔接）。
19. I/O 设备与控制方式（OS 侧） ★★★★★ · 近6年×4

定位：OS 第 5 章输入输出管理。合辑 co-25／co-26 讲的是计组口径——中断响应的硬件时序、DMA 怎样访存，那些本卡不重复；本卡只回答 OS 这一侧的问题：设备怎么分类、四种控制方式下 OS 如何组织一次 I/O、一次请求在 I/O 软件的各层之间怎样分工。第二节把 A1 点「设备独立性软件」并入本卡。

一、I/O 设备与控制方式

先摆一个场景：一台机器上同时挂着键盘、行式打印机和磁盘，三个进程分别要用它们。OS 管理设备的第一步，是先按三个维度认清每台设备是什么脾气——分类不是背表，每个维度都直接决定后面怎么管。

按传输速率键盘、鼠标是低速设备（每秒几个到几百字节）；行式打印机是中速设备；磁盘是高速设备（每秒兆字节量级）。考题只认典型设备所属的量级，不抠精确边界。
按交换单位磁盘是块设备：数据以固定大小的数据块为单位交换，块可按地址寻址、随机存取。键盘、打印机是字符设备：数据像水流一样逐字符进出，不能寻址，来了就得及时接，所以天然适合中断方式。
按共享属性打印机是独占设备：一段时间内只能分给一个进程，否则两份作业的输出会交错成一团。磁盘是共享设备：多个进程交替访问同一盘面互不干扰。独占设备经 SPOOLing 可以改造成逻辑上可排队共享的虚拟设备（见《SPOOLing 假脱机技术》卡）。

认清设备之后，OS 要决定「一次传送由谁盯着」。同样是读入数据，四种控制方式下 CPU 和进程的状态完全不同：

程序查询驱动发出读命令后，CPU 反复读控制器的状态寄存器问「好了没」，进程忙等不让出 CPU，设备没就绪就一直空转。CPU 与设备严格串行，只适合极简单、慢速的场合。
中断驱动在典型的阻塞式 I/O 请求中，进程发出请求后就阻塞、让出 CPU 去跑别的进程；设备传完一个数据单位就发一次中断，中断处理把它接走、再唤醒或继续喂下一个单位。键盘敲一个字中断一次，正合适；但单位一多，中断就频繁。
DMA进程要整块读盘时，驱动把内存首址、字节数写进 DMA 控制器就阻塞等待；DMA 控制器自己管着把整批数据在内存与设备之间搬完；在本卡的一次批量传输模型中，整批全部完成才中断一次。为高速块设备而生（搬运细节与访存计算在计组卡里，本卡只记 OS 的分工）。
通道设备很多的大型系统里，CPU 把一串 I/O 操作写成存放在内存中的通道程序，只发一条启动指令把首址交给通道；通道是一个独立的 I/O 处理机，自己取通道指令执行、管着一组控制器和设备，在本卡的一次批量传输模型中，整串活干完才向 CPU 发一次中断。

通道再分三种（了解即可）：字节多路通道轮流为多台低速设备按字节交叉服务；数组选择通道独占通路伺候一台高速设备、一批传完才换人；数组多路通道让多台高速设备按数据块交叉传送。

OS 眼中的设备从来不是设备本体。进程要读盘，OS 碰的全是设备控制器的寄存器：往控制寄存器写命令、从状态寄存器读「忙／就绪／出错」、从数据寄存器取数据——机械与电气的脏活被控制器挡在下面，一台控制器还可以挂多台同类设备。再往上，通道在 OS 眼中是一个能代管一串 I/O 的下级处理机：CPU 只下「启动」，通道负责盯着它那组控制器把活干完。一条链记清：CPU — 通道 — 控制器 — 设备，OS 的命令逐级向下、完成报告逐级向上。

例题 1（真题风格，程序验算）
某系统有键盘、行式打印机、磁盘各一台。① 给三台设备分别按传输速率、交换单位、共享属性分类；② 进程要从磁盘一次读入 8 个数据块，分别比较中断方式与 DMA 方式的「完成中断次数」和「CPU 启动开销」；③ 磁盘这次读应选哪种控制方式？
推导 ①：键盘——低速、字符设备；行式打印机——中速、字符设备、独占设备；磁盘——高速、块设备、共享设备。三个维度互相独立，一台设备要在每个维度上各落一个格。
推导 ②：先分开两个指标。完成中断次数：中断方式每传完 1 个块产生 1 次完成中断，8 个块共 8 次；DMA 把 8 个块作为一次批量任务，整批完成产生 1 次完成中断。CPU 启动开销另计：在本示意模型中，中断方式要逐块发起或续发，启动处理随块数增长（计 8 次）；DMA 只在任务开始时设置控制器参数，计 1 次启动开销，完成中断的处理不算启动开销。程序查询不产生完成中断，它的反复轮询开销也不能与完成中断次数并列相加；通道承接整串任务时同样是 1 次完成中断，另有 1 次发启动指令的开销。
推导 ③：磁盘是高速块设备、批量大，选 DMA：一次任务只有 1 次完成中断，CPU 启动开销也只在开始设置参数时发生一次。若误用中断方式，8 次完成中断还只是小数目，大批量读盘时 CPU 会被频繁的完成中断和逐块启动处理淹没。
结论：分类抓「典型设备落格」，选型抓「批量越大、越要选打扰少的」。
二、设备独立性软件（I/O 软件层次）

一次 I/O 要分清两条路径，不能把四层软件的排列误读成一条单向调用链：

请求路径：用户进程 → 用户层 I/O 软件 → 设备独立性软件 → 设备驱动程序 → 控制器与设备。

完成路径：硬件中断 → 中断处理程序 → 完成通知、唤醒等待进程。

层次排列≠调用路径：中断处理程序位于软件层次的底层，并不表示用户请求先经它转发到硬件。

用户层离进程最近：提供库函数，把请求先加工成标准格式——如 printf 先把整数、浮点数拼成字符串，才发出系统调用。SPOOLing 的排队守护进程也住在这一层。
独立性层本节主角，对上给出统一接口：不管底下是磁盘还是打印机，进程用的都是同一套读／写调用，硬件细节被屏蔽。所有设备共有的公共活也都在这层干：逻辑设备名到物理设备的映射、独占设备的分配与回收、公共缓冲管理、差错处理与报告、按权限做设备保护。
驱动层与硬件直接绑定，一类设备一个驱动程序（同类不同型号也可各有驱动）：把上层抽象的「读第 k 块」翻译成往这台控制器的哪个寄存器写什么命令，并负责设置、检查寄存器状态。它只听独立性层的抽象命令，不负责分配和命名。
中断处理层离硬件最近的软件层：中断一到，先保存被中断进程的现场、辨认中断源，把最急的处理做完，再唤醒等待这次 I/O 的进程；中断的细节被它挡住，上层软件感觉不到。

映射具体怎么走一遍：进程用逻辑名 printer1 发起打印，独立性层查逻辑设备表，得到实际是哪台物理打印机、该用哪个驱动；再查设备状态，空闲就把这台独占打印机分配给该进程（正忙则让进程排队等待），随后把请求交给对应驱动去操作控制器；打印完成、逐层返回后，独立性层再回收设备给下一个进程。正因为映射在独立性层，临时把 printer1 改指另一台同型号打印机，进程的代码一个字都不用改——这就是「设备独立性」四个字的落点。

例题 2（真题风格，程序验算）
下列工作各属哪一层？I. printf 把待输出的整数格式化为字符串；II. 把逻辑设备名 printer1 映射到 2 号物理打印机；III. 为打印请求分配公共缓冲区并在出错时向上报告；IV. 向打印机控制器的寄存器写入启动命令；V. 中断到达时保存现场并唤醒等待打印的进程。
推导：I 发生在进程调用库函数、还没进内核的阶段 → 用户层。II、III 都是所有设备共有的公共事务、与具体硬件无关 → 设备独立性层（映射、缓冲、差错正是独立性层的三件标志性工作）。IV 直接摆弄寄存器、话里全是这台设备的细节 → 设备驱动程序。V 是中断现场的第一手处理 → 中断处理程序。
结论：I 用户层；II、III 设备独立性层；IV 驱动层；V 中断处理层。判题口诀：沾寄存器的是驱动，管公共事务的是独立性层。
坑：
① 查询方式下进程是忙等、不让出 CPU；中断方式下才是发完请求就阻塞。把两者状态说反是本节头号坑。
② DMA 不是「全程不用 CPU」：启动时设参数、完成时处理中断都要 CPU，它省的是搬运途中的干预。
③ 通道不是一种设备、也不是控制器：它是能执行通道程序的 I/O 处理机，站在控制器之上。
④ 块设备／字符设备看的是交换单位不是快慢：打印机再快也是字符设备，磁盘的立身之本是「以块为单位、可寻址」。
⑤ 设备独立性靠的是独立性层的统一接口，不是驱动通用——恰恰相反，驱动是每类设备专用的，正因为驱动各异，才需要独立性层来屏蔽差异。
⑥ 缓冲、差错、分配三件公共事都在设备独立性层：别把设备分配安到驱动头上，驱动只负责把分到手的设备操作起来（缓冲的单／双／池细节见《缓冲管理》卡）。
⑦ 层次顺序别倒：自上而下是用户层 → 独立性层 → 驱动层 → 中断处理层；中断处理层在最底，不是最上。

来源：王道《操作系统》第 5 章输入输出管理（设备分类与控制方式、I/O 软件层次与设备独立性）。真题依据：I/O 设备与控制方式 A 类正考 2010、2012、2017、2019、2022、2023、2024、2026；设备独立性软件 A 类正考 2009、2011、2012、2013、2020、2026（两点合并一卡两节）。例题经脚本状态／归属断言验算。与 co-25／co-26 分工：硬件中断时序、DMA 访存计算不在本卡。

22. SPOOLing 假脱机技术 ★★★

合辑的 I/O 部分讲了中断与 DMA，却没有这项把独占设备「变」成共享设备的经典技术——它几乎只考选择题，概念边界一错就丢分。

SPOOLing（假脱机技术，Simultaneous Peripheral Operations On Line，同时联机外围操作）

在多道程序环境下，用磁盘（可共享设备）作中转，模拟脱机输入/输出：利用磁盘上的输入井和输出井实现数据暂存与排队。

输入方向由输入进程把设备数据送入输入井、供进程读取。

输出方向由进程把数据提交到输出井、再由输出进程送往设备。

这样多个进程可以排队共享同一台独占设备的使用权，设备在逻辑上表现为一台虚拟设备，但同一时刻仍只服务一个作业。

组成作用
输入井 / 输出井磁盘上开辟的两块存储区：输入井暂存外部设备送来的数据，输出井暂存各进程待输出的数据（按作业组织成文件排队）
输入 / 输出缓冲区内存中的缓冲，负责井与设备、井与进程之间的数据中转，抹平速度差
输入 / 输出进程常驻的井管理进程（守护进程）：把设备数据搬进输入井、把输出井队列里的数据逐个送往设备
打印全流程（输出 SPOOLing）

① 进程申请打印，系统在输出井给它分配空闲空间，把要打印的数据拷入输出井。

② 系统把这次打印请求挂到输出井的请求队列上。

③ 进程至此即可返回继续运行，不必等打印机。

④ 输出进程按队列顺序，把输出井里的数据逐份送打印机打完。

多个进程可以先后「申请打印」，各自的数据在井里排队——对每个进程而言，打印机仿佛是它独占的，实则共享。

例题（示意数字，程序验算）
某作业要打印 200 页，打印机速度 5 页/分钟，实际打印需 200 ÷ 5 = 40 分钟。
无 SPOOLing 且采用同步独占打印方式时，进程可能因等待打印设备而长时间阻塞。
有 SPOOLing 时，进程只需把 200 页数据按磁盘速度写入输出井、挂上请求队列即可返回做别的事，40 分钟的打印由输出进程在后台完成，打印机完成 200 页仍需 40 分钟。
结论：SPOOLing 解耦的是「进程的等待时间」与「设备的服务时间」，设备本身一分钟也快不了。
坑：
① SPOOLing 没有把打印机变成真共享设备：同一时刻打印机仍只服务一个作业，共享的是「排队提交」这一层，别选「多进程可同时打印」。
② 「井」在磁盘上，不在内存——把它说成内存缓冲区的选项是错的；内存里只有输入/输出缓冲区。
③ 与缓冲技术分工不同：缓冲是内存中转、解决速度不匹配；SPOOLing 是外存设井 + 专门进程排队调度，核心目的是独占改共享，两者常配合但不是一回事。
23. 缓冲管理 · 单缓冲 / 双缓冲 / 缓冲池 ★★★

合辑在生产者-消费者与 SPOOLing 卡里都提到缓冲，但缓冲本身——为什么能抹平速度差、单缓冲与双缓冲处理一块数据各要多久——没有卡。缓冲（Buffering，缓冲）是王道输入 / 输出管理一章的计算考点，公式就两条，代错对象整题皆错。

为什么要缓冲

① 缓和 CPU 与设备之间速度不匹配的矛盾。

② 减少对 CPU 的中断次数、放宽对中断响应时间的限制。

③ 解决数据粒度不匹配（一次产生 / 消费的数据量与设备传输块大小不一致）。

④ 提高 CPU 与设备、设备与设备之间的并行性。

记号（王道口径）
T
= 设备把一块数据送入缓冲区的时间
M
= 缓冲区数据传送到用户区（工作区）的时间
C
= CPU 处理（计算）工作区中这块数据的时间
以下均为连续处理多块数据时的稳态平均每块时间（忽略第一块的装入）。
方式平均每块处理时间为什么
单缓冲max(C, T) + M缓冲区只有一个：数据在缓冲区与用户区之间传送（M）期间设备不能往里送下一块；但 CPU 计算当前块（C）时设备可同时装入下一块（T），两者取大者，再串上每块都躲不掉的 M
双缓冲max(T, C + M)两个缓冲区轮换：设备装一块（T）与用户侧「传送 + 计算」上一块（M + C）可并行，稳态由较慢的一侧决定
缓冲池—（不考公式，考构成）系统公用缓冲池由空缓冲队列、装满输入数据的输入队列、装满输出数据的输出队列管理，工作方式有四种：收容输入、提取输入、收容输出、提取输出，输入进程与输出进程共享使用
例题（公式重算）
设 T = 100 μs、M = 20 μs、C = 80 μs。
单缓冲：max(80, 100) + 20 = 120 μs / 块。
双缓冲：max(100, 80 + 20) = 100 μs / 块。
即双缓冲把瓶颈压到设备侧的 T 上——当 T ≥ C + M 时再加缓冲区也压不下每块时间，瓶颈在设备本身 ✓。
坑：
① 两条公式里 M 的位置不同：单缓冲的 M 串在 max 之外（每块必付），双缓冲的 M 在 max 之内（与 T 并行比大小）——记混是头号丢分点。
② 双缓冲不是「时间减半」：它只消掉可重叠部分的等待，稳态下限是 max(T, C + M)，设备慢时（T 大）加缓冲无用。
③ 缓冲在内存中、SPOOLing 的「井」在外存上：两者目的也不同（缓冲抹速度差，SPOOLing 把独占设备改造成可共享的虚拟设备），别混为一谈。
④ 循环缓冲是缓冲区的组织方式（多个缓冲区环形轮转、配 in / out 指针），适合数据流连续到达的场合，与「双缓冲 = 恰好两个」不是一回事。
四、计算机网络 （26 条）
1. OSI 与 TCP/IP 参考模型 · 分层与功能归属 ★★★★★ · 近6年×3

分层、各层干什么、一个功能该归哪层追责——这张卡讲清。选择题最爱在「功能归属」上设套。

跟着一封邮件下楼：OSI 七层各干一件事
  • 应用层：直接为用户进程提供服务，HTTP、FTP、SMTP 在这里产生数据。
  • 表示层：管数据的「长相」——编码格式转换、加密解密、压缩解压。
  • 会话层：建立、管理、终止进程间的对话（会话）。
  • 传输层：把数据分段、加端口号，提供端到端的进程间通信与端口复用；TCP 等协议可提供可靠传输、流量控制，UDP 只提供无连接的数据报传输。
  • 网络层：给分组选路——路由选择与转发，靠 IP 地址跨网络送达。
  • 数据链路层：成帧、MAC 寻址、CRC 检错，管相邻结点之间这一段的流量控制。
  • 物理层：在介质上传比特流，规定接口与信号特性，不管比特的含义。
  • 封装路线：数据 →（传输层）段 →（网络层）分组 / 数据报 →（链路层）帧 →（物理层）比特；传输层、网络层、数据链路层逐级封装各自的协议控制信息（首部），链路层通常还附加尾部；物理层只负责比特的传输，不再添加首部。

2. 时延计算 · 发送 / 传播时延与带宽时延积 ★★ · 近6年×2

合辑后面的利用率、滑动窗口、拥塞控制全在用时延打底，但「时延到底由哪几段组成」一直没有一张卡单独讲清。

时延（Delay，时延）拆成四段：发送、传播两段靠公式算，处理、排队两段看题意给不给。

四段时延与带宽时延积
发送时延
= 分组长度 ÷ 发送速率。把整个分组全部推上链路要花的时间；只跟分组长和速率有关，与距离无关
传播时延
= 链路长度 ÷ 信号传播速度。一个比特跑完全程的时间；只跟距离和介质有关，与分组长无关
处理时延
结点查表、检错等耗时，题目给多少算多少，没给就不计
排队时延
分组在结点缓冲里排队等待的耗时，没给就不计
带宽时延积
= 传播时延 × 带宽，单位是 bit：这条链路的「管道」里同时能容纳多少比特
例题
例 1 · 单链路：第一比特和最后一比特差在哪（公式重算）
条件：分组长 10,000 bit，发送速率 10 Mbit/s，链路长 1000 km，传播速度 2 × 108 m/s。
发送时延 = 10,000 ÷ 107 = 1 ms——到 1 ms 时，最后一比特才刚离开主机。
传播时延 = 106 ÷ (2 × 108) = 5 ms——任意一个比特跑完全程要 5 ms。
所以第一比特在 5 ms 时到达，最后一比特在 1 + 5 = 6 ms 时到达，整个分组收齐用 6 ms。
带宽时延积 = 107 × 0.005 = 50,000 bit = 5 个分组——链路上最多同时漂着 5 个分组的比特 ✓
例 2 · 两跳存储转发：每一段都要重付发送时延（公式重算）
同一个 10,000 bit 分组经一台路由器转发：第一段速率 10 Mbit/s、长 500 km；第二段速率 5 Mbit/s、长 500 km。传播速度同例 1。
存储转发（Store-and-Forward，存储转发）：路由器必须收齐整个分组才能往下一段发。
第一段：发送 10,000 ÷ 107 = 1 ms，传播 5 × 105 ÷ (2 × 108) = 2.5 ms。
第二段：发送 10,000 ÷ (5 × 106) = 2 ms，传播同为 2.5 ms。
总时延 = 1 + 2.5 + 2 + 2.5 = 8 ms（处理、排队时延未给，不计）✓
坑
① 发送时延的终点是「最后一比特离开主机」，不是到达对端；到达时刻还要再加一段传播时延。
② 单位先行：速率是 bit/s，分组长若给的是字节，先 × 8 换成 bit 再代公式。
③ 带宽时延积算出来是 bit 数、不是时间；问「能容纳几个分组」再除以分组长。
④ 多跳别偷懒乘倍数：每段速率可能不同，发送时延逐段重算；只有各段参数都相同时才可以简单乘跳数。

例 3 · 同一报文、同一链路，三种交换方式各算一遍（脚本验算；参数与例 1、例 2 错开）
条件：报文长 107 bit，经 2 段链路、1 个中间结点到达终点；每段速率 5 Mbit/s、传播时延 2 ms；电路交换的建立时延 50 ms；分组交换把报文切成 104 bit 一组（为简化不另计首部开销）。不计处理、排队时延。
先算公共量：分组数 n = 107 ÷ 104 = 1000 组；整报文在一段上的发送时延 = 107 ÷ (5 × 106) = 2000 ms；一个分组一段的发送时延 = 104 ÷ (5 × 106) = 2 ms。
电路交换：建立 50 + 发送 2000（整份只付一次，比特连续流过中间结点不再停）+ 传播 2 × 2 = 2054 ms。
报文交换：每段都要收齐整份再发：(2000 + 2) × 2 段 = 4004 ms——段数越多、报文越长，它涨得越狠。
分组交换：第一段串行发出 1000 组要 1000 × 2 = 2000 ms；第一组到达中间结点后，第二段只需再多等它转发 1 组的发送时延 2 ms，最后一组随即跟到；再加传播 2 × 2。总计 2000 + 2 + 4 = 2006 ms。
排序：分组 2006 ms < 电路 2054 ms < 报文 4004 ms ✓ 电路输在一次性建立开销，报文输在整份重发；分组靠流水线把第二段的等待压到只剩一个分组。

4. 物理层编码 · 不归零 / 曼彻斯特 / 差分曼彻斯特 ★★★★ · 近6年×1

《香农公式与奈奎斯特公式》只讲了信道容量，没讲数据怎么变成信号。本卡补物理层三种编码的规则对照——画波形题与“哪种编码自同步、带宽几倍”的选择题都从这里出。

编码规则（王道 / 802.3 约定）同步与带宽
不归零编码1 为高电平，0 为低电平（或相反，题干为准）；一位一个码元，码元内无跳变带宽利用高，但长串 0 / 1 无跳变，接收方难以同步，且有直流分量
曼彻斯特编码每位中间必跳变：1 为高 → 低，0 为低 → 高；中间跳变既传数据又作时钟自同步好，无直流分量；码元速率 = 2 × 数据速率，占用带宽约为不归零编码的 2 倍；用于 10 Mbps 以太网
差分曼彻斯特编码每位中间必跳变作时钟；位开始处：有跳变表示 0，无跳变表示 1自同步好；信号线接反仍可解码，对极性不敏感；用于令牌环等
例（数据 1011，曼彻斯特与差分曼彻斯特按每位前后两半列出，H 为高电平、L 为低电平）
不归零编码：H　L　H　H。
曼彻斯特编码：H L　|　L H　|　H L　|　H L。
差分曼彻斯特编码（设起始电平为低）：L H　|　L H　|　H L　|　L H。
核对差分曼彻斯特编码：
第 1 位 1，开始无跳变（L），中间跳变（H）。
第 2 位 0，开始跳变（L），中间跳变（H）。
第 3 位 1，开始无跳变（H），中间跳变（L）。
第 4 位 1，开始无跳变（L），中间跳变（H）✓
  • 补充：4B/5B 编码是分组码：每 4 位数据编为 5 位码字，效率 80%，码字经挑选保证有足够跳变助同步，用于快速以太网等；它不靠每位中间跳变，与曼彻斯特编码不是一回事。
易错：曼彻斯特编码与差分曼彻斯特编码的 1 / 0 规则不要只记“有跳变 = 1”：差分曼彻斯特编码是开始处有跳变表示 0；有些教材的曼彻斯特编码 1 / 0 取反，做题先看题干约定，以题干为准。
传输介质

本卡前面讲的是「比特怎么变成波形」（编码），这里补「波形在哪儿跑」：介质选错，后面的编码与速率都无从谈起。四类介质按「认特性、辨场景」记，不背参数表。

介质构造与原理特性与适用
双绞线两根绝缘铜线按规则绞合，绞合抵消相互干扰；多对再包成一根电缆。屏蔽双绞线（STP）每对 / 整缆外加金属屏蔽层，非屏蔽双绞线（UTP）没有最便宜、最易布线，局域网主力；STP 抗电磁干扰强于 UTP，但更贵更硬。5 类双绞线可用于 100BASE-TX，也可在满足相应布线要求时用于 1000BASE-T；超 5 类通常提供更好的传输裕量，常见于千兆以太网布线
同轴电缆内导体 + 绝缘层 + 网状外导体 + 护套，同心共轴；外导体兼作屏蔽抗干扰强于双绞线、带宽更高；基带同轴（50Ω）传数字信号、曾用于早期以太网，宽带同轴（75Ω）传模拟信号、用于有线电视。现在局域网里基本被双绞线与光纤取代
光纤纤芯（高折射率）+ 包层（低折射率），光在纤芯内靠全反射前进；发送端光源把电信号变光脉冲，接收端检测器再变回来带宽极大、损耗低、抗电磁干扰、不串扰、保密性好；贵、脆、接续难。两种见下行辨析
无线介质电磁波在自由空间传播：无线电波、微波、红外线等，不用铺线能过障碍到有线到不了的地方；代价是易受干扰、衰减随环境变、保密性差，定性辨析见下
单模光纤
纤芯很细（约 8～10 μm），光只沿一条路径（一个模式）直进，没有模式色散；用激光光源，衰减小、带宽大，适合长距离、大容量（骨干、城域），但光源与连接都贵
多模光纤
纤芯较粗（约 50 μm 量级），光以多条路径反射前进，各路径到达时间不同 → 模式色散把脉冲展宽，带宽与距离受限；可用便宜的 LED 光源，适合短距离（楼内、园区）
无线定性辨析
在其他条件可比时，较高频率的无线电波通常绕射能力较弱，穿透障碍物时的损耗也往往较大；具体传播损耗仍取决于介质、环境和天线条件。
例 · 介质说法逐项判（真题风格，脚本逐项核对）
问：下列关于传输介质的说法中，错误的是（　）。
A. 5 类非屏蔽双绞线可支持 100 Mbit/s 的以太网 —— 成立，类别与速率对应正是 5 类的定位。
B. 单模光纤纤芯细、使用激光光源、适合长距离传输 —— 成立，三点恰是单模与多模的分界。
C. 多模光纤存在模式色散，限制了带宽与传输距离 —— 成立，多路径到达时间差把脉冲展宽。
D. 无线电波频率越高，穿透能力越强、衰减越小 —— 不成立：错在把频率与穿透、衰减的关系说成必然规律——在其他条件可比时，高频电磁波通常绕射较弱、穿透障碍物的损耗往往较大；具体结果还受传播环境与材料等因素影响。→ 答案 D ✓
易错：光源别配反——单模配激光、多模常用 LED，题干常把两者对调设错；「屏蔽」防的是外界电磁干扰，STP 不是「更快」的代名词，速率看类别不看屏蔽；光纤传的是光脉冲不是电流，「抗电磁干扰」正因为它根本不导电，别写成「屏蔽得好」。
5. 组帧与透明传输 · 零比特填充 ★★★ · 近6年×2

合辑讲了物理层编码与 CRC，却没讲数据到了链路层先要解决的问题：一段比特流里，帧从哪儿开始、到哪儿结束；数据里恰好出现定界符的图案时怎么办。这正是组帧与透明传输。

组帧（Framing）四种方法
方法定界方式关键点
字符计数法帧首字段给出本帧的字节数计数字段一旦出错，可能导致后续所有帧边界失去同步、无自同步能力，现已少用
字符填充法帧首尾用特殊字符（如 DLE STX / DLE ETX）定界数据中出现 DLE 时，发送方在其前再填充一个 DLE、写成 DLE DLE 实现转义（单独的 STX／ETX 不带 DLE 前缀、不转义）；接收方见到成对 DLE 删去第一个、还原为数据 DLE，见到 DLE STX／DLE ETX 则作帧定界
零比特填充法帧首尾用标志字段 01111110 定界（HDLC，高级数据链路控制规程采用）见下：靠「连续 5 个 1 后插 0」保证数据中永不出现 6 个连 1
违规编码法用物理层不会出现的编码组合定界如曼彻斯特编码中用「高—高」「低—低」这种违规电平组合，只适用于有冗余编码的物理层

透明传输（Transparent Transmission）：不管数据里是什么比特组合，都能原样、无歧义地传过去——实现手段就是上面的填充/转义：发送方加工，接收方逆向还原。

零比特填充规则（必背）

发送方扫描整个数据字段，每遇到连续 5 个 1，就在其后自动插入 1 个 0。

接收方反向操作：每收到连续 5 个 1，若其后是 0 就删掉这个 0（填充位）。

若其后是第 6 个 1，须再看下一位才能判定——第 7 位是 0 才是标志字段（01111110），第 7 位仍是 1（连 1 达 7 个以上）则是帧出错／中止，不能仅凭第 6 个 1 就下结论。

这样数据字段中最多出现 5 个连 1，标志图案 01111110 永不与数据混淆。

例题（程序验算）
数据字段比特串：01101111101111111111011111（26 位）。
先数连 1 段：原串的连 1 段长依次为 2、5、10、5。长 2 的一段不足 5，不插；其余三段共插 4 个 0——位置逐个标出：第 2 段（长 5）在其第 5 个 1 后插 1 个，即原串第 9 位之后；第 3 段（长 10）在第 5、第 10 个 1 后各插 1 个，即原串第 15、20 位之后；第 4 段（长 5）在其第 5 个 1 后插 1 个，即原串第 26 位（末位）之后。
→ 发送比特串：011011111001111101111100111110（30 位，共填充 4 个 0；此位数仅指填充后的数据字段，不含首尾标志字段等帧开销）
接收方按逆规则删去这 4 个 0 后恰好还原为原 26 位 ✓（已做插删往返验证）
坑
① 插入点是「5 个 1 之后」，不是等出现 6 个 1 再插——真出现 6 个连 1 已经是标志或错误了。
② 填充统计要数清每一段连 1：连 1 跨过 5 后继续数（如 10 个连 1 要在第 5、第 10 个后各插一个 0，共 2 个）。
③ 透明传输不是没有代价：填充使实际发送长度膨胀（例题 26 → 30 位），算有效数据率时别忘了扣。
④ 字符计数法的死穴是「一错全乱」，与有自同步能力的填充法正好相对，选项里常互换设套。
6. CRC 循环冗余校验 · 计算步骤 ★★★ · 近6年×2
  1. 1收发双方约定生成多项式 G(x)，校验位数 r = G(x) 的最高次数。
  2. 2信息码左移 r 位，低位补 0。
  3. 3对移位后的码做模 2 除法（按位异或，不借位、不比较大小），得 r 位余数。
  4. 4余数补足 r 位作帧检验序列 FCS，拼在信息码后发送。
  5. 5接收端对整帧再模 2 除 G(x)：余数为 0 认为无错；余数非 0 则出错，丢弃 / 重传。
CRC 只检错、不纠错；能检出全部单比特错、全部奇数个错（前提：生成多项式 G(x) 含有因子 (x + 1)）和长度 ≤ r 的突发错。
余数为 0 不等于“绝对无错”，只是漏检概率极低。

8. GBN（后退 N 帧协议） 与 SR（选择重传协议） 窗口大小 ★★★★★ · 近6年×3

设序号位数为 n 位，序号范围 0 ～ 2n − 1。

GBN（后退 N 帧）
发送窗口 WT ≤ 2n − 1，接收窗口 WR = 1。
SR（选择重传）
发送窗口 + 接收窗口 ≤ 2n，通常各取 2n−1。

为什么 GBN 的接收窗口只能是 1、代价是什么，看例子：

例（一帧丢失，两种协议的反应）
序号 3 bit，发送窗口取 4。发送方连发 0、1、2、3 号帧，其中 1 号帧在途中丢失。
GBN：接收方只按序接收——0 号收下。
2、3 号到达时，它期待的是 1 号，乱序帧直接丢弃（重复发送对 0 号帧的累计确认；若按「下一期待帧」编号则写作 ACK 1）。
发送方超时后从 1 号起重传 1、2、3 三帧：2、3 明明已经到过一次，还得白传一遍，这就是「后退 N 帧」的代价。
接收窗口 = 1 的根源就在这：它不缓存乱序帧。
SR：接收窗口同样是 4，2、3 号先缓存下来。
发送方只需单独重传 1 号。
1 号一到，1、2、3 按序一起交付。
只补缺口、不传冤枉路，代价是接收方要有缓存、双方窗口都要受「和 ≤ 2n」约束。
9. 介质访问控制对比 · CSMA/CD（载波监听多路访问/碰撞检测） vs CSMA/CA（载波监听多路访问/碰撞避免） ★★★★★ · 近6年×5
项目CSMA/CD（检测）CSMA/CA（避免）
适用有线以太网 IEEE 802.3无线局域网 IEEE 802.11

交换表（MAC 地址表）：每项记（MAC 地址，所在端口，老化时间）。交换机对收到的每一帧做：

  1. 学源：把帧的源 MAC 地址与进入端口记入交换表（已有该项则更新端口并刷新老化计时）——学的是「谁从哪个口进来」。
  2. 查目的：用帧的目的 MAC 地址查表。查到且端口 ≠ 入端口 → 只从该端口转发（单播）；查到且端口 == 入端口 → 丢弃（过滤，说明收发双方在同一侧，不必转发）。
  3. 查不到就泛洪（Flooding，泛洪）：向除入端口外的所有端口转发；目的地址为全 1 的广播帧同样泛洪。
例题（按规则逐步推演）
交换机 4 个端口分别接主机 A（口 1）、B（口 2）、C（口 3）、D（口 4），初始交换表为空。
① A → B：学 A 在口 1；目的 B 查不到 → 泛洪到口 2、3、4。
② B → A：学 B 在口 2；目的 A 在口 1 → 只从口 1 转发。
③ C → A：学 C 在口 3；目的 A 在口 1 → 只从口 1 转发。
④ A → C：A 已在表（刷新计时）；目的 C 在口 3 → 只从口 3 转发。
最终交换表：A–1、B–2、C–3；D 从未发过帧、不在表中，此后发往 D 的帧仍要泛洪 ✓。
坑
① 学的是源 MAC、查的是目的 MAC——方向记反是此题型头号丢分点。
② 交换机按 MAC 在数据链路层转发，不看 IP、不做路由选择，别与路由器混。
③ 未划分 VLAN 的普通交换机每个端口是独立的冲突域、但整机默认仍是同一个广播域：广播帧照样泛洪到所有端口；配置 VLAN 后不同 VLAN 属于不同广播域，划分广播域也可经路由器。
④ 表项会老化：主机久不发帧其表项被删，下次发往它的帧又变回泛洪，不是「学过就永远单播」。
⑤ 与集线器对比：集线器（Hub，集线器）无交换表、收到信号都向除接收端口外的其他端口重复转发，且所有端口同属一个冲突域。
12. 网络层的功能 ★★★ · 近6年×2

定位：NET 第 4 章网络层的总纲。后面各卡分别细讲 IP、子网、分片、路由协议，本卡先立框架：网络层一共管哪几件事、每件事由谁做。用一个分组的旅程贯穿全卡：主机 A（以太网，10.0.1.2）要把一个 IP 分组送给另一个以太网里的主机 B（10.0.3.9），途中依次经过路由器 R1、一段广域网 PPP 链路、路由器 R2。

转发 vs 路由选择：查表与建表是两件事

分组到达 R1 时，R1 做的事只有一件：看分组的目的 IP，查本机的转发表，决定从哪个端口送出去——这叫转发。它逐分组发生、只看自己手里这张表、只管眼前这一步。那张表从哪来？路由协议可独立于具体用户数据分组持续运行和更新路由信息：路由器之间互相交换路由信息，运行路由算法（如 RIP、OSPF，细则见《RIP 与 OSPF 对比》卡）算出到各个网络该走哪条路，生成并更新转发表——这叫路由选择。一句话记牢：路由选择负责建表（控制层面，面向全网），转发负责查表（数据层面，面向单个分组）；考题最爱把两者的定义对调。

网络互联：把异构网络缝成一个网络

这趟旅程的三段路并不相同：两段以太网用的是一种帧格式，中间 PPP 链路是另一种，地址格式、最大帧长也各不一样。分组每经过一个路由器，链路层封装通常需要重新建立；无 NAT 时源、目的 IP 通常不变，但 IPv4 的 TTL 与首部校验和会相应更新；经不同链路时帧格式及寻址字段也可能不同（例如以太网帧有 MAC 地址字段，PPP 帧没有）。网络层的核心本事，就是用统一的 IP 协议把这些物理上异构的网络屏蔽成一个逻辑网络。路由器是通过网络层实现不同 IP 网络互联的典型设备；具有三层转发能力的交换设备也能承担路由功能；普通二层交换机主要在同一二层网络内转发帧。中继器只放大信号（物理层），缝不了异构网络。途经小 MTU 链路时的分片处理见《IP 数据报分片》卡。

拥塞控制在网络层的定位：辅助位，不是主角

假设旅程中 PPP 链路突然被大量分组挤满、路由器队列溢出，这就是拥塞：整个网络的负载超过了它的处理能力，是全局问题（区别于流量控制——那是收发双方点对点的事）。定位要记准：根据拥塞反馈真正调小发送速率的主体在传输层，即 TCP 的慢开始与拥塞避免（见《TCP 拥塞控制四阶段》卡）；网络层站在辅助位：路由选择时绕开拥塞热点，路由器通过队列调度、丢弃或标记分组，把「堵了」的信号递给端系统。所以「拥塞控制完全由网络层负责」和「拥塞与网络层无关」两种说法都错。

SDN：把「建表」从路由器里搬出来

传统网络里，转发和路由选择挤在同一台路由器中。SDN（软件定义网络）把两者拆开：数据平面只剩下交换机，按流表做匹配—转发，相当于纯粹的转发员；控制平面是一个逻辑集中的控制器，掌握全网视图，集中算好流表再下发给各交换机。两类接口别记反：控制器与交换机之间是南向接口（典型协议 OpenFlow），管的是「向下发流表」；上层网络应用与控制器之间是北向接口（一组 API），管的是「向上供应用调用」。

例题（真题风格，程序验算）
沿上面的旅程回答：① 分组离开 A 时 TTL＝64，到达 B 时 TTL 是多少？② 下列说法正确的有哪几项？I. R1 查转发表把分组送往 R2 方向的端口，属于转发；II. 各路由器运行 OSPF 更新转发表，属于路由选择；III. SDN 控制器通过北向接口向交换机下发流表；IV. 拥塞控制完全由网络层负责，传输层不参与。
推导 ①：TTL 只在被路由器转发时减 1，主机发出和二层设备转发都不减。这趟旅程只有 R1、R2 两台路由器：64 → 经 R1 得 63 → 经 R2 得 62。
推导 ②：I ✓——查现成的表、送单个分组，正是转发的定义。II ✓——运行路由协议算路建表，正是路由选择。III ✗——向交换机下发流表走的是南向接口，北向接口朝上服务应用，方向反了。IV ✗——拥塞控制的主体是传输层的 TCP，网络层只是辅助，「完全由网络层负责」错。
结论：① 62；② 只有 I、II 正确。
坑：
① 转发≠路由选择：一个查表送分组、一个算路建表，定义对调是本点头号出题法。
② 逐跳看链路层与网络层：链路层封装通常需要重新建立，帧格式及寻址字段也可能不同；无 NAT 时源、目的 IP 通常不变，但 IPv4 的 TTL 与首部校验和会相应更新。经普通二层交换机转发不减 TTL。
③ 路由器是通过网络层实现不同 IP 网络互联的典型设备；具有三层转发能力的交换设备也能承担路由功能；普通二层交换机主要在同一二层网络内转发帧。
④ SDN 接口方向：南向朝下对交换机（OpenFlow），北向朝上对应用（API）——按「向下／向上」的画面记，别按字母记。
⑤ 拥塞控制（全网、主体在传输层、网络层辅助）≠流量控制（点对点、收发双方之间），两个概念的范围和楼层都不同。

15. CIDR 与路由聚合 · 最长前缀匹配 ★★★★★ · 近6年×5

合辑《子网划分计算》讲的是把一个网分小；本卡补反方向：用 CIDR（Classless Inter-Domain Routing，无分类域间路由选择）把多个连续小网在路由表里合并成一条，以及路由器拿到目的地址后到底按哪条走。

划分与聚合是一对镜像考点。

CIDR 记法：地址写成 a.b.c.d / x，x 为网络前缀位数（等价于掩码中 1 的个数）。

它取消了 A / B / C 类的固定边界，前缀长短可任意。

路由聚合（超网）：把若干网络号连续的网络合并为一条路由。能整段聚合的条件有三：

① 地址连续。
② 高位（二进制前缀）相同，共同前缀有多长、聚合后的 /x 就是多少。
③ 起始地址对齐——聚合块的起始地址必须是块大小的整数倍（等价于被合并段恰好构成一个完整的对齐块）。

聚合能减少路由表项、降低路由信息的存储与维护开销、提高可扩展性，这是 CIDR 的主要目的（实际转发速度是否提升还取决于路由器的查表实现）。

例题（ipaddress 模块独立验证）：
① 聚合：将 192.168.0.0/24、192.168.1.0/24、192.168.2.0/24、192.168.3.0/24 四个网合并。
第三段字节 0～3 的二进制为 00000000 ～ 00000011，前 6 位相同 → 聚合为 192.168.0.0/22（前缀 24 − 2 = 22）✓。
② 对齐反例：192.168.4.0/24 与 192.168.5.0/24 可聚合成 192.168.4.0/23。
但 192.168.5.0/24 与 192.168.6.0/24 虽然地址连续，不能整段聚合成一条 /23——/23 块必须从偶数段起（5 与 6 跨了对齐边界），只能写成两条 ✓。

最长前缀匹配（Longest Prefix Match，最长前缀匹配）：转发时路由表可能有多条都「匹配」目的地址，规则是选前缀最长（网络最具体）的那一条优先。

默认路由 0.0.0.0/0 前缀长为 0、能匹配一切地址，永远是最后兜底。

例题（ipaddress 模块独立验证）：
路由表：192.168.0.0/16 → 接口 0；192.168.5.0/24 → 接口 1；192.168.5.128/25 → 接口 2。
目的 192.168.5.200 三条全匹配，取最长的 /25 → 接口 2。
目的 192.168.5.10 只匹配 /16 与 /24 两条 → 接口 1 ✓。
坑：
① 聚合只看「连续」不够，还要对齐——5.0 与 6.0 连续但不可整聚，是最常见的设套点。
② 精确聚合要求聚合块恰好覆盖原有网络、且这些网络能经相同下一跳正确到达：把额外的网包进聚合块又无更具体路由兜底，会误收本应转发他人的分组、甚至形成黑洞。
③ 最长前缀匹配先比前缀长度，不是先比跳数或度量；度量只在同一前缀的多条路由之间再比。
④ /x 里的 x 数的是前缀位数：/22 的掩码是 255.255.252.0，别与主机位数混算。

20. TCP 可靠传输 · 序号、确认与超时重传 ★★★★★ · 近6年×6

合辑已有 TCP 滑动窗口（流量控制）、拥塞控制、握手挥手，本卡补传输层另一半：数据丢了、乱了，TCP 靠什么发现并补回来。

注意与《GBN / SR 窗口》卡对照：TCP 的接收方行为与 GBN 不同。

序号（Sequence Number）：TCP 是字节流：每个字节编一个序号，报文段的序号 = 其首字节的序号。

初始序号（ISN，Initial Sequence Number）随机选取，避免旧连接的报文混入新连接。

32 位序号按模 232 循环，空间用完即回绕。

回绕未必很慢：以 1 Gbit/s 持续发送计，绕完 232 字节只需约 34.4 s，可能短于报文的最大生存时间，旧报文的序号可能与新数据重叠。

两件事分工不同：随机 ISN 让不同连接实例的序号空间错开，降低旧连接的报文混入新连接的风险。

同一连接在高速传输中发生序号回绕时，则靠 TCP 时间戳与 PAWS（Protection Against Wrapped Sequence Numbers，序号回绕保护）按时间戳新旧拒收旧段。

确认（Acknowledgment）：累计确认：确认号 ack = 期望收到的下一字节序号，表示该号之前的所有字节已正确收到。

确认可捎带在数据段中发出。

收到失序段时，TCP 接收方一般缓存该段并立即发重复 ACK——这与 GBN（接收窗口为 1，失序段直接丢弃）不同，是选择题常设的对比点。

校验和出错的段直接丢弃，发送方靠超时重传补回（TCP 没有否定确认 NAK）。

超时重传（Retransmission Timeout, RTO）：发送方发完段启动计时器，超时未收到确认即重传。

RTO 不能定死：网络时延会变，故用加权平均估计（Jacobson 算法，王道口径，α = 1/8，β = 1/4）：

平滑往返时间 SRTT（Smoothed Round-Trip Time）
SRTT新 = (1 − α) × SRTT旧 + α × RTT样本
往返时间偏差 RTTVAR
RTTVAR新 = (1 − β) × RTTVAR旧 + β × |SRTT旧 − RTT样本|
超时重传时间
RTO = SRTT新 + 4 × RTTVAR新
例题（程序验算）：SRTT旧 = 100 ms，RTTVAR旧 = 20 ms，新测 RTT样本 = 120 ms →
SRTT新 = 0.875 × 100 + 0.125 × 120 = 102.5 ms。
RTTVAR新 = 0.75 × 20 + 0.25 × |100 − 120| = 15 + 5 = 20 ms。
RTO = 102.5 + 4 × 20 = 182.5 ms。
重传触发条件随后处理（接《拥塞控制》卡）
超时重传计时器超时仍未收到确认慢开始门限 ssthresh = cwnd / 2，cwnd = 1，从慢开始重来
快重传（Fast Retransmit）收到 3 个重复 ACK，不等超时立即重传缺失段快恢复：ssthresh = cwnd / 2，cwnd = ssthresh（408 简化模型），进入拥塞避免
坑：
① 快重传的门槛是“3 个重复 ACK”，即连同原确认共 4 个相同 ack，不要写成“3 个 ACK”。
② 超时与快重传的 cwnd 处理不同：超时回 1，快重传不回 1——这是拥塞控制卡与本卡的联动考点。
③ RTO 公式里的偏差项用的是旧 SRTT 与样本之差的绝对值，不是新 SRTT；α、β 别互换（α 管 SRTT 为 1/8，β 管偏差为 1/4）。

区分：流量控制是端到端的接收能力问题；拥塞控制是全网负载问题。糊涂窗口综合征（接收方通告极小窗口、发送方发极小段）是流量控制的副作用，解法是接收方攒够再通告、发送方用 Nagle 算法攒够再发。
22. TCP（传输控制协议） 拥塞控制四阶段 ★★★★★ · 近6年×6
  • 慢开始：cwnd（拥塞窗口） 从 1 开始，每 RTT（往返时延） 翻倍。
  • 拥塞避免：cwnd 超过 ssthresh（慢开始门限） 后，每 RTT + 1。
  • 快重传：收到 3 个重复 ACK 立即重传。
  • 快恢复：ssthresh = cwnd2，cwnd = ssthresh。
【坑】超时时 ssthresh = cwnd2，cwnd = 1，从慢开始重来！
【口径】快恢复（cwnd = ssthresh）是 408 简化模型；TCP Reno 实现中还会把已收到的重复 ACK 计入窗口（cwnd = ssthresh + 3）。考试按简化模型答。
23. TCP（传输控制协议） 三次握手 ★★★★★ · 近6年×6
  • 1客户端 → 服务器：SYN = 1，seq = x。
  • 2服务器 → 客户端：SYN = 1，ACK = 1，seq = y，ack = x + 1。
  • 3客户端 → 服务器：ACK = 1，seq = x + 1，ack = y + 1。
【记】第三次握手可以携带数据，前两次不行。
24. TCP（传输控制协议） 四次挥手 ★★★★★ · 近6年×6
  • 1主动方 → 被动方：FIN = 1，seq = u。
  • 2被动方 → 主动方：ACK = 1，seq = v，ack = u + 1。
  • 3被动方 → 主动方：FIN = 1，ACK = 1，seq = w，ack = u + 1。
  • 4主动方 → 被动方：ACK = 1，seq = u + 1，ack = w + 1。
【坑】主动关闭方进入 TIME-WAIT 状态，等待 2MSL 后才关闭。

26. DNS 解析与 DHCP 分配过程 ★★★★ · 近6年×1

合辑《应用层协议对比》里 DNS（Domain Name System，域名系统）与 DHCP（Dynamic Host Configuration Protocol，动态主机配置协议）各只占一行表格，但两者的工作过程是选择题的固定考法：谁问谁、先问谁、用广播还是单播，一步记错整题皆错。本卡把两个过程补齐。

DNS 解析（主机查 www 的 IP 地址为例）：

域名空间是分层树：根域名服务器 → 顶级域名服务器 → 权威（权限）域名服务器。
主机先问本地 DNS 服务器，本地服务器代它向各级查询。
结果层层缓存（缓存有生存时间 TTL，到期失效）。
方式含义用在哪一段
递归查询被问的服务器必须给出最终答案：自己不知道就替询问者继续问下去，最后把结果带回主机 → 本地 DNS 服务器
迭代查询被问的服务器不知道就返回「下一级该问谁」，由询问者自己接着问本地 DNS 服务器 → 根 / 顶级 / 权威服务器（通常）
例题（流程计数）
设主机与本地 DNS 服务器均未缓存结果，解析不涉及额外域名委派、CNAME 跳转及重试，采用根 → 顶级 → 权威三级查询模型。
主机查一个这样的域名：主机向本地服务器发 1 次递归查询。
本地服务器依次向根、顶级、权威服务器发 3 次迭代查询，拿到地址后答复主机。
全程查询报文共 4 次（不计各级之间的答复报文）。
若本地服务器缓存命中，则对外查询为 0 次、直接答复 ✓。

DHCP 分配（四步 DORA，以下指首次申请地址时）：新主机还没有 IP 地址，只能用 0.0.0.0 作源地址、向 255.255.255.255 广播（客户端口 68、服务器端口 67、基于 UDP）：

  1. 发现 Discover：客户端广播找服务器；
  2. 提供 Offer：服务器（可有多台）各自提出一个待分配的地址等配置；
  3. 请求 Request：客户端选定一个后仍以广播形式正式请求——广播是为了让未被选中的服务器知道、收回各自的 Offer（续租阶段通常可改用单播）；
  4. 确认 ACK：被选服务器向客户端发送 DHCPACK，确认地址租约及配置——ACK 可采用广播或单播，取决于客户端状态与广播标志等条件；客户端收到确认后才能正式使用该地址（租期到期前要续租）。

跨子网时客户端广播到不了外网的服务器，由 DHCP 中继代理（通常在路由器上）代为转发。

坑：
① 递归与迭代的主体别记反：「主机对本地服务器是递归」指本地服务器负全责；本地服务器对根服务器一般是迭代——被问者只指路、不代跑。
② DNS 主要用 UDP 53，但区域传送以及响应过大等场合用 TCP 53，「DNS 只用 UDP」是错误选项。
③ DHCP 的 Request 还用广播不是失误：此时地址尚未经 ACK 确认、客户端还不能当作自己的单播地址用，且需要通知落选服务器。
④ DHCP 分配的不只是 IP 地址，还包括子网掩码、默认网关与 DNS 服务器地址等配置；「自动分配」不等于「永久拥有」，地址有租期。

最容易混的三对
页框号 vs 主存块号：切分粒度不同——页框号是把物理地址按 4 KB 的页切出的高位，主存块号是按 64 B 的块切出的高位；同一个物理地址里同时存在两套切法，位数也不同（18 位 vs 24 位）。
页内偏移 vs 块内地址：都是偏移量（块内序号），但位数由各自的页 / 块大小决定——本例页内偏移 12 位、块内地址 6 位；一个地址的低 12 位是页内偏移，其中最低 6 位同时也是块内地址。
虚页号 vs 标记：都起「对身份」的作用，但虚页号是查页表 / TLB 的索引（地址里现成的字段），标记是 Cache 行里存着的字段、要拿主存地址的高位与它逐行比对。本例两者恰好同为 18 位，纯属数字巧合，含义完全不同。
