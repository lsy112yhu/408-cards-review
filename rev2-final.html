5. 浮点数加减运算 · 五步法 ★☆☆☆☆

五步法光背步骤没用，跟着一个例子走一遍就会了。设阶码 4 位补码（可表示 −8 ~ +7）、尾数双符号位、6 位数值位，均用补码，算 X + Y，其中 X = 23 × 0.1010（= 5），Y = 24 × 0.1101（= 13）。

  1. 1对阶（小阶向大阶看齐，阶差几位、尾数右移几位）：X 的阶 3 < Y 的阶 4，差 1 → [X]尾补 = 00.101000 算术右移 1 位，得 00.010100，阶变为 4。移出的位是 0，本次不丢精度。
  2. 2尾数加减（按补码相加）：00.110100 + 00.010100 = 01.001000。双符号位出现 01，是尾数溢出的形态——先别慌，这不是运算溢出，看第 3 步。
  3. 3规格化：补码规格化形式是正数 00.1×××××、负数 11.0×××××。现在是 01.×××，尾数溢出 → 右规：尾数右移 1 位得 00.100100，阶码 4 + 1 = 5。若结果形如 00.0××× 或 11.1×××（首数值位与符号位相同），则反过来左规：尾数每左移 1 位、阶码减 1，直到达标。
  4. 4舍入：对阶、右规时被移掉的位要处理。看一小段：尾数 00.100100 对阶右移 3 位，移出位恰为 100（正好半个单位）→ 按「0 舍 1 入」末位进 1，得 00.000101；若右移 4 位，移出位为 0100（不足半个单位）→ 直接舍去，得 00.000010。本例对阶、右规都没移出有效位，无舍入。（注：这是教学简化舍入；IEEE 754 默认是就近舍入、遇半取偶，不同。）
  5. 5溢出判断（只看阶码）：阶码 5 在 −8 ~ +7 内 → 无溢出。阶码上溢才是真溢出；阶码下溢按机器零处理（408 教学简化口径；IEEE 754 则用次正规数实现渐进下溢，数值过小时仍可能因舍入变为 0）。

结果：25 × 0.100100 = 18。十进制验算：5 + 13 = 18 ✓。

真题 · 2009 年第 13 题：浮点数加减运算包括对阶、尾数运算、规格化、舍入和判溢出等步骤。设浮点数的阶码和尾数均采用补码表示，位数分别为 5 位和 7 位（均含 2 位符号位）。若 X = 27 × 29/32，Y = 25 × 5/8，则用浮点加法计算 X + Y 的最终结果是（　）。A. 00111 1100010　B. 00111 0100010　C. 01000 0010001　D. 发生溢出
解：对阶（小阶向大阶看齐）：Y 尾数右移 2 位；尾数相加得 01,00010，符号位 01 需右规：尾数 00,10001、阶码 + 1 变为 8。阶码数值位只有 3 位、最大可表示 7，阶码 8 超出范围 → 判溢出 → D。（速算验证：X + Y = 27 × (29/32 + 5/32) = 28 × 17/32，阶 8 同样超限。）
易错：尾数溢出 ≠ 运算溢出——尾数溢出只需右规；只有阶码上溢才算溢出。尾数「双符号位判溢出」是定点数那套，别搬到浮点数上。
4. IEEE 754 浮点数【必背】 ★★★★★
类型总位数符号位阶码尾数偏置值
单精度 float32 位1 位8 位23 位127
双精度 double64 位1 位11 位52 位1023

规格化尾数隐含最高位 1（即实际尾数是 1.×××，存的只是小数部分）。

例（十进制 → 单精度）：把 −18.625 写成 IEEE 754 单精度。四步：① 符号位：负数 → 1。② 把数值写成 1.××× × 2e 形式：18.625 = 10010.1012 = 1.0010101 × 24，故 e = 4。③ 阶码 = e + 偏置 127 = 131 = 10000011。④ 尾数存小数部分 0010101，后补 0 凑满 23 位：00101010000000000000000。拼起来：1 10000011 00101010000000000000000（十六进制 C1950000）。反过来读一个数也一样：先拆三段，阶码减 127 得真阶，尾数前面补回隐含的 1。
坑：特殊编码要分清四种——阶码全 0 且尾数全 0 = ±0；阶码全 0、尾数非 0 = 次正规数（没有隐含 1）；阶码全 1、尾数全 0 = ±∞；阶码全 1、尾数非 0 = NaN。另：尾数存的是去掉隐含 1 之后的小数部分，别把 1 也写进去占位。
2. 补码运算规则 ★★★★★

求 [−X]补：[X]补 连同符号位取反加 1。

溢出判断（双符号位法）：00 正确（正）、11 正确（负）、01 正溢出、10 负溢出。如 +11 与 +13 用双符号位相加：001011 + 001101 = 011000，双符号位 01 → 正溢出（一眼可判，不用看数值位）。

Booth 算法（补码一位乘）：[X×Y]补 不能由 [X]补 与 [Y]补 直接相乘得到，要走部分积递推：看乘数相邻两位之差决定加 [X]补、加 [−X]补 还是加 0，再把（部分积， 乘数）整体算术右移一位；符号位全程参与运算。下面用定点整数完整走一遍。小数双符号位版与整数版的核心 Booth 判断及加减规则相同，但操作步数和最后移位安排不同（见本卡末注），不能混用：

例（Booth 全过程）：X = −13（[X]补 = 10011，[−X]补 = 01101），Y = +11（[Y]补 = 01011）。部分积 A 初值 00000，附加位 Q−1 = 0；每步看（Q 最低位， Q−1）这一对：(1,0) 加 [−X]补，(0,1) 加 [X]补，(0,0)/(1,1) 加 0，随后（A, Q）算术右移。
步判断位操作右移后 A右移后 QQ−1
1(1, 0)A += [−X]补 → 0110100110101011
2(1, 1)A += 000011010101
3(0, 1)A += [X]补 → 1011011011001010
4(1, 0)A += [−X]补 → 0100000100000101
5(0, 1)A += [X]补 → 1011111011100010
乘数 5 位就走 5 步。结果 = A 拼 Q = 11011 10001 = [−143]补。验算：−13 × 11 = −143 ✓。注意：整数单符号位版与小数双符号位版的轮数和移位安排不同，不要混用——整数版执行 n 轮、每轮均移位；小数双符号位版（见《定点数乘除运算》卡）通常执行 n + 1 步、最后一步只加减不移位。
8. Cache 替换算法与写策略 ★★☆☆☆

替换算法只在组相联 / 全相联才需要：直接映射中每个主存块只对应一个固定 Cache 行，冲突时直接替换该行，没有「选哪块换出」的问题。

替换算法换出对象特点
FIFO（先进先出）最先进入 Cache 的块实现简单，不看实际使用情况
LRU（最近最久未使用）最久未被访问的块有时间局部性的访问下通常命中率较高（但不保证对任何访问串都优于 FIFO），实现代价较大
LFU（最不经常使用）访问次数最少的块需维护计数；曾高频的旧块计数居高难被换出，对访问模式变化适应差
随机替换随机选一块实现最简单，命中率略低
例（同一访问串，两种算法）：Cache 共 3 行，块访问串 2, 1, 3, 2, 4, 2, 5, 1, 2, 3。
FIFO（只看进场先后）：2✗、1✗、3✗ 装满；2✓；4✗ 换出最老的 2；2✗ 换出 1；5✗ 换出 3；1✗ 换出 4；2✓；3✗ 换出 2 → 缺失 8 次。
LRU（看最近使用）：2✗、1✗、3✗ 装满；2✓（2 变最新）；4✗ 换出最久未用的 1；2✓；5✗ 换出 3；1✗ 换出 4；2✓；3✗ 换出 5 → 缺失 7 次。
差别就在第 5 步：2 刚被访问过，LRU 保它、FIFO 照样按进场顺序把它换出——这就是本例中 LRU 缺失次数更少的原因。
写策略（写命中时）代价 / 注意
写直通同时写 Cache 和主存：主存始终一致，写操作慢；无需脏位；常配非写分配
写回只写 Cache 并置脏位，换出时才写回主存：写得快，需脏位，一致性处理更复杂；常配写分配

写直通 / 写回说的是「写命中」；写不命中是另配一对策略（写分配 / 非写分配），两对不要混成一对答。

星级注：本卡星级依据弱——「Cache 写策略」标签仅 2 年（2015、2021）且替换算法无独立标签，多随 Cache 综合题附带考查，2★ 为保守定档，待更细的逐题统计校准。

2. KMP（克努特–莫里斯–普拉特模式匹配算法） 串模式匹配 · next 数组与 nextval ★★☆☆☆

核心思想：匹配失配时主串指针 i 不回退，只按 next 数组回退模式串指针，跳过已知不可能匹配的位置。复杂度：求 next 为 O(m)，匹配为 O(n)，总计 O(n + m)，空间 O(m)；朴素 BF 最坏 O(n·m)。

例（next 与 nextval 全计算）：模式串 P = ABABAC，用 408 / 王道口径（下标 1 起）：next[1] = 0，next[j] = 「P 前 j − 1 个字符的最长相等真前缀与真后缀长度」+ 1。逐位算：
j1 (A)2 (B)3 (A)4 (B)5 (A)6 (C)
考察串—AABABAABABABABA
最长相等前后缀—001 (A)2 (AB)3 (ABA)
next[j]011234
nextval[j]010104
nextval 是 next 的「防白比」优化：若 P[j] = P[next[j]]，失配跳过去还会再失配，索性一步跳到底，nextval[j] = nextval[next[j]]；不同则 nextval[j] = next[j]。如 j = 5：P[5] = A，P[next[5]] = P[3] = A，相同 → nextval[5] = nextval[3]；而 P[3] = A = P[1]，nextval[3] = nextval[1] = 0，故 nextval[5] = 0。j = 6：P[6] = C ≠ P[4] = B → nextval[6] = next[6] = 4。
手算口诀：在失配位置之前划一条分界线，将模式串逐步后退，直到分界线之前的前缀能与刚划过的后缀对齐，此时 j 指向哪里，next 值就是多少。滑动规则：失配时主串指针 i 不动，模式串右移 j − next[j] 位。

另有「长度定义」（下标 0 起）：next 值即最长相等真前后缀长度本身，如 ABABAC 依次为 0, 0, 1, 2, 3, 0。两套口径数值整体差 1，做题先认题干给的定义。

真题 · 2019 年第 9 题：设主串 T = “abaabaabcabaabc”，模式串 S = “abaabc”，采用 KMP 算法进行模式匹配，到匹配成功时为止，单个字符间的比较次数是（　）。A. 9　B. 10　C. 12　D. 15
解：S 的 next 数组（下标 0 起口径）为 −1, 0, 0, 1, 1, 2。第一趟从 T[0] 起连比 6 次，在 T[5] = a 与 S[5] = c 处失配；按 next[5] = 2 回退，S[2] 与 T[5] 对齐继续，连比 4 次（T[5..8] 依次对 S[2..5]）匹配成功。共 6 + 4 = 10 次 → B。
坑：不同教材下标起点不同（0 起 / 1 起），next 数值会整体差 1。做题先认题干给的 next 定义，不要硬背一组数字。
10. 图的遍历与生成树 ★★★★☆

DFS（深度优先）一路走到底再回头，得到深度优先生成树 / 森林；BFS（广度优先）按层推进，得到广度优先生成树 / 森林。连通图遍历一次得生成树，非连通图得生成森林。序列怎么来，看例子：

例（同一张图跑 DFS 与 BFS）：无向图邻接表（邻接点按编号从小到大）：V1: V2, V3；V2: V1, V4, V5；V3: V1, V5；V4: V2, V6；V5: V2, V3, V6；V6: V4, V5。从 V1 出发。
DFS：访问 V1 → 钻 V2 → 钻 V4 → 钻 V6 → V6 的邻居只剩 V5 未访，钻 V5 → V5 的邻居只剩 V3，钻 V3 → 全部访问完回溯。序列：V1, V2, V4, V6, V5, V3。
BFS：访问 V1，V2、V3 入队；出队 V2，V4、V5 入队；出队 V3（邻居都已在队中）；出队 V4，V6 入队；再依次出队 V5、V6。序列：V1, V2, V3, V4, V5, V6。
真题 · 2020 年第 6 题：修改递归实现的 DFS 算法，将输出顶点信息的语句移到退出递归前（递归返回时才输出）。用修改后的算法遍历有向无环图 G，若输出结果包含 G 中的全部顶点，则输出的顶点序列是 G 的（　）。A. 拓扑有序序列　B. 逆拓扑有序序列　C. 广度优先搜索序列　D. 深度优先搜索序列
解：任取一条边 ⟨vi, vj⟩：vi 入栈后必须先递归遍历完其后继 vj 才会返回输出，故 vj 总在 vi 之前输出——每条边都是终点在前、起点在后，正是逆拓扑序 → B。
坑：邻接表存储时，遍历序列不唯一（取决于边的存储顺序）。
11. 最小生成树对比 · Prim vs Kruskal ★★★☆☆
项目Prim（点出发）Kruskal（边出发）
做法从任一顶点长出一棵树，每步加「树内—树外」最小边边按权从小到大排序，依次加不成环的边（并查集判环）
时间复杂度邻接矩阵 O(V2)；邻接表 + 堆 O(E log V)排序主导 O(E log E) = O(E log V)
适合图稠密图稀疏图
停止条件连通图：共加 V − 1 条边；非连通图只能得到最小生成森林
例（同一张图，两种算法）：无向图边（端点，权）：(1,2)6、(1,3)1、(1,4)5、(2,3)5、(2,5)3、(3,4)5、(3,5)6、(3,6)4、(4,6)2、(5,6)6。
Prim（从 1 出发，每步在「已收顶点 ↔ 未收顶点」的边里挑最小）：先收 (1,3)=1；候选里最小是 (3,6)=4；再 (6,4)=2；再 (3,2)=5；最后 (2,5)=3。选中边的权依次为 1、4、2、5、3，总权 15。
Kruskal（边按权从小到大，能连不同集合就要）：(1,3)=1 ✓、(4,6)=2 ✓、(2,5)=3 ✓、(3,6)=4 ✓（合并两组）、(1,4)=5 ✗（已在同一集合，加了成环，跳过）、(2,3)=5 ✓。共 5 条边，总权 15。
本例两条路线选边顺序不同，但最终选中的边集相同、得到同一棵树。一般规律是：最小生成树的权和唯一，树本身可以不唯一（存在可替代的等权边时）。另：求最小生成树的前提是图连通；非连通图没有覆盖全部顶点的生成树，两种算法都只能得到最小生成森林——Kruskal 跑完自然成森林，Prim 需对每个连通分量各启动一次。

13. 拓扑排序（AOV 网：顶点活动网） ★★★☆☆

做法只有三步：① 选一个入度为 0 的顶点输出；② 删掉它和它的全部出边（邻接点入度减 1）；③ 重复，直到输出全部顶点，或无入度为 0 的顶点可选（说明有环）。跟着例子走：

例（拓扑排序全过程）：有向边：1→3、2→3、2→4、3→5、4→5、5→6、1→2。初始入度：1: 0、2: 1、3: 2、4: 1、5: 2、6: 1。
输出 1 → 2、3 入度减 1（2 变 0）；输出 2 → 3、4 入度减 1（都变 0）；输出 3 → 5 入度变 1；输出 4 → 5 入度变 0；输出 5 → 6 入度变 0；输出 6。
得到序列 1, 2, 3, 4, 5, 6。第 3 步时 3、4 同时可选，先输出 4 也合法（1, 2, 4, 3, 5, 6）——拓扑序列一般不唯一。若中途输出数 < 顶点总数就无点可选，说明网中有环、工程不可行。
真题 · 2012 年第 6 题：若用邻接矩阵存储有向图，矩阵中主对角线以下的元素均为零，则关于该图拓扑序列的结论是（　）。A. 存在，且唯一　B. 存在，且不唯一　C. 存在，可能不唯一　D. 无法确定是否存在
解：下三角全零 ⇒ 边只可能由小编号顶点指向大编号顶点（i → j 蕴含 i < j），图必无环，拓扑序列一定存在（1, 2, …, n 本身就是一个）；但唯一性不能保证，如无边图的任意排列都是拓扑序列 → C。

真题 · 2020 年第 8 题：若用 AOE 网估算工程进度，则下列叙述中正确的是（　）。A. 关键路径是从源点到汇点边数最多的一条路径　B. 关键路径是从源点到汇点路径长度最长的路径　C. 增加任一关键活动的时间不会延长工程的工期　D. 缩短任一关键活动的时间将会缩短工程的工期
解：关键路径按路径长度（权值之和）最大界定，与边数无关，A 错、B 对；关键活动的时间余量为 0，增时会延长工期，C 错；存在多条关键路径时，只缩短其中一条路径上的活动不一定能缩短工期，D 错 → B。
坑：关键路径可能不唯一；缩短工期要求每条关键路径都被缩短——加快所有关键路径共有的关键活动最直接，也可分别加快每条关键路径上的活动；只加快某一条路径上的活动、其他关键路径不缩短，工期不变；关键活动缩过头会变成非关键活动（新关键路径出现），工期不再减少；但延长任一关键活动必延长工期。

例（信号量值全程追踪）：某资源共 2 台，信号量 S 初值 2。
时刻动作S发生了什么
t1P1 执行 P(S)1P1 占用 1 台，剩 1 台空闲
t2P2 执行 P(S)0P2 占用最后 1 台，无空闲

真题 · 2010 年第 25 题：设与某资源关联的信号量初值为 3，当前值为 1。若 M 表示该资源的可用个数，N 表示等待该资源的进程数，则 M、N 分别是（　）。A. 0、1　B. 1、0　C. 1、2　D. 2、0

坑：生产者—消费者问题中，P 操作顺序不能换（先 P 同步，后 P 互斥）。

算法选哪块效果 / 代价
首次适应从低地址起第一个够大的空闲区实现简单、通常查找开销较低；低地址碎片多，但高地址常保留大块
最佳适应够大空闲区中最小的那块每次分配的剩余空间最少，但容易留下大量难以利用的小碎片，不保证整体利用率最高；空闲区未按大小组织时需扫描全部空闲区
最坏适应最大的那块空闲区剩下的碎片较大、较可能再用；大块被快速切碎
邻接适应（循环首次）从上次分配处往后找第一个够大的空闲区分布均匀；大空闲区匮乏
例（同一内存、同一请求序列，三种算法）：空闲区按地址从低到高为 100K、500K、200K、300K、600K；请求依次为 212K、417K、112K、426K。
首次适应：212 → 500K 块（余 288K）；417 → 600K 块（余 183K）；112 → 288K 余块（余 176K）；426 → 无块可容，失败（空闲总量还剩 935K，却没有一块 ≥ 426K——这就是外部碎片）。
最佳适应：212 → 300K 块（余 88K）；417 → 500K 块（余 83K）；112 → 200K 块（余 88K）；426 → 600K 块（余 174K）→ 全部装下，代价是留下三个几十 K 的小碎片。
最坏适应：212 → 600K 块（余 388K）；417 → 500K 块（余 83K）；112 → 388K 余块（余 276K）；426 → 失败。

碎片：外部碎片 = 空闲区总量够、单块都不够；内部碎片 = 已分配区内用不上的零头。紧凑（拼接）能消除外部碎片，但要移动进程、代价大。

真题 · 2019 年第 32 题：在下列动态分区分配算法中，最容易产生内存碎片的是（　）。A. 首次适应算法　B. 最坏适应算法　C. 最佳适应算法　D. 循环首次适应算法
解：最佳适应每次选取与需求大小最接近的空闲分区，剩余部分往往是难以再利用的微小空闲块，外碎片最多 → C。
16. 磁盘调度算法 ★★★☆☆

FCFS（先来先服务）：按请求到达顺序服务，简单但效率低。SSTF（最短寻道时间优先）：每次选离磁头最近的请求，可能饥饿。SCAN（电梯）：磁头单向移动服务沿途请求，到端点再反向。C-SCAN：到端点后直接返回起点、只单向服务。LOOK / C-LOOK：不用到端点，到本方向最远请求即返回。

例（同一请求队列，四种算法）：磁道 0 ~ 199，磁头在 53，请求队列依次为 98, 183, 37, 122, 14, 124, 65, 67。
算法服务顺序总移动距离
FCFS98, 183, 37, 122, 14, 124, 65, 67（原序）640
SSTF65, 67, 37, 14, 98, 122, 124, 183236
SCAN（先向大号）65, 67, 98, 122, 124, 183,（到 199 后反向）37, 14331
C-SCAN（先向大号）65, 67, 98, 122, 124, 183,（到 199 后直接回 0）14, 37382
FCFS 的 640 几乎全浪费在来回横跳上；SSTF 贪心就近最省路，但远处请求可能一直等；SCAN 多走「到端点」的路，换来公平、无饥饿。
真题 · 2021 年第 26 题：某系统中磁盘的磁道数为 200（0 ~ 199），磁头当前在 184 号磁道上。用户进程提出的磁盘访问请求对应的磁道号依次为 184, 187, 176, 182, 199。若采用最短寻道时间优先（SSTF）调度算法完成磁盘访问，则磁头移动的距离（磁道数）是（　）。A. 37　B. 38　C. 41　D. 42
解：184 就地服务（移动 0）；当前最近的是 182（2）；再选 187（5）；再选 176（11）；最后 199（23）。总移动距离 = 0 + 2 + 5 + 11 + 23 = 41 → C。
6. GBN（后退 N 帧协议） 与 SR（选择重传协议） 窗口大小 ★★★★☆

设序号位数为 n 位，序号范围 0 ～ 2n − 1。GBN（后退 N 帧）：发送窗口 WT ≤ 2n − 1，接收窗口 WR = 1。SR（选择重传）：发送窗口 + 接收窗口 ≤ 2n，通常各取 2n−1。为什么 GBN 的接收窗口只能是 1、代价是什么，看例子：

例（一帧丢失，两种协议的反应）：序号 3 bit，发送窗口取 4。发送方连发 0、1、2、3 号帧，其中 1 号帧在途中丢失。
GBN：接收方只按序接收——0 号收下；2、3 号到达时，它期待的是 1 号，乱序帧直接丢弃（重复发送对 0 号帧的累计确认；若按「下一期待帧」编号则写作 ACK 1）。发送方超时后从 1 号起重传 1、2、3 三帧：2、3 明明已经到过一次，还得白传一遍，这就是「后退 N 帧」的代价。接收窗口 = 1 的根源就在这：它不缓存乱序帧。
SR：接收窗口同样是 4，2、3 号先缓存下来；发送方只需单独重传 1 号；1 号一到，1、2、3 按序一起交付。只补缺口、不传冤枉路，代价是接收方要有缓存、双方窗口都要受「和 ≤ 2n」约束。
真题 · 2023 年第 35 题：假设通过同一信道，数据链路层分别采用停等协议、GBN 协议和 SR 协议（发送窗口和接收窗口相等）传输数据，三个协议数据帧长相同，忽略确认帧长度，帧序号位数为 3 bit。若三个协议的发送方最大信道利用率分别是 U1、U2、U3，则它们满足的关系是（　）。A. U1 ≤ U2 ≤ U3　B. U1 ≤ U3 ≤ U2　C. U2 ≤ U3 ≤ U1　D. U3 ≤ U2 ≤ U1
解：在未饱和前，发送窗口越大、信道利用率越高（达到 100% 后饱和、不再增长）：停等窗口为 1，最小；GBN 发送窗口最大 23 − 1 = 7；SR 发送窗口最大 23−1 = 4。故 U1 ≤ U3 ≤ U2 → B。
